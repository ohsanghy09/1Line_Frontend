# 1Line React + TypeScript 구현 가이드라인

> 기준 파일: [1Line_reference.html](./1Line_reference.html) · 분석일: 2026-10-31
>
> Growth Map을 제거한 현재 HTML의 마크업, 스타일, 데이터, JavaScript 전체를 기준으로 작성했다. 이 문서는 구현 명세이며, 앱 구현이나 백엔드 연동을 완료했다는 의미가 아니다. 브라우저에서 렌더링한 결과의 시각 검수는 별도 수행해야 한다.

## 1. 문서 적용 원칙

- **원본 기준**: HTML에서 확인되는 화면 구성, 문구, 색상, 간격, 반응형 전환, 예시 시나리오를 재현한다.
- **구현 보완**: 원본의 고정 데이터, 잘못된 연결, 미동작 버튼은 디자인 의도를 유지하면서 데이터 기반 동작으로 바꾼다. 아래에서 별도로 표시한다.
- **제안**: URL, 디렉터리, 타입 이름, 상태 구조는 React 구현을 위한 제안이다. 원본에 이미 존재하는 사양으로 해석하지 않는다.
- **연동 미정**: API 주소, 인증, 파일 용량 제한, 허용 확장자, AI 응답 계약은 HTML에 없다. 임의로 확정하지 않고 서비스 경계와 mock 구현을 먼저 만든다.
- Growth Map 화면, 메뉴, 네트워크 그래프, 연결 필터는 구현 범위에서 제외한다.
- 소스 파일 이름은 `1Line`이지만, 화면의 브랜드 표기는 원본대로 **Growth Archive**, 부제는 **Personal AI Knowledge**다. 임의로 브랜드를 변경하지 않는다.

## 2. 현재 프로젝트 상태

| 항목 | 확인된 설정 |
| --- | --- |
| 실행 기반 | Vite 8 계열 + React 19 계열 + TypeScript 7 계열 |
| 스타일 | Tailwind CSS 4 계열, `@tailwindcss/vite` 설치 및 Vite 플러그인 등록 완료 |
| 글로벌 스타일 | `src/index.css`에 `@import "tailwindcss";` 존재 |
| 진입점 | `src/main.tsx`, `StrictMode`, `src/index.css` import |
| 현재 화면 | `src/pages/MainPage.tsx`, `src/examples/ExamplePage.tsx`의 임시 화면 |
| 현재 라우팅 | `src/main.tsx`의 BrowserRouter, `src/App.tsx`의 `/`, `/example` 연결 |
| 검사 | `npm run build` → TypeScript 검사 후 Vite 빌드, `npm run lint` → oxlint |
| 앞으로 만들 구성 | MainPage의 Sidebar/Outlet, Home·GrowthJourney·Footprints 자식 페이지, 앱 데이터 계층, React 아이콘 |

이미 구성된 Vite/Tailwind를 다시 초기화하지 않는다. HTML의 Tailwind CDN, `tailwind.config` 스크립트, Lucide 전역 스크립트를 React 앱에 그대로 붙이지 않는다.

## 3. 서비스 구조와 화면 이동

핵심 흐름은 **자료 또는 경험 먼저 입력 → AI가 활동/자료 유형 분류 → 기존 기록과 비교 → 사용자 확인 또는 수정 → 아카이브와 변화 기록 반영**이다. 프로젝트 생성부터 요구하는 별도 온보딩은 원본에 없다.

### 3.1 화면 목록

| 화면 컴포넌트 | 원본 section ID | 목적 | URL 제안 | 사이드바 소속 |
| --- | --- | --- | --- | --- |
| `Home` | `page-home` | AI 채팅, 자료 입력, 최근 활동/기록 | `/` | 홈 |
| `GrowthJourney` | `page-growthJourney` | 여러 활동에 걸친 개인 성장 흐름 | `/journey` | Growth Journey |
| `Footprints` | `page-footprints` | 활동 검색/필터/목록 | `/archive` | 나의 발자국 |
| `ActivityArchivePage` | `page-activityArchive` | 특정 활동 정보와 자료 폴더 | `/archive/:activityId` | 나의 발자국의 하위 화면 |
| `ProjectTimelinePage` | `page-projectTimeline` | 특정 활동의 변화 과정 | `/archive/:activityId/timeline` | 나의 발자국의 하위 화면 |

### 3.2 이동 규칙

| 시작 위치 | 동작 | 목적지/결과 |
| --- | --- | --- |
| 브랜드 로고 | 클릭 | 홈 |
| 사이드바 3개 메뉴 | 선택 | 해당 상위 화면 |
| 홈 최근 활동 카드 | 클릭 | 현재 홈 작업에서는 나의 발자국(`/archive`); 활동 상세 연결은 이후 작업 |
| 홈 최근 활동의 전체 보기 | 클릭 | 나의 발자국(`/archive`) |
| 홈 최근 추가된 기록 | 클릭 | 현재 홈 작업에서는 나의 발자국(`/archive`); 기록이 속한 활동 상세 연결은 이후 작업 |
| 나의 발자국 활동 행 | 클릭 | 해당 활동 상세 |
| 활동 상세 상단 | 변화 과정 보기 | 동일 활동 Project Timeline |
| 활동 상세 뒤로가기 | 클릭 | 나의 발자국 |

| 파일 Drawer 하단 | Project Timeline에서 보기 | Drawer 닫기 후 동일 활동 타임라인, 관련 이벤트가 있으면 위치 표시 권장 |
| Project Timeline 뒤로/관련 자료 | 클릭 | 동일 활동 상세 |
| AI 결과 카드 | 수정/다른 활동 선택 | 해당 분석 결과의 분류 수정 Modal |
| 입력창 링크 버튼 | 클릭 | 링크 추가 Modal |

**구현 방식**: 원본의 전역 `currentPage`와 `hidden` 토글 대신, 이미 설치한 React Router의 중첩 라우트를 사용한다. MainPage는 사이드바와 본문 틀을 유지하고, URL에 맞는 자식 페이지를 Outlet에 표시한다. 별도 메뉴 선택 state로 같은 페이지 전환을 중복 관리하지 않는다. 상세/타임라인에서는 사이드바의 나의 발자국을 활성화한다. 원본은 상세 메뉴 ID가 없어 활성 표시가 사라진다.

### 3.3 MainPage와 자식 페이지 연결

`MainPage`는 독립적인 홈 콘텐츠가 아니라 사이드바와 본문 자리를 담는 부모 페이지다. `Home`, `GrowthJourney`, `Footprints`는 각각 별도 파일로 작성하는 자식 페이지다. 재사용하지 않는 화면도 React 컴포넌트로 작성하지만, 역할상 페이지라고 구분한다. 자식 관계는 라우팅 관계이며 파일을 MainPage 폴더 안에 넣는다는 뜻이 아니다.

```text
MainPage
├── Sidebar                  메뉴 이동 시 유지
└── Outlet                   URL에 맞춰 본문 교체
    ├── Home                 /
    ├── GrowthJourney        /journey
    └── Footprints           /archive

ExamplePage                  /example, MainPage 밖의 독립 예시 페이지
```

아래는 앞으로 적용할 라우팅 예시다. 실제 앱 코드를 이미 수정했다는 뜻은 아니다. 페이지 파일을 만든 뒤 해당 import와 Route를 함께 추가한다.

```tsx
// src/App.tsx
import { Route, Routes } from 'react-router'
import MainPage from './pages/MainPage'
import Home from './pages/Home'
import GrowthJourney from './pages/GrowthJourney'
import Footprints from './pages/Footprints'
import ExamplePage from './examples/ExamplePage'

export default function App() {
  return (
    <Routes>
      <Route path="/" element={<MainPage />}>
        <Route index element={<Home />} />
        <Route path="journey" element={<GrowthJourney />} />
        <Route path="archive" element={<Footprints />} />
      </Route>
      <Route path="/example" element={<ExamplePage />} />
      <Route path="*" element={<p>페이지를 찾을 수 없어요.</p>} />
    </Routes>
  )
}
```

- `src/main.tsx`의 기존 BrowserRouter를 유지한다. MainPage나 자식 페이지에서 BrowserRouter를 추가하지 않는다.
- `index`는 부모 경로 `/`에서 보여줄 기본 자식 페이지다. 자식 경로 `journey`, `archive`는 `/` 아래에 연결된다.
- MainPage에는 `<Sidebar />`와 `<main><Outlet /></main>`을 둔다. Home에 공통 사이드바를 다시 넣거나 MainPage에서 자식 페이지를 직접 조건부 렌더링하지 않는다.
- Sidebar는 `NavLink`로 이동하며 `isActive`로 활성 메뉴 스타일을 정한다. 홈 링크는 `<NavLink to="/" end>`로 정확히 일치할 때만 활성화한다. 나의 발자국은 `/archive` 하위 상세 경로에서도 활성화한다.
- 이후 활동 상세와 Project Timeline도 MainPage의 자식 Route로 추가해 사이드바를 유지한다. 경로가 `/archive/:activityId`라고 해서 Footprints 안에 렌더링할 필요는 없다.
- 기존 `/example`은 MainPage의 자식으로 옮기지 않고 현재처럼 독립 예시 페이지로 유지한다.

## 4. 공통 레이아웃

### 4.1 MainPage의 공통 화면 틀

- `src/pages/MainPage.tsx`가 공통 레이아웃 역할을 맡는다. 별도 AppShell/AppLayout 파일이나 layouts 폴더를 만들지 않는다.
- 전체 배경 `#F8F9FC`, 기본 글자 `#111827`, Pretendard 기반 sans-serif, 최소 화면 높이 `100vh`.
- `md` 미만: 사이드바가 콘텐츠 위에 놓이는 세로 배치. 원본에 햄버거 메뉴나 접이식 모바일 메뉴는 없다.
- `md` 이상: 사이드바와 본문 가로 배치. 사이드바 너비 240px, `sticky top-0`, 높이 `100vh`.
- 본문: `flex-1 min-w-0 max-w-[1400px] mx-auto`, 기본 padding 16px, `sm` 24px, `lg` 32px, 큰 블록 간격 24px.
- 본문의 최대 너비 1400px에는 사이드바 너비를 포함하지 않는다. React 루트 래퍼에 레이아웃을 적용해 `body`와 `#root`의 flex 관계가 달라지지 않게 한다.

### 4.2 Sidebar

- 브랜드: 36px 정사각형 연한 파란 배경 + Sparkles 아이콘, 제목 16px bold, 부제 11px.
- 메뉴 순서: 홈 → 섹션 제목 `나의 성장일지` → Growth Journey → 섹션 제목 `아카이브` → 나의 발자국.
- 메뉴: 14px medium, 아이콘 16px, 둥근 모서리 12px, 가로 padding 14px.
- 활성 메뉴: 연한 파란 배경, 파란 글자, 왼쪽 4px 파란 border.
- 하단 프로필: 연한 slate 카드, 파랑/보라 그라데이션 32px 아바타, `김성장 님`, `활동 6개 기록 중`, Settings 아이콘.
- `활동 6개`는 구현 시 데이터에서 계산한다. Settings는 원본에 클릭 동작과 설정 화면이 없으므로 별도 기능을 만들어 범위를 늘리지 않는다.
- 원본 주석에는 성장일지 섹션을 collapsible이라고 쓰지만, 실제 접기 기능은 없다.

## 5. 화면별 상세 명세

### 5.1 홈: Home

순서는 **페이지 제목 → 채팅 패널 → 최근 활동/최근 기록**이다.

1. 제목 `오늘 어떤 경험을 기록해볼까요?`, 설명 `파일이나 링크를 올리거나, 오늘 있었던 일을 간단히 적어보세요. Growth AI가 기존 기록과 연결해 정리해드려요.`
2. 채팅 패널: 높이 520px, 흰색 배경, radius 16px, 테두리와 soft shadow, 세로 flex, overflow hidden.
3. 헤더: Growth AI 아이콘/이름, 초록 점과 `기록 정리 준비됨` 배지, `대화 초기화` 버튼.
4. 메시지 영역: 내부 세로 스크롤, padding 20px, 메시지 간격 16px. 메시지 추가 시 마지막으로 스크롤한다.
5. 초기 AI 인사: `안녕하세요! 오늘 만든 자료나 기록하고 싶은 경험을 남겨주세요.` + `어떤 활동인지 제가 먼저 확인하고 기존 기록과 연결해볼게요.`
6. 시연 시나리오 바: 4개 버튼을 표시하고 좁은 화면에서 줄바꿈한다. 실제 사용자의 AI 추천 메뉴와 혼동하지 않도록 시연 UI로 분리한다.
7. 입력 영역: 숨김 multiple 파일 input, 첨부 버튼, 링크 버튼, 한 줄 텍스트 input, 전송 버튼. form submit으로 Enter 전송, 공백 입력 무시, 전송 후 입력값 초기화.
8. 하단: 기본 1열, `lg` 이상 3열 중 최근 활동 2열/최근 기록 1열. 최근 활동 카드 내부는 기본 1열, `md`부터 3열.

| 메시지 요소 | 시각 기준 | 구현 조건 |
| --- | --- | --- |
| 사용자 메시지 | 오른쪽, 파란 말풍선/흰 글자, 최대 80%, 오른쪽 위 작은 radius | 텍스트/파일명/링크를 구조화 데이터로 표시 |
| 초기 AI 인사 | 왼쪽 bot 아바타, slate 말풍선, 최대 85% | 초기화 시 복구 |
| AI 결과 카드 | 왼쪽 Sparkles 아바타, 흰색 border/shadow 카드, 최대 90%, `sm`부터 85% | 결과 종류별 내부 구성 분기 |
| 타임스탬프 | 10px muted | 원본은 `방금 전`; 실제 앱은 생성 시각으로 표시 |
| 타이핑 | 8px 원 3개, 1.4초 반복, 0/0.2/0.4초 delay | 분석 대기 중만 표시 |
| 파일 분석 진행 | 256px 카드, 완료 체크 3줄 + 비교 중 spinner | 단계 데이터로 렌더링 |

### 5.1.1 현재 홈 작업 범위 — API 연동 준비와 목데이터 목록

아래는 2026-11-01에 정한 현재 홈 이슈의 구현 범위다. **현재 홈 작업은 이 절의 범위와 완료 기준을 우선한다.** 5.2의 분석/저장 시나리오와 이후 단계의 전체 서비스 동작은 후속 작업이며, 이번 이슈에서 모두 구현하지 않는다.

**채팅 영역**

- 원본의 페이지 제목, 설명, Growth AI 채팅 패널과 입력 영역을 구성한다.
- 입력값과 메시지 목록을 React 상태로 관리한다. 메시지는 사용자/AI 역할과 내용을 구분할 수 있는 타입으로 정의한다.
- 버튼 또는 Enter로 메시지를 전송하면 사용자 메시지를 목록에 추가하고 입력값을 초기화한다. 공백만 있는 메시지는 전송하지 않는다.
- 전송 처리와 응답 메시지 추가 로직을 분리해, 추후 API 응답을 채팅 목록에 반영할 수 있도록 만든다. API 주소나 응답 계약을 임의로 확정하지 않는다.
- 현재는 실제 채팅 API를 호출하지 않으며, 입력에 대한 가짜 AI 응답이나 분석/저장 성공 문구를 자동으로 생성하지 않는다. 원본의 초기 AI 인사는 표시용 메시지로 사용할 수 있다.

**파일 첨부**

- 첨부 버튼으로 숨겨진 파일 input을 열고 다중 파일 선택을 지원한다.
- 선택한 `FileList`를 `File[]`로 변환해 브라우저 개발자 도구 콘솔에 파일 객체를 출력한다. 파일명(`name`), 크기(`size`), 타입(`type`)을 확인할 수 있게 한다.
- 파일 선택 취소 또는 빈 목록에서는 오류 없이 종료한다.
- 이번 단계는 브라우저에서 파일을 선택하고 확인하는 범위다. 서버 업로드, 파일 내용 분석, 영구 저장은 후속 작업이다.

**최근 활동과 최근 추가된 기록**

- 활동/기록 목데이터를 JSX와 분리한 별도 파일에 정의하고, 타입이 있는 배열을 반복 렌더링한다.
- 원본을 기준으로 활동 카드 3개와 최근 기록 행 3개를 표시한다. 표시 항목은 5.3을 따른다.
- 최근 활동 카드, 최근 활동의 전체 보기, 최근 추가된 기록의 각 행은 모두 나의 발자국(`/archive`)으로 이동한다. 현재는 활동 ID에 따른 상세 페이지나 파일 Drawer를 연결하지 않는다.
- 이동 요소는 React Router의 `Link` 또는 `NavLink`를 사용해 키보드로도 접근할 수 있게 한다. 페이지 이동 시 MainPage의 Sidebar를 유지한다.

**반응형과 완료 기준**

- 모바일에서는 최근 활동과 최근 추가된 기록을 세로 배치한다. `lg` 이상에서는 최근 활동 2열, 최근 추가된 기록 1열의 3열 구성을 사용한다.
- 최근 활동 카드 내부는 기본 1열, `md` 이상 3열로 구성한다. 작은 화면에서 가로 넘침이 없어야 한다.
- [ ] 원본 디자인에 맞게 제목, 채팅, 최근 활동, 최근 추가된 기록 영역이 표시된다.
- [ ] 사용자 메시지 전송/입력 초기화/공백 전송 방지가 동작한다.
- [ ] 추후 API 응답을 메시지 목록에 추가할 수 있도록 전송 처리와 응답 반영 로직이 분리되어 있다.
- [ ] 다중 파일 선택 후 브라우저 콘솔에서 파일 객체와 이름·크기·타입을 확인할 수 있다.
- [ ] 파일 선택 취소 시 오류가 발생하지 않는다.
- [ ] 최근 활동과 최근 기록이 별도 파일의 목데이터로 렌더링된다.
- [ ] 활동 카드, 전체 보기, 최근 기록을 선택하면 `/archive`로 이동하고 사이드바가 유지된다.
- [ ] 모바일·데스크톱 배치를 확인하고 `npm run lint`, `npm run build`를 통과한다.

실제 API 연결, AI 분석/저장, 링크 분석, 시연 시나리오 동작, 분류 수정 Modal, 파일 Drawer 및 상세 페이지 연결은 이번 이슈의 완료 조건에 포함하지 않는다.

### 5.2 AI 입력/분석 시나리오

이 절은 후속 분석/저장 기능의 목표 명세다. 현재 홈 이슈의 구현 범위는 5.1.1을 따른다.

| 시나리오 | 원본 입력 | 결과 내용 | 사용자 동작 | 원본 대기 시간 |
| --- | --- | --- | --- | --- |
| 일반 텍스트 | 사용자가 입력한 문장 | 항상 1호선톤 분석/기록 완료 문구 | Timeline 확인, 수정 | 1000ms |
| 텍스트 시연 | 기능 6개를 핵심 3개로 줄인 회의 경험 | 1호선톤 추정, 확신도 높음, Before/After, 변화 유형 MVP 최적화, 사용자 기록 근거 | 1호선톤에 기록, 수정, 다른 활동 선택 | 1200ms |
| 단일 파일 시연 | `wireframe_v2.pdf` | 활동, 자료 유형, 진행 단계, 이전 자료, AI 요약, 변화 1개, Before/After | 저장, 수정 | 600ms 후 진행 카드, 추가 1300ms 후 결과 |
| 변화 없음 시연 | `presentation_typo_fix.pdf` | 오탈자 수정만 확인, 새 Turning Point 없음, 버전 업데이트 안내 | 아카이브 저장, 수정 | 1000ms |
| 다중 파일 시연 | 기획안 2개, 와이어프레임 2개, 회의록 1개 | 5개 자동 매칭, 유형별 개수, 버전 관계 요약 | 전체 저장, 자료 확인 | 1300ms |
| 링크 입력 | GitHub repository/ChatGPT 공유 URL 안내 | AI 대화 기록/기획 리포지토리 분류, 1호선톤 요약 | 저장, 수정 | 1100ms |

- 다중 파일 예시 이름: `idea_v1.pdf`, `idea_final.pdf`, `wireframe_v1.pdf`, `wireframe_v2.pdf`, `meeting.docx`.
- **원본 한계**: 실제 파일은 읽지 않는다. 선택 개수 1개면 단일 고정 시나리오, 2개 이상이면 무조건 5개 고정 시나리오다. 링크 본문도 가져오지 않는다.
- **구현 보완**: 실제 입력 경로는 `File[]`/URL/텍스트를 전달하고, 시연 버튼만 고정 fixture를 전달한다. 선택한 파일명과 개수를 보존한다.
- **구현 보완**: 사용자 확인을 기다리는 결과와 자동 저장된 결과를 명확히 구분한다. 원본 일반 텍스트의 “기록했습니다” 문구를 저장 성공 응답 없이 표시하지 않는다.
- **구현 보완**: 대화 초기화 시 진행 중 mock 타이머/요청을 취소하거나 응답을 무시한다. 오래된 결과가 초기화된 채팅으로 다시 들어오지 않게 한다.
- **핵심 규칙**: 주요 변화가 없는 자료도 저장할 수 있다. 저장했다는 이유만으로 성장 이벤트나 Turning Point를 만들지 않는다.
- 저장 상태는 결과별 `draft → saving → saved/error`로 관리한다. 같은 결과의 중복 저장을 차단한다.

### 5.3 홈 하단 목록

**최근 활동**: 제목/전체 보기, 활동 카드 3개. 각 카드에 활동명, 상태, 유형, 두 줄 요약, 자료 개수, 업데이트 시각. 원본은 정렬 없이 `mockActivities.slice(0, 3)`을 사용한다. 실제 구현은 `updatedAt` 기준 내림차순 상위 3개를 계산한다.

**최근 추가된 기록**: 파일/대화 아이콘, 이름, `활동 · 자료 유형`, 시각을 표시한 행 3개. 현재 홈 작업에서는 모든 행을 `/archive`로 연결한다. 후속 상세 페이지 작업에서는 원본의 모든 행이 1호선톤으로 이동하는 동작을 보완해, 각 기록의 `activityId`에 해당하는 활동 상세로 이동한다.

### 5.4 GrowthJourney

- 제목 `Growth Journey`, 설명 `시간에 따라 내가 어떻게 달라졌는지 확인해보세요.`
- 상단 AI 분석 배너: primarySoft → white → secondarySoft 그라데이션, padding 24px, radius 16px.
- 고정 예시 흐름: `서비스 기획 경험 → 사용자 중심 기획 → MVP 기준 설정 → PM 역할 확장`.
- 경험 배지: 첫 PM, 첫 사용자 인터뷰, 첫 배포, 첫 연합해커톤. 원본은 데이터에서 계산하지 않는 고정 문구다.
- 유형 필터: 전체/🧩 능력 확장/🏆 성과 향상/🌱 경험 축적/⚡ 효율성/🔁 경험 전이.
- 성장 축 select: 전체 분야/기획 · PM(원본 값 `기획 / PM`)/AI·기술/데이터/발표·협업.
- 두 필터는 AND 조건. 필터 바는 기본 세로, `md`부터 가로 정렬.
- 타임라인: 왼쪽 세로선, 원형 점, 카드. 카드에 연월, 성장 유형 배지, 활동 배지, 성장 축, 제목, 설명.
- Before가 있는 이벤트에만 접힌 상세가 존재한다. 해당 카드 클릭 시 Before/After 및 근거를 펼친다. 원본 fixture에서는 PM 역할 확장 이벤트 1개만 해당한다.
- 상세가 없는 카드는 펼치기 버튼을 제공하지 않는다. 필터 후에도 안정적인 이벤트 ID로 펼침 상태를 식별한다.
- 원본 순서는 오래된 이벤트부터 최신 이벤트다. 실제 날짜로 정렬하되 같은 날짜는 안정적으로 처리한다.
- 빈 상태: 조건에 맞는 성장 이벤트가 없음을 안내한다. 원본의 `해본 조건에 부합하는…` 문구는 `선택한 조건에 맞는 성장 이벤트가 아직 없어요.`로 교정 권장.
- 원본은 필터에 따라 상단 AI 배너가 바뀌지 않는다. 전체 요약을 유지하는 것을 기본으로 하며 필터별 요약 생성은 추가 요구로 분리한다.

### 5.5 Footprints

- 제목 `나의 발자국`, 설명 `지금까지의 활동과 그 안에 남겨둔 자료를 한곳에서 확인해보세요.`
- 검색창: Search 아이콘, placeholder `활동명, 파일명, 내용으로 검색...`.
- 유형 필터: 전체/해커톤/수업(데이터 값 전공수업)/프로젝트/공모전.
- 상태 select: 전체/진행 중/완료. 정렬 select: 최근 업데이트/자료 많은 순/오래된 순.
- 결과 행: 활동명, 유형 배지, 상태 배지, 한 줄 요약, 기간, 역할, 자료 개수 배지, 오른쪽 화살표.
- 행은 기본 세로 배치 + 자료 영역 상단 구분선, `md`부터 가로 배치 + 구분선 제거.
- 결과 없음: `조건에 맞는 활동이 없어요.`
- **구현 보완**: 원본 검색은 활동명/요약만 검사한다. 실제 구현은 안내 문구에 맞춰 파일명/파일 요약까지 포함한다. trim과 대소문자 정규화를 적용한다.
- **구현 보완**: 원본 정렬 select는 상태에 반영되지 않고 정렬 로직도 없다. `recent`는 updatedAt 내림차순, `materials`는 자료 개수 내림차순, `oldest`는 updatedAt 오름차순으로 구현한다. 오래된 순을 활동 시작일로 바꿀지는 기획 확인 사항이다.
- 계산 순서: 검색 + 유형 + 상태 AND 필터 → 복사한 배열 정렬 → 렌더링. 원본 배열 자체를 sort로 변경하지 않는다.
- 자격증/개인학습 활동은 원본 개별 유형 필터가 없지만 전체 목록에는 나타난다. 추가 필터는 별도 요구로 다룬다.

### 5.6 ActivityArchivePage

- 상단 왼쪽 목록 복귀, 오른쪽 파란 `변화 과정 보기 (Project Timeline)` 버튼.
- 활동 정보 카드: 활동명, 유형, 상태, 역할/기간, 연한 indigo 배경 AI 활동 요약.
- 폴더 제목 `보관된 자료 폴더`, 폴더 아코디언 목록.
- 폴더 헤더: FolderOpen 아이콘/폴더 이모지, 이름, 자료 개수, ChevronDown. 초기에는 모든 폴더가 펼쳐져 있다.
- 폴더별 독립 접기/펼치기. 파일 행: FileText 아이콘, 이름, 유형/날짜, 선택적 버전 배지(v1/v2/final).
- 파일 선택 시 해당 파일 상세 Drawer. 다른 활동으로 이동하면 이전 활동의 폴더/파일 선택 상태를 정리한다.
- 폴더 없음: `보관된 자료 폴더가 아직 준비되지 않았습니다.`
- **구현 보완**: 폴더는 있지만 파일이 없는 경우도 별도 안내한다. 실제 파일 다운로드/미리보기 버튼은 원본에 없으므로 범위에 자동 추가하지 않는다.

### 5.7 ProjectTimelinePage

- 상단 활동 상세 복귀/관련 자료 보기. 두 버튼 모두 동일 활동 상세로 이동한다.
- 헤더: `[활동명] Project Timeline`, 상태, 유형/역할/기간, 주요 변화 개수, Turning Point 개수.
- 기본 예시는 5개 이벤트, 그중 Turning Point 2개. 원본 헤더 숫자는 활동에 상관없이 고정이므로 실제 구현에서는 `events.length`와 `isTurningPoint` 개수로 계산한다.
- 일반 이벤트: 날짜, 제목, 선택적 설명. 흰 카드, 회색 테두리/점.
- Turning Point: 보라색 점/날짜, `⭐ TURNING POINT` 배지, accentBg 배경, Before/After, Reason, Evidence.
- Before/After는 기본 세로, `md`부터 2열. 이 변형은 홈/파일 Drawer의 2열 비교 카드와 구분한다.
- 원본 타임라인은 정적 표시이며 접기 기능이 없다.
- 이벤트 없음: `등록된 타임라인 이벤트가 없습니다.`
- **구현 보완**: 완료 상태도 원본에서는 초록색이다. 공통 StatusBadge로 완료는 회색, 진행 중은 초록색으로 일관되게 표시한다.

- 한 번에 하나의 활성 오버레이를 기본으로 한다. 중첩이 필요하면 modal을 drawer보다 높은 레이어에 두고 포커스/스크롤 잠금 소유권을 관리한다.
- Drawer 등장: 0.25초, `cubic-bezier(0.16, 1, 0.3, 1)`, 오른쪽 100%에서 원래 위치로 이동. 닫기 애니메이션은 원본에 없다.

## 7. 컴포넌트 설계

컴포넌트 이름과 분리는 제안이다. 작은 정적 조각까지 모두 파일로 분리하지 않고 독립 상태, 반복 사용, 복잡도에 따라 분리한다.

### 7.1 공통 컴포넌트

| 컴포넌트 | 책임 | 주요 props/입력 |
| --- | --- | --- |
| `MainPage` (부모 페이지) | Sidebar + 본문 Outlet, 필요 시 공통 오버레이 루트 | 자식 페이지는 중첩 Route로 연결 |
| `Sidebar`, `SidebarNavItem`, `UserProfile` | 브랜드, 메뉴, 활성 상태, 프로필 | activeSection, user, activityCount |
| `PageHeader` | 화면 제목/설명 | title, description, actions? |
| `Button`, `IconButton` | primary/secondary/ghost 버튼, disabled/loading | variant, children, aria-label |
| `SurfaceCard` | 반복 카드 기본 표면 | className, children |
| `StatusBadge`, `CategoryBadge`, `VersionBadge` | 서로 다른 의미의 배지 | status/category/version |
| `FilterGroup` | 단일 선택 필터 모음 | options, value, onChange |
| `BeforeAfterPanel` | 비교 내용 | before, after, layout(compact/responsive), tone |
| `EmptyState`, `LoadingState`, `ErrorState` | 비정상/비어 있는 데이터 상태 | message, retry? |
| `Modal`, `Drawer` | 포커스/스크롤/닫기/portal | open, title, onClose, children |
| `Toast` | 저장/수정 성공 피드백 | message, tone |

### 7.2 기능 컴포넌트

| 소유 화면/기능 | 하위 컴포넌트 | 핵심 입력/콜백 |

### 8.3 Tailwind 4 토큰 등록 예시

원본은 CDN의 JavaScript theme 설정을 사용한다. 현재 프로젝트는 CSS `@theme` 방식으로 옮긴다. 아래는 **제안하는 kebab-case 명명**이다. JSX 클래스도 같은 이름으로 함께 변환해야 한다. [Tailwind theme 공식 문서](https://tailwindcss.com/docs/theme)

```css
/* src/index.css */
@import "tailwindcss";

@theme {
  --font-sans: 'Pretendard', '-apple-system', 'BlinkMacSystemFont',
    'system-ui', 'Roboto', sans-serif;
  --color-brand-bg: #F8F9FC;
  --color-brand-surface: #FFFFFF;
  --color-brand-primary: #4F6EF7;
  --color-brand-primary-hover: #3B57E0;
  --color-brand-primary-soft: #EEF2FF;
  --color-brand-secondary: #8B7CF6;
  --color-brand-secondary-soft: #F5F3FF;
  --color-brand-text: #111827;
  --color-brand-muted: #6B7280;
  --color-brand-border: #E8EAF0;
  --color-brand-success: #10B981;
  --color-brand-warning: #F59E0B;
  --color-brand-accent-bg: #FAF5FF;
  --shadow-soft: 0 4px 20px -2px rgba(17,24,39,.04),
    0 2px 6px -1px rgba(17,24,39,.02);
  --shadow-card-hover: 0 10px 25px -3px rgba(79,110,247,.08),
    0 4px 6px -2px rgba(0,0,0,.03);
  --shadow-drawer: -4px 0 24px rgba(0,0,0,.08);
}
```

- 클래스 변환: `bg-brand-primarySoft` → `bg-brand-primary-soft`, `hover:bg-brand-primaryHover` → `hover:bg-brand-primary-hover`, `shadow-cardHover` → `shadow-card-hover`.
- Pretendard는 루트 `index.html`에서 원본 stylesheet 링크를 불러오거나 로컬 폰트로 관리한다. `--font-sans` 선언만으로 폰트 파일이 로드되지는 않는다. 원본 링크: `https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard.min.css`.

**버전 차이 확인**: 원본은 Tailwind 3 스타일 CDN 설정을 포함한다. Tailwind 4의 기본 shadow/radius/ring 등은 일부 달라질 수 있으므로 클래스 문자열만 복사해 시각적으로 동일하다고 판단하지 않는다. 특히 bare `shadow-sm`, `shadow`, `rounded` 같은 값은 원본을 비교해 필요하면 명시적 토큰으로 고정한다. [공식 업그레이드 안내](https://tailwindcss.com/docs/upgrade-guide)

### 8.4 반응형 기준

| 구간 | 변화 |
| --- | --- |
| 기본, 640px 미만 | 사이드바 상단, 본문 16px, Drawer 전체 폭, 홈 하단 1열 |
| sm, 640px 이상 | 본문 24px, 제목 24px, Drawer 440px, AI 결과 최대 폭 85% |
| md, 768px 이상 | 사이드바 240px 좌측 sticky, 최근 활동 카드 3열, 필터/활동 행 가로 배치, 프로젝트 비교 2열 |
| lg, 1024px 이상 | 본문 32px, 홈 하단 2:1 배치 |

원본은 홈 채팅 높이를 모바일에서도 520px로 유지한다. 우선 이 기준을 재현하고, 작은 화면에서 입력창 가림/내용 압축이 발생하면 `min-height`, viewport 기반 최대 높이 등을 별도 개선한다. 320/375/768/1024/1440px에서 수평 overflow와 오버레이를 확인한다.

### 8.5 아이콘/스크롤/모션

- 아이콘은 Lucide 계열의 선형 스타일을 유지한다. React 컴포넌트 형태의 아이콘 또는 관리되는 SVG를 사용한다. `lucide.createIcons()`와 DOM 치환 호출은 제거한다.
- 주요 아이콘: Sparkles, Home, TrendingUp, Footprints, Settings, RotateCcw, Bot, Paperclip, Link, Send, FolderGit2, ChevronRight, History, Search, ArrowLeft, GitCommit, Folder, FolderOpen, ChevronDown, FileText, X, Check, CheckCircle, Loader, Info, MessageSquare, Edit 계열.
- 패키지를 도입할 때 실제 export 이름을 확인한다. HTML `edit-3` 등 문자열과 React export가 항상 같은 이름은 아니다.
- WebKit 스크롤바: 폭/높이 6px, track 투명, thumb `#CBD5E1`, hover `#94A3B8`, pill radius.
- 카드 hover는 border/text primary, card-hover shadow, 원본 `transition` 유지. 일반 버튼에 과한 확대/이동 효과를 추가하지 않는다.
- 타이핑 1.4초, Drawer 0.25초, 분석 진행 spinner/pulse. `prefers-reduced-motion`에서는 반복/슬라이드 애니메이션을 줄인다.

## 9. TypeScript 데이터 모델 제안

원본의 화면 표시 문자열을 영속 ID로 사용하지 않는다. 화면용 label과 데이터 key를 분리한다. 아래는 핵심 필드이며 API 계약 확정 후 매핑 계층으로 조정한다.

```ts
type ActivityCategory =
  | 'hackathon' | 'course' | 'project' | 'contest' | 'self-study';
type ActivityStatus = 'in-progress' | 'completed';
type GrowthType =
  | 'capability' | 'achievement' | 'experience' | 'efficiency' | 'transfer';
type GrowthAxis = 'planning-pm' | 'ai-tech' | 'data' | 'presentation-collaboration';

interface Activity {
  id: string;
  title: string;
  category: ActivityCategory;
  status: ActivityStatus;
  role: string;
  periodLabel: string;
  summary: string;
  fields: string[];
  updatedAt: string; // ISO 시각; '오늘/어제'는 렌더링 시 계산
  materialCount: number; // 페이지 일부만 로드되면 서버 총계 사용
  folderIds: string[];
  timelineEventIds: string[];
}

interface ArchiveFolder {
  id: string;
  activityId: string;
  name: string;
  materialCount: number;
  materialIds: string[];
}

interface Material {
  id: string;
  activityId: string;
  folderId: string;
  name: string;
  typeLabel: string;
  createdAt: string;
  summary: string;
  version?: string;
  versionGroupId?: string;
  relatedTimelineEventId?: string;
  comparison?: { before: string; after: string };
}

interface JourneyEvent {
  id: string;
  activityId: string;
  occurredAt: string;
  title: string;
  description: string;
  type: GrowthType;
  axis: GrowthAxis;
  comparison?: { before: string; after: string; evidence: string[] };
}

type ProjectEvent = {
  id: string;
  activityId: string;
  occurredAt: string | null;
  dateLabel?: string; // NOW 같은 표시용 값
  title: string;
} & (
  | { isTurningPoint: false; description: string }
  | { isTurningPoint: true; before: string; after: string;
      reason: string; evidenceMaterialIds: string[] }
);

type AnalysisInput =
  | { kind: 'text'; text: string }
  | { kind: 'files'; files: File[] }
  | { kind: 'link'; url: string };

interface AnalysisResult {
  id: string;
  kind: 'text' | 'file' | 'no-change' | 'batch' | 'link';
  activityId: string | null;
  materialTypeLabel: string;
  summary: string;
  confidence?: 'high' | 'medium' | 'low';
  comparison?: { before: string; after: string };
  evidence: string[];
  files: { name: string; typeLabel: string; version?: string }[];
  hasMajorChange: boolean;
  saveState: 'draft' | 'saving' | 'saved' | 'error';
}

type ChatMessage =
  | { id: string; role: 'user'; createdAt: string;
      content: { kind: 'text' | 'files' | 'link'; text: string; fileNames?: string[] } }
  | { id: string; role: 'assistant'; createdAt: string;
      content: { kind: 'welcome'; text: string } | { kind: 'result'; resultId: string } };

type OverlayState =
  | { kind: 'none' }
  | { kind: 'file-detail'; activityId: string; materialId: string }
  | { kind: 'link-input' }
  | { kind: 'edit-category'; resultId: string };
```

- 분석 작업은 메시지와 별도 `AnalysisJob`으로 관리한다: job ID, 입력, 단계(`queued/reading/matching/classifying/comparing/completed/error`), 결과 ID, 오류, 취소 정보. 여러 작업이 겹쳐도 작업별 결과를 연결한다.
- 최근 기록은 `id`, `activityId`, 선택적 `materialId`, 이름, 유형, 생성 시각, 아이콘 종류를 가진다.
- 파일 버전은 파일명 문자열 치환으로 추정하지 않고 `versionGroupId`로 연결한다.
- Project Timeline과 Growth Journey는 별도 데이터다. 자료 저장 시 두 타임라인을 무조건 동시에 추가하지 않는다.
- JSX 포함 파일은 `.tsx`, 일반 타입/로직은 `.ts`. `verbatimModuleSyntax`에 맞춰 타입은 `import type`으로 가져온다. [React TypeScript 안내](https://react.dev/learn/typescript)

## 10. 상태와 서비스 경계

| 상태 | 소유 위치 제안 | 비고 |
| --- | --- | --- |
| 활동/폴더/자료/이벤트 | repository + 앱 공유 상태 | 홈/상세/타임라인 간 동일 데이터 참조 |
| 현재 활동 ID | URL params | 상태와 URL에 중복 저장하지 않음 |
| 대화/분석 결과/작업 | `useChat` 또는 채팅 provider | 원본처럼 화면 이동 후에도 채팅 유지 |
| Journey 필터/펼침 | `useJourneyFilters`/페이지 상태 | ID 기반, 필터 조합은 파생 계산 |
| 활동 검색/필터/정렬 | `useActivityFilters` | 화면 복귀 시 유지 권장, URL query 활용 가능 |
| 폴더 펼침 | 활동 상세 로컬 상태 | 활동 ID별 독립 |
| 오버레이 선택 | `OverlayState` | 결과/자료 ID로 대상 명시 |
| 입력창/Modal draft | 해당 컴포넌트 | 취소하면 원본 데이터 미변경 |
| 저장 성공 피드백 | Toast 상태 | 알림만 띄우고 저장한 척하지 않음 |

필터 결과, 선택 항목, 개수 등은 원본 데이터에서 계산한다. 데이터가 적은 초기 버전은 React state/context와 순수 함수로 충분하며 전역 상태/서버 캐시 라이브러리를 필수 조건으로 삼지 않는다.

### 10.1 서비스 인터페이스 제안

```ts
interface AnalysisService {
  analyze(input: AnalysisInput, options?: { signal?: AbortSignal }): Promise<AnalysisResult>;
}

interface ArchiveRepository {
  listActivities(): Promise<Activity[]>;
  getActivity(id: string): Promise<Activity | null>;
  getFolders(activityId: string): Promise<ArchiveFolder[]>;
  getMaterials(activityId: string): Promise<Material[]>;
  getProjectEvents(activityId: string): Promise<ProjectEvent[]>;
  getJourneyEvents(): Promise<JourneyEvent[]>;
  updateClassification(resultId: string, value: {
    activityId: string;
    materialTypeLabel: string;
  }): Promise<AnalysisResult>;
  saveAnalysis(resultId: string): Promise<void>;
}
```

- 실제 HTTP endpoint는 원본에 없다. 위 함수명은 프런트엔드 경계 제안이다.
- 초기에는 메모리 mock을 사용한다. 새로고침 유지가 필요하면 별도 localStorage 저장 정책을 도입하고 mock임을 명확히 한다.
- 저장 성공 후 해당 활동 자료/폴더/최근 기록/개수를 일관되게 갱신한다. major change일 때만 관련 이벤트를 생성한다. 저장 실패는 draft를 유지하고 재시도할 수 있게 한다.
- AI 분류 수정은 대상 `resultId`의 draft에 연결한다. 저장된 자료를 편집하는 별도 흐름과 섞지 않는다.
- 원본의 `confirmSaveToTimeline`은 alert만 띄우는 함수다. 이름과 달리 실제 Timeline/자료 추가가 없으므로 그대로 이식하지 않는다.

## 13. 간결한 폴더 구조

기존 `pages`, `examples` 위치를 유지한다. MainPage가 부모 화면 역할을 맡으므로 `layouts`, `app`, `components/layout` 폴더를 추가하지 않는다. 초기 구조는 다음처럼 단순하게 둔다.

```text
src/
  App.tsx                      # 중첩 라우팅 정의
  main.tsx                     # 기존 BrowserRouter 유지
  index.css                    # 폰트, 토큰, 글로벌 스타일
  components/
    Sidebar.tsx
  pages/
    MainPage.tsx               # Sidebar + Outlet
    Home.tsx
    GrowthJourney.tsx
    Footprints.tsx
  examples/
    ExamplePage.tsx            # 기존 독립 예시 페이지
references/
  1Line_reference.html
  구현_가이드라인.md
```

초기 작업에서는 Sidebar와 MainPage의 화면 틀, 자식 페이지의 임시 제목과 라우팅까지만 만든다. Home의 채팅 등 세부 콘텐츠는 그 다음 작업이다. 활동 상세와 Project Timeline은 구현할 때 `pages`에 추가한다.

채팅 패널/버튼/배지/Modal 등 실제로 분리할 필요가 생긴 요소는 우선 `components`에 추가한다. 파일이 늘어나 탐색이 어려워질 때만 하위 폴더를 나눈다. `SidebarNavItem`, `UserProfile` 같은 작은 조각도 처음부터 각각 파일로 분리할 필요는 없다.

목데이터와 동작을 연결하는 단계에서 `mocks`, `types`, `services`, `hooks`를 필요한 만큼 추가할 수 있다. 7장의 컴포넌트 표와 10장의 서비스 구분은 책임을 설명한 것이며, 그 수만큼 폴더/파일을 미리 만들라는 요구가 아니다. 공통 타입은 중복 정의하지 않는다. `references`는 프로젝트 루트에 유지하며 앱 배포 자산으로 import하지 않는다.

## 14. 구현 순서

**화면 개발 우선순위는 홈(채팅 화면) → Growth Journey → 나의 발자국이다.** 활동 상세와 Project Timeline은 나의 발자국에 이어 구현한다. 문서의 컴포넌트/타입 나열 순서는 개발 우선순위를 뜻하지 않는다.

전체 개발 흐름은 **공통 레이아웃 준비 → 1단계: 화면·디자인 완성 → 2단계: 목데이터로 사용자 동작 완성 → 3단계: 실제 API 연결**이다. 각 단계에서도 위 화면 우선순위를 유지한다. 화면을 만드는 순서와 API를 연결하는 시점을 구분한다.

### 14.1 공통 레이아웃 준비

첫 작업은 **MainPage 화면 틀과 Sidebar, 자식 페이지의 라우팅**이다. Pretendard, Tailwind theme, 기본 배경, 본문 폭/간격도 이때 구성한다.

1. 기존 `pages`, `examples` 폴더를 유지하고 `components/Sidebar.tsx`를 만든다.
2. Sidebar에 브랜드, 홈/Growth Journey/나의 발자국 메뉴, 활성 표시, 하단 프로필을 구현한다.
3. `pages/MainPage.tsx`에 Sidebar와 본문 Outlet을 배치하고 모바일/데스크톱 반응형을 적용한다.
4. Home, GrowthJourney, Footprints 페이지 파일을 만들고 우선 구분 가능한 임시 제목만 표시한다.
5. `App.tsx`에서 MainPage의 자식 Route로 세 페이지를 연결하고 `/example`은 독립 경로로 유지한다.
6. 메뉴 클릭 시 URL과 본문이 바뀌며 사이드바가 유지되고 활성 메뉴가 맞는지 확인한다. lint/build를 통과하면 화면 틀 작업을 완료한다.

이후 홈의 세부 화면을 구현한다. 버튼/배지/카드는 홈에서 필요한 것부터 만든다. 모든 화면의 타입, 공통 컴포넌트, 서비스 계층을 미리 완성하느라 홈 작업을 뒤로 미루지 않는다. 별도 layouts 폴더는 만들지 않는다.

### 14.2 1단계 — 화면·디자인 완성

목표는 원본에 맞는 화면 구조와 디자인을 완성하는 것이다. **이 단계부터 간단한 목데이터를 사용한다.** 예시 메시지/활동/이벤트를 타입이 있는 배열이나 객체로 만들고 props로 전달해 반복 렌더링한다. 화면 곳곳의 JSX에 데이터를 직접 박아두지 않는다. 아직 백엔드 요청이나 실제 저장 기능은 필요하지 않다.

| 순서 | 화면 | 이 단계에서 만들 내용 |
| --- | --- | --- |
| 1 | 홈·채팅 | 우선 5.1.1의 범위 구현: 제목/헤더, 초기 인사, 메시지 상태와 전송 처리, 파일 선택 및 콘솔 확인, 최근 활동/기록 목데이터와 `/archive` 연결. 결과 카드, 시연 동작, 링크 입력·분류 수정 Modal은 후속 작업 |
| 2 | Growth Journey | AI 요약 배너, 경험 배지, 필터 UI, 개인 성장 타임라인, 비교 상세의 외형 |
| 3 | 나의 발자국 | 검색/유형/상태/정렬 UI와 활동 목록 |
| 4 | 활동 상세 | 활동 요약, 폴더/파일 목록, 파일 Drawer의 외형 |
| 5 | Project Timeline | 활동 헤더, 일반/Turning Point 카드, Before/After와 근거 자료 |

로딩·오류·빈 결과와 분석 중/분석 완료 화면도 예시 상태로 렌더링해 디자인을 준비한다. 기본 페이지 이동과 Modal/Drawer 열기·닫기는 화면 확인에 필요한 만큼 먼저 구현해도 된다. 오버레이를 도입할 때부터 포커스/키보드 접근성을 적용한다.

**완료 기준**: 다섯 화면과 필요한 오버레이를 예시 데이터로 확인할 수 있고, 주요 화면 크기에서 원본의 색상·간격·구성에 맞게 표시된다. 이 단계의 완료를 실제 분석/저장 완료와 혼동하지 않는다.

### 14.3 2단계 — 목데이터로 사용자 동작 완성

목표는 실제 API 없이도 입력부터 결과 확인까지 사용자 흐름이 동작하도록 만드는 것이다. 1단계의 표시용 목데이터에 상태 변경과 비동기 mock 서비스를 연결한다. 10장의 서비스 인터페이스는 구현 경계의 제안이며, API 계약이 확정되기 전의 필드를 서버 사양으로 간주하지 않는다.

1. **홈·채팅**: 텍스트/파일/링크 입력 → 타이핑/분석 진행 → 결과 카드, 4개 시연, 분류 수정, 저장, 취소/오류/대화 초기화를 연결한다. 선택한 파일명과 개수를 보존한다.
2. **Growth Journey**: 유형/성장 축 AND 필터, 이벤트 ID 기반 상세 펼침, 빈 결과를 연결한다.
3. **나의 발자국**: 검색, 유형/상태 필터, 3종 정렬, 결과 없음 상태를 연결한다.
4. **활동 상세·Project Timeline**: 활동 ID로 데이터 조회, 폴더 독립 토글, 파일별 상세 표시, 관련 이벤트 이동, 활동 상세 복귀, 잘못된 ID/자료 없음 상태를 연결한다. 임시 상세 페이지를 실제 화면으로 교체한다.
5. **전체 데이터 흐름**: 저장/수정을 mock 공유 상태에 반영해 홈/성장 흐름/아카이브/타임라인이 같은 데이터를 보게 한다. 자료 개수/날짜/중복 저장을 검증하고, 주요 변화가 없는 자료는 아카이브에만 저장하며 이벤트를 생성하지 않는다.

컴포넌트에서 목데이터 배열을 직접 수정하는 대신 요청/저장 함수를 통해 데이터를 다루도록 분리한다. 로딩·오류·빈 상태와 저장 전/중/완료/실패를 실제 상태 전환으로 확인한다. 대화 초기화나 화면 이동 후 오래된 비동기 응답이 잘못 반영되지 않도록 취소/무시 처리를 한다.

**완료 기준**: 목데이터로 핵심 흐름을 끝까지 실행할 수 있고, 입력·수정·저장 결과가 관련 화면에 일관되게 반영된다. 이 상태가 실제 AI 분석이나 서버 저장을 지원한다는 뜻은 아니다. mock 데이터의 새로고침 유지 여부도 명시한다.

### 14.4 3단계 — 실제 API 연결

API 계약이 확정되면 **목데이터를 반환하던 서비스 함수를 실제 요청으로 교체**한다. 실제 서버 응답을 프런트엔드 타입에 맞게 매핑하고, 컴포넌트는 가능한 한 기존 props와 상태 구조를 유지한다. 응답 형태가 달라지면 매핑 계층과 필요한 타입을 조정한다.

1. API 주소/인증/요청·응답 계약, 업로드 제약, 분석 및 저장 방식을 확인한다.
2. 홈·채팅 → Growth Journey → 나의 발자국 → 상세/타임라인 순서로 관련 API를 연결한다. 서버가 준비되지 않은 기능은 서비스 단위로 mock을 유지할 수 있다.
3. 실제 응답의 로딩·오류·빈 결과, 요청 취소, 재시도, 중복 저장을 검증한다. 성공 문구는 서버의 성공 응답 후 표시한다.
4. 저장/수정 후 관련 데이터를 재조회하거나 공유 상태를 갱신해 각 화면을 동기화한다.
5. 새로고침·직접 URL 접근·브라우저 뒤로가기와 전체 사용자 흐름을 확인한다.

**완료 기준**: 실제 분석/조회/수정/저장 결과가 올바른 활동과 자료에 연결되고, 새로고침 후에도 서버 데이터로 복구된다. 목데이터 단계에서 확인한 시나리오를 실제 응답으로 다시 검증한다.

### 14.5 단계별 검수

각 단계에서 `npm run lint`, `npm run build`와 해당 화면의 반응형/상호작용을 확인한다. 전체 구현 후에는 홈 입력부터 저장, 성장 흐름 확인, 활동/자료 탐색까지 연결해서 검수한다. 세부 완료 기준은 15장을 따른다.

## 15. 완료 기준과 검증

### 15.1 필수 동작

- [ ] 3개 상위 메뉴와 2개 상세 화면이 올바르게 연결되고 Growth Map이 노출되지 않는다.
- [ ] MainPage의 Sidebar는 자식 페이지 이동 시 유지되고 Outlet의 본문만 바뀐다.
- [ ] 홈 메뉴는 `/`에서만 활성화되고 나의 발자국은 활동 상세/타임라인에서도 활성화된다.
- [ ] 기존 pages/examples 구조와 독립 `/example` 경로를 유지한다.
- [ ] 활동 ID를 직접 열거나 새로고침해도 해당 활동을 유지한다(URL 라우팅 적용 시).
- [ ] 홈 최근 기록의 활동 연결이 정확하며 검색/유형/상태/3종 정렬이 실제로 작동한다.
- [ ] Journey의 두 필터가 AND로 적용되고 펼침 상태가 다른 이벤트로 이동하지 않는다.
- [ ] 모든 파일 상세가 해당 파일 정보를 보여주고 변화 없는 파일에 비교 카드를 꾸며내지 않는다.
- [ ] 텍스트/단일/다중/변화 없음/링크 흐름, 빈 입력/파일 선택 취소/잘못된 URL을 처리한다.
- [ ] 저장 전/중/완료/실패가 구분되고 중복 저장을 막는다. 성공 뒤 관련 화면 데이터가 갱신된다.
- [ ] 새 주요 변화가 없으면 아카이브에만 저장하고 Turning Point를 생성하지 않는다.
- [ ] 대화 초기화/화면 이동/컴포넌트 해제 후 오래된 비동기 응답이 잘못 반영되지 않는다.
- [ ] Modal/Drawer 닫기, Escape, 포커스 복귀, 배경 스크롤 잠금이 동작한다.
- [ ] 데이터 없음/로딩/오류/잘못된 activityId 상태를 구분한다.

### 15.2 디자인/접근성

- [ ] Pretendard 로드, 정확한 브랜드 컬러/그림자/간격/모서리 확인.
- [ ] 320/375/768/1024/1440px에서 제목, 필터, 채팅, 파일명, 상세 버튼의 overflow 확인.
- [ ] Sidebar는 원본 반응형 배치를 유지하고 상세 화면에서 상위 메뉴가 활성화된다.
- [ ] 카드/파일 선택은 링크 또는 버튼으로 키보드 접근이 가능하다. 큰 카드 안의 중첩 버튼은 중첩된 button 요소로 만들지 않는다.
- [ ] 아이콘 전용 버튼에 aria-label, 입력에 label, 필터에 aria-pressed, 펼침에 aria-expanded/aria-controls를 제공한다.
- [ ] 메시지/진행 상태는 적절한 aria-live로 알리되 매 프레임 스크린리더를 방해하지 않는다.
- [ ] 포커스 표시, reduced-motion, Drawer/Modal 내부 스크롤을 확인한다.

### 15.3 검증 방법

```powershell
npm run lint
npm run build
npm run dev
```

위 명령은 앞으로 구현할 앱의 검사 절차다. 이 문서를 만들면서 실행/통과했다고 뜻하지 않는다. 의미 있는 로직 테스트는 복합 필터/정렬, 저장 중복 방지, 변화 없는 결과의 이벤트 미생성, 분류 수정 대상 연결, 요청 취소에 집중한다. 정적 마크업을 그대로 반복하는 테스트는 피한다.

브라우저에서 원본과 앱을 동일한 viewport/시나리오로 비교하고, 홈 기본/분석 중/분석 결과, Journey 펼침/빈 결과, 발자국 필터, 활동 폴더, 파일 Drawer, 두 Modal, 타임라인을 캡처해 검수한다.

## 16. 원본 위치와 남은 결정 사항

### 16.1 HTML 탐색 기준

행 번호는 편집 시 바뀔 수 있으므로 ID/함수/주석으로 찾는다.

| 영역 | 검색 기준 |
| --- | --- |

### 16.2 구현 중 독립적으로 진행할 수 있는 항목

원본 화면 재현, 컴포넌트 분리, mock 서비스, 데이터 기반 파일 상세, 필터/정렬, 접근성, 반응형은 이 문서 기준으로 진행할 수 있다.

### 16.3 실제 서비스 연동 전에 확정할 항목

- API 계약, 인증/사용자 데이터, 파일 업로드 방식, 허용 형식/용량/보관 정책.
- 분석 결과의 자동 저장 여부와 사용자 확인이 필요한 조건/확신도 기준.
- major change/Turning Point/개인 성장 이벤트의 생성 기준과 수정 가능 범위.
- 오래된 순의 날짜 기준, 자료 총계의 의미, 샘플 날짜 불일치, 브랜드 최종 표기.
- URL 직접 접근을 지원할 배포 환경의 SPA fallback 설정.
