# 채팅 서비스 준비 상태

현재 프론트엔드의 목 서비스와 화면용 타입을 설명한다. 실제 API 주소·인증·응답 형식은 미확정이다.

## 현재 흐름

`Home` → `getChatServiceStatus()` → `getMockChatServiceStatus()` → `ChatServiceStatusBadge`

공통 타입 `ChatServiceStatus`는 `src/types/chat.ts`, 목 응답은 `src/mocks/Home/chatStatus.ts`, 서비스 경계는 `src/services/chat.ts`에 있다.

```json
{
  "status": "ready",
  "label": "기록 정리 준비됨"
}
```

| 필드 | 역할 |
| --- | --- |
| `status` | `ready` 또는 `unavailable`. 배지의 의미와 색상 결정 |
| `label` | 배지에 표시할 문구 |

서비스는 응답의 복사본을 반환한다. 목 상태의 `status`와 `label`을 바꾸면 화면도 해당 값으로 표시한다. 색상과 조회 중·실패 문구는 UI가 관리한다.

## 조회 생명주기

- 홈 진입 시 한 번 조회한다. 응답 전에는 ‘상태 확인 중’을 표시한다.
- 실패하면 ‘상태 확인 실패’를 표시한다. 요청 실패와 서버가 응답한 `unavailable`을 구분한다.
- 화면을 떠난 뒤 도착한 응답은 무시한다.
- 자동 재조회·폴링·전용 재시도 버튼은 추가하지 않았다.

이 상태는 현재 고정 목 응답이다. AI 서버의 실제 가용성이나 메시지 분석 단계를 나타내지 않으며, 전송 가능 여부를 제어하는 용도로 연결하지 않았다.

## 실제 API로 교체할 때

`getChatServiceStatus` 내부에서 서버 상태를 조회하고 응답을 `ChatServiceStatus`로 변환한다. 화면은 같은 구조를 사용한다. 외부 JSON의 필수 필드·상태 코드는 서비스에서 검증해야 한다.

연결 전에는 상태의 의미, 조회 API·인증·실패 처리, 재조회 주기, 문구를 서버에서 제공할지 상태 코드로 프론트에서 결정할지, 사용 불가일 때 전송을 차단할지를 협의한다. 아직 이 동작들을 확정하지 않았다.
