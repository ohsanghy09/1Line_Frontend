# 파일 분석 진행·결과 응답

현재 프론트엔드 목 구현 설명이다. 확정된 서버 API 계약이 아니다.

## 화면이 사용하는 서비스

`getChatReply(message, files, onProgress?)`는 `Promise<ChatReply>`를 반환한다. 선택적인 `onProgress` 콜백으로 결과 도착 전 진행 상태를 알릴 수 있다.

진행 표시용 `ChatProgress`는 제목과 단계 배열을 가진다. 각 단계에는 `label`과 `status`(`completed` 또는 `working`)가 있다. 이 콜백과 필드는 프론트엔드 내부 구조이며 서버에서 같은 형태로 전송해야 한다는 의미는 아니다.

모든 단일 파일 전송은 파일 이름·확장자와 관계없이 600ms 후 예시 진행 상태를 한 번 알리고 1300ms 후 파일 분석 목 응답을 반환한다. 파일 내용이나 실제 서버 처리 상태를 측정하지 않는다.

시연 버튼과 전용 서비스 `getFileUploadDemoReply`는 제거했다. 실제 입력은 모두 `getChatReply`를 사용한다. 단일 파일은 내부의 `getMockFileReply(file, onProgress?)`가 처리하며 실제 선택 파일명을 응답 제목·파일 정보·변화 근거에 반영한다.

활동·자료 유형·요약·Before/After는 고정 예시다. 현재 `mocks/Home/chat.ts`의 `mockSingleFileAnalysisMode`가 `'no-change'`이므로 모든 단일 파일은 변화 없음 목 응답을 사용한다. `'change'`로 바꾸면 기존 변화 있음 목 응답을 사용한다. 파일명으로 실제 변화를 판단하지 않는다. 이전 버전은 해당 원본 목 예시 파일에만 사용하고, 다른 파일을 임의로 `wireframe_v1.pdf`와 연결하지 않는다. 2개 이상은 기존 다중 파일 목 분류, 텍스트만 보내면 기존 텍스트 목 응답을 사용한다.

## 최종 결과 카드에서 사용하는 값

| 값 | 표시 |
| --- | --- |
| `kind: 'file-analysis'` | 단일 파일 분석 결과 구분 |
| `analysis.files[0].name` | 제목의 파일명 |
| `analysis.changes.length` | 발견한 변화 개수 |
| `analysis.activity.name` | 활동명 |
| `analysis.materialType` | 자료 유형 |
| `analysis.stage` | 단계. 값이 없으면 ‘—’ 표시 |
| `analysis.files[0].previousVersion` | 관련 이전 자료. 값이 없으면 ‘없음’ 표시 |
| `analysis.summary` | AI 요약 |
| `analysis.changes[].before/after` | 변화 전후 비교 |

파일이 한 개인 `file-analysis` 또는 `no-change` 응답은 변화 배열로 본문을 선택한다. 변화가 있으면 기존 파일 분석 본문, `changes: []`이면 원본 ‘변화 없음 파일’ 스타일의 `NoChangeAnalysisContent`를 사용한다. 자료 개수 그룹이나 실제 파일명으로 형식을 나누지 않는다.

변화 없음 카드의 `content`는 정리 제목, 선택 필드 `analysis.noChangeMessage`는 변화 없음 안내, `analysis.summary`는 상세 사유다. 안내 필드가 없으면 일반적인 변화 없음 문구를 사용한다. `suggestedSaveMode: 'version-only'`는 제안일 뿐 저장 완료를 의미하지 않는다. 실제 서버 JSON 형식은 아직 확정되지 않았다.

## 실제 API 연결 전에 협의할 내용

- 서버에서 분석을 어떤 단계로 실행하며 각 단계의 시작·완료·실패를 제공할 수 있는지
- 진행 이벤트 전달 방식, 최종 결과·오류 형식, 요청 식별과 취소 방식
- 파일 업로드 주소·인증·허용 형식과 용량·분석 요청 방식
- 저장·수정 API와 분석 응답의 구분

서버에서 최종 응답만 제공한다면 대기 표시만 사용한다. AI의 내부 처리 단계나 백분율을 프론트엔드 타이머로 실제 진행처럼 표현하지 않는다.
