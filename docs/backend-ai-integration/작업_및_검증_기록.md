## 2026-11-13 — 작업 범위 정리 및 문서 작성

### 확인한 방향

- 공유 DB에 의존하는 백엔드·AI 연동을 내부 HTTP 데이터 전달로 변경한다.

- 서버 간 토큰은 양쪽 서버에만 설정하고, 송신·수신 코드와 HTTPS를 함께 적용한다.

## 2026-11-13 — Spring 서버 간 인증 구현

### 구현

- InternalServiceAuth: 프로세스 환경변수 INTERNAL_SERVICE_TOKEN 검증, Bearer 헤더 생성·비교. 비밀값을 toString이나 오류에 포함하지 않는다.
- AppConfig: 인증 설정을 생성하고 DB 초기화 전에 유효성을 확인한다. 실제 토큰값은 설정하지 않았다.
- Fetch 및 세 호출부: 활동·Journey·남은 파일 분석에 인증 설정을 전달한다. 토큰을 다른 주소로 전달하지 않도록 자동 리다이렉트를 끈다.
- InternalServiceAuthFilter: JSON 파싱 전에 내부 경로를 검사한다. 대소문자를 구분하지 않는 기존 라우팅에 맞추고 컨테이너가 정규화한 servletPath를 사용한다. 누락·불일치·중복 헤더는 401과 internal_unauthorized 반환.
- 공개 API 경로·본문·응답, 활동·파일 분석 본문, 홈 내부 컨트롤러는 변경하지 않았다. 내부 컨트롤러는 정상 토큰에도 아직 404다.
- 테스트용 AI는 테스트 토큰이 없거나 틀리면 401을 반환하도록 변경했다. 기존 세 분석 경로 회귀 검사에서도 송신 인증을 확인한다.

### 검사 상태

- 인증 설정·내부 경로·공개 API·context-path·중복 헤더·실제 HTTP 송신 헤더·리다이렉트 미추적 검사를 추가했다.
- JDK 21.0.13+9 및 Gradle 9.5.1을 임시 폴더에 준비했다. 기본 셸에 Java가 없었으며 초기 다운로드·의존성 해석은 네트워크 제한으로 실패했다. 승인된 실행으로 도구·의존성을 내려받아 재실행했다. 프로젝트 의존성 버전은 변경하지 않았다.
- `test bootJar --console=plain`: BUILD SUCCESSFUL. 기존 ApiTest 11개·JourneyTest 8개와 신규 InternalServiceAuthTest 5개, 총 24개 통과.
- 신규 검사는 잘못된 설정과 설정 누락 시 시작 실패, 정상·누락·오류·중복 인증 헤더, 잘못된 JSON보다 먼저 인증, 내부 OPTIONS, 대소문자·인코딩·경로 매개변수·context-path, 공개 API 유지, 본문 유무별 실제 HTTP 송신 헤더와 리다이렉트 미추적을 확인했다. 인증을 통과한 미구현 내부 경로는 404로 확인했다.
- 기존 활동 분석·남은 파일 분석·Journey 회귀 검사는 테스트용 AI가 올바른 토큰을 요구하는 상태에서 통과했다.
- JAR: `api-server-spring/build/libs/1line-api-server-0.1.0.jar`. 생성물이며 Git 추가·배포는 수행하지 않았다.
- AI 서버 코드 변경·실제 토큰 배포 설정·실제 HTTPS/AI 연동·브라우저 검증: 미수행.

재현 명령 (JDK 21의 JAVA_HOME을 설정한 환경, api-server-spring 폴더):

```powershell
$authGradleCache = Join-Path $env:TEMP 'growth-auth-tools/gradle'
.\gradlew.bat --gradle-user-home $authGradleCache --no-daemon test bootJar --console=plain
```

테스트는 테스트 전용 토큰·임시 DB·로컬 가짜 AI 서버를 사용한다. 운영 토큰·개인 DB·실제 AI 모델을 사용하지 않는다.
