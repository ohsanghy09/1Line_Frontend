# 파일 업로드 분석 구현 기록

최종 정리: 2026-11-03

## 구현 범위

[1Line_reference.html](../references/1Line_reference.html)의 파일 업로드 진행·결과 카드를 기준으로 **실제로 첨부한 단일 파일을 전송하는 흐름**을 구현했다. 파일 이름·확장자와 관계없이 같은 카드 구조를 사용한다. 실제 AI 호출·서버 업로드·내용 분석은 하지 않으며 분석 내용은 목 응답을 사용한다. 앱의 시연 버튼과 전용 호출 코드는 제거했다.

## 실행 방법

- 파일 한 개를 선택하거나 입력창·첨부 영역에 드롭한 뒤 보내기 버튼 또는 Enter로 전송한다. 선택만으로 분석을 시작하지 않는다.
- 파일만 또는 설명 텍스트와 함께 보낼 수 있다. 전송하면 글과 전송 전 첨부 목록을 비운다.
- 현재 목 설정은 변화 없음이므로 어떤 파일을 한 개 보내도 변화 없음 전용 카드가 표시된다. `src/mocks/Home/chat.ts`의 `mockSingleFileAnalysisMode`를 `'change'`로 바꾸면 기존 변화 있음 목 카드도 확인할 수 있다. 실제 파일 분석은 아니다.
- 2개 이상 첨부하면 기존 다중 파일 결과를 표시한다. 별도 시연 버튼은 없다.

## 표시 순서

1. 사용자 말풍선에 파일 아이콘과 실제 선택한 파일명을 표시한다.
2. Bot 아이콘과 점 3개를 600ms 동안 표시한다.
3. Sparkles 아이콘과 ‘파일을 확인하고 있어요...’ 진행 카드를 1300ms 동안 표시한다.
4. 진행 카드를 제거하고 파일 분석 결과 카드를 표시한다.

진행 카드에는 원본과 같이 파일 확인 완료·기존 활동 비교 완료·자료 유형 분석 완료·이전 기록과 비교 중이 한 번에 표시된다. 하나씩 완료되는 애니메이션이나 실제 서버 이벤트가 아니다. 타이머와 상태는 목 서비스에서 제공한다.

## 결과 카드

- ‘분석이 끝났어요.’와 파일명, 새로운 변화 개수 배지
- 활동·자료 유형·단계·관련 이전 자료의 2열 정보 박스
- AI 요약
- 인디고 배경의 Before/After 비교
- 저장·수정 버튼

위 구성은 변화가 있는 응답의 카드다. 값은 `ChatReply.analysis`에서 표시하며 파일명·현재 파일의 근거는 실제 입력을 사용하고 나머지 분석 내용은 목데이터다. 알 수 없는 이전 자료는 ‘없음’, 단계가 없으면 ‘—’로 표시한다.

변화가 없으면 정보 그리드와 비교 카드 대신 [변화 없음 전용 카드](변화_없는_파일.md)를 표시한다. 이 카드는 원본처럼 정보 아이콘·정리 제목·회색 설명 박스·아카이브 저장/수정 버튼으로 구성한다. 제목·안내·사유는 응답 데이터에서 읽는다.

저장·수정 버튼은 실제 기능 연결 전까지 비활성이고 가짜 성공 알림을 띄우지 않는다. 이전 사용자 요청에 따른 카드 최대 너비(85%, sm 이상 80%)와 ‘{실제 응답 시각} · Growth AI’ 하단 표시는 유지한다. 좁은 화면에서는 제목·배지가 줄바꿈할 수 있다.

## 요청과 상태 처리

분석 원본은 [목데이터 chat.ts](../../src/mocks/Home/chat.ts)의 `mockFileAnalysisReply`와 `mockNoChangeReply`에 있다. [chatResponse.ts](../../src/mocks/Home/chatResponse.ts)가 선택 파일명을 반영하고 [FileAnalysisContent.tsx](../../src/components/FileAnalysisContent.tsx)가 응답 필드를 렌더링한다. 활동·유형·단계·관련 자료·요약·Before/After의 필드 대응은 [채팅 기능 문서](채팅_기능.md)의 ‘분석 내용은 어디에서 변경하는가’를 참고한다.

이 데이터·서비스·화면의 분리를 이후 카드와 다른 UI 개발에도 적용하기로 사용자와 확인했다. 실제 입력값을 보존하면서 분석 응답은 목데이터로 유지하고, 이후 실제 API 응답으로 교체한다.

- 모든 입력은 `sendChatMessage` → `getChatReply`로 전송하며 중복 실행을 막는다.
- 진행 상태가 바뀌면 자동으로 채팅 하단으로 스크롤한다.
- 대화 초기화 시 진행 상태도 비운다. 이전 요청의 진행 알림·최종 응답은 요청 ID가 다르면 무시한다. 화면 해제 후 응답에도 같은 보호를 적용한다.
- 실제 API로 전환할 때는 목 타이머를 실제 서버 진행 이벤트로 교체한다. 서버가 최종 결과만 제공하면 단계 완료를 임의로 표시하지 않는다.

## 검증

- `npm run lint`, `npm run build` 통과.
- 실제 서비스·목 모듈을 Node에서 불러와 가상 타이머로 단일 파일 6종의 진행 알림 순서와 600ms/1300ms 대기, 실제 이름·변화 근거 보존·고유 응답 ID를 확인했다.
- 변화 없음 분기, 잘못된 이전 파일 연결 방지, 목 원본 불변, 다중 파일·텍스트 회귀, 빈 입력 거부, 시연 전용 코드 제거를 함께 확인했다.
- 초기화·화면 해제 보호는 코드로 확인했다. 브라우저에서의 클릭·취소 재현, 실제 렌더링 및 픽셀 단위 일치는 미검증이다.

2026-11-03 기록 보완: 현재 분석 값이 목데이터라는 점과 데이터 위치, 이후 다른 UI에도 적용할 개발 방식을 기록했다. 이번 문서 정리에서 검사를 새로 실행하지는 않았다.
