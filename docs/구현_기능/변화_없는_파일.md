# 변화 없는 파일 구현 기록

최종 정리: 2026-11-03

## 현재 동작

단일 파일을 첨부 후 전송하고 응답의 `analysis.changes`가 비어 있으면, [기준 HTML](../references/1Line_reference.html)의 ‘변화 없음 파일’ 카드 스타일을 표시한다. 실제 분석은 하지 않으며 문구·사유는 목데이터다.

파일 이름에 관계없이 확인할 수 있도록 현재 단일 파일 목 설정은 **변화 없음**이다. 실제 파일명은 사용자 말풍선과 응답의 파일 정보에 보존한다. 파일 선택·드롭만으로 전송하지 않으며 기존 점 3개 → 진행 카드 → 결과 흐름은 유지한다.

## 카드 구성

1. 정보 아이콘과 정리 결과 제목
2. 회색 설명 박스 안의 변화 없음 안내와 상세 사유
3. ‘아카이브 저장’, ‘수정’ 버튼

원본의 폰트·간격·배경·테두리·버튼 스타일을 사용한다. 이전 사용자 요청에 따른 카드 최대 너비 85%/80%와 실제 응답 시각·Growth AI 표시는 유지한다.

활동/유형 등의 정보 그리드, AI 요약 라벨, Before/After, 새로운 변화 개수 배지는 표시하지 않는다. 버튼은 아직 비활성이며 아카이브 저장이나 Timeline 생성은 수행하지 않는다. 설명도 버전 업데이트를 제안하는 문구로 두어 저장 완료로 오해하지 않게 한다.

| 위치 | 역할 |

| [mocks/Home/chatResponse.ts](../../src/mocks/Home/chatResponse.ts) | 목 응답 선택·실제 파일명 반영·진행 알림 |

목 응답의 `content`는 제목, `analysis.noChangeMessage`는 변화 없음 안내, `analysis.summary`는 상세 사유다. `changes: []`와 `suggestedSaveMode: 'version-only'`를 사용한다.

현재 `mockSingleFileAnalysisMode = 'no-change'`다. 목데이터 파일에서 `'change'`로 바꾸면 기존 변화 있음 카드도 임의의 파일로 확인할 수 있다. 파일명으로 실제 변화를 판단하지 않으며 화면에 시연 버튼을 다시 추가하지 않았다. 두 예시 응답은 모두 보존한다.

## 실제 API 교체

`getChatReply`의 응답을 같은 화면용 구조로 변환하면 된다. 파일이 한 개인 `file-analysis` 또는 `no-change`에서 `changes: []`이면 전용 카드를 선택하므로 `kind`가 `file-analysis`인 실제 응답도 처리한다. 목 모드는 API 전환 시 사용하지 않는다.

## 검증

- lint/build 통과.
- 임의 파일명 3종으로 변화 없음 응답·실제 이름 보존·진행 알림·버전 저장 제안을 확인했다.
- 실제 컴포넌트를 React 서버 렌더링해 목 문구 표시와 비교/배지/정보 그리드 미생성을 확인했다. `file-analysis`이면서 변화가 빈 응답, 변화 있음 카드, 다중 파일·텍스트 분기도 확인했다.
- 브라우저 렌더링과 픽셀 단위 일치는 미검증이다. 서버 렌더링 검증은 실제 화면 시각 검증을 대체하지 않는다.
