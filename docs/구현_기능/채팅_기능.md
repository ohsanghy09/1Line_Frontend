# 채팅 기능 구현 기록

최종 정리: 2026-11-03

## 현재 상태

홈의 Growth AI 채팅에서 **입력 → 전송 → 응답 대기 → 목 분석 결과 카드 표시**까지 구현했다. 현재는 **모든 단일 파일 전송을 원본 파일 업로드와 같은 진행·결과 카드 형식으로 연결**했고, 시연 시나리오 영역과 전용 호출 코드는 제거했다. 실제 AI API, 파일 내용 분석, 서버 저장은 연결하지 않았다.

화면 기준은 [1Line_reference.html](../references/1Line_reference.html)이다. 이후 사용자 요청으로 정한 카드 최대 너비와 실제 시각 표시는 유지한다. 작업을 이어갈 때는 이 문서와 [개발 기록](../개발_기록.md), 실제 소스를 함께 확인한다.

카드별 작업과 응답 데이터 확인은 **`/example`**에서 할 수 있다. 실제 컴포넌트로 텍스트·변화 있음·변화 없음·다중 파일 카드, 진행 카드와 상태 배지를 함께 표시한다. [채팅 카드 미리보기](채팅_카드_미리보기.md)를 참고한다.

## 구현한 기능

| 기능 | 현재 동작 |
| --- | --- |

| 준비 상태 배지 | 홈 진입 시 상태 서비스를 조회하고 목 응답의 상태·문구 표시. 조회 중·실패 구분 |

| 파일 첨부 | 여러 파일 선택·추가 선택, 전송 전 첨부 목록 표시, 개별 삭제 |
| 드래그 앤 드롭 | 입력창·첨부 영역에 파일을 놓으면 첨부 목록에 추가. 자동 전송하지 않음 |

| 변화 없는 파일 | 변화 배열이 비어 있으면 원본의 정보 아이콘·회색 설명 박스·아카이브 저장/수정 버튼 카드 표시 |
| 결과 카드 | 텍스트·단일 파일·변화 없는 예시 파일·다중 파일 결과 표시 |

| 대화 초기화 | 메시지·입력·첨부·대기·분석 진행·오류·드래그 상태와 초기 안내 시각 초기화 |
| 비동기 보호 | 중복 전송 방지, 초기화·화면 해제 이전의 늦은 진행 알림·최종 응답 무시 |
| 오류 안내 | 응답 실패 시 다시 전송해달라는 안내 표시 |

## 메시지와 카드 표시

- 사용자 말풍선은 최대 너비 80%, 하단 시간과 4px 간격을 사용한다.
- AI 카드는 최대 너비 85%, `sm` 이상에서는 80%로 표시한다. 원본을 기준으로 맞춘 뒤 사용자의 요청으로 너비를 조금 줄였다.
- 사용자 메시지는 전송 시각, AI 메시지는 응답 도착 시각을 기록한다.
- 1분 미만은 ‘방금 전’, 1시간 미만은 ‘N분 전’, 그 이상이면서 오늘이면 ‘오후 2:30’, 이전 날짜면 ‘11월 3일 오후 2:30’ 형식으로 표시한다. 연도가 다르면 연도도 표시한다.
- AI 카드 하단은 ‘{시간} · Growth AI’다. 상대 시간은 30초마다 갱신한다.
- 시각에 마우스를 올리면 정확한 날짜와 시간을 확인할 수 있다. 사용자 기기의 현지 시간을 기준으로 한다.

## 채팅 서비스 준비 상태

헤더의 ‘기록 정리 준비됨’은 JSX의 고정 문구에서 **목데이터 → 상태 조회 서비스 → 배지 표시** 구조로 변경했다.

- 목 응답: [chatStatus.ts](../../src/mocks/Home/chatStatus.ts)의 `mockChatServiceStatus`. 현재 `status: 'ready'`, `label: '기록 정리 준비됨'`을 반환한다.
- 서비스: [services/chat.ts](../../src/services/chat.ts)의 `getChatServiceStatus(): Promise<ChatServiceStatus>`. 실제 연결 시 함수 내부를 API 요청과 응답 변환으로 교체한다.
- 표시: [ChatServiceStatusBadge.tsx](../../src/components/ChatServiceStatusBadge.tsx). `ready`는 기존 초록 스타일, `unavailable`은 주황색 계열로 표시하며 문구는 응답의 `label`을 사용한다.
- 응답을 기다릴 때는 회색 ‘상태 확인 중’, 요청이 실패하면 회색 ‘상태 확인 실패’를 표시한다. 실패를 준비 완료나 사용 불가로 임의 해석하지 않는다.
- Home 진입 시 한 번 조회하고 화면을 떠난 뒤 도착한 응답은 무시한다. 대화 초기화는 준비 상태를 초기화하지 않는다.
- 이 상태는 목 응답이며 실제 서버 가용성을 확인하지 않는다. 메시지별 분석 진행 상태와 별개이고, 상태 조회 결과로 전송을 새로 차단하는 동작은 추가하지 않았다.

응답 구조와 API 협의 사항은 [채팅 서비스 상태](../api/채팅_서비스_상태.md)에 기록했다.

## 최근 구현: 실제 단일 파일 전송과 목 분석

### 실행과 화면 전환

파일 한 개를 첨부한 뒤 전송하면 확인할 수 있다. 파일명은 제한하지 않으며 텍스트와 함께 보낼 수도 있다. 시연 시나리오 영역과 모든 시연 버튼은 제거했다.

1. 파일 아이콘과 파일명을 사용자 말풍선에 표시한다. 단일 파일은 첨부 개수·별도 파일 박스 없이 원본처럼 표시한다.
2. Bot 아이콘과 점 3개를 600ms 동안 보여준다.
3. 다음 진행 카드를 1300ms 동안 보여준다.
   - 파일 확인 완료
   - 기존 활동 비교 완료
   - 자료 유형 분석 완료
   - 이전 기록과 비교 중...
4. 진행 카드를 제거하고 파일 분석 결과 카드로 교체한다.

진행 항목은 순서대로 완료되는 실제 작업이 아니라 원본의 한 장면을 표시하는 목데이터다. 파일 선택·드롭만으로는 분석을 시작하지 않는다. 전송 후 글과 첨부 목록을 비운다.

### 결과 카드와 데이터

제목의 파일명·새로운 변화 개수, 활동·자료 유형·단계·관련 자료의 2열 정보 박스, AI 요약, 인디고 Before/After, 저장·수정 버튼을 표시한다. 화면은 응답의 `analysis`를 사용한다. 서비스는 실제 파일명을 보존하고, 활동·유형·요약·변화 내용은 목데이터를 넣는다. 임의의 파일을 고정 예시의 이전 파일과 연결하지 않는다.

`ChatReplyCard`는 `file-analysis` 또는 `no-change`이며 파일이 1개일 때 변화 배열을 확인한다. 변화가 있으면 `FileAnalysisContent`, `changes: []`이면 원본의 변화 없음 전용 `NoChangeAnalysisContent`를 표시한다. 그룹 개수나 파일명으로 카드 스타일을 선택하지 않는다.

현재는 [목데이터 chat.ts](../../src/mocks/Home/chat.ts)의 `mockSingleFileAnalysisMode`를 `'no-change'`로 설정하여 어떤 파일로도 변화 없음 카드를 확인할 수 있다. `'change'`로 바꾸면 기존 변화 있음 목 응답을 사용할 수 있다. 실제 API 연결 후에는 목 모드 대신 서버 응답을 사용한다. 자세한 구성은 [변화 없는 파일](변화_없는_파일.md)을 참고한다.

### 서비스와 상태 처리

- 모든 전송: `sendChatMessage` → `getChatReply(message, files, onProgress?)`
- 단일 파일 목 처리: `getMockFileReply(file, onProgress?)` → 진행 콜백 → `Promise<ChatReply>` 반환
- `getFileUploadDemoReply`와 시연 전용 플래그·예시 첨부 생성 코드는 제거했다.
- `ChatProgress`는 제목과 단계별 문구·상태를 갖는 화면용 구조다. 확정된 서버 응답 계약이 아니다.
- `analysisProgress`가 있으면 점 3개 대신 진행 카드를 표시한다. 최종 결과·실패·대화 초기화 시 진행 상태를 비운다.
- 진행 콜백과 최종 결과 모두 요청 ID를 확인하므로 초기화 후 과거 요청이 다시 표시되지 않는다. 실제 브라우저에서 초기화·재전송을 재현한 검증은 아직 하지 않았다.

상세 기록은 [파일 업로드 분석](파일_업로드_분석.md), API 교체 시 확인할 구조는 [파일 분석 응답](../api/파일_분석_응답.md)을 참고한다.

## 목 응답의 범위와 미구현 사항

- 텍스트는 현재 모두 같은 기능 축소 예시를 반환한다. 입력 의미에 따른 실제 분류는 하지 않는다.
- 단일 파일은 실제 파일명을 보존하며 목 설정에 따라 변화 있음/없음 응답을 반환한다. 현재는 파일명과 무관하게 변화 없음 목 응답을 사용한다. 파일 내용을 실제로 해석한 결과가 아니다.
- 파일과 텍스트를 함께 보내면 목 응답 분기는 파일을 우선한다.
- 저장·분류 수정·다른 활동 선택 버튼은 비활성 상태다. 다중 파일의 ‘자료 확인’은 `/archive` 이동만 한다.
- 단일 파일의 진행·결과는 [파일 업로드 분석](파일_업로드_분석.md)에 정리했다. 진행 상태는 실제 서버 처리 현황이 아닌 목 상태다.
- 링크 입력, 변화 없는 텍스트 분기는 미구현이다. 시연 버튼은 사용자 요청으로 모두 제거했으므로 남은 구현 대상으로 취급하지 않는다.
- 대화는 메모리에만 보관하므로 새로고침하거나 홈을 다시 열면 보존되지 않는다.

## 관련 코드

### 분석 내용은 어디에서 변경하는가

단일 파일 카드의 분석 값은 [목데이터 chat.ts](../../src/mocks/Home/chat.ts)의 `mockFileAnalysisReply`에 있다. 변화 없는 예시는 같은 파일의 `mockNoChangeReply`다.

| 화면 항목 | 목 응답 필드 |
| --- | --- |
| 활동 | `analysis.activity.name` |
| 자료 유형 | `analysis.materialType` |
| 단계 | `analysis.stage` |
| 관련 자료 | `analysis.files[].previousVersion` |
| AI 요약 | `analysis.summary` |
| Before / After | `analysis.changes[].before` / `after` |

[chatResponse.ts](../../src/mocks/Home/chatResponse.ts)는 예시 분석을 선택하고 실제 파일명을 응답 제목·파일 정보·변화 근거에 넣는다. 관련 이전 자료는 원본 예시 파일일 때만 목 연결을 사용하며, 다른 파일은 연결 없음으로 처리한다. [FileAnalysisContent.tsx](../../src/components/FileAnalysisContent.tsx)는 이 값을 읽어 표시한다. 따라서 분석 내용을 바꿀 때 JSX에 특정 파일의 분석 문장을 직접 넣지 않는다.

현재는 이들 분석 값 모두 실제 AI 판단이 아니다. 나중에 [서비스](../../src/services/chat.ts)에서 실제 API 응답을 같은 화면용 구조로 변환하면 카드 렌더링을 재사용할 수 있다.
