## 문서 구성

브라우저 문서는 [Swagger 사용 안내](Swagger_사용안내.md)를 따른다. 프론트 주소의 `/swagger/`에서 정적 문서를 제공하며 기존 화면 메뉴·React 라우트에는 연결하지 않는다. 프론트 Vercel 배포에도 함께 포함한다. AI 모델은 미정이고 기존 계약값을 유지한다.

| 문서 | 받는 값과 반환하는 값의 기준 |
| --- | --- |
| [백엔드 API 계약](백엔드_API_계약.md) | 활동·기록·자료의 저장·조회·수정 및 현재 개발 서버의 분석 접수 |
| [AI API 계약](AI_API_계약.md) | 텍스트·파일·링크·성장 분석에 필요한 입력과 분석 결과 |

[화면별 구현 현황](../현재구현_현황_정리/문서_안내.md)은 현재 기능을 설명하고, 이 폴더는 기능별 요청·응답 데이터를 설명한다. 개발용 카드 미리보기는 전달 대상 화면에서 제외한다.

## 호출 구조와 문서 상태

2026-11-06 사용자가 다음 실제 구현 예정 구조를 확정했다.

1. **홈 분석:** 프론트 → AI 서비스 → 분석 결과 카드 표시.
2. **기록·저장:** 프론트 → 백엔드 → 분석 결과와 자료 저장.
3. **나의 발자국·Timeline:** 프론트 → 백엔드 → 저장된 데이터 조회.
4. **Growth Journey:** 백엔드·AI가 성장 분석 결과를 생성·저장하고 프론트는 백엔드에서 조회.

현재 코드를 이 구조로 전환한 것은 아니다. 현재 홈도 로컬 Express가 입력을 받아 목 분석을 생성하고, 확정 저장 후 아카이브에서 조회한다. Journey는 DB 저장 없이 고정 목 응답을 조회한다. AI 모델·공급자는 계속 미정이다.

AI 서비스는 AI 담당자가 제공하는 서버 API를 뜻한다. 저장 대상 사용자·자료 권한 및 분석 결과의 유효성은 백엔드가 검증한다. 홈 분석을 프론트에서 직접 요청하더라도 기존 문맥 준비·파일 보관·분석 식별자·저장 검증의 상세 방식은 협의가 필요하다.

2026-11-06 추가 확정: 신규/기존 활동 판단과 활동 DB 연결은 AI 서비스가 담당한다. 신규이면 AI 서비스가 DB에 활동을 생성하고 기존이면 해당 활동을 사용한다. 프론트의 별도 새 활동 생성 화면은 만들지 않는다. 생성/매칭된 활동 ID를 프론트 저장 요청에 연결하는 방향이며 실제 응답 필드, 생성 시점, 중복 생성 처리, 기록 확정 저장과의 관계는 담당자 협의가 필요하다. 현재 로컬 목 분석과 Swagger 초안은 이 자동 생성 흐름으로 전환하지 않았다.

- **현재 구현:** 로컬 개발 서버·서비스·타입에서 확인한 동작이다.
- **화면용 요구사항:** 기존 화면을 유지하기 위해 필요한 값이다. 외부 API가 동일한 키를 그대로 반환할 의무는 없으며 변환 계층을 둘 수 있다.
- **제안·협의 필요:** 실제 AI 요청 스키마·경로·담당·저장 정책 등 아직 구현하거나 합의하지 않은 내용이다.

## 연동 협의사항

호출 구조는 위와 같이 사용자 확정이며, 아래 상세 항목은 담당자 협의가 필요하다. 결정 시 담당자·내용·날짜를 추가한다.

| 항목 | 결정할 내용 |
| --- | --- |
| 호출 구조 반영 | 홈은 프론트→AI 서비스, 저장·화면 조회는 백엔드. 이 구조에 맞춘 실제 경로·서비스 주소 확정 |
| 인증·권한 | 각 서비스 사용자 인증, 사용자별 활동·파일·기록 접근, 브라우저 직접 호출 시 CORS |
| 입력 준비 | 활동 후보·기존 기록 조회, 파일 보관·본문 추출, 링크 수집을 누가 수행하는지 |
| 파일 전달 | multipart 원본·자료 ID·접근 가능한 임시 URL·추출 텍스트 중 사용할 방식 |
| 분석 식별자 | 요청·작업·분석 ID 발급 주체와 서비스 간 연결, 중복 요청 처리 |
| 결과 저장 | 초안 보관 주체, 분석 ID로 확정 저장할지 결과를 제출할지, 결과 검증·위변조 방지 |
| 작업 상태 | 동기/비동기, 폴링/이벤트, 완료·실패·취소·재개·시간 초과 |
| 데이터 의미 | 분류 선택지, 성장 유형·분야, Turning Point와 근거·버전 관계 |
| 갱신·삭제 | 기록 수정·이동·삭제 시 분석 결과·근거·이벤트의 갱신·보존 |
| 환경·오류 | 서버 주소, 오류 코드, 제한값, 환경 변수·비밀키 관리 |

## 다음 진행과 검증

1. 백엔드·AI 문서의 입력·출력 의미를 담당자와 확인한다.
2. 확정 구조를 기준으로 인증·입력 준비·분석 결과와 자료 저장의 상세 방식을 정한다.
3. AI가 필요 없는 기록 조회를 실제 서버에 연결한다.
4. 홈에서 입력 → AI 서비스 → 카드 표시 → 백엔드 확정 저장 → 백엔드 재조회 흐름을 검증한다.
5. 변화 없음·빈 결과·실패·재시도·중복 저장·근거 ID·활동 이동을 확인한 뒤 범위를 넓힌다.

문서 예시는 모두 가상 데이터다. 이번 문서 작성은 실제 API·AI·브라우저 검증을 새로 수행했다는 의미가 아니다. 기존 사용자 DB와 화면·서버 코드는 변경하지 않는다.
