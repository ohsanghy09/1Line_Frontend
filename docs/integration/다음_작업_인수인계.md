## 지금 이어갈 작업

사용자는 Swagger·연동 준비 이후 홈 채팅의 수정·기록 버튼이 원본과 다른 점을 검토했다. **먼저 수정 버튼이 있는 카드들의 수정 모달을 변화 없는 단일 파일 카드처럼 통일할 예정**이다. 사용자가 코드 변경을 하지 말라고 했으므로 이번 대화에서는 비교·설명·문서 정리만 했다. 실제 구현은 다음 요청 범위에 맞춰 진행한다.

화면 수정 전에 [공통 개발 규칙](../개발_규칙.md)을 확인한다. 원본 HTML은 수정하지 않고 기존 사용자 DB·다른 화면·스타일을 임의로 변경하지 않는다.

## 1. 실제 연동 구조 — 사용자 확정

| 기능 | 실제 구현할 호출 흐름 |
| --- | --- |
| 홈 분석 | 프론트 → AI 담당자의 서비스 API → 분석 결과 카드 표시 |
| 기록·저장 | 프론트 → 백엔드 → 분석 결과와 자료 저장 |
| 나의 발자국·활동 상세·자료 패널·Timeline | 프론트 → 백엔드 → 저장된 데이터 조회 |
| Growth Journey | 백엔드·AI가 성장 분석 결과 생성·저장 → 프론트는 백엔드에서 조회 |

AI 서비스는 AI 담당자가 제공하는 서버 API다. AI 모델·공급자·주소·인증과 상세 요청/응답은 아직 미확정이다. 홈의 실제 AI 직접 호출도 현재 구현한 것은 아니다.

**프론트는 변화 여부를 자체 판단하거나 Timeline 이벤트를 생성해 DB에 저장하는 로직을 구현하지 않는다.** AI는 분석 결과·변화 판단을 제공하고, 백엔드는 결과·자료를 저장하며 변화 결과에 따라 Timeline 이벤트를 처리한다. 프론트는 카드 표시, 사용자 분류 수정, 계약된 저장 요청, 결과 재조회를 담당한다.

## 2. 기록·저장 의미 — 대화에서 정리한 개념

‘1호선톤에 기록’은 이번에 입력한 글·자료와 AI 분석 결과를 **1호선톤 활동에 연결된 새 기록으로 추가**한다는 의미다. 기존 기록이나 활동 전체 요약을 자동으로 덮어쓴다는 의미가 아니다.

예:

1. 사용자 입력: ‘인터뷰를 반영해서 기능 6개를 3개로 줄였어요.’
2. AI 분석: 기록 요약·자료 유형·변화·근거 등을 반환한다.
3. 사용자가 ‘1호선톤에 기록’을 누르면 프론트가 확인한 활동과 저장에 필요한 정보를 백엔드에 보낸다.
4. 백엔드가 새 기록을 만들고 해당 활동에 연결한다. 기존 기록은 유지한다.

| 구분 | 의미·담당 |
| --- | --- |
| 이번 기록 요약 | 이번 입력·자료에 대한 AI 분석. 새 기록에 함께 저장 |
| 기존 기록 수정 | 이미 저장된 특정 기록 변경. 새 기록 추가와 구분 |
| 활동 전체 AI 요약 | 해당 활동의 여러 기록을 종합. 생성·갱신은 백엔드·AI 담당이며 시점·방식 미정 |
| Project Timeline | 의미 있는 변화의 이벤트와 근거. 생성·저장은 백엔드 담당 |
| Growth Journey | 여러 활동의 성장 분석. 백엔드·AI 생성·저장 후 조회 |

저장된 기록은 Timeline·활동 요약·Journey의 분석 근거로 활용할 수 있다. **매 저장마다 전체 분석을 다시 실행하기로 정한 것은 아니다.** 갱신 시점·재분석·수정/삭제 후 처리는 담당자 협의 대상이다. AI 서비스가 직접 DB에 접근해 활동 요약을 고치는 구조로 확정하지 않았다.

실제 저장 요청을 분석 ID로 보낼지, 분석 결과를 포함할지, 원본 파일을 언제 어디에 보관할지는 미정이다. 설명용 저장 개념을 최종 요청 필드로 확정하지 않는다.

## 3. 수정 모달 — 사용자 변경 예정 범위

현재 텍스트·링크·변화 있는 단일 파일 등의 수정 버튼은 확장된 활동 정보 확인 모달을 연다. 이를 변화 없는 단일 파일 카드와 같은 분류 수정 범위로 바꿀 예정이다.

- **표시할 항목:** 연결할 기존 활동 선택, 자료 유형.
- **제외할 항목:** 신규 활동 생성, 활동명·활동 유형·상태·역할·기간·활동 전체 요약 편집, 기존 활동 정보 적용 체크박스.
- **저장 전 수정:** 카드·세션의 활동/자료 유형에 적용하며, 확정 기록 저장은 별도 버튼에서 수행한다.
- **저장 후 수정:** 해당 기록의 활동·자료 유형만 백엔드 수정 API로 반영한다.
- **적용 대상:** 수정 버튼이 있는 텍스트·링크·단일 파일 등 카드.
- **다중 파일:** 수정 버튼을 새로 추가하지 않는다. 기존 전체 저장·자료 확인 버튼 유지.
- 사용자가 먼저 지정한 것은 **수정 동작의 통일**이다. 이를 이유로 기록·저장 흐름까지 동시에 바꾸지 않는다.

## 4. 기록·저장 버튼 — 다음 검토 방향

대화에서 제안한 방향은 활동 전체 정보 모달을 거치지 않고 확인된 활동으로 백엔드 저장 요청을 보내는 것이다. 다만 수정 모달 통일과 별도 작업으로 진행하며, 사용자 다음 요청에서 범위를 확인한다. **아직 구현하지 않았다.**

- 프론트가 저장 API를 호출한다는 의미이며 AI 분석·DB 저장 로직을 프론트로 옮기는 것이 아니다.
- 활동 연결이 미확정·삭제된 경우의 안내, 새 활동이 필요한 경우의 진입 흐름은 추가로 정리해야 한다.
- 모달 제거만을 위해 활동명을 임의 ID로 추측하거나 데이터·분석 값을 변경하지 않는다.
- 기록 확정 전 ‘저장 완료’라고 표시하지 않는다. 중복 클릭·실패 처리·원본 파일 연결을 보존한다.

## 5. 원본·기능명세와의 차이

기능명세 1-3은 분석 결과를 활동 아카이브에 저장하고, 의미 있는 변화는 Project Timeline 이벤트로 기록하며, 변화 없는 자료는 아카이브에 보관하되 Timeline 이벤트를 생성하지 않도록 정의한다. 분류 수정은 활동·자료 유형 수정이다.

원본 HTML의 수정 모달은 ‘기록 분류 수정’ 제목과 활동 선택·자료 유형, 취소·수정 저장으로 구성된다. 기록/저장 버튼은 실제 저장 대신 alert만 띄운다. 원본을 따른다고 가짜 성공 처리를 복원하지 않는다.

이전 구현에서 실제 저장과 활동 메타정보 확인 기능을 연결하면서 수정·기록 버튼에 `ActivityReviewModal`을 공통 연결했다. 원본보다 넓어진 입력 항목과 저장 전 확인 단계는 이번 검토 대상이다. 이전 문서에 확장 이력이 있다는 이유로 변경을 막거나 기존 확장 UI를 확정 요구로 간주하지 않는다.

링크도 URL 접수 → 분석 → 활동·자료 유형·요약 카드 → 수정/저장 흐름이다. 링크만의 활동 전체 정보 편집 모달 요구는 없다. 지원 사이트 범위는 기능명세상 일부로 제한할 수 있다.

## 6. 현재 구현 상태 — 아직 위 변경을 적용하지 않음

- 홈은 프론트 → 로컬 Express `/api/chat`·`/api/chat/links` → 서버 목 분석이다. 실제 AI 호출 없음.
- 로컬 서버는 입력·파일·분석 초안을 보관하고, 별도 확정 저장 요청에서 기록을 저장한다.
- 나의 발자국·활동 상세·자료 패널·Timeline은 SQLite의 확정 기록을 백엔드에서 조회한다. 저장된 분석 내용은 목 값일 수 있다.
- 로컬 서버는 changes가 있으면 기록과 이벤트를 함께 저장한다. 기본 Turning Point는 false다. 이것은 이미 있는 백엔드 개발 코드이며 새 프론트 책임이 아니다.
- Growth Journey는 `/api/journey`에서 고정 목 응답을 받는다. 실제 DB 문맥·AI 분석·성장 결과 저장은 미구현이다.
- 변화 없는 단일 파일만 현재 `classificationOnly`로 활동·자료 유형 수정이 가능하고 아카이브 저장은 모달 없이 처리한다.
- 다른 카드의 수정·기록은 아직 확장 `ActivityReviewModal`을 사용한다.

## 8. 이전 완료 작업과 검증 한계

화면별 구현 현황·백엔드/AI 요청·응답 초안과 Swagger를 작성했다. Swagger는 프론트 개발·빌드 전에 정적 생성되고 `/swagger/`로 직접 접속한다. 기존 메뉴에 링크를 추가하지 않았다. [사용 안내](API_계약/Swagger_사용안내.md) 참고.

앞선 Swagger 작업에서 build 통과, lint 오류 없음(기존 홈 경고 3개), 서버 검사 19개 통과와 로컬 개발·preview 문서 HTTP 확인을 기록했다. 이번 모달 비교·설명·문서 정리에서 다시 실행한 검사 결과는 아니다. 실제 브라우저의 원본 비교·모달 조작, Vercel 배포·터널·실제 서버·AI 연결 완료로 기록하지 않는다.

이번 요청은 인수인계 문서 작성이며 실행 코드는 변경하지 않았다. 다음 작업도 기능을 하나씩 진행하고, 문서의 계획을 전체 일괄 구현 지시로 취급하지 않는다.
