# 나의 발자국 목록 구현 현황

정리일: 2026-11-05. 경로: `/archive`. 공통 전제는 [문서 안내](../문서_안내.md)를 따른다.

## 구현된 동작

- 활동명·유형·상태·역할·기간·활동 요약·확정 자료 수·최근 업데이트를 표시한다.
- 검색·유형·상태를 AND로 적용하고 최근 업데이트·자료 많은 순·오래된 순으로 정렬한다. 오래된 순도 업데이트 시각 기준이다.
- 한글 조합 중을 포함해 입력 변경마다 즉시 서버에 요청한다. 이전 요청을 취소하고 최신 응답만 반영한다.
- 최초 로딩, 기존 목록을 옅게 유지하는 재조회, 실패·재시도, 전체 없음·조건 결과 없음을 구분한다. 재조회 중 이전 목록 이동을 막는다.
- 활동 카드에서 활동 상세로 이동한다. 목록 재진입 시 필터는 기본값으로 초기화한다.

## API와 데이터

GET `/api/archive/activities?q=...&category=...&status=...&sort=...`

- 응답은 `items`와 조건 적용 전 전체 활동 수 `total`이다. 프론트에서 결과를 다시 검색·필터링하지 않는다. 현재 페이지네이션은 없다.
- 서버 SQLite의 활동과 확정 기록을 집계한다. 분석만 하고 확정 저장하지 않은 초안은 제외한다.
- 자료 수는 확정 파일 수 + 파일 없는 텍스트/링크 기록 수다. 다중 파일은 파일 수로 센다.
- 검색 대상은 활동명·활동 전체 요약·자료 이름·입력 글/URL·기록 요약이다. 파일 원본 BLOB·PDF 내부 본문 검색은 제외한다.
- 기존 DB에서 활동 정보가 없으면 미분류·미설정·요약 없음으로 표시한다. 기록 하나의 요약을 활동 전체 요약으로 대신하지 않는다.
- 저장된 분류·요약은 목 분석값 또는 사용자가 확인·수정한 값일 수 있다. DB 조회 자체는 실제다.

## 실제 연동 시 남은 작업

- 검색·필터·정렬 값, 집계·total 의미 및 페이지네이션 도입 여부 합의
- 사용자별 활동 조회·권한, 활동 정보 및 실제 AI 활동 전체 요약 계약
- 열린 화면·다른 탭의 자동 갱신 정책. 현재는 재진입·조건 변경 등 조회 시 갱신한다.
- 독립 활동 관리 화면은 미구현이다. 현재 활동 정보 확인·적용은 채팅 카드 흐름에서 제공한다.
