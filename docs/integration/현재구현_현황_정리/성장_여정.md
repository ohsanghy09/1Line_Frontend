# 성장 여정 구현 현황

정리일: 2026-11-05. 화면명: Growth Journey. 경로: `/journey`. 공통 전제는 [문서 안내](문서_안내.md)를 따른다.

## 구현된 동작

- 최근 성장 흐름 요약·첫 경험 배지·유형/분야 필터·세로 성장 이벤트 목록을 표시한다.
- 서버에서 전체 응답을 한 번 받고 유형·분야를 프론트에서 AND로 필터링한다. 필터는 목록만 바꾸며 요약·배지는 유지한다.
- 이벤트는 `YYYY-MM` 정밀도로 오래된 순, 같은 월은 응답 순서로 표시한다.
- Before/After가 모두 있는 카드만 상세를 펼친다. 이벤트 ID별로 여러 카드를 독립적으로 열 수 있고 필터로 숨겨도 펼침 상태를 유지한다.
- 모든 이벤트 카드에 호버 효과가 있다. 타임라인 원은 호버 중에만 채워지고 클릭·펼침 상태로 고정되지 않는다.
- 최초 로딩·오류·다시 불러오기·전체 이벤트 없음·필터 결과 없음을 구분한다.

## API와 데이터

GET `/api/journey`

- 화면 → `getGrowthJourney(signal)` → 공통 request → 개발 API → 서버 목 공급자 순서다.
- 진입·오류 재시도 시 요청한다. 필터 변경·상세 펼침으로 AI/API를 재호출하지 않는다.
- 응답: `source`, `summary`, `badges`, `typeOptions`, `axisOptions`, `events`. 이벤트에는 활동·분류·제목·설명·선택적 comparison이 있다.
- 프론트·서버에서 필수 문자열·월 형식·중복 ID·선택지 참조·비교 정보를 검증한다. 오류를 예시 성공 응답으로 대체하지 않는다.
- 현재 요약·배지 4개·이벤트 5개는 전부 서버 예시다. DB를 조회하거나 수정하지 않는다. `source`는 `mock`, 활동 ID는 null이다.
- 화면의 ‘예시 데이터’ 배지는 사용자 요청으로 제거했지만 실제 AI 연결 상태로 바뀐 것은 아니다.
- 비교 근거는 문자열이며 실제 파일 링크·자료 ID가 아니다. 이름으로 실제 활동이나 자료에 연결하지 않는다.

## 실제 연동 시 남은 작업

1. 확정 저장 기록·활동·자료 ID와 입력을 AI에 전달할 분석 문맥 구성
2. 원본 화면과 기능명세가 다른 최종 성장 유형·분야 기준 합의
3. 분석 실행·저장·갱신·재분석·분석 중 상태 계약
4. 실제 AI 분석과 응답 검증, 안정적인 이벤트 ID 관리
5. 근거 자료 ID 기반 연결 및 기록 수정·삭제·이동 후 관계 처리

변화 없는 자료나 일반 Timeline 이벤트를 저장했다는 이유로 Journey 성장 이벤트·첫 경험 배지를 자동 생성하지 않는다. 분석 실행·갱신 API와 Journey 전용 저장은 현재 구현하지 않았다.
