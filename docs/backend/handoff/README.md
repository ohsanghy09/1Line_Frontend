# 백엔드 담당자 안내

기준일: 2026-11-06. [전체 안내](../../common/handoff/README.md) · [공통 시작](../../common/handoff/에이전트_시작_안내.md)

백엔드는 사용자 확정 저장, 활동 생성·수정, 원본 연결, 발자국 검색·조회·삭제, Timeline, 활동 종합 예약, Journey 결과 검증·저장을 담당한다. AI의 activity=new는 활동 생성 완료가 아니다.

읽는 순서: [구현 환경](../../common/handoff/개발환경과_구현_범위.md) → [API](API_정의서.md) → [DB](데이터베이스_정의서.md) → [ERD](ERD.md) → [저장·삭제](저장과_삭제_규칙.md) → [서버 간 전달](../../common/handoff/서버간_데이터_전달_계약.md) → [배포](../../common/integration/handoff/배포와_서버_연결.md) → [시나리오](../../common/integration/handoff/연동_검증_시나리오.md).

개발 소스·DB 파일·검사 스크립트는 제공하지 않는다. Node/Express/SQLite 설치는 요구하지 않는다. 선택한 환경에서 정의된 API·무결성·트랜잭션 효과를 구현한다. 활동 종합은 저장 성공 뒤 별도 실행하고 실패해도 확정 기록을 보존한다. 검사는 실제 모델 대신 합성 공급자를 사용할 수 있지만 실사용 API에 가짜 성공을 반환하지 않는다.

정식 DB 엔진은 SQLite로 확정한 것이 아니다. 현재 테이블·트랜잭션·응답 동작을 기준으로 새 서버에서 호환 구현한다. 파일 저장소를 바꿔도 analysisId와 원본 파일 연결을 유지한다. 인증·사용자 분리·서버 간 신뢰 경계는 [배포 문서](../../common/integration/handoff/배포와_서버_연결.md)의 전환 결정 대상이다.
