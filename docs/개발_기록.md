# 개발 기록 · 홈 AI 채팅

최종 정리: 2026-11-03

본문의 구현 현황은 2026-11-03 코드 기준이다. 문서 하단의 날짜별 기록은 변경 이력을 보존한다. 기능별 상세는 [채팅 기능](구현_기능/채팅_기능.md)과 [파일 업로드 분석](구현_기능/파일_업로드_분석.md)에 정리했다.

## 다음 작업을 시작할 때 먼저 읽을 내용

홈 채팅을 실제 AI API와 연결하기 전에 **목 응답으로 입력 → 응답 대기 → 분석 카드 표시**를 구현한 상태다. 사용자는 기능을 하나씩 확인하면서 진행하기를 원한다. 다음 기능을 한꺼번에 추가하기보다 최신 요청에 해당하는 범위부터 진행한다.

### 다음 대화를 위한 현재 상태 요약

- **앞으로 카드와 다른 UI도 같은 방식으로 개발한다:** 실제 입력 → 서비스 → 타입이 있는 목 응답 → 데이터 기반 렌더링 → 추후 실제 API 교체. 이 방식은 2026-11-03 사용자가 확인했다. 구체적인 범위는 다음 사용자 요청에 맞춰 하나씩 진행한다.

- **기준은 `docs/references/1Line_reference.html`**이다. 문서·참고 자료는 `docs/`로 통합했다. 원본은 수정하지 않고 React 구현을 변경한다. 이후 사용자 요청으로 정한 카드 너비와 시간 표시는 원본보다 우선한다.
- 헤더 준비 상태도 목 서비스로 분리했다. `getChatServiceStatus` → `mockChatServiceStatus`의 상태·문구를 표시하며 조회 중·조회 실패를 구분한다. 실제 서버 상태 확인이나 전송 차단은 아직 연결하지 않았다.
- **`/example`에 카드 작업용 미리보기를 추가했다.** 텍스트·변화 있음·변화 없음·다중 파일 카드, 진행 화면·준비 상태를 실제 컴포넌트로 표시한다. 카드별 응답 JSON과 버튼 상태를 확인할 수 있으며 홈의 목 모드는 유지한다.
- 가장 최근에 **모든 실제 단일 파일 전송**을 원본의 파일 분석 진행·결과 카드 구조로 통일했다. 이름·확장자와 관계없이 한 개를 첨부 후 전송하면 점 3개(600ms) → 진행 카드(1300ms) → 파일 분석 결과가 표시된다. 분석은 목데이터이며 실제 이름을 보존한다.
- 현재 단일 파일 목 모드는 **변화 없음**이다. `src/mocks/Home/chat.ts`의 `mockSingleFileAnalysisMode`로 예시를 선택한다. 파일명과 무관하게 원본의 정보 아이콘·회색 설명·아카이브 저장/수정 카드가 나오며, `'change'`로 바꾸면 기존 변화 있음 목 카드도 확인할 수 있다. 실제 API 연결 시에는 응답의 변화 배열이 표시를 결정한다.
- 진행 화면의 세 완료 문구와 한 비교 중 문구는 원본의 한 장면을 재현한 목 상태다. 실제 파일을 읽거나 서버의 진행도를 받는 기능은 아니다.
- 변화 있는 파일 결과에는 파일명·변화 개수·분류 정보·AI 요약·인디고 Before/After가 있다. 변화 없음은 전용 간결한 본문을 사용한다. 양쪽 모두 저장·수정은 아직 비활성이다.
- AI 결과 카드 최대 너비는 기본 85%, `sm` 이상 80%다. 사용자 말풍선은 최대 80%이며 하단 시각과 4px 간격이다.
- 사용자 전송 시각과 AI 응답 도착 시각을 저장한다. 하단에는 ‘방금 전/N분 전/시각/날짜’를 표시하고 AI는 ‘ · Growth AI’를 붙인다. 30초마다 갱신한다.
- 텍스트·다중 파일의 기존 분기를 유지했고 변화 없는 예시도 같은 단일 파일 진행·결과 카드로 표시한다. **시연 시나리오 UI와 전용 호출 코드는 모두 제거했다.**
- 마지막 코드 변경 후 lint/build, 목 서비스 분기와 시간 표시 로직 검증은 통과했다. **브라우저 렌더링·픽셀 단위 일치·실제 API 연동은 미검증**이다.
- 다음 작업은 최신 사용자 요청을 먼저 확인하며 저장·수정·다른 기능을 자동으로 추가하지 않는다. 제거한 시연 UI를 다시 도입하지 않는다.

### 최신 사용자 지시: 다음 작업의 우선순위

사용자는 저장 기능을 먼저 추가하는 것보다 **실제 AI API를 연결했을 때 시연 시나리오가 원본처럼 동작할 수 있도록 채팅 흐름을 완성하는 것**을 우선한다. API 결과를 받는 부분은 당분간 목데이터로 유지한다.

| 우선 점검할 시나리오 | 목표 | 현재 부족한 부분 |
| --- | --- | --- |
| 텍스트 경험 입력 | 활동 분류, 주요 변화, 근거, 결과 카드 | 모든 텍스트가 같은 기능 축소 응답으로 나옴 |
| 파일 업로드 | 파일 입력, 응답 대기, 단일 파일 결과 카드 | 모든 단일 파일의 목 진행·공통 결과 카드 구현. 브라우저 시각 검증과 실제 서버 연동은 남음 |
| 변화 없는 파일 | 주요 변화 없이 자료 버전 업데이트를 제안 | 전용 카드 구현. 현재 목 모드로 임의 파일에서 확인 가능. 실제 AI 판단은 미연결 |
| 변화 없는 텍스트 | 주요 변화를 억지로 생성하지 않고 자연스러운 답변·분석 결과 표시 | 이 경우를 선택하는 목 분기와 시연 경로 미구현 |
| 다중 파일 일괄 업로드 | 자료 분류·합계·버전 관계를 원본 형식으로 표시 | 목 분류 구현됨. 실제 응답과 시나리오별 화면 검증 필요 |

**원본 `docs/references/1Line_reference.html`은 수정하지 않는다.** 원본의 대화 흐름이 부자연스럽다면 현재 구현 중인 `src/pages/Home.tsx`에 반영하고, 필요한 화면·데이터 처리는 연결된 컴포넌트와 서비스에서 보완한다. 원본과 같은 결과 구성을 목표로 하되 부자연스러운 대화까지 그대로 복제하지 않는다.

최신 지시는 목표와 작업 기준을 정한 것이며, 이 문서에 기록했다고 아직 없는 목 분기나 시연 기능까지 구현된 것은 아니다.

## 3. 목 분석의 현재 분기

| 입력 | 응답 |
| --- | --- |
| 파일 2개 이상 | 실제 파일명으로 다중 파일 결과 생성 |
| 파일 1개 | 공통 진행 후 목 모드의 결과. 현재는 이름과 관계없이 변화 없음 카드. 실제 파일명 보존 |
| 텍스트만 입력 | 기능 축소 시나리오의 고정 목 응답 |

시연 전용 서비스와 버튼은 제거했다. 모든 단일 파일은 `getMockFileReply(file, onProgress?)`에서 이름을 보존한 목 응답을 반환한다. 실제 API 연결 시 목 분석 내용을 서버 응답으로 교체하고 현재 카드 구조를 유지한다.

파일과 텍스트를 함께 보내면 현재 목 분기는 파일을 우선한다. 파일 내용은 읽지 않고 서버 업로드도 하지 않는다. **1호선톤은 예시 활동명**이며 실제 사용자 활동 매칭 결과가 아니다.

### 다중 파일 분류 규칙

| 파일명 키워드 | 자료 유형 |
| --- | --- |
| `wireframe`, `와이어프레임` | 와이어프레임 |
| `meeting`, `회의록`, `회의` | 회의록 |
| `idea`, `proposal`, `기획`, `제안` | 기획안 |
| `presentation`, `발표` | 발표자료 |
| 해당 없음 | 기타 자료 |

위 순서대로 먼저 일치하는 유형을 사용한다. 영문 대소문자는 구분하지 않는다.

버전은 같은 기본 이름·확장자 안에서 `_v1`, `_v2`, `_final` 등을 비교한다. 구분자는 밑줄·하이픈·공백을 지원한다. 입력 순서와 관계없이 낮은 버전 중 가장 가까운 것을 이전 버전으로 연결하며, `final`은 숫자 버전 뒤로 취급한다. 파일명이 다른 자료나 확장자가 다른 자료는 연결하지 않는다.

원본의 `idea_v1.pdf`, `idea_final.pdf`, `wireframe_v1.pdf`, `wireframe_v2.pdf`, `meeting.docx`를 보내면 기획안 2개·와이어프레임 2개·회의록 1개가 된다. 원본의 두 버전 연결이 모두 있으면 안내 문구도 원본과 같게 반환한다.

## 4. 다중 파일 카드의 최종 화면 상태

표시 순서는 **완료 문구 → 활동명·자동 매칭 개수 → 분류별 개수 → 💡 버전 안내 → 버튼 → 응답 시각·Growth AI 문구**다.

- 일반 카드의 추가 활동 제목·확신도 영역과 개별 파일 상세 목록은 다중 파일 카드에 표시하지 않는다.
- 바깥 카드는 사용자 요청에 따라 채팅 영역의 최대 `85%`, `sm` 이상에서는 최대 `80%` 너비로 표시한다. 다중 파일 전용 `28rem` 제한은 제거했다.
- 분류 박스는 `flex-wrap`과 `flex-auto`로 남는 공간을 채운다. 고정 3열이 아니다.
- 유형명과 개수는 한 줄을 유지한다. 공간이 부족하면 박스 전체를 다음 행에 배치한다.
- 박스 하나의 문구가 카드보다 길면 박스 내부 가로 스크롤로 전체 내용을 볼 수 있다.
- 분류가 1개일 때도 별도 좌우 마진을 추가하지 않는다.
- 제목·활동명·하단 안내 문구에는 말줄임 처리를 하지 않는다. 제목과 안내는 필요한 경우 줄바꿈한다.

최근 캡처에서 4개 분류 중 ‘와이어프레임 2개’의 ‘개’가 다음 줄로 떨어졌다. 기존 자동 그리드 대신 위 방식으로 수정했다. 이 수정 이후 브라우저에서 새 캡처로 시각 검증을 완료했다는 기록은 없다.

- lint/build, 비동기 상태 반환·복사본 반환·목 상태/문구 변경 전달 검증 통과. 브라우저 렌더링 검증은 수행하지 않았다.

## 16. 2026-11-03 변화 없음 파일 카드

- 기준 HTML의 ‘변화 없음 파일’ 본문을 `NoChangeAnalysisContent`로 구현했다. 정보 아이콘과 제목, 회색 안내·사유 박스, 아카이브 저장·수정 버튼을 표시하며 비교·개수 배지·분류 그리드는 표시하지 않는다.
- 제목·안내·사유는 `mockNoChangeReply.content`, `analysis.noChangeMessage`, `analysis.summary`에서 읽는다. 저장 완료로 안내하지 않고 버전 업데이트를 제안한다.
- `ChatReplyCard`는 단일 파일 응답의 `changes: []`를 기준으로 전용 본문을 선택한다. `kind: 'file-analysis'`이더라도 변화가 없으면 처리한다.
- 임의 파일로 확인할 수 있도록 `mockSingleFileAnalysisMode`를 `'no-change'`로 설정하고 특정 파일명 분기를 제거했다. `'change'` 설정과 기존 목 응답으로 변화 있음도 확인 가능하다. 실제 이름·진행 흐름·시간 표시·카드 너비는 유지했다.
- lint/build 통과. 임의 단일 파일 3종, 실제 이름·진행·버전 저장 제안, 실제 컴포넌트의 React 서버 렌더링에서 비교·배지 미생성, API 형태 분기, 변화 있음·다중·텍스트 회귀를 확인했다. 브라우저 시각 검증은 수행하지 않았다.
- 상세는 [변화 없는 파일](구현_기능/변화_없는_파일.md), 응답 구조는 [파일 분석 응답](api/파일_분석_응답.md)을 참고한다.
