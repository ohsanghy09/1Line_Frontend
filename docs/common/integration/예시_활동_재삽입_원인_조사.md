# 예시 활동 재삽입 원인 조사

조사일: 2026-11-06. 대상: 나의 발자국에 사용자 미입력 예시 활동 4개 표시.

## 결론과 확실성

과거 develop 코드로 잠깐 전환한 동안, 개발 서버의 watch 재시작으로 예시 자동 삽입이 다시 실행된 경로가 원인으로 강하게 뒷받침된다. Git 전환 시각·DB 쓰기 시각·과거 코드·현재 행 순서가 일치하고, 별도 임시 DB에서 동일한 4행 추가를 재현했다. 당시 서버 stdout의 재시작 로그 자체는 확보하지 않았으므로 프로세스 재시작 이벤트까지 직접 관측했다고 쓰지는 않는다.

현재 파일에 자동 삽입 코드가 없는 사실만으로 과거 실행까지 배제한 앞선 설명은 충분하지 않았다. 최신 파일이 안전해도 브랜치 이동 중 과거 파일이 실행되면 비추적 사용자 DB에 행이 남을 수 있다.

f8f4488의 서비스 DB 초기화 함수에는 다음과 같은 예시 삽입이 있었다.

```sql
INSERT OR IGNORE INTO activities (id, name) VALUES (?, ?);
```

반복 입력은 line1-hackathon/1호선톤, computer-vision/컴퓨터비전, scent-orbit/Scent Orbit, data-vis/데이터분석과시각화, ai-contest/AI 분석 공모전 5개다. 같은 커밋의 개발 실행 명령은 node --watch src/server.js이며, 서비스 기동 때 기본 사용자 DB를 열면서 초기화 함수를 실행한다.

현재 DB의 rowid 순서는 사용자 모아책방 독서모임(1), 사용자 1호선톤(2), computer-vision(3), scent-orbit(4), data-vis(5), ai-contest(6)이다. 뒤 네 행은 updated_at=null·연결 기록 0·파일 0이다. 이미 사용자 1호선톤이 있어 name UNIQUE와 INSERT OR IGNORE에 의해 예시 1호선톤은 추가되지 않고 나머지 4개만 삽입되는 구조다.

DB 파일은 Git 추적 대상이 아니다. 최신 코드를 pull해 삽입문이 없어져도 이미 기록된 예시 행은 자동으로 없어지지 않는다. 활동 목록 API는 자료가 없는 활동도 조회하므로 화면 재진입 시 네 행을 그대로 표시한다.

## 임시 DB 재현

사용자 DB를 변경하지 않고 OS 임시 폴더에 별도 DB를 만들었다.

1. 현재 서비스 DB 초기화로 빈 DB 준비.
2. 모아책방 독서모임·1호선톤 이름의 합성 활동 2개 추가.
3. git show f8f4488:api-server/src/database.js로 읽은 과거 초기화 함수를 임시 DB에만 실행.
4. 기존 2개 뒤에 computer-vision/scent-orbit/data-vis/ai-contest가 rowid 3~6으로 추가됨을 확인.
5. 재현 DB와 보조 파일은 닫은 뒤 제거.

현재 사용자 DB와 같은 예시 ID·개수·행 순서가 재현됐다. 별도 이전 검사에서는 현재 서비스 초기화·재접속은 활동 0개이며, 테스트 전용 예시 생성기로 실제 사용자 DB 경로를 열려 하면 차단됨을 확인했다.

## 이번 작업의 변경 범위

원인 조사와 임시 재현만 수행했다. 사용자 DB의 네 예시 행이나 실제 사용자 활동·기록·파일은 삭제하지 않았다. 최신 서비스 코드·홈·컴포넌트도 수정하지 않았다.

재발 방지를 위해 과거 브랜치로 이동하거나 pull하기 전에는 사용자 DB를 사용하는 watch 서버를 중지하고, 최신 코드에서 다시 기동한다. 같은 작업 폴더에서 실행 중인 서버는 브랜치 전환의 파일 변경에도 반응할 수 있다. 조사 근거 문서는 저장소 관리자용이며 파트 전달용 handoff 묶음과 구분한다.
