- [x] 고정 성장 유형을 AI 생성 분류·이모지로 교체, 필터/이벤트/경험 배지 표시
- [x] 요청한 DB 전체 초기화, 재등장한 예시 활동 정리, 서버 시작 시 예시 자동 INSERT 제거

- [ ] 확인된 화면·분석·오류 문제를 한 기능씩 보완

Journey 자동 분석은 확정 구현 지시가 아닌 검토 사항이다. 현재는 GET 조회 자동·모델 분석 수동이다. 변경 없음에는 모델 호출을 하지 않고 변경 후 방문에만 분석하는 방식의 비용·중복 실행·실패 처리·버튼 변경 범위를 이후 요청에 맞춰 정한다. 인증/권한, 문맥 분할·관련성 조회, 초안 정리, 분산 작업 잠금·재시작 복구도 장기 후속 범위다.

이번 요청은 문서 최신화이며 추가 기능 구현·DB 변경·유료 모델 호출을 수행하지 않는다.

## 이전 연동 준비 계획

> 2026-11-06 최신 작업 계획은 [개발 서버 분리·연동 작업 계획](개발서버_분리_연동_작업계획.md)을 따른다. 채팅 수정 모달 통일과 바로 저장은 적용했다. 이제 기존 백엔드 조정·AI 개발 서버 추가·연동 검증·API 명세/ERD 정리가 다음 범위다. 아래는 이전 연동 준비 문서 작성 당시 계획이다.

작성일: 2026-11-05

다음 작업 진입점: [다음 작업 인수인계](다음_작업_인수인계.md)(2026-11-06). 우선 채팅의 수정 모달을 활동·자료 유형만으로 통일할 예정이며 아직 코드 변경 전이다. 기록·저장 버튼의 동작 정리와 실제 API 연결은 별도 단계다. 변화 판단·Timeline 생성·DB 저장·활동 전체 요약 갱신을 새 프론트 책임으로 추가하지 않는다.

최신 결정: 2026-11-06. 실제 구현은 **홈 분석: 프론트→AI 서비스**, **결과·자료 저장: 프론트→백엔드**, **나의 발자국·Timeline: 백엔드 조회**, **Growth Journey: 백엔드·AI 생성/저장 후 백엔드 조회**로 진행한다. 호출 구조만 사용자 확정이며 상세 전송·인증·저장 검증·갱신 계약은 협의 대상이다. AI 모델은 미정이다. 현재 로컬 호출 코드는 아직 전환하지 않았다.

## 목적과 범위

현재 프론트엔드와 로컬 개발 서버의 구현을 확인하고, 실제 백엔드 담당자와 AI API 담당자가 연동에 필요한 요구사항과 각자의 구현 범위를 이해할 수 있도록 문서화한다.

이번 작업은 구현 현황 조사와 연동 계약 초안 작성까지 진행한다. 실제 API 연결 구현은 담당자와 계약을 협의한 뒤 후속 작업으로 진행한다. 문서 작성을 위해 기존 화면·API·사용자 DB를 변경하지 않는다.

## 현재 이해한 상태

- 홈 채팅, 나의 발자국, Growth Journey의 화면과 주요 동작을 구현했다.
- 프론트엔드는 로컬 개발 서버의 API를 호출한다.
- 일부 기록 저장·조회와 파일 보관은 로컬 서버 및 SQLite에서 실제 처리한다.
- AI 분석 결과는 서버 목 응답이며 실제 외부 AI API 연결은 아직 없다.
- Growth Journey는 GET `/api/journey` 조회, 필터, 상세 펼침, 오류 재시도를 구현했지만 실제 DB 기반 성장 분석과 AI 분석은 연결하지 않았다.
- 자동 검사와 실제 브라우저 확인 범위는 구분한다. 기존 문서의 완료 기록을 실제 서버·AI 연동 완료로 해석하지 않는다.

위 내용은 기존 문서에 따른 시작점이다. 전달용 구현 현황은 관련 코드와 테스트를 대조해 작성한다.

## 문서 작성 원칙

각 문서에서 다음 상태를 구분한다.

| 구분 | 의미 |
| --- | --- |
| 현재 구현 | 코드에서 확인한 화면, 로컬 API, 저장·조회 동작 |
| 프론트 요구사항 | 현재 화면이 필요로 하는 데이터와 사용자 동작 |
| 협의 필요 | 담당자와 확정해야 하는 계약·정책·책임 범위 |
| 합의 완료 | 협의 결과와 확인 날짜를 기록한 항목 |

- 로컬 개발 서버의 경로와 응답을 최종 백엔드 명세로 확정하지 않는다.
- 실제 사용자 입력·저장값과 목 분석값을 필드 단위로 구분한다.
- 현재 동작과 새로 제안하는 동작을 구분하며, 없는 API를 구현된 것처럼 기록하지 않는다.
- API 예시는 가상 데이터로 작성하고 인증 정보·실제 사용자 자료를 포함하지 않는다.
- 외부 응답 형식이 달라지는 경우 서비스 경계에서 화면용 구조로 변환하는 방안을 검토한다.
- 문서와 코드가 다르면 차이를 기록하고, 현재 코드에서 확인한 근거 경로를 남긴다.

## 작업 순서와 산출물

### 1. 현재 구현 현황 조사

산출물: `현재구현_현황_정리/` 아래 화면별 마크다운 문서. [문서 안내](../../frontend/현재구현_현황_정리/문서_안내.md)에서 읽기 순서와 공통 연결 상태를 확인한다.

- 홈 채팅, 나의 발자국, Growth Journey를 화면·기능별로 정리한다.
- 프론트 페이지·서비스·타입과 개발 서버의 라우트·저장 로직을 대조한다.
- 실제 입력, 파일 업로드·보관, 확정 저장, 조회·수정, 목 분석의 경계를 표시한다.
- 수행한 자동 검사와 브라우저 확인, 미검증 항목을 기존 기록과 구분해 정리한다.
- 실제 백엔드·AI 연동 시 교체하거나 추가해야 할 지점을 기록한다.

### 2. 백엔드 API 계약 초안 작성

산출물: [API_계약/백엔드_API_계약.md](API_계약/백엔드_API_계약.md). 현재 로컬 요청·응답과 실제 서버 협의 사항을 구분한다.

기존 API 목록을 조사한 뒤 기능별로 다음 내용을 작성한다.

- 사용자 동작과 호출 시점
- 현재 경로·HTTP 메서드와 관련 코드
- 요청 파라미터·본문·파일 전송 형식
- 응답 필드·타입·필수 여부와 정상·빈 결과 예시
- 인증, 사용자별 접근 범위, 오류 응답과 재시도 처리
- 저장·수정 이후 관련 화면 갱신과 ID 연결
- 목록 검색·정렬·페이지네이션 등 현재 구현과 협의가 필요한 차이
- 분석 진행 상태를 전달하는 현재 방식과 실제 서버에서 필요한 방식

화면에 필요한 계약과 개발 서버에만 있는 임시 처리를 구분한다. Journey 조회와 분석 실행·갱신도 별도 동작으로 구분한다.

### 3. AI API 계약 초안 작성

산출물: [API_계약/AI_API_계약.md](API_계약/AI_API_계약.md). AI가 받는 값과 반환할 값을 정리한다. 홈 분석은 프론트가 AI 서비스에 직접 요청하고 Journey 분석 생성·저장은 백엔드·AI가 담당하는 확정 방향을 따른다.

- 분석 기능별 입력 문맥과 출력 항목을 정리한다.
- 텍스트·파일·링크 중 실제로 전달하거나 추출하는 내용과 아직 처리하지 않는 내용을 구분한다.
- 홈 입력 분석과 여러 확정 기록을 대상으로 하는 Journey 분석을 구분한다.
- 자료 분류·활동 매칭·변화 판단·요약·전후 비교·성장 분석 등 현재 목 응답의 의미를 설명한다.
- 변화 없음, 근거 부족, 빈 결과, 분석 실패를 구분한다.
- 기록·활동·자료 ID를 입력과 결과에서 연결하는 요구사항을 정리한다. 이름으로 실제 ID를 추측하지 않는다.
- 출력 검증과 화면용 데이터 변환의 책임 범위를 협의 사항으로 기록한다.
- AI 공급자, 모델, 호출 경로, 인증 방식과 최종 출력 스키마는 확인되지 않은 상태에서 확정하지 않는다.

Journey의 분석 대상은 확정 저장 기록을 기준으로 검토한다. 일반 Timeline 이벤트나 변화 없는 자료 저장만으로 성장 이벤트·첫 경험 배지를 자동 생성하는 계약을 만들지 않는다.

### 4. 담당자별 범위와 협의 사항 정리

산출물: [API_계약/문서_안내.md](API_계약/문서_안내.md)의 연동 협의사항. 호출·저장 책임은 최신 사용자 결정에 따르고 아래 상세 구현 범위는 담당자와 협의한다.

아래 책임 범위는 협의를 위한 초안이며 담당자 합의 후 확정한다.

| 담당 | 협의할 주요 범위 |
| --- | --- |
| 프론트엔드 | 사용자 입력·파일 전송, 화면용 응답 변환, 로딩·오류·재시도, 저장 후 화면 갱신 |
| 백엔드 | 인증·권한, 저장·조회·수정, 파일 보관, 결과 저장·조회, ID와 근거 관계 관리. AI 호출 조율 담당 여부는 협의 |
| AI API | 입력 분석, 분류·요약·변화·성장 판단, 근거를 포함한 구조화된 결과 반환 |

주요 협의 항목:

- 인증과 사용자별 데이터 접근 방식
- 파일 업로드·보관·본문 추출 및 링크 내용 수집 책임
- AI에 전달할 자료 범위와 크기 제한
- 분석 실행 시점, 동기·비동기 처리와 진행 상태 전달
- 분석 결과 저장·갱신 및 중복 요청 처리
- 최종 성장 유형·분야 분류
- 기록 수정·삭제·활동 이동 후 분석 결과와 근거 관계 처리
- 타임아웃·실패·재시도와 오류 응답
- 개발·운영 환경 주소, 프록시·CORS, 환경 변수와 비밀키 관리

각 항목에는 논의 내용, 결정 상태, 담당, 확정 결과를 남긴다.

### 5. 실제 연동 순서와 검증 기준 정리

`API_계약/문서_안내.md`에 후속 구현 순서와 검증 기준을 함께 기록한다.

1. 실제 서버의 접근·인증·오류 응답을 확인한다.
2. AI가 필요 없는 저장 기록 조회부터 실제 서버에 연결한다.
3. 분석 기능 하나를 선택해 실제 입력 → 합의한 호출 경로 → AI → 결과 표시·확정 저장 흐름을 검증한다.
4. 정상·변화 없음·빈 결과·실패·재시도와 ID·근거 관계를 확인한다.
5. 확인한 계약을 기준으로 다른 입력 유형과 Journey로 확대한다.

실제 저장·수정 후 재조회했을 때 화면과 서버 데이터가 일치하는지 확인한다. 외부 서버나 실제 AI 호출을 수행하지 않은 검사를 실제 연동 검증으로 기록하지 않는다. 기존 사용자 DB를 초기화하거나 테스트 기록으로 대체하지 않는다.

Vercel에는 dist와 함께 배포하며 별도 3002 문서 서버는 필수가 아니다. 백엔드는 현재 API를 문서화하고 AI는 모델·경로 미정과 기존 입력·출력값을 유지한다. 기존 화면 메뉴·React 라우트·DB·API 동작은 변경하지 않는다. 실행·공유 방식은 [Swagger 사용 안내](API_계약/Swagger_사용안내.md)를 따른다.
