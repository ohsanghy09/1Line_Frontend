공개 API의 프론트 수용 여부는 [호환성 점검 결과](프론트_호환성_점검결과.md)에서 20개 API·53개 사례로 확인했다. 아래 실제 저장·모델·내부 전달·브라우저 시나리오가 모두 통과했다는 의미는 아니다.

## 실행 조건과 판정 기준

사용자 DB를 검사 목적으로 초기화하지 않는다. 파괴적 시나리오는 임시 DB·검사 전용 서버와 식별 가능한 활동/원본으로 실행한다. 실제 모델 검사는 비용이 발생하므로 문서 링크 검사와 구분한다. 아래 표는 수행 절차이며 모든 시나리오를 이번에 실행했다는 뜻은 아니다.

기본 사전 조건: 프론트·백엔드·AI 버전이 같고 공통 DB 또는 대체 문맥 계약이 준비돼 있어야 한다. 서버 상태 검사·모델 생성 검증·브라우저 UI 검증을 별도로 기록한다. 문구·이모지·이벤트 개수는 고정 정답으로 만들지 않는다.

## 코드 제공 없이 수행할 추가 검증

공개 API 테스트와 서버 간 전달 테스트를 구분한다. 내부 전달은 새 분리 구현용 설계이므로 기존 서버의 검증 이력이 그대로 적용되지 않는다.

## 각 파트가 제출할 검증 기록

- 사용한 OS·언어·런타임·프레임워크·DB·저장소·배포 환경과 실제 버전.
- 공개 Base·내부 전달 방식·인증/사용자 범위·기능 ID별 성공/실패·미수행.
- 요청과 응답의 상태 코드·비밀정보를 제거한 예시, DB/원본/화면 기대 결과.
