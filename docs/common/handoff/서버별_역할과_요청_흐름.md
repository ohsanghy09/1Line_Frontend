# 서버별 역할과 요청 흐름

2026-11-14 갱신: 부분 삭제 후 속성 임시 보존, 미저장 원본 정리, AI 로그에 이어 F19 v2·F11 백엔드를 구현했다. 아래 과거 초기화·변화 비움 설명보다 [단독 작업 기록](../../integration-test-fixes/백엔드_단독작업_구현_검증.md)과 [공동 연동 안내](../../integration-test-fixes/공동작업_백엔드_연동안내.md)가 우선한다. 공동 기능의 활성화·실제 AI 연결은 별도로 확인한다.

기준일: 2026-11-06. [데이터](공통_데이터_계약.md) · [상태](상태와_오류_처리.md)

| 구성 | 현재 책임 | 쓰는 데이터 |
| --- | --- | --- |
| 프론트 | 입력·진행·결과·확정·분류 수정·조회·오류 표시 | 탭 sessionStorage의 화면 복원값 |
| AI 서비스 | 홈 접수·원본 보관·작업 관리·실제 모델 분석, 활동/성장/남은 파일 분석 | 홈 작업·원본·초안을 백엔드에서 조회 가능하게 게시. 활동·확정 기록·성장 결과 저장은 백엔드 책임 |
| 백엔드 | 스키마 준비, 활동 생성·직접 수정, 확정 기록·조회·검색·삭제, 활동 종합 큐, 성장 결과 검증·저장 | 논리 활동·초안·원본·확정 기록·작업·변화·성장 데이터 |

브라우저의 백엔드 Base는 `/api`, AI Base는 `/ai-api`다. 이 상대경로는 기존 프론트 개발용 별칭이며 AI 실제 경로는 `/api`다. 배포 때는 실제 Base 또는 프록시를 설정한다. 아래 경로는 **각 서버가 받는 실제 `/api/...`** 기준이다. [API 목록](../../backend/handoff/API_정의서.md)과 [AI API](../../ai/handoff/API_정의서.md)를 함께 읽는다.

| 기능 ID | 실제 순서 | 저장·반영 |
| --- | --- | --- |
| HOME-01 | 프론트 → AI POST /api/chat multipart, Prefer: respond-sync | 파일 없는 텍스트는 완료까지 한 요청. general은 말풍선, analysis는 카드. 초안 보관까지만 수행 |
| HOME-02, HOME-03 | 프론트 → AI POST /api/chat 또는 /api/chat/links → jobId → GET /api/chat/jobs/:id | 파일/링크는 400ms 순차 폴링. 완료 result를 검증한 뒤 카드 표시 |
| HOME-04, HOME-05 | 필요 시 백엔드 GET /api/activities → POST /api/records | analysisId로 초안·원본을 찾아 활동·기록·변화를 한 트랜잭션에 저장. 성공 후 활동 종합 예약 |
| HOME-06 | GET /api/activities → 저장 전 카드만 수정 또는 저장 후 PATCH /api/records/:id | 자료 유형·연결 활동 변경. 이동은 양쪽 활동 종합 예약 |
| HOME-07 | AI 홈 결과 kind=activity-update → 백엔드 POST /api/activities/apply-chat-update | 프론트는 analysisId만 전달. 서버 초안의 허용 필드를 적용하고 완료 general로 교체. 신규 records 없음 |
| HOME-08 | 탭 세션 복원 → 작업 ID가 있으면 AI 작업 GET. 저장된 카드는 백엔드 GET /api/records/:id | 동일 분석 카드 중복 추가 방지. 대화 초기화는 클라이언트만 초기화 |
| HOME-09 | AI GET /api/chat/health + 백엔드 GET /api/home/recent | 모델 호출 없음. 최근 자료 클릭은 활동 URL의 file query로 연결 |
| META-01 | 저장/수정/이동 → 백엔드 500ms 묶음 큐 → AI POST /api/analyze/activities/:id → 백엔드 재검증·저장 | UI GET /api/activities/:id/analysis를 진행 중 1500ms 조회. 수동 POST /api/activities/:id/analyze |
| ARCHIVE-01 | 백엔드 GET /api/archive/activities?q=&category=&status=&sort= | 서버에서 검색·필터·정렬. 프론트는 재필터링하지 않음 |
| ARCHIVE-02, TIMELINE-01 | GET /api/archive/activities/:id | folders와 timeline 함께 조회. Timeline 페이지는 별도 raw timeline API를 사용하지 않음 |
| ARCHIVE-03 | GET /api/archive/activities/:id/materials/:fileId | file·events·versionHistory를 표시 |
| ARCHIVE-04 | DELETE /api/archive/activities/:id + confirmation | 기록·원본·활동 삭제, 대화 카드 무효화, 성장 결과 비움 |
| ARCHIVE-05 | DELETE 자료 → 다른 파일이 남으면 AI POST /api/analyze/records/:recordId/exclude-file → 백엔드 스냅샷 확인·삭제 | 실패 시 자료 보존. 성공 후 활동 정보 초기화·필요 시 재분석 |
| JOURNEY-01, JOURNEY-03 | 백엔드 GET /api/journey → 프론트 필터·펼침 | 저장된 스냅샷만 조회. 필터는 추가 요청·모델 호출 없음 |
| JOURNEY-02 | 백엔드 POST /api/journey/analyze → AI POST /api/analyze/journey → 백엔드 해시·근거 재검증·INSERT → 조회 결과 | 실패 시 이전 결과 보존. 홈 기록·Timeline은 수정하지 않음 |
| SETTINGS-01 | 백엔드 POST /api/settings/reset-data | 해당 저장 범위의 활동·초안·원본·기록·작업·성장 데이터를 원자적으로 제거. 물리 테이블 수는 구현 선택. 성공 응답 확인 후 현재 탭 세션 제거 |

독립 서버에서는 [서버 간 전달 계약](서버간_데이터_전달_계약.md)의 문맥·초안·원본 게시를 구현한다. 내부 분석 POST에는 그 문서의 JSON 문맥을 전달한다. 기존 개발환경의 ID만 보내고 공유 로컬 DB를 읽는 동작은 설치·연동 요구가 아니다. 이 내부 규격은 분리 구현용 설계이며 기존 개발 서버의 지원을 뜻하지 않는다.

쓰기 성공 후 프론트는 `1line:activities-changed`, `1line:records-changed` 이벤트로 현재 창의 구독 화면을 갱신한다. 직접 활동 수정은 activities 이벤트만 발생한다. 다른 탭·다른 사용자에게 실시간 동기화하는 체계는 구현돼 있지 않다.
