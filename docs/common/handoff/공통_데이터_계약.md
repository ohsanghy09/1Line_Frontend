# 공통 데이터 계약

> Growth Journey 변경 안내 (2026-11-12): 이 문서의 자유 유형·비교 규칙은 현재 구현 이력이다. 새 구현은 [확정 공통 JSON 계약](../../growth-journey-update/공통_JSON_계약.md)을 따른다. Spring·DB·프론트와 OpenAPI·Swagger는 새 계약을 반영했다. 아래 이전 Journey 세부 규칙보다 링크된 최신 계약이 우선한다. 실제 AI 구현·연동·배포는 미검증이다.

기준일: 2026-11-06. [흐름](서버별_역할과_요청_흐름.md) · [백엔드 API](../../backend/handoff/API_정의서.md) · [AI API](../../ai/handoff/API_정의서.md)

JSON의 생략과 null은 다르다. 아래 ‘필수’는 응답에 키가 있다는 뜻이며 nullable은 별도 표시한다. 필수 키·자료형·null·제약은 아래에 명시하며 특정 검증 라이브러리를 요구하지 않는다. 각 파트는 선택한 언어의 검증기로 동일 조건을 검사한다.

## 공통 검증 규칙

분석 결과의 비빈 문자열은 별도 한도가 없으면 trim 후 1~20000자다. AI 입력/출력의 식별자와 분류 value는 1~200자다. 요청 ID·이름·요약은 각 API의 더 구체적인 제약을 우선한다. 숫자 count는 정수이며 NaN/Infinity/음수는 허용하지 않는다. 배열은 없음을 null 대신 []로 표시하며 nullable이라고 명시한 객체만 null을 허용한다.

날짜 문자열은 정규식 모양만 검사하지 않고 실제 달력 날짜까지 검증한다. 시작 월이 종료 월보다 늦을 수 없으며 두 날짜가 모두 일 단위라면 일 단위 순서도 확인한다. 같은 월의 월 단위/일 단위 혼합은 월 정밀도를 유지하며 임의의 일자를 만들어 순서를 뒤집지 않는다.

요청·모델 출력에서 추가 키 거절이라고 명시한 객체는 정의된 키만 허용한다. 공개 응답에 내부 원본 bytes·키·인증정보·DB 경로를 추가하지 않는다. 구조 검증과 원문 인용·실제 ID·상호 참조 검증은 별도로 모두 수행한다.

## 식별자·시각

| 값 | 의미 |
| --- | --- |
| conversationId | 대화 묶음. 브라우저가 발급하고 대화 초기화 시 변경. 사용자 ID가 아님 |
| requestId | AI 접수 중복 방지 키. 현재 프론트는 전송마다 UUID 생성. 같은 키·같은 입력이면 기존 작업, 다른 입력이면 409 |
| jobId | AI 작업 `ai-UUID`. 분석 ID·기록 ID와 다름 |
| analysisId | 원본·완료 응답을 가진 분석 초안. 저장 요청은 이 ID를 사용 |
| recordId / activityId / fileId | 확정 기록 / 실제 활동 / 원본 자료 식별자. 이름·배열 순서로 대체하지 않음 |
| 링크 자료 ID | `record:기록ID`. 물리 파일 ID가 아닌 조회용 논리 ID |
| 폴더 ID | URL 인코딩한 활동 ID와 자료 유형을 `:`로 연결. 별도 DB 폴더 테이블 없음 |
| createdAt·updatedAt·savedAt·uploadedAt | 서버 ISO 시각 문자열. 프론트 `*Label`은 한국어 표시용으로 생성하며 서버 필드와 분리 |
| period | 활동 계약에서는 `{start,end}` 또는 null. 조회 화면에서는 표시 문자열. 날짜는 YYYY-MM / YYYY-MM-DD, 유효 달력·순서 검증 |
| Journey occurredAt | 근거 기록 중 가장 늦은 최초 저장 시각의 YYYY-MM. 실제 발생 날짜가 아님 |

## 활동 선택과 메타정보

ActivityMetadataValues(일반 활동 정보)의 필수 키: category(string ≤200 또는 null, all/전체 금지), status(진행 중/완료/null), role(string ≤20000/null), summary(string ≤20000/null), period({start:날짜/null,end:날짜/null}/null). 비null 문자열은 trim 후 비어 있을 수 없다. AI가 근거와 함께 반환하는 ActivityMetadataAnalysis와는 다른 구조다.

ActivityProposal은 name(필수 비빈 문자열), confidence(high/medium/low/null 필수), id(선택 string/null), match(선택 existing/new/unresolved), 위 메타정보(선택)를 가진다. 현재 AI는 match와 id를 명시한다. existing은 실제 id 필수, new/unresolved는 id=null. 미확정 유형은 null이다.

확정 선택은 `{activityId, activityUpdates?}` 또는 `{newActivity:{name,...ActivityMetadataValues}}` 중 하나다. 현재 새 활동 카드는 name·category만 제안값을 사용하고 나머지는 null로 보낸다. 기존 활동의 일반 메타정보 적용은 null을 보존값으로 취급하지만, 대화 수정의 value=null은 명시적 삭제다.

## 화면용 ChatReply

| 필드 | 자료형·필수·제약 |
| --- | --- |
| id, role, content | 필수 string, role=assistant. 백엔드 비빈 문자열 최대 20000 |
| kind | general 또는 text-analysis/file-analysis/no-change/batch-analysis/link-analysis. greeting은 클라이언트 초기 인사용 타입이며 서버 검증 대상 아님 |
| analysis | general이면 null. 분석이면 아래 객체 필수 |
| sourceUrl | 선택 string, 최대 4096, 사용자정보 없는 HTTP(S) |
| activityCreated | 선택 boolean. 사용자 확정 저장에서 신규 활동 생성 여부 |
| updatedActivityId | 직접 수정 완료 general의 선택 string |
| analysisId, conversationId | 서비스가 완료 envelope에서 카드에 합침 |
| recordId, activityId | 저장 성공 후 프론트가 카드에 합쳐 탭 세션 복원. 원래 모델 출력이 아님 |

analysis의 필수 키:

| 필드 | 자료형·제약 |
| --- | --- |
| activity | ActivityProposal |
| materialType, summary | 비빈 string ≤20000. summary는 이번 기록 요약 |
| stage | 비빈 string ≤20000 또는 null |
| changes | `{before,after,category,evidence:string[]}` 배열. 백엔드 최대 100개·근거 최대 100개. 실제 AI는 변화 최대 10개·근거 1~10개 |
| files | `{name,materialType,previousVersion:string/null}` 배열. 백엔드 최대 100개, 실제 입력 10개 이하. 현재 previousVersion=null |
| groups | `{materialType,count:양의 정수}` 배열. 서버가 파일 유형별 집계 |
| suggestedSaveMode | record-change/version-only/archive. 실제 생성은 changes 유무로 record-change 또는 archive |
| noChangeMessage | 선택 비빈 string. 첨부가 있고 변화가 없을 때 서버가 추가 |

AI의 `activity-update`는 중간 응답이다. 프론트 서비스가 백엔드 적용 후 general로 바꾸므로 화면·세션의 ChatReply로 그대로 보관하지 않는다. general은 기록 저장 API가 받지 않는다.

## 발자국 응답

ActivitySummary 필수 키: id,title,category,role,period,summary(모두 string), status(진행 중/완료/미설정 중 하나), updatedAt(ISO/null), materialsCount와 recordsCount(각각 0 이상 정수), metadataAnalysis(ActivityAnalysis). 미확인 표시는 category=미분류, status/role/period=미설정, summary=활동 전체 요약이 아직 없습니다. 조회용 활동에는 role/period/summary를 null로 보내지 않는다. 활동 선택용 ActivityMetadataValues와 조회 화면의 표시 구조를 구분한다.

ActivityDetail은 위 정보에 folders와 timeline을 추가한다. folder는 id,name,materialsCount,files를 가진다. Material은 id,name,type,kind(file/link),originalFileId(string/null),recordId,recordPosition(0부터),savedAt,uploadedAt,updatedAt,summary,sourceUrl(string/null),summaryScope=record를 반환한다. 프론트가 사용하는 필드가 일부이더라도 정의된 필수 필드는 반환한다. 채팅 원문 content는 반환하지 않는다.

ArchiveEvent는 id,occurredAt,title,evidenceFileIds:string[],evidenceLabels:string[],change:{before,after}와 isTurningPoint를 가진다. false이면 description, true이면 before,after,reason을 추가한다. 근거 이름이 같은 기록에서 유일할 때만 자료 ID에 연결하며, 연결 불가 근거는 evidenceLabels에 남긴다.

ActivityAnalysis는 `{status:idle|queued|running|ready|failed,error:string|null,updatedAt:ISO|null,stale:boolean}`이다. 준비 상태와 최신 자료 반영 여부는 별개다.

## Journey 저장·조회 계약

| 필드 | 자료형·제약 |
| --- | --- |
| source | api |
| summary | title,description 필수 비빈 string. evidence는 과거 조회 호환상 선택, 새 분석에서는 1개 이상 필요 |
| badges | 최대 10개. id,label 필수, icon(1~16자)·evidence는 과거 호환상 선택. 새 분석에서는 둘 다 필수 |
| typeOptions,axisOptions | `{value,label,icon?}` 배열. value 유일, all 포함. 새 분석은 사용 유형/분야 각각 최대 8개 + 전체 선택지 |
| events | 최대 20개. id,occurredAt,activity:{id:string|null,name},type,axis,title,description,evidence?,comparison? |
| event.type/axis | all 금지, 대응 선택지 value 참조 |
| evidence | `{recordId,quote}` 배열. 저장된 해당 기록 message 또는 analysis.summary의 연속 원문. 새 결과의 요약·배지·이벤트 모두 필수 |
| comparison | 생략 가능. 있으면 before,after,evidence:string[]. 신규 결과는 서로 다른 기록 2개 이상 근거 필요 |
| analysis | 실행 서버가 추가: id/string|null,generatedAt/ISO|null,stale/boolean,recordCount/currentRecordCount/0 이상 정수,model/promptVersion/string|null |

journey-v5에서도 위 공개 evidence 형식은 동일하다. AI 모델만 내부 evidenceId를 선택하며 AI 서버가 원문을 복원한다. evidenceId는 공개 응답·DB 저장 필드가 아니며 홈/활동 정보 분석의 근거 형식은 바꾸지 않는다.

요약·배지의 evidence도 API에 있지만 현재 화면은 이벤트의 인용만 펼쳐 보여준다. 이벤트·배지 ID는 백엔드가 저장 시 UUID로 새로 부여한다. 재분석 전 ID를 영구 참조로 사용하지 않는다.

## 화면이 거절하는 null·누락 형태

- Journey event.comparison은 값이 없으면 키를 생략한다. 모델 출력의 comparison=null을 그대로 공개 응답에 복사하지 않는다.
- Journey 옵션/배지의 icon은 값이 없으면 키를 생략한다. icon=null 또는 빈 문자열은 거절된다. 새 분석의 유형/배지 icon은 필수다.
- summary/badge/event의 evidence는 과거 조회 호환상 생략할 수 있으나, 키가 있으면 1개 이상의 {recordId,quote} 배열이어야 한다. evidence=[]·null은 거절된다. 새 분석에서는 실제 근거가 필수다.
- ChatReply의 sourceUrl은 없으면 생략한다. sourceUrl=null은 거절된다. 반면 발자국 자료의 sourceUrl은 null을 허용한다.
- ChatReply의 stage와 각 files[].previousVersion은 키를 포함하며 모르는 값은 null이다. 생략하면 응답 검증에 실패한다.
- ActivityMetadataValues.period가 객체이면 start/end 두 키를 모두 포함한다. 한쪽만 모르면 그 값을 null로 보낸다.
- 분석 필드가 없는 일반 답변은 kind=general·analysis=null이다. activity-update는 백엔드 적용 전의 중간 reply이므로 그대로 화면 카드에 전달하지 않는다.

## 빈 응답 예시

```json
{"source":"api","summary":{"title":"아직 성장 분석이 없어요.","description":"홈에서 기록을 저장한 뒤 성장 분석을 실행해 주세요."},"badges":[],"typeOptions":[{"value":"all","label":"전체"}],"axisOptions":[{"value":"all","label":"전체 분야"}],"events":[],"analysis":{"id":null,"generatedAt":null,"stale":false,"recordCount":0,"currentRecordCount":0,"model":null,"promptVersion":null}}
```

필드의 과거 호환 허용 범위와 새 공급자 출력의 엄격한 범위를 혼동하지 않는다. 새 서버도 공급자 결과를 검증한 뒤 화면 계약으로 변환해야 한다.
