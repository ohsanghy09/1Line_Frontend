# 문서 전용 구현 인수인계

기준일: 2026-11-06. 문서 전달 범위는 아래 목록을 따른다. 프로젝트별 재배치일: 2026-11-08. 기존 개발 소스·개인 DB·실행 스크립트는 제공하지 않는다. 다른 언어·OS·프레임워크에서 현재 프론트에 맞는 서버를 구현하기 위한 정의서다.

## 문서 전달 범위

프로젝트별로 문서를 나누었으므로 `common/handoff/`만 복사하지 않는다. 다음 폴더를 `docs/` 기준 상대 구조 그대로 함께 전달해야 문서 간 링크가 유지된다.

- `docs/common/handoff/`: 공통 계약과 시작 안내.
- `docs/common/integration/handoff/`: 배포·검증·호환성 규격.
- `docs/common/review/`: 서비스·화면 정의.
- `docs/backend/handoff/`: 백엔드 계약.
- `docs/ai/handoff/`: AI 계약과 프롬프트 전문.

위 다섯 폴더가 문서 전용 인수인계 묶음이다. 기존 개발 소스·개인 DB·환경설정·개발 서버 실행 안내는 전달 대상에 포함하지 않는다. 이전 ZIP은 과거 폴더 구조이므로 새로 전달할 때 위 구조로 다시 구성한다.

## 적용 범위

현재 프론트가 보내는 공개 API와 화면 동작이 호환 기준이다. 기술 선택과 내부 DB·큐 구조는 각 파트가 결정한다. API 정의에 없는 개인 실행환경·소스 파일을 전제하지 않는다. 논리 DB의 기존 타입 표기는 제품 설치 요구가 아니다.

독립 서버에서 필요한 초안·원본·문맥 전달은 서버 간 계약 문서에 기본 HTTP 경로·본문·응답·Bearer 인증·버전 규칙으로 정의했다. 해당 전달 규격은 문서 전용 구현을 위한 설계이며 기존 개발 서버가 이미 그 요청을 처리한다는 뜻은 아니다. 다른 내부 전송은 양 파트가 함께 변경하고 공개 API·데이터·처리 결과는 보존한다.

일반 대화와 분석, 사용자 확정 저장, 활동 종합·대화 수정, 발자국 조회·검색·삭제, 수동 Journey가 범위다. Journey는 journey-v5다. 개발용 독립 카드 페이지와 코드 안내 문서는 제공 범위에서 제거했다.

Journey v5는 AI 내부에서 원문 근거 목록을 만들고 모델은 근거 ID만 선택한다. 서버가 원래 {recordId,quote}로 복원하므로 공개 API·기존 저장 결과·DB 구조는 유지한다. 백엔드가 근거 카탈로그를 따로 구현할 필요는 없다. [AI 분석 규칙](../../ai/handoff/분석_입출력과_검증_규칙.md)과 [프롬프트](../../ai/handoff/프롬프트_정의서.md)를 함께 적용한다. 홈·활동 정보 분석의 근거 방식은 변경하지 않는다.

## 검증 범위

기존 동작을 대조해 계약과 프롬프트 전문을 정리했다. 문서만 복사했을 때의 내부 링크·예시 JSON·필수 항목을 검사한다. 문서 정리가 실제 운영 연결이나 모든 브라우저 시나리오의 성공을 보장하지는 않는다. 각 파트는 자체 서버에서 [검증 시나리오](../integration/handoff/연동_검증_시나리오.md)를 수행하고 결과를 전달한다.

추가 점검: 실제 프론트 서비스와 독립 Python 합성 HTTP 서버로 공개 API 20개·정상/실패/응답 검증 53개 사례를 통과했다. 실제 서버의 저장·모델·내부 전달·CORS/인증은 검사 범위에 포함하지 않는다. 자세한 근거와 한계는 [호환성 점검 결과](../integration/handoff/프론트_호환성_점검결과.md)를 따른다.
