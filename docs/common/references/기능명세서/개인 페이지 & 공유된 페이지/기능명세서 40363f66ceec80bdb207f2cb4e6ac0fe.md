## 1-2. AI 자료 분석

| 기능명 | 설명 | 입력/출력 | 비고 |
| --- | --- | --- | --- |
| ✨ 업로드 자료 분석 상태 표시 | 파일 또는 링크 분석 중임을 사용자에게 표시 | 입력: 파일/링크 
출력: 분석 진행 UI | 로딩 UI 간단하게 구현 가능 |
| ✨ 활동 자동 분류 | 입력된 자료가 어떤 활동에 속하는지 AI가 판단 | 입력: 파일·링크·텍스트 
출력: 활동명 | 예: 1호선톤 |
| ✨ 자료 유형 자동 분류 | 자료의 종류를 AI가 판단하여 분류 | 입력: 자료 내용 
출력: 기획안, 와이어프레임, 회의록 등 | 아카이브 폴더 분류에 활용 |
| ✨ 활동 상태 표시 | 해당 활동이 진행 중인지 완료 상태인지 표시 | 출력: 🟢 진행 중 / ✓ 완료 | 활동 데이터 기준 |
| ✨ AI 자료 요약 | 업로드된 자료의 핵심 내용을 짧게 요약 | 입력: 자료 내용 
출력: AI 요약 | 분석 결과 카드에 표시 |
| ✨ 기존 자료 비교 | 같은 활동에 저장된 과거 자료와 신규 자료를 비교 | 입력: 신규 자료 + 기존 자료 
출력: 비교 결과 | 서비스 핵심 AI 기능 |
| ✨ 변화 여부 판단 | 기존 자료와 비교하여 의미 있는 변화가 존재하는지 판단 | 출력: 변화 있음 / 주요 변화 없음 | 단순 수정은 성장으로 과장하지 않음 |
| ✨ Before / After 추출 | 의미 있는 변화가 있을 경우 이전 상태와 변경된 상태를 정리 | 출력: Before / After | 예: 기능 6개 → 핵심 기능 3개 |
| ✨ 변화 유형 판단 | 발견된 변화를 지정된 변화 유형으로 분류 | 출력: 변화 유형 | 의사결정 / 피드백 반영 / 범위 변경 / 구조 변경 / 성과 / 역할 / 외부 피드백 / 리스크 등 |
| 관련 자료 연결 | 새 파일과 이전 버전 또는 관련 파일을 연결 | 출력: 관련 자료명 | 예: wireframe_v1 → wireframe_v2 |
| 버전 관계 자동 인식 | 같은 종류의 자료가 반복 업로드되었을 경우 버전 관계 판단 | 입력: 다수 자료 
출력: v1 → v2 → final | 시간 남으면 구현 |

## 1-3. AI 분석 결과 확인 및 저장

| 기능명 | 설명 | 입력/출력 | 비고 |
| --- | --- | --- | --- |
| ✨ AI 분석 결과 카드 | AI가 분석한 활동, 자료 유형, 상태, 요약, 변화 등을 한 카드에 표시 | 출력: 분석 결과 | 홈의 핵심 결과 UI |
| ✨ 분석 결과 저장 | AI 분석 결과를 해당 활동 아카이브에 저장 | 입력: 저장 버튼  
출력: 활동 자료 추가 | 필수 |
| ✨ 변화 Timeline 저장 | 의미 있는 변화로 판단된 내용은 해당 활동 Project Timeline 이벤트로 기록 | 입력: 저장 
출력: Timeline 이벤트 생성 | Turning Point 여부 함께 저장 |
| ✨ 변화 없음 자료 저장 | 의미 있는 변화가 없어도 자료 자체는 아카이브에 저장 | 입력: 저장 
출력: 자료·버전 업데이트 | Timeline 이벤트는 생성하지 않음 |
| ✨ AI 분류 수정 | AI가 판단한 활동이나 자료 유형을 사용자가 직접 수정 | 입력: 수정 버튼 → 활동/자료 유형 
출력: 수정 결과 | AI 오판 대응 필수 |
| ✨ 다른 활동 선택 | 자동 분류된 활동이 잘못된 경우 다른 활동으로 변경 | 입력: 활동 선택 
출력: 연결 활동 변경 | 수정 모달과 통합 가능 |
| AI 확신도 표시 | 자동 분류 결과의 확신 정도를 표시 | 출력: 확신도 높음 등 | 선택 구현 |
| 전체 저장 | 다중 파일 업로드 시 분석된 자료를 한 번에 저장 | 입력: 전체 저장 
출력: 일괄 저장 | 다중 업로드 구현 시 적용 |

| 자료 유형 필터 | 기획안, 디자인, 개발자료 등 자료 유형별 필터링 | 입력: 유형 선택 
출력: 해당 자료만 표시 |  |
| 자료 정렬 | 최근순 / 오래된순 / 이름순으로 정렬 | 입력: 정렬 기준

# 6. Growth Journey

> **여러 활동을 통틀어 사용자가 시간에 따라 어떻게 성장했는지 보여주는 페이지**
> 

Project Timeline이 **한 활동 내부의 변화 과정**이라면 Growth Journey는 **사용자 전체 경험에서 확인된 성장 흐름**을 보여준다.

## 6-1. 성장 요약

| 기능명 | 설명 | 입력/출력 | 비고 |
| --- | --- | --- | --- |
| ✨ Growth Journey 페이지 | 사용자의 전체 성장 경험을 시간 흐름에 따라 제공 | 출력: 성장 Timeline | 핵심 결과 화면 |
| ✨ 최근 성장 흐름 AI 분석 | 여러 활동 기록을 분석하여 반복적으로 나타난 성장 흐름 요약 | 입력: 전체 활동 데이터 
출력: 성장 흐름 문장 | 예: 서비스 기획 → 사용자 중심 기획 → PM |
| ✨ 새롭게 쌓인 경험 Badge | 사용자가 처음 수행한 경험을 Badge 형태로 표시 | 출력: 첫 PM / 첫 인터뷰 / 첫 배포 등 | 시간 부족 시 생략 가능 |

HTML에서도 상단에 최근 성장 흐름 AI 분석과 새롭게 쌓인 경험 Badge가 별도로 구성되어 있다.

## 6-2. 성장 이벤트

| 기능명 | 설명 | 입력/출력 | 비고 |
| --- | --- | --- | --- |
| ✨ 성장 이벤트 시간순 표시 | 여러 활동에서 발견된 성장 근거를 시간순으로 표시 | 출력: 날짜 / 활동 / 성장 유형 / 설명 |  |
| ✨ 활동명 표시 | 각 성장 이벤트가 어느 활동에서 발생했는지 표시 | 출력: 활동명 |  |
| ✨ 성장 유형 표시 | 성장 이벤트를 성장 유형으로 분류 | 출력: 성장 유형 | 5개 성장 기준 사용 |
| ✨ 능력 확장 | 이전에 하지 않았던 역할/기술/업무를 새롭게 수행한 성장 | 출력: 성장 이벤트 |  |
| ✨ 성과 향상 | 이전보다 결과물 또는 성과가 개선된 경우 | 출력: 성장 이벤트 |  |

| ✨ 반성·재시도 | 실패나 피드백을 바탕으로 다시 개선한 경우 | 출력: 성장 이벤트 |  |
| ✨ Before / After 상세 | 성장 변화가 명확한 이벤트 클릭 시 전후 상태 표시 | 입력: 이벤트 클릭 
출력: Before / After |  |
| ✨ 근거 자료 표시 | 성장 판단에 사용된 파일·회의록·결과물 등을 표시 | 출력: Evidence |  |

# 7. Growth Map

> **※ 후순위 기능 — 시간 남을 경우 구현**
> 
> 
> 따라서 Growth Map에는 ✨ 필수 표시를 사용하지 않음.
> 

HTML에서는 활동을 Node, 활동 간 관계를 Edge로 표현하는 네트워크 구조다.

| 기능명 | 설명 | 입력/출력 | 비고 |
| --- | --- | --- | --- |
| Growth Map 페이지 | 사용자의 활동 간 연결 관계를 네트워크로 시각화 | 출력: 네트워크 Map | 후순위 |
| 활동 Node 표시 | 각 활동을 하나의 Node 카드로 표시 | 출력: 활동명 / 유형 / 상태 |  |
| 활동 연결선 표시 | 서로 관련된 활동을 선으로 연결 | 출력: Edge |  |
| 연결 유형 표시 | 활동 간 관계의 의미를 라벨로 표시 | 출력: 경험 전이 / 같은 분야 / 같은 핵심 프로젝트 등 |  |
| 분야 필터 | 특정 분야 활동만 표시 | 입력: AI·데이터 / 기획 / 개발 등 |  |
| 연결 유형 필터 | 특정 관계의 연결선만 표시 | 입력: 연결 유형 |  |
| Node 상세 보기 | 활동 Node 클릭 시 해당 활동 상세 Drawer 표시 | 입력: Node 클릭 
출력: 활동 정보 |  |
| 활동 상세 이동 | Node Drawer에서 해당 Activity Archive로 이동 | 입력: 버튼 클릭 |  |
| 연결 상세 보기 | 연결 라벨 클릭 시 두 활동이 연결된 이유 표시 | 입력: 연결 클릭 
출력: 연결 설명 |  |
| 연결 수정 | AI가 판단한 연결 관계를 사용자가 수정 | 입력: 수정 | 시간 남으면 |
| 연결 숨기기 | 불필요하거나 잘못된 연결을 Map에서 숨김 | 입력: 숨기기 | 시간 남으면 |
