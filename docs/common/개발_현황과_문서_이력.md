## 작업을 이어갈 때

문서 전용 전달 기준(2026-11-06): 백엔드·AI 담당자에게는 [docs/handoff/](handoff/README.md) 묶음만 제공하며 기존 개발 소스·개인 DB·실행/검사 스크립트는 제공하지 않는다. 해당 묶음은 폴더 밖 소스 링크와 코드 실행 요구를 제거했고, [개발환경·구현 범위](handoff/개발환경과_구현_범위.md)와 [서버 간 전달 규격](handoff/서버간_데이터_전달_계약.md)을 추가했다. 내부 전달 규격은 공유 DB 없는 새 구현을 위한 설계이며 기존 개발 서버의 적용 완료와 구분한다. 아래 기존 개발 서버 실행·제거 안내는 이 저장소 관리자의 작업 이력·전환 절차다.

### 각 파트의 실제 서버로 전환할 때

백엔드·AI 파트가 인수인계 문서의 API 계약대로 구현하고 서버 주소를 전달하면, 프론트를 해당 서버에 연결하는 것이 최종 목표다. **주소 연결과 기능 검증을 먼저 하고, 정상 동작을 확인한 뒤 로컬 개발 서버를 제거한다.** 주소만 바꾸면 반드시 동작한다고 가정하지 않는다.

1. 프론트의 백엔드/AI Base URL 환경변수와 필요한 Vercel 라우팅을 실제 HTTPS 서버 주소에 맞춰 변경하고 재배포한다. 로컬 Vite 프록시 설정은 Vercel에 그대로 적용되지 않으므로 현재 서비스 코드와 배포 설정을 확인한다. 비밀키는 프론트 환경변수에 넣지 않는다.
2. 백엔드 → AI 내부 호출 주소와 요청/응답 계약도 연결한다. 현재 두 개발 서버가 공유 SQLite를 읽는 부분은 각 파트의 실제 서버 구조에 맞는 데이터 전달/접근 방식으로 대체해야 한다. 인증·사용자별 데이터 분리·CORS·시간 제한·파일 업로드 제한도 합의한 계약과 대조한다.
3. 배포 프론트에서 일반 채팅, 텍스트/단일·다중 파일/링크 분석, 활동 제안과 확정 저장, 대화 수정, 나의 발자국 조회/검색/타임라인, 자료·활동·전체 삭제, 활동 정보 자동 갱신, Growth Journey 분석/갱신을 검증한다. 실패·빈 결과·중복 요청·삭제 후 재추가도 포함한다. 실제 서버 전환 시 기존 개발 DB 데이터를 이관할지 새로 시작할지도 별도로 결정한다.
4. 검증이 끝난 뒤 `api-server/`와 `ai-api-server/`의 개발용 실행 코드, 프록시·실행 스크립트·개발 전용 설정 및 의존성을 확인해 제거하거나 보관한다. 프론트가 사용하는 클라이언트 서비스 코드와 API 계약은 유지한다. 프롬프트·DB 정의·ERD·검증 시나리오 등 인수인계 근거는 보존한다.

이 절차는 전환 계획이며 아직 실제 파트 서버 연동이나 개발 서버 제거가 완료됐다는 뜻은 아니다. 서버 주소를 받기 전 또는 연동 확인 전에 개발 서버를 미리 삭제하지 않는다. 작성할 `docs/common/integration/handoff/배포와_서버_연결.md`와 `연동_검증_시나리오.md`에도 이 기준을 반영한다. 상세 작성 범위는 [파트별 인수인계 문서 작성 계획](integration/파트별_인수인계_문서_작성계획.md)을 따른다.

### 현재 구현과 다음 문서 작업

**현재 구현 인수인계:** [docs/handoff 안내](handoff/README.md)에서 시작한다. 사용자용 [서비스 전체 흐름](review/서비스_전체_흐름.md)과 [화면별 기능 정의](review/화면별_기능_정의.md), 공통 요청·데이터·오류 계약, 백엔드 API·DB·ERD·저장/삭제, AI API·입출력·프롬프트 원문, 배포 연결·검증 시나리오를 현재 코드와 대조해 작성했다. 사용자용 별도 합의 문서는 제외하고 서버 전환 결정은 배포 문서에 모았다. 개발용 독립 카드 페이지는 라우트·명세에서 제거했다. [작성 계획](integration/파트별_인수인계_문서_작성계획.md)은 작성 배경과 품질 기준이며, 작성 완료가 실제 운영 서버 연결·브라우저 전체 검증 완료를 뜻하지 않는다.

최신 Growth Journey 보완: [journey-v4 분류 정리](../frontend/journey/성장_분석_API.md). AI 분류 중복/미사용 선택지로 갱신이 실패하던 경로를 보완했다. 실제 기록 3개로 갱신 성공·이벤트 1개·갱신 필요 해제를 확인했다.

최신 삭제 기능: [활동 전체·자료 개별 삭제](../frontend/footprints/활동_자료_삭제.md). 활동명 확인 삭제, 자료 삭제 확인, 다중 파일의 남은 원본 재분석, 타임라인 정리와 성장 결과 무효화를 구현했다. 실제 DB를 검사용으로 삭제하지 않았다. 백엔드·AI 서버 재시작 필요.

Growth Journey는 journey-v3부터 [성장 분야도 AI 분석 분류](../frontend/journey/성장_분석_API.md)를 사용한다. 고정 목록 대신 실제 이벤트의 분야를 생성하며 이전 저장 결과는 유지한다. 서버 재시작 후 분석 갱신에서 반영한다.

최신 자료 기준: [채팅 자료 제외](../frontend/footprints/채팅_자료_제외.md). 입력 채팅은 참고 자료·최근 추가 자료로 표시하지 않는다. 파일·링크 확정 기록에는 함께 입력한 채팅을 복사하지 않고 자료 상세의 ‘입력한 내용’도 제거했다. 기존 자료의 입력문은 상세·검색에서 제외하며 DB 행과 별도 채팅 이력은 보존한다.

최신 채팅 기능: [대화로 활동 정보 수정](../frontend/chat/구현_기능/대화로_활동_정보_수정.md). 역할·상태·기간·전체 요약을 말로 요청하면 해당 DB 값만 직접 변경한다. 별도 정정 기록·모달은 없으며 이후 자료 저장 시 AI가 다시 갱신할 수 있다.

최신 추가 기능: [활동 전체 정보 AI 자동 갱신](../frontend/footprints/활동_정보_AI_갱신.md). 자료 저장 후 활동 요약·상태·기간·역할을 AI가 종합하며 실패 시 자료와 기존 정보는 보존한다. 백엔드와 AI 서버 재시작이 필요하다. 사용자 요청으로 Swagger 최신화는 진행하지 않는다.

최신 홈 UI: 신규 활동 추가는 확인 모달 없이 카드의 ‘새 활동으로 저장’ 또는 ‘기존 활동에 연결’로 판단한다. 신규 추가 과정에서 활동 전체 요약·기간·역할을 입력받지 않는다. [현재 기능 기록](../frontend/chat/구현_기능/홈_응답_구분_및_활동_확인_저장.md)을 따른다.

개선 범위는 [사용자 확인 기반 기록 및 활동 관리 개선계획](integration/사용자_확인_기반_기록_및_활동_관리_개선계획.md)에 정리했다. 홈 응답 구분·확인 저장, 활동 정보 자동 갱신·대화 수정, 채팅 자료 제외, 활동·자료 삭제, 성장 분야 동적 분류와 journey-v4 갱신 보완까지 구현했다. 기능별 검증 범위는 각 문서와 최신 인수인계를 따른다. Growth Journey는 실제 모델 갱신·저장도 확인했으며 브라우저 UI 확인과 Swagger 갱신은 수행하지 않았다.

사용자 프로필 설정의 [전체 데이터 삭제](../frontend/chat/구현_기능/전체_데이터_삭제.md)를 추가했다. 확인 문구 입력 후 실행하며 홈·성장 분석 중에는 삭제를 막는다. 기능 구현만으로 실제 DB를 삭제하지는 않았다.

**[현재 작업 인수인계](integration/현재_작업_인수인계.md)부터 읽는다.** 홈·Growth Journey 실제 AI 연동, 동적 분류/아이콘, DB 초기화·예시 자동 생성 제거, 실행 명령, 검사 결과와 다음 작업을 정리했다. 이전 단계별 계획보다 이 문서의 현재 상태를 우선한다.

현재 홈의 텍스트·단일/다중 파일·링크는 FastAPI와 실제 OpenAI 분석으로 연결했다. AI 서버는 기존 활동을 확인하거나 신규 활동을 제안하고 원본·분석 초안을 보관한다. 신규 활동 생성은 카드의 저장 선택 시 백엔드가 수행한다. 일반 대화는 분석 없는 말풍선으로 표시한다. 기존 활동 분류 수정은 유지하고 신규 제안은 카드에서 새 활동 저장 또는 기존 활동 연결로 확정한다.

다음은 바탕화면 `1Line_AI_시나리오_자료/00_사용안내.md` 순서로 실제 화면을 확인하고 발견한 문제를 보완하는 단계다. Growth Journey도 확정 기록 조회·실제 AI 분석·백엔드 결과 저장·조회로 연결했다. [성장 분석 API](../frontend/journey/성장_분석_API.md)를 따른다. 실제 모델 통합 검사는 통과했지만 사용자 브라우저 전체 시나리오 완료는 아직 확인하지 않았다. 최종 협업용 API 명세·ERD와 외부 배포는 후속 작업이다.

최신 상태(2026-11-06): 사용자 요청으로 실제 공유 DB를 비웠고 예시 활동 자동 생성도 제거했다. 문서 갱신 시 8개 테이블이 모두 0건이다. 새로운 사용자 입력부터 확인한다. Journey는 화면 진입 시 저장 결과만 조회하며 실제 AI는 ‘성장 분석하기 / 분석 갱신’에서 호출한다. 자동 분석은 논의한 제안이며 아직 적용하지 않았다. 성장 유형과 이모지는 AI가 생성하고 분야 기준은 유지한다.
