# 서비스 전체 흐름

기준일: 2026-11-06. [문서 입구](../handoff/README.md) · [화면별 기능](화면별_기능_정의.md)

이 서비스는 사용자가 남긴 경험과 자료를 활동별로 모으고, 저장된 기록을 바탕으로 변화와 성장 흐름을 보여준다.

## 입력부터 저장까지

1. 홈에서 경험을 글로 적거나 파일을 첨부한다. 링크는 링크 입력창에서 보낸다. 파일을 선택하거나 놓기만 하면 첨부 목록에 머무르며 보내기를 눌러야 분석한다.
2. AI가 일반 질문에는 말풍선으로 답하고, 기록할 경험이나 자료에는 활동·자료 유형·요약을 제안한다. 변화가 확인되는 경우에만 이전/이후와 근거를 표시한다.
3. 새 활동 제안이면 ‘새 활동으로 저장’을 누르거나 ‘기존 활동에 연결’에서 활동을 선택해 저장한다. 활동을 특정하지 못했다면 기존 활동을 선택해야 한다. 새 활동의 역할·기간·전체 요약 입력 모달은 없다.
4. 이미 있는 활동에 연결된 결과는 카드의 기록·아카이브 저장·전체 저장 버튼으로 확정한다. 분석이 끝났다는 사실만으로 나의 발자국에 기록이 추가되지는 않는다. 분석을 위해 보낸 원본과 대화는 서버에 보관될 수 있다.
5. 저장 성공 후에만 카드가 ‘저장 완료’로 바뀐다. 이후 나의 발자국과 홈 최근 목록에서 저장 결과를 확인한다.

## 저장 뒤 자동으로 하는 일

한 활동에 기록을 저장하거나 수정·이동하면, 백엔드는 해당 활동의 기록을 종합해 전체 요약·상태·기간·역할을 갱신한다. 모르는 사실을 입력하라고 요구하지 않는다. 종합에 실패해도 저장한 기록과 이전 활동 정보는 유지하며 ‘활동 정보 다시 분석’으로 재시도할 수 있다.

의미 있는 변화가 포함된 기록은 Project Timeline에 변화 이벤트로 저장된다. 변화 없는 기록은 이벤트를 만들지 않는다. 현재 새로 생성하는 이벤트는 Turning Point로 지정하지 않는다.

Growth Journey는 별도의 분석 결과다. 기록 저장이 곧 성장 분석 실행은 아니다. 화면에서 ‘성장 분석하기’ 또는 ‘분석 갱신’을 눌러야 실행한다.

## 저장한 내용을 보는 방법

나의 발자국에서는 활동을 검색하고 유형·상태·정렬을 함께 선택한다. 활동 상세에서는 전체 요약과 역할·기간, 자료 유형별 폴더를 본다. 파일·링크를 누르면 오른쪽 자료 패널에서 기록 요약과 관련 변화를 확인한다. 채팅 글은 자료 폴더나 최근 추가 자료로 표시하지 않는다. 독립 텍스트 경험은 저장 기록으로 남아 검색과 성장 분석에 사용된다.

자료 패널의 요약은 그 자료가 속한 **기록 전체의 요약**이다. 여러 파일을 함께 저장한 경우 파일마다 서로 다른 상세 분석이 있다는 의미는 아니다. 현재 파일명으로 버전 관계를 추정하지 않으며 자료 패널에 원본 다운로드·미리보기 버튼은 없다.

Growth Journey에서는 전체 흐름·경험 배지·성장 이벤트를 본다. 유형과 분야는 실제 분석에서 만들어지며 이벤트를 펼치면 근거 문장과 가능한 경우 전후 비교가 나온다. 날짜는 근거 기록을 저장한 월이다. 실제 활동 발생일을 확정한 날짜가 아니다.

## 수정과 삭제

- 카드의 ‘수정’은 연결할 기존 활동과 자료 유형을 바꾼다. 저장 전에는 카드에만 적용하고, 저장 후에는 저장된 기록을 수정한다.
- ‘이 활동 역할을 팀장으로 바꿔줘’처럼 명시적으로 말하면 해당 활동 정보만 수정한다. 새 자료·정정 기록은 만들지 않는다. 이후 자료 저장의 자동 종합에서 다시 바뀔 수 있다.
- 자료 삭제는 확인창을 거친다. 같은 기록에 다른 파일이 남으면 남은 원본으로 먼저 재분석하며, 실패하면 삭제하지 않는다.
- 활동 전체 삭제는 활동명을 정확히 입력해야 한다. 활동과 연결 기록·자료·타임라인이 삭제된다. 대화는 남고 삭제된 기록은 다시 저장할 수 없게 처리한다.
- 자료·활동 삭제 후에는 오래된 성장 요약·배지·이벤트를 비우고 남은 기록으로 갱신하도록 안내한다.
- 홈의 ‘대화 초기화’는 화면 대화를 새로 시작한다. 설정의 ‘전체 데이터 삭제’는 서버 데이터 전체를 지우는 별도 기능이다. 기존 공개 계약에는 사용자 식별 규약이 없어 공유 서비스 데이터 전체가 대상이었다. 사용자별 운영 범위는 배포 연결 때 정하고 문맥·자료·삭제에 일관되게 적용해야 한다.

실패·로딩·빈 결과 및 버튼별 자세한 동작은 [화면별 기능 정의](화면별_기능_정의.md)에 이어진다.
