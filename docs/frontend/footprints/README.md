# 나의 발자국 작업 시작 안내

2026-11-06 최신 기능: [활동 전체·자료 개별 삭제](활동_자료_삭제.md). 활동 상세 더보기와 자료 Drawer 휴지통에서 삭제한다. 다중 파일은 남은 원본을 재분석한 뒤 삭제하며, 성장 결과와 타임라인도 정리한다. 아래 삭제 미구현 설명은 이전 이력이다.

2026-11-06 최신 기능: [활동 전체 정보 AI 자동 갱신](활동_정보_AI_갱신.md). 확정 자료 저장·수정·이동 뒤 전체 요약·상태·기간·역할을 AI가 종합한다. 분석 실패 시 자료와 기존 정보는 유지하고 상세·홈 저장 카드에서 재시도할 수 있다. 실제 모델·브라우저 확인은 대기다.

최신 마무리: 2026-11-04 사용자가 나의 발자국을 현재 범위에서 마무리하기로 했다. 다음 작업은 [Growth Journey 구현 계획](../journey/README.md)이다. 이 문서의 남은 작업을 자동으로 재개하지 않는다.

최신 검색 동작: 입력의 250ms 대기와 한글 조합 완료 대기를 제거했다. 입력 변경마다 서버에 즉시 요청하며 이전 요청은 취소한다. 아래 대기 시간 개선 설명은 이전 작업 이력이다. 현재 계약은 [검색 API](검색_API.md)를 따른다.

작업 이력: 2026-11-04 사용자가 기본 화면 확인 후 나의 발자국 작업을 마무리했다. 이후 추가 요청으로 홈 최근 목록 연동·날짜/카드 표시·서버 검색·목록 로딩 표시와 대기 시간 개선을 진행했다. 다음 작업에서는 아래 최신 문서부터 읽는다. 이전 화면 확인을 후속 변경의 브라우저 검증 완료로 간주하지 않는다.

최종 정리: 2026-11-04. 다음 작업에 필요한 읽기 순서·소스·검증·후속 항목 안내다. 실제 작업 범위는 최신 사용자 요청을 따른다. 남은 작업 목록을 자동 구현 지시로 해석하지 않는다.

구현 범위: 활동 목록의 실제 DB 조회, 활동명·자료명·저장 입력/요약 검색, 유형/상태 필터, 정렬, 활동 상세와 폴더별 자료, 파일 Drawer·Project Timeline 연결을 완료했다. 최신 동작·데이터 구분·검증·남은 작업은 [현재 구현 상태](현재_구현_상태.md)를 확인한다.

최신 연동: 목록·상세·Drawer·Timeline의 목 조회를 기존 개발 서버·SQLite의 확정 기록 조회로 교체했다. 기존 목 파일은 화면 서비스에서 사용하지 않는다. 실행·기존 DB 처리·API 계약은 [DB 연동 안내](DB_연동.md)를 참고한다.

검색 후속: [검색 API](검색_API.md)로 활동명·자료명·저장 입력/요약 검색과 유형·상태·정렬을 서버에 연결했다. PDF 등 파일 내부 본문은 읽거나 검색하지 않는다. 목록 응답은 `{ items, total }`로 확장했다.

홈 연동 후속: 최근 활동·최근 추가된 기록도 같은 DB 자료와 ID를 사용하며 각각 변경 시각순·최초 저장 시각순으로 조회한다. 제목 줄바꿈·상태 배지 유지와 오늘/어제/이전 날짜 표시 변경은 [홈 최근 활동·기록](../chat/구현_기능/최근_활동_기록.md)에 기록했다. 활동 제안 응답과 확인 저장은 [활동 정보 계약](../chat/api/활동_정보_응답_저장.md)을 참고한다.

현재 로딩: 최초 조회는 큰 회전 아이콘·안내 카드, 재조회는 기존 목록을 옅게 유지한 안내와 이전 결과 이동 차단, 실패는 재시도 버튼을 제공한다. 검색 입력을 포함한 모든 조회에서 250ms 대기를 제거했다. 한글 조합 중에도 즉시 검색한다. API/DB 로컬 측정과 브라우저 렌더링 미측정 범위는 검색 문서에 기록했다. DB 원본값과 파일 내부 본문은 이 변경에서 수정하거나 읽지 않았다.

## 작업 시 구분할 사항

- 원본 목록의 외형과 미동작 검색/정렬을 구분한다. 선택 UI가 있다는 이유로 필터·정렬이 구현되었다고 보지 않는다.
- 검색 범위, 필터의 AND 조합, 오래된 순의 날짜 기준과 빈 결과를 확인한다. 원본 배열을 직접 변경하지 않는다.
- 표시용 활동 수·자료 수와 실제 배열/서버 총계가 다를 수 있다. 숫자를 맞추기 위한 가짜 자료를 만들지 않는다.
- 목록과 활동 상세·파일 Drawer·Project Timeline은 별도 작업 범위다. 아직 없는 화면으로의 이동까지 완료로 기록하지 않는다.
- 기능명세서의 필수 항목과 선택 항목을 구분하고 사용자 요청 순서대로 구현한다.

## 문서·검증 기록

나의 발자국 기능을 구현하면 해당 기능의 현재 동작·관련 코드·목/실제 값·검증·남은 작업을 이 폴더에 기록한다. 채팅 기록에 새 화면의 상세 이력을 계속 덧붙이지 않는다.

변경 범위에 맞게 빌드·린트와 필요한 동작 검사를 수행한다. 화면 비교는 원본과 같은 조건에서 하고, 실제 브라우저 확인과 자동 검사 결과를 구분한다. 나의 발자국의 사용자 화면 확인과 후속 홈 변경의 자동 검증은 각 기능 문서에 기록했다.

다음 작업은 사용자 요청을 확인하고 관련 코드의 현재 상태를 읽은 뒤 진행한다. 기존 DB를 초기화하거나 예시 자료로 대체하지 않는다. 검색 UI·한글 입력·로딩/재시도·좁은 화면·키보드의 후속 브라우저 확인은 아직 보고받지 않았으며, 실제 AI 호출·본문 추출·버전 관계·다운로드/미리보기·운영 인증은 구현 완료로 기록하지 않는다.
