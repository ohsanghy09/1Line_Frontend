# 활동 전체 삭제와 자료 개별 삭제

구현일: 2026-11-06. 설정의 DB 전체 삭제와 별개로 선택한 활동/자료를 삭제한다.

## 사용자 흐름

- 삭제 메뉴·자료 휴지통·확인창 삭제/취소 버튼에 손 모양 커서와 hover 배경/색상/테두리 전환을 적용했다. 삭제 처리 중에는 비활성 커서를 사용하며 키보드 초점도 표시한다. 설정의 전체 삭제 버튼에도 동일한 커서·색상 전환을 적용했다.

- 활동 상세 헤더 더보기 → 활동 삭제 → 활동명을 정확히 입력한다. 기록·자료 수와 복구 불가 안내를 표시한다. 미입력/불일치는 연한 빨간 테두리와 하단 오류 문구로 안내한다.
- 자료 상세 오른쪽 위 휴지통 → 삭제 확인. 처리 중에는 중복 제출과 확인창 닫기를 막으며 실패 문구를 표시한다.
- 자료 삭제 후 Drawer를 닫고 활동을 재조회한다. 활동 삭제 후 나의 발자국 목록으로 이동한다. 홈 최근 활동·자료, 사이드바 목록도 갱신 이벤트를 사용한다.

## 삭제 범위

- 활동: 해당 활동의 확정 기록(텍스트 경험 포함), 원본 파일 BLOB, 타임라인을 삭제하고 활동 행을 삭제한다. 다른 활동은 유지한다.
- 마지막 파일 또는 링크: 원본/링크와 연결된 기록·타임라인을 삭제한다. 활동은 빈 활동으로 유지할 수 있다.
- 다중 파일 중 하나: 삭제 대상 이외의 원본만 AI가 재분석한다. 기존 요약·대화는 분석 문맥에 전달하지 않는다. 새 요약/분류로 기록을 교체하고 기존 변화 이벤트를 제거한 뒤 원본을 삭제한다. 실패 시 기존 자료를 그대로 보존한다.
- 자료 삭제 후 기존 활동 요약·상태·기간·역할을 비운다. 남은 기록이 있으면 기존 활동 정보 자동 분석 큐로 갱신하며 실패 시 재시도할 수 있다. 기록이 없으면 미설정으로 남긴다.
- 모든 과거 Growth Journey 스냅샷의 전체 요약·배지·이벤트를 비우고 갱신 필요 상태로 만든다. 전체 요약은 여러 기록을 종합하므로 일부 문구만 추정해서 남기지 않는다. 남은 기록이 없어도 삭제한 내용은 표시하지 않는다.
- 별도 대화 이력은 보존한다. 삭제 기록의 분석 초안은 일반 말풍선으로 전환해 재저장을 막고 첨부 원본을 제거한다. 다중 파일 일부 삭제 시에도 이전 분석 초안의 카드 저장은 막으며 남은 자료는 확정 기록에서 조회한다.
- 브라우저에 저장된 확정 카드는 홈 재진입 시 DB를 재조회한다. 삭제된 기록은 일반 안내로 바꾸고 남은 기록은 새 요약을 표시한다. 다른 탭의 이미 열린 화면은 재진입/새로고침이 필요하다.

## API와 정합성

- `DELETE /api/archive/activities/:id`: JSON `{ "confirmation": "활동명" }` 필수.
- `DELETE /api/archive/activities/:id/materials/:fileId`: 해당 활동에 실제로 속한 자료만 삭제한다. 링크 ID는 `record:기록ID`이며 URL 인코딩한다.
- 두 DELETE는 성공 시 `{ "deleted": true }`를 반환한다. 없는 자료/활동은 404, 확인 불일치는 400, 진행 충돌/동시 변경은 409다.
- FastAPI 내부 `POST /api/analyze/records/:recordId/exclude-file`: `{ "fileId": "삭제할ID" }`로 남은 원본을 분석한다. 이 API 자체는 DB를 변경하지 않는다.
- 여러 파일 재분석 실패/대상 불일치는 502로 삭제하지 않았음을 안내한다. 삭제 대기 중 기록이 바뀌면 입력 fingerprint로 감지해 409로 거절한다. 같은 기록의 동시 삭제는 거절한다.
- 채팅 AI 작업 진행 중에는 삭제를 거절한다. 기존 활동 정보 큐는 삭제 확정 후 취소하고 필요 시 최신 입력으로 다시 접수한다. 진행 중 성장 분석은 기존 fingerprint 검사로 오래된 결과 저장을 막는다.
- 삭제·기록 교체·타임라인 정리·성장 결과 정리는 SQLite 트랜잭션으로 처리한다. 모델 요청 중에는 트랜잭션을 열어 두지 않는다.
- 테이블/컬럼을 변경하지 않는다. 일반 대화, 미확정 자료 보관 정책 전체를 삭제하는 기능은 아니다.

## 검증 및 적용

- 백엔드 전체 44개 통과(Swagger 전용 검사 제외): 소유 활동 확인, 확인 문구, 링크·마지막 파일·다중 파일, 대화 보존/재저장 차단, 다른 활동 보존, 재분석 실패/동시 수정/DB 오류 롤백과 성장 결과 무효화.
- Python 전체 57개 통과: 남은 원본만 전달, 이전 요약/채팅 미전달, 1회 모델 요청, AI API 무쓰기 및 실패 보존.
- 프론트 자료·검색 14개 통과: 실제 서비스 → Vite 프록시 → API → 임시 SQLite 삭제 검증 포함.
- TypeScript/Vite 직접 빌드 통과. lint 기존 경고 3개. 실제 공유 DB 삭제, 실제 유료 모델 호출, 브라우저 UI 검증은 수행하지 않았다. Swagger는 사용자 지시대로 갱신하지 않았다.
- 백엔드와 AI 서버를 재시작하고 화면을 새로고침한다.
