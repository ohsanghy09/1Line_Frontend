# 대화로 활동 정보 직접 수정

최신 정리: 2026-11-06. 코드·자동 검사 완료. 실제 모델 의도 판단·브라우저 확인은 대기다.

## 사용자 동작

홈 채팅에 ‘북클럽봄 역할을 팀장으로 바꿔줄 수 있어?’처럼 말하면 AI가 대상과 수정 항목을 해석하고 백엔드가 해당 활동 DB 값만 바로 변경한다. 확인 모달·저장 버튼·새 정정 기록 없이 완료 말풍선을 표시한다.

- 역할: ‘북클럽봄 역할을 팀장으로 바꿔줘.’
- 상태: ‘해커톤을 완료 상태로 바꿔줘.’
- 기간: ‘북클럽봄 시작일을 2026년 3월, 종료일을 2026년 6월로 바꿔줘.’
- 전체 요약: ‘북클럽봄 전체 요약을 …로 바꿔줘.’
- 명시적 비우기: ‘북클럽봄 종료일을 비워줘.’

요청한 필드만 변경한다. 역할만 수정하면 전체 요약·상태·기간·활동명·유형은 유지한다. 상태 값은 현재 화면과 동일한 진행 중/완료 또는 명시적 비우기만 지원한다. 활동명·유형 변경, 활동/자료 삭제는 이 동작에 포함하지 않는다.

대상이 생략되면 같은 대화에서 최근 언급·저장·수정한 실제 활동을 참고한다. 문맥으로 대상을 결정할 수 없으면 일반 말풍선으로 묻도록 프롬프트를 구성했다. ‘어떤 활동인가요?’ 다음의 활동명 답변도 최근 대화로 해석할 수 있다. 직전 활동이 미저장 제안이면 다른 기존 활동에 임의 적용하지 않고 먼저 제안 저장을 안내한다. 기능 질문·부정 요청·일반 경험 서술은 수정 명령과 구분한다.

현재 채팅 입력은 홈에 있으므로 활동 상세 화면에 별도 채팅창을 추가하지 않았다. 대상 문맥은 최근 같은 conversationId의 완료 요청 6개(사용자·응답 최대 12개, 각 2000자)와 기존 활동 목록을 사용한다. 홈 문맥의 활동 최대 50개 제한은 유지한다.

## 처리 흐름

1. 기존 홈 모델 호출에서 일반 대화/경험 분석/활동 수정(kind=activity-update)을 구분한다. 수정 전용 추가 모델 호출은 없다.
2. 수정 응답에는 실제 활동 ID와 허용된 필드·값 목록만 둔다. AI 서버는 대상 ID·필드·값을 검증하고 기존 작업 응답으로 보관한다. 이 단계에서는 활동 DB 값을 바꾸지 않는다.
3. 프론트 서비스가 POST `/api/activities/apply-chat-update`에 완료된 analysisId만 전달한다. SQL이나 수정 값을 클라이언트가 재구성해 보내지 않는다.
4. 백엔드가 DB의 실제 완료된 AI 요청을 읽고 변경 내용을 재검증한다. 허용 항목은 role, status, summary, startDate, endDate다. 파일·링크 요청, 미완료 작업, 일반 대화는 수정으로 실행하지 않는다.
5. 해당 필드 변경과 작업 응답의 일반 완료 말풍선 교체를 한 트랜잭션으로 수행한다. 새 records·timeline_events·별도 수정 이력은 생성하지 않는다.
6. 완료 응답에 updatedActivityId를 포함하고 최근 활동·발자국·열린 상세의 재조회를 알린다. 성공 이후에만 ‘활동 정보를 수정했어요’와 적용 값을 표시한다.

새로운 정정 이력은 만들지 않지만 일반 채팅과 동일한 요청·작업·응답 보관은 유지한다. 이전 활동 값의 별도 스냅샷도 추가하지 않는다. 후속 사용자 요청에 따라 직접 수정 성공 시 활동의 updated_at을 적용 시각으로 갱신한다. 홈 최근 활동과 발자국 최근 업데이트 정렬·시각에 반영하며 기존 프론트 완료 재조회 알림을 사용한다. 기록·원본 파일의 저장 시각은 바꾸지 않고 최근 추가 자료도 생성하지 않는다. 중복 요청 재조회와 거절된 수정은 updated_at을 갱신하지 않는다.

기간은 실제 날짜와 기존 반대쪽 날짜를 함께 검증한다. 날짜가 잘못됐거나 기간이 역전되면 다른 항목까지 모두 적용하지 않는다. 잘못된 요청의 확정 거절은 채팅 대기를 해제해 다시 말할 수 있게 한다. 통신 실패처럼 성공 여부가 불명확하면 기존 작업 재조회로 확인하며 자동 유료 재전송은 하지 않는다.

같은 analysisId를 다시 적용하거나 새로고침 후 복원해도 DB 수정을 반복하지 않는다. 첫 적용 시 일반 완료 응답으로 바꾸므로 이후 자동 AI 갱신으로 역할이 달라져도 옛 수정 요청을 재적용하지 않는다.

## 자동 활동 분석과의 관계

대화로 직접 수정한 뒤 활동 전체 종합 분석을 즉시 다시 실행하지 않는다. 이전에 접수/진행 중이던 활동 종합 분석도 취소·무효화하여 오래된 결과가 방금 수정한 값을 바로 덮지 못하게 한다. 분석 상태 관리 값은 정리하지만 요청하지 않은 업무 필드는 바꾸지 않는다.

영구적인 사용자 값 잠금이나 수동 우선 정책은 없다. 이후 새 자료 저장·수정 또는 사용자의 수동 분석이 실행되면 AI가 기록을 종합해 역할·기간 등을 다시 갱신할 수 있다. 정정 기록을 추가하지 않았으므로 그때는 해당 채팅의 수정값이 확정 기록의 근거로 추가되지 않는다.

## 코드와 검증

- 모델 계약·프롬프트: `ai-api-server/app/home_schemas.py`, `app/prompts/home.md`
- 대상·최근 대화 조회: `ai-api-server/app/database.py`, `app/chat.py`, `app/home_analysis.py`
- 백엔드 적용: `api-server/src/activity-chat-update.js`, `app.js`
- 기존 자동 분석 무효화: `api-server/src/activity-metadata.js`
- 프론트 적용·재조회: `src/services/chat.ts`, `src/types/chat.ts`

검사 결과:

- Python 53개 통과. 신규 명령 계약·대상 검증·첨부 속 수정 거절·최근 대화·실제 활동명 사용·잘못된 값/중복 필드 거절 포함.
- 백엔드 39개 통과(Swagger 전용 검사 제외). 신규 4개는 역할만 변경·기록/타임라인 미생성·중복 재적용 방지·기간/상태/비우기·잘못된 요청 롤백·미완료/파일/일반 대화 거절·진행 중 분석 무효화·이후 자동 갱신 허용을 확인한다.
- 프론트 서비스/세션 검사 통과. 수정 요청이 실제 테스트 백엔드·SQLite를 거쳐 일반 말풍선으로 바뀌고, AI 요청 1회·백엔드 적용 1회·복원 후 재적용 없음·확정 오류 해제를 확인했다.
- TypeScript·Vite 직접 빌드 통과. lint는 기존 경고 3개. Swagger 갱신/정적 생성은 사용자 요청에 따라 하지 않았다.
- 검사 데이터는 메모리·임시 DB다. 실제 공유 DB의 활동 값을 검사 목적으로 바꾸지 않았고 유료 모델 호출·브라우저 직접 검증은 하지 않았다.

실제 모델에서 정중한 요청·대상 생략·여러 활동의 모호함·추가 질문에 대한 답변·미저장 제안을 확인해야 한다. 자동 검사에서는 모델 출력을 합성했으므로 자연어 의도 판단 품질까지 검증했다고 해석하지 않는다. 백엔드와 AI 서버를 재시작한 뒤 확인한다.
