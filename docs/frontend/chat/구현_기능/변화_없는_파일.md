# 변화 없는 파일

최종 정리: 2026-11-04

## 현재 동작

파일 하나의 응답이 file-analysis 또는 no-change이고 analysis.changes가 빈 배열이면 NoChangeAnalysisContent를 사용한다. 원본의 정보 아이콘·제목·회색 안내/사유 박스·아카이브 저장/수정 버튼을 표시하고, 분류 그리드·Before/After·변화 개수 배지는 만들지 않는다.

제목은 content, 안내는 analysis.noChangeMessage, 사유는 analysis.summary에서 읽는다. 카드 너비와 실제 시각은 공통 규칙을 사용한다.

홈은 로컬 서버의 변화 없음 목 응답을 기본으로 사용한다. 실제 이름과 원본은 보존하고 분석은 목 값이다. 프론트 mockSingleFileAnalysisMode는 홈을 제어하지 않는다.

## 저장·수정과 API 전환

아카이브 저장·수정은 실제 REST API에 연결했다. 변화가 없는 기록은 자료만 저장하고 Timeline 이벤트를 만들지 않는다. 저장 전에는 버전 업데이트/기록을 제안하고 저장 후에만 성공을 표시한다.

사용자 요청에 따라 변화 없음 카드의 아카이브 저장은 확인 모달 없이 카드에 연결된 기존 활동으로 바로 저장한다. 활동 ID가 없거나 더 이상 존재하지 않으면 오류로 안내하고 수정 버튼에서 활동을 선택하게 한다. 이전 형식 응답(match 없음)은 기존과 같이 활동명으로 활동 목록의 ID를 찾는다. 새 활동 생성이나 활동 메타정보 자동 적용은 하지 않는다.

수정 모달은 연결할 기존 활동과 자료 유형만 제공한다. 상태·역할·기간·활동 전체 요약과 기존 활동 정보 적용 체크박스는 표시하지 않는다. 저장 전 수정은 카드/세션에만 적용하고, 이후 아카이브 저장 시 그 활동과 자료 유형으로 저장한다. 저장 후 수정은 해당 기록의 활동·자료 유형만 PATCH한다. 다른 종류의 카드에는 기존 활동 확인 흐름을 유지한다. 관련 코드: `ConnectedChatReplyCard.tsx`, `modals/ActivityReviewModal.tsx`.

[기록·수정](카드_기록_수정.md), [파일 분석](파일_업로드_분석.md), [실제 서버 전환](../api/실제_서버_전환_가이드.md)을 참고한다. 실제 AI 연결 시 서버 응답의 변화 배열을 사용하고 프론트가 별도로 변화 여부를 판정하지 않는다.

## 검증

초기 전용 본문의 React 서버 렌더링, 이후 API·DB 저장/수정·변화 이벤트 미생성 검사가 통과했다. 브라우저 픽셀 일치는 미검증이다.

저장 확인 모달 제거·분류 전용 수정 후 build/lint와 `node scripts/check-chat-api.mjs`, `node scripts/check-chat-session.mjs`가 통과했다. API/세션 검사는 저장·분류 수정 데이터 흐름을 확인한 것이며 이번 모달의 실제 브라우저 조작과 클릭 경로를 검사한 결과는 아니다.
