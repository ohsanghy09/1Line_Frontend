# 홈 최근 활동과 최근 추가된 기록

작성: 2026-11-04. 원본의 두 영역 배치를 유지하고 목 배열을 실제 개발 서버·SQLite 조회로 교체했다. 실제 AI 연결은 별도다.

## 시간 기준과 표시

| 영역 | 기준 | 개수·클릭 |
| --- | --- | --- |
| 최근 활동 | 자료 저장·기록 수정·활동 정보 수정 시의 활동 updated_at 내림차순 | 최대 3개, `/archive/:activityId` |
| 최근 추가된 기록 | 최초 확정 저장 시각 records.created_at 내림차순 | 자료 최대 3개, `/archive/:activityId?file=:materialId` |

최근 활동은 변경 시각이 없는 초기 예시 활동을 제외한다. 동률이면 활동의 DB 삽입 순서 역순으로 정렬한다. 자료가 다른 활동으로 이동하면 출발·도착 활동을 모두 같은 수정 시각으로 갱신하고 현재 자료 수를 조회한다. 자료가 0개가 된 출발 활동도 최근 변경 활동이다. 나의 발자국도 같은 활동 변경 시각을 표시한다.

최근 추가된 기록은 수정해도 추가 시각과 위치를 바꾸지 않는다. 활동 이동·유형 수정 시 표시 정보와 이동 대상만 현재 값으로 갱신한다. 다중 파일은 파일별 자료로 표시하고 파일 없는 텍스트/링크도 하나의 자료로 표시한다. 같은 저장 시각은 기록 삽입 순서 역순, 같은 기록 안의 파일은 입력 순서다. 업로드 시각과 최초 확정 저장 시각은 구분하며 홈은 저장 시각을 사용한다. 분석 초안과 미저장 원본은 두 목록에 포함하지 않는다.

활동 카드의 유형·상태·요약·자료 수는 나의 발자국의 집계를 재사용한다. 없는 메타정보를 원본 예시로 채우지 않는다. 기록 아이콘은 file/text/link에 대응한다. 날짜는 실제 ISO 시각에서 한국어 표시로 변환한다.

사용자 후속 요청: 최근 활동 카드의 제목/상태 행은 줄을 바꾸지 않고 상태 배지를 오른쪽 상단에 유지한다. 배지는 축소·줄바꿈하지 않고 제목이 남은 너비에서 여러 줄로 표시되도록 한다.

날짜 표시 후속: 홈 최근 활동의 우측 하단과 최근 추가된 기록의 시각을 브라우저 현지 날짜와 비교해 오늘은 ‘오전 11:34’, 어제는 ‘어제 오후 3:34’, 이전은 ‘2026.11.02’로 표시한다. 최근 활동은 updatedAt, 최근 추가된 기록은 savedAt을 사용하며 오전/오후는 12시간제다. 기존 현재 시각의 30초 갱신을 사용한다. 서버 ISO 값·DB·정렬 기준·나의 발자국 표시는 변경하지 않는다. 변환은 `src/utils/recentActivityTime.ts`에 둔다.

## API와 DB

`GET /api/home/recent`는 `{ activities, records }`를 반환한다. activities는 기존 아카이브 활동 카드 계약이고, records는 id(자료 ID)·recordId·activityId·activityName·title·materialType·kind·savedAt 필드다. 서버에서 정렬·개수 제한을 수행한다. `readArchive`의 자료 ID와 집계를 공유하므로 Drawer와 같은 자료를 조회한다.

activities에 nullable TEXT `updated_at`을 추가한다. 기존 DB에서는 소속 확정 기록의 MAX(updated_at)으로 비어 있는 활동 시각만 채운다. 기록이 없으면 null을 유지하고 서버 시작 시각을 입력하지 않는다. 저장·수정과 활동 시각 변경은 같은 트랜잭션이다.

## 갱신과 오류

홈 진입 시 조회하고 기록 저장·수정 서비스가 보내는 `1line:activities-changed` 이벤트에서 두 목록을 재조회한다. 새 활동 생성과 메타정보 적용도 같은 저장 경로이므로 갱신된다. 초기 로딩·빈 목록·오류·다시 불러오기를 제공하고 장애를 목 데이터나 빈 결과로 감추지 않는다.

새 요청은 이전 요청을 취소하며 요청 ID와 컴포넌트 생존 상태로 늦은 응답 반영을 막는다. 홈 이탈 시 요청·이벤트 구독을 정리한다. 다른 브라우저 탭·외부 DB 변경의 실시간 구독은 없으며 홈 재진입이나 다시 불러오기로 조회한다.

## 코드와 검증

- `api-server/src/home.js`: 두 목록 집계·정렬·자료 ID.
- `api-server/src/activities.js`, `app.js`, `database.js`, `archive.js`: 시각 보관·마이그레이션·API·공통 집계.
- `src/services/home.ts`, `src/types/home.ts`: 조회·응답 검증·시각 변환.
- `src/hooks/useHomeRecent.ts`, `src/pages/Home.tsx`: 조회 수명·성공 이벤트 재조회·상태 표시·라우팅.
- `src/utils/recentActivityTime.ts`, `tests/recent-activity-time.test.mjs`: 홈 두 목록의 프론트 날짜 표시와 달력 경계 검사. 날짜 테스트 3개와 변경 후 build/lint가 통과했다.
- 과거 src/mocks/Home 예시는 미사용을 확인해 2026-11-11 제거했다. 현재 홈은 API 조회만 사용한다.
- 서버 테스트: 빈 DB/초안 제외, 최대 3개, 시간 기준 차이, 다중 파일 순서·실제 파일 ID, 수정 후 추가 순서 보존, 활동 이동 양쪽 시각·개수·라우팅, 메타정보 수정, 동률 안정 정렬, 과거 DB 시각 이관.
- 프론트 서비스→Vite→API→임시 DB: 최근 목록·아카이브 데이터 일치, 저장·이동 반영, 오류·잘못된 응답.
- 홈 연동 당시 build/lint·서버 테스트 11개·프론트 통합·기존 채팅 API/세션 회귀 검사를 통과했다. 이후 검색 API 검사 추가로 서버 전체 검사는 12개이며, 최근 로딩 변경 뒤에는 build/lint와 홈/아카이브 서비스·검색/정렬·날짜를 포함한 루트 검사 16개를 통과했다. 사용자 DB에 테스트 데이터를 추가하지 않았다. 후속 홈 변경의 브라우저 표시·이벤트 재조회·키보드·좁은 화면 확인은 아직 수행하지 않았다. 이전 나의 발자국 화면 확인과 구분한다.
