# 다중 파일 응답

최종 정리: 2026-11-04

## 현재 계약

파일 2개 이상을 POST /api/chat에 FormData로 전송한다. 홈은 Prefer: respond-async를 사용하고 작업 ID의 진행을 조회한 뒤 result.reply를 카드에 표시한다. [진행 API](파일_분석_진행.md) 참고.

서버 응답은 kind: batch-analysis다. 실제 파일명·개수·원본을 유지하고 현재 목 분석은 기타 자료 한 그룹으로 분류한다. 버전 관계와 중요한 변화를 임의로 만들지 않는다.

화면은 content, analysis.activity.name, files.length, groups, summary를 표시한다. 분류 박스는 줄바꿈하되 문구 내부의 유형명·개수는 한 줄을 유지한다. 긴 문구는 박스 내부 가로 스크롤을 사용한다. 전체 저장은 파일 목록을 포함한 분석 하나를 기록으로 저장하고 자료 확인은 /archive로 이동한다.

## 개발용 예시 구분

/example의 고정 목 응답은 기획안·와이어프레임·회의록과 예시 버전 관계를 포함한다. src/mocks/Home/batchAnalysis.ts의 파일명 분류는 기존 프론트 목 구현이며 현재 홈 서버의 분류 규칙이 아니다. 실제 AI 연결 시 서버 분류·버전 관계를 사용한다.
