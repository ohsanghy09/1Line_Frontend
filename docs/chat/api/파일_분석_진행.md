# 로컬 서버 파일 분석 진행 API

최종 정리: 2026-11-04. 실제 AI 단계가 아닌 서버 시간 기반 목 진행이다. 파일과 링크는 같은 작업 조회·실패·완료 계약을 사용하며 단계 문구만 다르다. 프론트는 서버 상태를 조회하고 접수된 작업을 세션에서 복원한다.

## 흐름

1. 파일이 있는 `POST /api/chat` 요청에 `Prefer: respond-async` 헤더를 보낸다.
   링크는 `POST /api/chat/links`에 URL을 보내 같은 형태의 작업 ID를 받는다.
2. 서버는 원본·입력·목 결과와 SQLite 작업 행을 보관하고 HTTP 202를 반환한다.
3. 프론트는 즉시 첫 진행을 표시하고 `GET /api/chat/jobs/:jobId`를 400ms 간격으로 순차 조회한다.
4. `completed`의 `result`를 기존 결과 카드에 표시한다. 텍스트 전용은 이전 동기 응답과 점 3개 대기를 유지한다.

헤더가 없는 기존 클라이언트는 HTTP 201 최종 응답을 받는다. 단일·다중 파일 모두 비동기 경로를 지원한다. 파일 원본 전송 중에는 점 3개를 표시하며 진행 카드는 서버 접수 후부터 표시된다. 업로드 바이트 비율은 제공하지 않는다.

## 응답

```json
{
  "jobId": "작업 ID",
  "status": "running",
  "analysisProvider": "mock",
  "pollAfterMs": 400,
  "progress": {
    "title": "파일을 확인하고 있어요...",
    "steps": [{ "label": "파일 확인 중...", "status": "working" }]
  }
}
```

단계는 파일 확인 → 기존 활동 비교 → 자료 유형 분석 → 이전 기록 비교 순서다. 서버가 700ms마다 목 단계를 변경한다. 완료된 항목과 현재 작업만 내려주고 앞으로 진행할 항목을 완료로 표시하지 않는다. 총 목 진행 시간은 약 2.8초이며 네트워크·조회 간격에 따라 화면 전환은 조금 늦을 수 있다.

완료 응답은 `status: completed`, 완료 진행과 `result: { analysisId, conversationId, message, attachments, reply, createdAt }`다. 실패 응답은 `status: failed`, `error`를 포함한다. 실제 작업 엔진은 없으므로 현재 정상 목 작업은 자동 실패하지 않으며 DB의 작업 오류가 설정되면 실패 상태를 전달한다. 없는 작업은 404다.

## 서버·화면 보호

- `analysis_jobs` 테이블을 기존 DB에 추가한다. 작업 ID·초안 ID·시작 시각·오류를 보관한다. 프로세스 메모리나 백그라운드 타이머를 사용하지 않고 시작 시각으로 목 상태를 계산한다.
- 서버를 재시작해도 작업을 조회할 수 있다. 서버 중지 중 지난 시간도 목 경과 시간에 포함한다.
- 파일 원본·목 최종 결과는 접수 시 이미 보관되고 진행은 시각 기반 재현이다. 실제 문서 파싱·AI 분석이 실행되는 것이 아니다.
- 진행 중·실패 작업은 기록 확정 API에서 409로 막는다.
- 프론트는 전체 폴링 30초 제한, 응답 구조 검증, 실패 안내를 적용한다. 조회를 겹쳐 실행하지 않는다.
- 초기화·화면 해제 시 HTTP 요청과 폴링 대기를 취소하고 요청 ID로 늦은 콜백·결과를 무시한다. 서버에 보관된 원본·작업은 삭제하지 않는다.
- 작업 ID는 [sessionStorage](../구현_기능/채팅_세션_보관.md)에 보관한다. 재진입 시 GET만으로 조회를 재개하고 결과 중복을 막는다. 작업 ID 수신 전 중단은 복원하지 않는다. 조회 실패 시 재확인 버튼을 제공한다.
- `/example`의 진행 카드는 고정 목 미리보기로 유지한다. 실제 상태 전환은 홈에서 파일을 전송해 확인한다.

## 코드·검증

- `api-server/src/progress.js`: 목 단계와 시간 계산, 실제 AI 연결 시 교체할 위치.
- `api-server/src/app.js`: 비동기 접수·작업 조회·확정 제한.
- `src/services/chat.ts`: 폴링·취소·검증·진행 콜백.
- `src/pages/Home.tsx`: 서버 진행을 `FileAnalysisProgress`에 전달하고 완료/실패/초기화 시 제거.

build/lint, 서버 테스트 4개, 프론트 서비스 → Vite 프록시 → API → SQLite 검증 통과. 단계 경계·완료·실패·없는 작업·완료 전 저장 차단·재연결 시 작업 유지, 단일/다중 파일·링크와 진행 콜백, 조회 재개·취소·잘못된 진행 응답을 확인했다. 브라우저 클릭·시각 검증은 미실시다.
