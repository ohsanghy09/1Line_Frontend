# 로컬 REST API 채팅 연결

최종 정리: 2026-11-04. Home은 로컬 REST API를 호출하며 분석은 서버 목 응답이다. 텍스트는 동기 결과, 파일·링크는 작업 ID로 진행을 조회한다. 정확한 계약은 [진행 API](파일_분석_진행.md)와 [링크 구현](../구현_기능/링크_입력_분석.md)에 정리했다.

## 실행

터미널 두 개에서 각각 실행한다.

```powershell
# 첫 번째 터미널: 프로젝트 루트에서
cd api-server
npm.cmd run dev
```

```powershell
# 두 번째 터미널: 프로젝트 루트에서
npm.cmd run dev
```

Vite가 출력하는 주소로 홈을 연다. `/api` 요청은 `http://127.0.0.1:3001`로 전달된다. 프록시 설정 변경 전부터 Vite를 실행 중이었다면 재시작한다.

프론트 기본 주소는 `/api`다. 다른 서버는 `VITE_API_BASE_URL`에 `/api`까지 포함한 기본 주소를 설정한다. 이 경우 서버의 `FRONTEND_ORIGIN`도 실제 프론트 출처와 맞춘다. 빌드 배포에서는 환경변수 또는 호스팅 측 `/api` 프록시가 필요하며 Vite 개발 프록시는 배포 파일에 포함되지 않는다.

## 요청·응답

- `getChatServiceStatus()` → `GET /api/health`. 연결 실패는 기존 조회 실패 배지로 표시한다.
- `getChatReply(message, files, options)` → `POST /api/chat`. options는 conversationId·signal·onProgress·onJobStarted를 받는다.
- `getLinkReply(url, options)` → `POST /api/chat/links`. 접수된 파일·링크 작업은 `resumeChatReply(jobId)`로 조회를 재개한다.
- 요청은 FormData의 `message`, 반복 `files`, `conversationId`다. Content-Type 경계는 브라우저가 설정한다.
- 응답의 `reply`를 검증한 뒤 `analysisId`, `conversationId`를 붙여 기존 `Promise<ChatReply>`로 반환한다. 두 ID는 이후 기록 확정에 사용한다.
- 프론트는 `mode`를 지정하지 않아 서버 기본 `no-change` 목 응답을 사용한다. 기존 프론트 목 설정은 실제 전송에 사용하지 않는다.
- 텍스트·파일 원본·목 분석이 SQLite에 초안으로 보관된다. 저장 버튼 없이 활동 기록이나 Timeline을 만들지 않는다.

## 화면 동작

파일 선택·드롭은 전송 전 첨부만 한다. 전송 버튼/Enter 또는 링크 모달로 접수한다. 접수 전과 텍스트 전용 요청에는 점 3개를 표시한다. 파일·링크는 서버의 단계별 목 진행을 조회하고 최종 결과 카드로 바꾼다. 프론트 자체의 고정 진행 타이머는 사용하지 않는다. `/example`은 고정 진행 미리보기를 유지한다.

개별 HTTP와 전체 폴링에 각각 30초 제한을 두며 서버·형식·연결 오류를 안내한다. 작업 ID가 있으면 재확인을 제공하고 재업로드하지 않는다. ID를 받기 전 실패한 글·파일은 재전송할 수 있게 복원하며 대기 중 새로 작성한 글은 덮어쓰지 않는다. 링크 모달은 마지막 제출 URL을 유지한다. 자동 재전송은 하지 않는다.

초기화·화면 해제 시 요청을 취소하고 늦은 응답은 요청 ID로 무시한다. 서버에 이미 저장된 초안을 삭제하거나 되돌리지 않는다. 초기화하면 새 conversationId를 사용한다. 같은 탭의 대화·카드·접수된 작업은 sessionStorage로 복원한다. 서버의 전체 대화 목록을 조회해 복원하는 기능과는 구분한다.

## 검증

- `npm.cmd run build`, `npm.cmd run lint`.
- `node scripts/check-chat-api.mjs`: 실제 프론트 서비스·Vite 프록시·REST API·임시 SQLite 경유. 상태 조회, 텍스트·단일 한글 파일·다중 파일, 원본 보존, 대화 ID, 확정 기록 미생성, 빈 입력·용량 조건, 취소, 서버 오류·잘못된 응답·연결 실패 확인.
- 실제 브라우저 클릭·시각 검증은 수행하지 않았다.
