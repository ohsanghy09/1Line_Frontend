# 텍스트 채팅 응답

최종 정리: 2026-11-04

## 현재 요청과 반환

홈은 getChatReply(message, [], options)로 POST /api/chat에 message·conversationId를 FormData로 보낸다. 텍스트 전용은 HTTP 201 동기 응답이며 서버 목 분석을 반환한다. 파일·링크 작업 조회와는 구분한다.

서버의 최종 응답에는 analysisId, conversationId, message, attachments, reply, createdAt, analysisProvider가 있다. 프론트는 reply를 검증한 뒤 분석·대화 ID를 붙여 Promise<ChatReply>로 반환한다. 카드 기록은 별도 POST /api/records를 호출한다.

홈 기본 목 응답은 변화 없음이다. 입력 의미에 따른 실제 활동 분류·자료 비교는 하지 않는다. 아래 변화 있음 예시는 /example과 응답 구조 설명에 사용하는 값이며 현재 모든 텍스트에 적용하는 응답이 아니다.

## 변화 있는 텍스트 카드 예시

```json
{
  "id": "reply-text-001",
  "role": "assistant",
  "kind": "text-analysis",
  "content": "1호선톤 활동 기록으로 보이네요. 기존 기획 기록과 비교했을 때 기능 범위를 축소한 중요한 변화가 확인됐어요.",
  "analysis": {
    "activity": {
      "name": "1호선톤",
      "confidence": "high"
    },
    "materialType": "사용자 경험 기록",
    "stage": null,
    "summary": "회의 피드백을 바탕으로 기능 6개를 핵심 기능 3개로 줄였어요.",
    "changes": [
      {
        "before": "기능 6개",
        "after": "핵심 기능 3개",
        "category": "기능 범위 변경 (MVP 최적화)",
        "evidence": ["사용자 직접 기록"]
      }
    ],
    "files": [],
    "groups": [],
    "suggestedSaveMode": "record-change"
  }
}
```

활동과 비교 내용은 목 값이다. 실제 분석에서는 전달받은 활동·기존 기록을 근거로 판단하며 근거가 없으면 비교했다고 단정하지 않는다.

## 화면용 구조

| 필드 | 의미 |
| --- | --- |
| id·role·kind | 응답 ID·assistant·카드 종류 |
| content | HTML이 아닌 일반 답변 문구 |
| analysis.activity | 활동명·선택적인 확신도 |
| analysis.materialType·stage | 자료 유형·활동 단계. 없는 단계는 null |
| analysis.summary | 분석 요약 |
| analysis.changes | before·after·category·evidence 목록. 없으면 빈 배열 |
| analysis.files·groups | 텍스트 예시에서는 빈 배열 |
| analysis.noChangeMessage | 변화 없음 안내의 선택 필드 |
| analysis.suggestedSaveMode | record-change/version-only/archive 저장 제안 |
| analysisId·conversationId | 프론트 서비스가 보관하는 서버 식별자 |
| recordId·activityId | 저장된 홈 카드의 세션 복원용 선택 필드 |

현재 서버 분석 응답은 analysis 객체를 제공한다. 인사·일반 질문의 analysis: null은 타입에는 있으나 현재 전송 API 검증 경로에서 받지 않는다. 이를 실제 서버에서 제공하려면 서비스 검증과 화면 계약을 함께 확장한다.

텍스트 카드의 요약은 현재 별도 라벨 영역이 없고 content와 변화 본문으로 표시한다. 저장 전 수정은 카드 상태, 저장 후 수정은 API를 사용한다. 저장 제안은 실제 저장 완료와 다르다.
