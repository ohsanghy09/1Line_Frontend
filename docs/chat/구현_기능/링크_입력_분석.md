# 링크 입력과 목 분석

2026-11-04 구현. 홈의 링크 버튼 → 원본 스타일 모달 → 링크 접수 REST API → 서버 목 진행 → 링크 결과 → 기록·수정 흐름을 연결했다.

## 사용

서버와 프론트를 함께 실행한 뒤 홈 입력창의 링크 아이콘을 누른다. URL을 입력하고 ‘분석’을 누르면 사용자 말풍선에 실제 URL을 표시하고 서버에 접수한다. 입력창에 작성 중인 글과 첨부 파일은 이때 전송하거나 지우지 않는다. 분석 완료 후 기존 카드의 활동에 기록·수정·다른 활동 선택을 사용할 수 있다.

원본 HTML의 링크 모달 배경·크기·간격·테두리·아이콘·필드·버튼 스타일을 Tailwind로 재현했다. 저장 확정은 결과 카드에서 별도로 하므로 원본의 ‘분석 및 저장’ 문구는 ‘분석’으로 표시한다. 네이티브 dialog로 초점 제한·복귀, Escape, 취소·X를 처리한다.

## 실제 값과 목 값

- 실제 값: 입력 URL(주변 공백 제거), 전송/응답 시각, 대화·분석·작업·저장 ID.
- 목 값: 예시 활동·자료 유형·요약·진행 단계. 결과에 실제 페이지를 읽은 내용이 아님을 명시한다.
- 외부 URL을 서버에서 열거나 크롤링하지 않는다. 로그인된 페이지·공유 권한 확인·실제 AI 분석도 하지 않는다.
- 링크 목 응답은 `changes: []`다. 근거 없는 Timeline 이벤트를 만들지 않는다.

## API와 저장

`POST /api/chat/links` JSON:

```json
{ "url": "https://github.com/example/project", "conversationId": "현재 대화 ID" }
```

URL은 최대 4096자, HTTP/HTTPS만 허용하며 사용자명·비밀번호가 포함된 주소는 받지 않는다. 클라이언트와 서버에서 검증한다. 형식 오류는 400이다. 실제 링크 접근 가능 여부는 검사하지 않는다.

사용자 요청으로 잘못된 URL의 안내는 브라우저 기본 팝업 대신 입력창 바로 아래에 표시한다. form의 noValidate로 기본 제출 검증 팝업을 끄고 기존 isHttpUrl 검증을 사용한다. 오류 문구는 ‘HTTP 또는 HTTPS 링크를 입력해 주세요.’이며 aria-invalid·aria-describedby·role=alert로 입력과 연결한다. 입력을 수정하면 오류를 지운다. 검증 실패 시 링크를 제출하지 않는다.

오류 안내 스타일: 입력창과 문구 사이 간격은 6px(`space-y-1.5`), 문구는 왼쪽에서 8px 들여쓰기(`pl-2`)하고 연한 빨간색(`text-red-400`)으로 표시한다. 오류 상태의 입력창 테두리는 `border-red-300`이며 초점이 있어도 같은 색을 유지한다. 입력을 수정해 오류가 지워지면 기본 테두리와 초점 색상으로 돌아간다. 입력 내용의 글자색은 변경하지 않았다.

응답은 HTTP 202의 작업 ID·첫 진행·`analysisProvider: mock`다. `GET /api/chat/jobs/:jobId`로 400ms마다 조회한다. 서버는 700ms 단위로 링크 확인 → 활동 분류 → 자료 유형 정리 → 결과 준비를 재현한다. 실제 처리 진행이 아닌 시간 기반 목 상태다.

완료 `result.reply`는 기존 `ChatReply`의 `kind: link-analysis`, 선택 필드 `sourceUrl`을 사용한다. 카드에 원본 링크·유형·목 요약을 표시한다. URL은 카드·세션·SQLite 분석 JSON·확정 기록 JSON에 남는다. DB 테이블 변경 없이 기존 analyses와 analysis_jobs를 재사용한다.

기록 전 수정은 카드에 반영하고 확정 요청의 활동·분류로 함께 저장한다. 기록 후 수정은 기존 PATCH를 사용한다. 양쪽 모두 원본 URL을 유지한다. 분석 진행 중에는 기록 확정을 막고 새 링크 중복 접수도 화면에서 막는다.

## 복원·오류

파일과 같은 작업 ID 보관·조회 재개를 사용한다. 새로고침·홈 재진입 시 기존 링크 작업을 조회하고 결과 중복을 방지한다. 완료된 링크 카드와 저장 ID도 세션에서 복원된다. 실패 시 작업 ID가 있으면 ‘진행 상태 다시 확인’을 사용한다. ID를 받기 전 실패한 링크는 링크 모달을 다시 열면 마지막 제출 URL을 확인할 수 있다. 제출 전 URL 초안은 새로고침 복원 대상이 아니다.

조회 취소·전체 30초 제한·네트워크 오류 처리는 기존 서비스를 따른다. 초기화는 화면과 세션을 비우며 서버에 이미 접수된 작업을 삭제하지 않는다. 일반 텍스트 입력창에 URL만 입력하면 현재는 텍스트 전송이며, 링크 분석은 링크 모달을 통해 접수한다.

## 검증과 실제 연결

링크 모달의 입력창 하단 오류 표시와 들여쓰기·오류 테두리·문구 색상 조정 후 `npm.cmd run build`, `npm.cmd run lint`가 통과했다. 실제 브라우저의 오류 제출·색상·초점 동작은 아직 확인하지 않았다. 아래 API/세션 검증은 이전 연동 단계의 결과이며 이번 스타일 변경 후 다시 실행한 결과는 아니다.

build/lint, 서버 테스트 4개, 세션 검사, 실제 프론트 서비스 → Vite 프록시 → API → SQLite 검증 통과. 잘못된 URL·프로토콜·인증 포함 URL·길이 거부, 접수 전 DB 미생성, 링크 진행·완료·재조회, 저장 전 분류 적용, 저장 후 수정과 URL 보존, 변화 이벤트 미생성, 세션 복원과 위험한 URL 거부를 확인했다. 브라우저 클릭·초점・픽셀 일치는 미검증이다.

실제 연결 시 서버의 목 링크 응답·시간 기반 진행을 링크 내용 수집과 AI 작업 상태로 교체한다. URL 수집 대상·리다이렉트·접근 권한·오류 계약을 정식 백엔드에서 정한다. 프론트 화면용 응답 구조를 유지하면 기존 기록·수정·조회 복원 흐름을 재사용할 수 있다.
