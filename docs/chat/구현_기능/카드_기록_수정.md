# 카드 기록 저장과 분류 수정

최종 정리: 2026-11-06. 홈과 `/example`에서 같은 `ConnectedChatReplyCard`를 사용한다. 분석은 목데이터이며 저장·수정은 실제 로컬 API다. 홈의 수정값·저장 ID·활동 ID는 [sessionStorage](채팅_세션_보관.md)에서 복원하고 `/example`은 페이지 메모리만 사용한다.

## 화면과 동작

- 텍스트: 활동에 기록 / 수정 / 다른 활동 선택.
- 링크: 활동에 기록 / 수정 / 다른 활동 선택.
- 단일 파일 변화 있음: 저장 / 수정.
- 단일 파일 변화 없음: 아카이브 저장 / 수정.
- 다중 파일: 전체 저장 / 자료 확인. 원본과 같이 수정 버튼을 추가하지 않았다.
- 모든 카드의 기록·저장·전체 저장은 활동 정보 확인 모달 없이 연결된 기존 활동에 새 기록을 추가한다. 기존 기록과 활동 전체 요약은 덮어쓰지 않는다. 저장 중 버튼을 막고 성공 후에만 저장 완료로 표시한다. 실패는 카드에 안내하며 다시 시도할 수 있다.
- 저장 직전 최신 활동 목록에서 사용자가 선택한 활동 ID 또는 분석 결과의 기존 활동 ID가 유효한지 확인한다. 이름으로 ID를 추측하지 않는다. 활동이 미확정·삭제된 경우 수정 버튼에서 기존 활동을 선택하도록 안내한다. 다중 파일은 수정 버튼을 추가하지 않고 연결 확인 오류만 안내한다. 기존 활동이 하나도 없으면 활동이 준비된 뒤 재시도하도록 안내하며 새 활동 생성 흐름은 아직 제공하지 않는다.
- 홈 카드의 저장 ID·수정값은 sessionStorage로 복원한다. `/example`은 화면 메모리에만 보관하므로 재진입 후 저장하면 별도 기록이 추가된다.
- 자료 확인은 `/archive` 이동이다. 해당 페이지도 현재 실제 DB를 조회한다.

## 수정 모달

텍스트·링크·단일 파일(변화 있음/없음)의 수정 버튼은 모두 `ActivityReviewModal`의 `classificationOnly` 분기를 사용한다. 기존 활동 선택과 자료 유형만 표시하며, 신규 활동 생성·활동명·유형·상태·역할·기간·활동 전체 요약·기존 정보 적용 체크박스는 표시하거나 전송하지 않는다. ‘다른 활동 선택’도 같은 분류 수정 모달을 연다. 다중 파일에는 수정 버튼을 추가하지 않는다.

기록·저장 버튼에서는 모달을 열지 않는다. 모달은 분류 수정에만 사용하며 네이티브 dialog와 portal, 내부 스크롤, 초점 제한·복귀와 Escape 처리를 유지한다. 취소·X는 반영 없이 닫고 요청 중에는 중복 제출과 닫기를 막는다. [활동 정보 응답·저장 계약](../api/활동_정보_응답_저장.md)의 신규 활동·메타정보 확장 API는 서버에 남아 있지만 현재 카드에서는 호출하지 않는다.

활동 목록은 `GET /api/activities`에서 받고, 자료 유형은 현재 카드 값으로 채운다. 원본과 달리 활동을 고정 목록으로 JSX에 넣지 않았다.

- 저장 전 수정: 카드 상태와 응답 JSON만 변경한다. 기록 버튼에서 함께 확정 저장한다.
- 저장 후 수정: 활동 ID와 자료 유형만 `PATCH /api/records/:id`로 보내고 응답으로 카드를 갱신한다. 활동 전체 메타정보는 수정하지 않는다.
- 활동 변경 시 활동을 언급하는 카드 본문도 갱신한다. 유형을 바꾸면 파일별 분류와 다중 분류 합계도 일치시킨다.

## 데이터와 API

2026-11-06 사용자 결정: 실제 연동에서는 AI 서비스가 신규/기존 활동을 판단하고 DB에 신규 활동을 생성하거나 기존 활동에 연결한다. 프론트는 별도 새 활동 생성 화면을 만들지 않고 생성/매칭된 활동 ID를 저장에 활용하는 방향이다. 상세 응답 필드·생성 시점과 기록 확정 저장의 관계는 미정이다. 위의 ‘새 활동 생성 흐름 미제공’은 현재 목 서버의 한계이며 프론트 신규 생성 UI의 구현 계획이 아니다.

`src/services/records.ts`에서 활동 목록, 저장, 수정을 호출하고 응답을 검증한다.

홈은 `{ activityId, analysisId, classification: { materialType } }`로 저장한다. 서버는 초안의 원본 파일 연결과 입력을 유지하고 확정할 분류를 적용한다. `/example`은 `{ activityId, reply, classification }`으로 카드 JSON을 저장한다. 예시 파일명이 실제 파일 원본을 생성하지 않는다.

다중 파일은 전체 파일 정보를 포함하는 분석 결과 하나를 기록으로 저장한다. 변화가 있으면 관련 Timeline 이벤트를 함께 만들고 없으면 만들지 않는다. 같은 초안 재저장은 409이며, 독립 카드 저장의 중복 방지는 현재 화면 내에서 제공한다.
