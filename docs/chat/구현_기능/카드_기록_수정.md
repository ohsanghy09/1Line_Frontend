# 카드 기록 저장과 분류 수정

최종 정리: 2026-11-04. 홈과 `/example`에서 같은 `ConnectedChatReplyCard`를 사용한다. 분석은 목데이터이며 저장·수정은 실제 로컬 API다. 홈의 수정값·저장 ID·활동 ID는 [sessionStorage](채팅_세션_보관.md)에서 복원하고 `/example`은 페이지 메모리만 사용한다.

## 화면과 동작

- 텍스트: 활동에 기록 / 수정 / 다른 활동 선택.
- 단일 파일 변화 있음: 저장 / 수정.
- 단일 파일 변화 없음: 아카이브 저장 / 수정.
- 다중 파일: 전체 저장 / 자료 확인. 원본과 같이 수정 버튼을 추가하지 않았다.
- 저장 버튼에서 활동 정보 확인 화면을 열고 확인 후 저장한다. 저장 중 버튼을 막고, 성공 후 저장 완료로 표시한다. 실패는 카드 또는 모달에 안내한다.
- 홈 카드의 저장 ID·수정값은 sessionStorage로 복원한다. `/example`은 화면 메모리에만 보관하므로 재진입 후 저장하면 별도 기록이 추가된다.
- 자료 확인은 `/archive` 이동이다. 해당 페이지도 현재 실제 DB를 조회한다.

## 수정 모달

기존 분류 수정 흐름을 `ActivityReviewModal`로 확장했다. 기존 활동 연결/새 활동 후보·자료 유형에 더해 유형·상태·역할·기간·활동 요약을 확인한다. 새 필드가 늘어 max-w-lg와 내부 스크롤을 사용한다. 네이티브 dialog를 portal로 열어 초점 제한·복귀와 Escape를 처리한다. 취소·X는 반영 없이 닫고 요청 중에는 중복 제출과 닫기를 막는다. [활동 정보 응답·저장 계약](../api/활동_정보_응답_저장.md) 참고.

활동 목록은 `GET /api/activities`에서 받고, 자료 유형은 현재 카드 값으로 채운다. 원본과 달리 활동을 고정 목록으로 JSX에 넣지 않았다.

- 저장 전 수정: 카드 상태와 응답 JSON만 변경한다. 기록 버튼에서 함께 확정 저장한다.
- 저장 후 수정: `PATCH /api/records/:id`로 DB를 수정한 뒤 응답으로 카드를 갱신한다.
- 활동 변경 시 활동을 언급하는 카드 본문도 갱신한다. 유형을 바꾸면 파일별 분류와 다중 분류 합계도 일치시킨다.

## 데이터와 API

`src/services/records.ts`에서 활동 목록, 저장, 수정을 호출하고 응답을 검증한다.

홈은 `{ activityId, analysisId, classification: { materialType } }`로 저장한다. 서버는 초안의 원본 파일 연결과 입력을 유지하고 확정할 분류를 적용한다. `/example`은 `{ activityId, reply, classification }`으로 카드 JSON을 저장한다. 예시 파일명이 실제 파일 원본을 생성하지 않는다.

다중 파일은 전체 파일 정보를 포함하는 분석 결과 하나를 기록으로 저장한다. 변화가 있으면 관련 Timeline 이벤트를 함께 만들고 없으면 만들지 않는다. 같은 초안 재저장은 409이며, 독립 카드 저장의 중복 방지는 현재 화면 내에서 제공한다.

## 코드 위치

- `ConnectedChatReplyCard.tsx`: 카드별 수정본·저장 ID·비동기 상태.
- `ActivityReviewModal.tsx`: 활동 후보·정보 확인과 분류 수정. 기존 `EditCategoryModal.tsx`는 현재 연결 카드에서 사용하지 않는다.
- `RecordButtons.tsx`: 원본 버튼 문구·크기와 상태.
- `ChatReplyCard`와 각 본문: 표시 및 동작 전달.
- `api-server/src/validation.js`, `app.js`: 확정 분류 검증·저장·수정.

## 검증과 남은 작업

build/lint, 서버 통합 테스트, 실제 프론트 서비스 → Vite 프록시 → API → SQLite 검증을 수행했다. 수정 전 분류의 확정 저장과 파일 연결 보존, 저장 후 활동·유형 수정, 기존 `/example` 목 카드 4종 저장과 변화 이벤트 개수를 확인했다. 브라우저 클릭·초점·픽셀 일치는 미검증이다.

활동 목록·아카이브 DB 조회와 세션 복원은 연결했다. 실제 AI와 Growth Journey는 남은 작업이다. 서버 실행은 [로컬 채팅 연결](../api/로컬_채팅_연결.md)을 참고한다.
