# 홈 응답 구분 및 활동 확인 저장

최신 정리: 2026-11-06. 개선계획 1단계 구현. 실제 모델 호출·브라우저 직접 검증은 대기다.

## 새 활동 판단 모달 제거 — 최신 후속 변경

사용자 요청으로 신규 활동 확인 모달 대신 카드의 두 선택으로 단순화했다. ‘새 활동으로 저장’은 AI가 제안한 이름·유형으로 활동과 이번 자료를 한 번에 저장한다. 역할·기간·활동 전체 요약은 사용자에게 입력받지 않고 null로 둔다. 전체 요약의 AI 종합 생성은 별도 후속 작업이다.

‘기존 활동에 연결’을 누르면 최신 활동 목록을 조회하고 같은 카드 안에 선택 목록을 펼친다. ‘선택한 활동에 저장’을 눌러야 실제 기록이 생성된다. 목록을 펼치거나 선택만 하거나 취소하면 활동·기록을 생성하지 않는다. 기존 활동이 없으면 빈 목록 안내와 새 활동 저장 선택을 유지한다. 미확정 활동은 임의의 이름으로 생성하지 않고 기존 활동 연결만 제공한다.

신규 제안에는 수정 모달 버튼을 표시하지 않는다. 이미 연결했거나 저장한 기록의 기존 활동·자료 유형 수정 모달은 유지한다. 신규 저장 실패·이름 충돌 시 제안을 유지하고 오류를 표시하며 기존 활동을 선택할 수 있다. 중복 요청 방지·원본 연결·저장 성공 후 표시·서버 트랜잭션은 기존 계약을 유지한다.

이번 변경 검사: build·lint 통과(기존 경고 3개), 백엔드 실제 AI 저장 계약 2개·프론트 서비스 회귀 검사 통과. 브라우저 직접 조작·모바일·초점 검증은 아직 하지 않았다.

## 텍스트 대기 표시·한 번 요청·경량 모델 — 후속 변경

파일 없는 텍스트는 일반 대화인지 경험 기록인지 사전 분류용 모델을 추가 호출하지 않는다. 점 세 개 말풍선으로 기다리며 `Prefer: respond-sync`를 사용한 POST `/api/chat` 한 번에서 최종 completed/failed 응답(HTTP 200)을 받는다. 일반 대화/분석 판단과 답변은 같은 모델 호출에서 처리한다. 텍스트에는 서버 진행 제목·단계 표시와 자동 GET 폴링이 없다. 완료되지 않은 동기 응답을 받으면 서버 갱신 안내를 표시하고 추가 조회·유료 재전송을 자동 실행하지 않는다.

파일·링크는 기존 비동기 접수·진행 조회를 유지하며 조회 자체는 모델을 호출하지 않는다. 같은 requestId 재접수는 진행 중 작업을 공유하거나 기존 결과를 반환한다. 모델 SDK 자동 재시도도 0이다. 텍스트 HTTP 대기는 150초, 모델 제한 시간은 기존 서버 설정을 따른다. 응답 전 탭 이탈·통신 실패 시 작업이 서버에서 완료될 수 있으나 텍스트는 접수 즉시 작업 ID를 받지 않으므로 자동 복구가 보장되지 않는다. 응답을 받은 작업 ID의 수동 복원과 파일·링크 작업 복원은 유지한다. 사용자 새로고침·재전송을 새로운 모델 요청으로 취급할 수 있으므로 자동 재전송은 하지 않는다.

로컬 `.env`의 OPENAI_MODEL과 `.env.example`을 `gpt-5.4-mini`로 변경했다. API 키는 보존하고 출력하지 않았다. OPENAI_MODEL은 홈과 Journey의 공용 설정이며 AI 서버 재시작 후 적용된다. reasoning.effort=low는 유지한다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini)의 Responses API·이미지 입력·Structured Outputs·low 지원을 확인했고 현재 키의 모델 접근은 모델 메타정보 조회로 확인했다. 모델 실제 생성·분석 품질은 이번에 검증하지 않았다.

후속 검사: Python 46개·프론트 서비스/세션·build 통과, lint 기존 경고 3개. 텍스트 HTTP POST 1회·진행 콜백 0회, 서버 모델 처리 1회·동일 요청 중복 호출 방지·성공/실패 완료 응답을 합성 검사했다. 브라우저 직접 검증·실제 모델 분석 호출은 미수행이다.

## 현재 흐름

`입력 → AI 일반 대화/분석 판단 → 말풍선 또는 제안 카드 → 사용자 확인 → 활동·기록 저장`

- 일반 대화는 kind=general, analysis=null로 표시하며 저장 버튼이 없다. 일반 질문·인사 때문에 활동·기록을 생성하지 않는다.
- 신규 활동은 match=new, id=null인 제안으로 유지한다. 분석 완료 시 활동 INSERT를 하지 않는다.
- 신규·미확정 활동은 변화 배열·파일 개수보다 우선해서 활동 확인 카드를 표시한다. 새 활동의 첫 파일을 변화 없음 카드로 표시하지 않는다. 다중 파일·링크에도 같은 우선순위를 적용한다.
- 신규 제안에서 ‘새 활동으로 저장’을 누르면 제안명·유형으로 바로 저장한다. ‘기존 활동에 연결’은 카드 안의 선택 목록을 펼친다. 미확정 활동은 기존 활동을 선택한다.
- 카드의 명시적 저장에서 실제 `analysisId`와 `newActivity` 또는 `activityId`를 백엔드로 보낸다. 기존 활동의 일반 저장·분류 수정은 유지한다.
- 아무 동작을 하지 않거나 기존 활동 선택을 취소하면 제안 상태이며 실제 활동·기록은 생성하지 않는다. 선택 목록의 펼침 상태는 새로고침 후 초기화하지만 제안 카드와 원본 연결은 세션에서 유지한다.
- 저장 성공 후에만 저장 완료를 표시한다. `activityCreated`는 신규 활동으로 확정한 카드의 표시를 유지하며 기록 응답·세션에도 보관한다. 다른 활동으로 이동하면 해제한다.

## 서버 계약 및 보관 범위

모델 출력 `HomeResponse`는 `kind`(general/analysis), `content`(짧은 안내), `analysis`(분석 또는 null)다. 일반 대화에는 분석을 넣지 않고 분석 응답에는 반드시 분석을 제공한다. 파일·링크가 있는데 모델이 일반 대화만 반환하면 잘못된 응답으로 거절한다. 기존 활동 ID·첨부 ID·인용 근거 검증은 유지한다.

프론트의 분석 카드 kind는 기존 파일/텍스트/링크 구조를 유지한다. 활동 신규·미확정 여부는 `analysis.activity.match`로 먼저 판단하며 changes=[]만으로 신규 활동을 판단하지 않는다. 일반 응답은 kind=general, analysis=null이다.

AI 작업 처리·재조회와 대화 보관을 위해 일반 대화에도 analyses/ai_chat_jobs 행은 남는다. 활동·확정 기록·타임라인 생성과는 별개다. 일반 대화의 과거 대화 내용을 누적해서 모델에 전달하는 기능은 이번 단계에 추가하지 않았다.

원본 파일·분석 초안은 사용자 저장 전에도 기존 방식으로 보관한다. 미저장 제안 보관 기간·자동 정리 정책은 추가하지 않았다. 기존 활동도 분석만으로 메타정보를 바꾸지 않는다. 기존 유형은 보존하고 미분류의 AI 유형 후보는 사용자 저장에서 반영할 수 있다.

백엔드 POST `/api/records`는 신규 활동과 기록을 같은 트랜잭션에서 만든다. 같은 이름 충돌·동일 분석 중복 저장은 409이며 일반 대화 초안의 기록 저장은 거절한다. 확인 입력의 활동 유형은 200자 이내이며 `all`/`전체`를 허용하지 않는다. 원본 연결은 실제 analysisId로 유지한다. 일반 대화를 저장 가능한 분석으로 위장하는 프론트 전환은 제공하지 않는다.

홈 프롬프트에는 일반 대화/분석 구분, 새 활동 제안 표현, content와 summary 분리, 해요체 안내를 추가했다. Journey 말투 및 기존 모든 카드 제목 정리는 다음 단계다. AI 응답이 실제로 부드러운지와 분류 정확도는 실제 모델 확인이 필요하다.

## 검증 결과

- Python unittest 44개 통과: 신규 제안 미생성·일반 대화·유형 제안 시 DB 보존·잘못된 첨부 응답 거절 포함.
- 백엔드 30개 통과: 실제 AI 완료 초안의 신규 확정 저장·원본 유지·이름 충돌·중복 저장·일반 대화 저장 거절 포함.
- `check-chat-api` 통과: 서비스·Vite 프록시·SQLite·일반 응답 검증·오류/취소. 폴링이 중간 단계를 건너뛸 수 있어 진행 검사는 순서와 유효 범위로 확인하고 정확한 단계 경계는 백엔드 검사에 맡긴다.
- `check-chat-session` 통과: 신규 후보·일반 말풍선·신규 확정 카드 표시 복원 포함.
- build 통과, lint 오류 없음·기존 경고 3개. OpenAPI 내보내기·정적 Swagger 재생성 완료.
- 실제 모델용 `check-live-ai`도 제안 → 사용자 확정 흐름으로 수정했지만 실행하지 않았다. 이번 검사에서 실제 공유 DB를 초기화하거나 유료 모델을 호출하지 않았다.

## 남은 확인

빈 활동 목록에서 신규 텍스트·첫 파일·다중 파일·링크를 입력하고 제안 표시 → 새 활동 저장 또는 기존 활동 목록 펼침·선택·취소·저장을 브라우저에서 확인한다. 카드 안의 키보드 이동·취소 시 초점 복귀·모바일·저장 오류 후 재시도도 확인한다. 저장 전 세션 보존과 같은 이름의 제안이 연속 발생할 때 기존 활동 선택을 확인한다. 기존 기록의 분류 수정 모달은 별도로 확인한다.

Journey 분야·활동 전체 요약·기간·역할 자동 분석·개별 삭제·자동 분석은 이번 범위에 포함하지 않는다. [전체 개선계획](../../integration/사용자_확인_기반_기록_및_활동_관리_개선계획.md)의 후속 범위를 따른다.
