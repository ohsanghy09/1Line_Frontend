# 파일 업로드 분석

최종 정리: 2026-11-04

## 전송·진행

파일을 선택하거나 입력창·첨부 영역에 드롭한 뒤 보내기/Enter로 전송한다. 파일만 또는 텍스트와 함께 보낼 수 있다. 선택만으로 분석하지 않는다. 전송 시 입력과 전송 전 첨부 목록을 비운다.

FormData로 실제 원본과 이름을 REST API에 보관한다. 업로드 접수 전에는 점 3개를 표시하고, 접수된 작업 ID로 진행을 조회한다. 서버의 목 단계가 바뀌면 진행 카드를 갱신하고 최종 결과로 전환한다. 단일·다중 파일 모두 적용한다. [진행 API](../api/파일_분석_진행.md)에 시간·계약을 정리했다.

## 카드와 저장

단일 파일의 변화가 있으면 파일명·변화 개수·활동/자료 유형/단계/관련 자료·요약·Before/After를 표시한다. 변화가 없으면 [전용 본문](변화_없는_파일.md)을 표시한다. 다중 파일은 유형별 개수와 전체 저장·자료 확인을 표시한다.

이름으로 카드 종류를 예외 처리하지 않고 서버의 kind와 변화 배열로 선택한다. 홈의 기본 목 모드는 변화 없음이다. 실제 파일 내용 분석은 하지 않으며 임의의 이전 파일을 연결하지 않는다.

저장·수정은 [공통 카드 API 흐름](카드_기록_수정.md)을 사용한다. 새로고침 시 접수된 작업을 재조회하며 원본을 재업로드하지 않는다. 작업 ID를 받기 전 중단된 요청은 자동 복원하지 않는다.

## 위치·검증

Home, services/chat.ts, FileAnalysisProgress, FileAnalysisContent, NoChangeAnalysisContent, BatchAnalysisContent와 api-server의 app.js/mock-reply.js/progress.js가 담당한다.

build/lint와 API 통합 검사에서 원본·한글 파일명·단일/다중 결과·진행·조회 재개·저장 연결을 확인했다. 브라우저에서 좁은 화면·긴 파일명·초기화·업로드 조작은 직접 검증하지 않았다.
