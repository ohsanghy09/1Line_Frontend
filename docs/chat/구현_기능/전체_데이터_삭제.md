# 사용자 설정 · 전체 데이터 삭제

최신 정리: 2026-11-06.

## 현재 동작

사용자 프로필 오른쪽 톱니바퀴로 설정 모달을 연다. 삭제 범위·복구 불가 안내와 확인 입력을 표시한다. 삭제 버튼 클릭 또는 Enter 시 `전체 삭제`를 검증한다. 비어 있거나 잘못 입력했다면 연한 빨간색 테두리와 입력창 하단 오류 문구를 표시하고 입력창으로 초점을 이동하며 API를 호출하지 않는다. 입력을 수정하면 오류를 해제한다. 삭제 중에는 중복 요청·모달 닫기를 막는다. 실패하면 오류를 표시하고 다시 시도할 수 있다. 성공 후 현재 탭의 홈 채팅 세션만 제거하고 완료 안내의 ‘홈으로 이동’에서 페이지를 새로 로드해 빈 데이터를 조회한다. 다른 탭의 sessionStorage는 지우지 않는다.

## API와 데이터 범위

`POST /api/settings/reset-data`에 JSON `{ "confirmation": "전체 삭제" }`를 전송한다. 성공 응답은 `{ "deleted": true }`다. 입력 불일치는 400, 홈 작업 queued/running 또는 같은 백엔드의 Journey 분석 진행 중이면 409다.

한 트랜잭션에서 timeline_events, records, files, analysis_jobs, ai_chat_jobs, journey_analyses, analyses, activities의 모든 행을 삭제한다. 업로드 원본 BLOB도 포함하며 스키마·환경 설정은 보존한다. 중간 실패 시 모두 롤백한다. 빈 DB에서 재실행해도 성공한다. 현재는 인증 없는 로컬 개발의 공유 DB 전체가 대상이며 사용자별 삭제 기능은 아니다. 별도 호스트·여러 백엔드 간 Journey 실행 잠금은 후속 범위다.

## 코드와 검증

- UI: `src/components/Sidebar.tsx`, `src/components/SettingsModal.tsx`
- 서비스: `src/services/settings.ts`
- API: `api-server/src/app.js`, 명세 `api-server/docs/openapi.js`
- 검사: `api-server/test/settings.test.js`. 메모리 DB에서 확인 문구·진행 작업 거절·8개 테이블 삭제·외래 키 유지·실패 롤백·반복 삭제를 검증했다.
- 빌드 및 백엔드 29개 검사 통과. lint 오류 없음, 기존 경고 3개. 브라우저 직접 조작·초점·모바일 검증은 미수행이다.
- 구현 과정에서 실제 공유 DB 삭제 API는 호출하지 않았다.
