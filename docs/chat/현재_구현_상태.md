# 홈 채팅 현재 구현 상태

최종 정리: 2026-11-04

현재 상태를 확인할 때 이 문서를 먼저 읽는다. 기능·API 문서는 현재 동작을 설명하고 날짜별 이력은 개발 기록에서 관리한다. 이 문서는 현재 코드와 이번 대화에서 수행한 검사 기준이다.

채팅 문서는 docs/chat, 전용 컴포넌트는 src/components/chat, 모달은 그 아래 modals에 모았다. [폴더 안내](README.md)를 참고한다.

## 구현과 연결 범위

최신 변경: 변화 없음 단일 파일 카드에서는 아카이브 저장을 누르면 연결된 기존 활동으로 바로 저장한다. 수정 모달은 활동·자료 유형만 변경한다. 활동 전체 메타정보 확인/편집은 이 카드에서 제외하며, 다른 카드는 기존 흐름을 유지한다. [변화 없는 파일](구현_기능/변화_없는_파일.md) 참고.

## 목 데이터와 실제 데이터

현재 홈은 `src/services/chat.ts`·`records.ts`를 통해 `api-server/`를 호출한다. 서버의 `mock-reply.js`가 분석 예시를 생성하고 `progress.js`가 목 진행을 계산한다. `src/mocks/Home/`의 기존 예시는 `/example` 등의 개발용 데이터이며 홈 전송의 분석 설정을 제어하지 않는다.

실제 값은 입력 텍스트·파일 원본·파일명·URL·시각·작업/분석/기록 ID다. 활동 분류·자료 유형·요약·변화 내용은 목 값이다. 실제 문서 내용 추출·웹페이지 수집·기존 자료 비교·AI 호출은 하지 않는다. 일반 홈 전송은 변화 없음 목 응답을 사용한다. 서버의 변화 있음 모드나 `/example`의 변화 카드로 변화 이벤트 저장 흐름을 검증할 수 있다.

서버 SQLite에는 초안·파일·기록·작업이 저장된다. sessionStorage는 화면 복원을 담당하며 서버 DB 저장을 없애지 않았다. 브라우저를 닫아도 서버 DB 기록은 남는다. 브라우저의 닫은 탭/세션 복원 기능으로 sessionStorage가 복원될 수도 있다.

## 남은 작업과 한계

- 실제 백엔드·AI 서버의 인증·요청·응답·작업 상태 계약 적용. [전환 가이드](api/실제_서버_전환_가이드.md) 참고.
- 실제 AI 분류·요약·비교·변화와 Turning Point 판단. 현재 이벤트의 Turning Point 값은 false다.
- 아카이브·Timeline 화면은 [나의 발자국 DB 연동](../footprints/DB_연동.md)으로 실제 확정 기록 조회를 연결했다. Growth Journey 반영은 남은 작업이다. 다중 카드의 자료 확인은 `/archive` 이동이다.
- 작업 ID를 받기 전 중단된 업로드/동기 텍스트 요청은 자동 복원하지 않는다.
- 저장 전 File 객체·미전송 글·열린 모달은 세션 보관 대상이 아니다.
- `/example`은 재진입 시 저장 상태를 복원하지 않아 다시 저장하면 새 기록이 생길 수 있다.
- 인증·사용자별 접근 제어·운영 배포·삭제 정책은 개발용 서버 범위 밖이다.

현재까지 요청한 홈 채팅 UI 흐름을 구현한 상태이며, 기능명세 전체 또는 다른 화면까지 완료했다는 의미는 아니다.

## 검증 상태

이번 대화에서 다음 검사가 통과했다.

- `npm.cmd run build`, `npm.cmd run lint`
- `api-server`의 `npm.cmd test`: 현재 서버 테스트 12개
- `node scripts/check-chat-api.mjs`: 실제 프론트 서비스 → Vite 프록시 → REST API → 임시 SQLite
- `node scripts/check-chat-session.mjs`: 세션 검증·복원·초기화·저장 오류·카드 중복 방지

업로드·링크·진행·조회 재개·저장·수정·URL/파일 연결 보존·오류 응답·DB 유지 등을 검사했다. 브라우저에서 실제 클릭·새로고침·초점·좁은 화면·픽셀 일치를 확인한 것은 아니다. 실제 AI·운영 서버 연동 검증도 하지 않았다.

문서와 미사용 색상 정리 후 build/lint를 다시 확인했다. API·세션 검증 결과는 앞선 구현 작업에서 수행한 검사다. 브라우저 직접 검증을 대체하지 않는다.
