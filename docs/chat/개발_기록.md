# 개발 기록 · 홈 AI 채팅

## 2026-11-06 채팅 수정의 최근 활동 시각·정렬 반영

대화로 활동 정보를 직접 수정한 경우 같은 트랜잭션에서 activities.updated_at도 수정 완료 시각으로 갱신한다. 홈 최근 활동과 발자국 최근 업데이트 정렬이 함께 바뀐다. 새 자료·기록을 만들거나 기존 자료의 저장 시각을 변경하지 않으며 중복 재조회와 거절된 수정은 시각을 유지한다. 관련 백엔드 검사 6개 통과. 실제 사용자 DB를 검사 목적으로 수정하지 않았다.

## 2026-11-06 입력 채팅의 참고 자료·최근 자료 전환 제거

실제 DB에서 활동 전체 요약 작성 요청이 text-analysis/참고 자료로 저장된 것을 읽기 전용 확인했다. 원본 없는 채팅 본문을 가상 자료로 만들던 아카이브 분기를 제거하고 실제 파일·명시적 링크만 자료로 집계한다. 기존 행 삭제 없이 채팅 자료 표시를 제외하며 확정 경험 검색·분석은 보존한다. 요약 작성 요청을 summary 수정/일반 안내로 구분하도록 프롬프트를 보완했다. 백엔드 39개·직접 build 통과, lint 기존 경고 3개. [상세 기준](../footprints/채팅_자료_제외.md)을 따른다.

## 2026-11-06 대화로 활동 정보 직접 수정

‘역할을 팀장으로 바꿔줘’처럼 말하면 홈 AI가 수정 대상·항목을 해석하고 백엔드가 해당 필드만 직접 변경한다. 새 정정 기록·타임라인·확인 모달은 없다. 최근 완료 대화를 참고하고 대상이 모호하면 질문하도록 구성했다. 적용 결과를 일반 말풍선으로 저장해 재조회 시 중복 적용을 막는다. 이전 자동 분석은 무효화하지만 이후 자료 저장의 AI 갱신은 허용한다. Python 53개·백엔드 39개(Swagger 제외)·서비스/세션·직접 빌드 통과. 실제 모델·브라우저 확인은 대기다. [상세 기능](구현_기능/대화로_활동_정보_수정.md)을 따른다.

## 2026-11-06 확정 저장 후 활동 전체 정보 AI 갱신

자료 저장 뒤 활동 전체 요약·상태·기간·역할을 자동 종합한다. 같은 활동의 연속 저장은 묶고, 기록 수정·이동은 관련 활동을 갱신한다. 활동별 근거와 해시를 검증하며 실패해도 자료와 기존 정보는 유지한다. 홈 저장 카드·상세에 상태/재시도를 연결했다. Python 50개·백엔드 35개(Swagger 제외)·프론트 서비스/세션·직접 build 통과, lint 기존 경고 3개. 실제 모델·브라우저 확인은 대기다. Swagger는 사용자 요청으로 갱신하지 않았다. [기능 기록](../footprints/활동_정보_AI_갱신.md) 참고.

## 2026-11-06 새 활동 추가 판단을 카드로 단순화

새 활동 확인 모달을 제거하고 제안 카드에 ‘새 활동으로 저장’과 ‘기존 활동에 연결’을 표시한다. 전자는 제안명·유형으로 활동·자료를 바로 저장하고 후자는 카드 안의 목록에서 선택 후 저장한다. 새 활동 추가 시 전체 요약·기간·역할 입력란은 노출하지 않는다. 미확정은 기존 활동 연결, 저장된 기록은 기존 수정 모달을 유지한다. build·lint(기존 경고 3개)·백엔드 저장 계약 2개 통과. 실제 모델·브라우저 확인은 대기다. [현재 기능](구현_기능/홈_응답_구분_및_활동_확인_저장.md) 참고.

## 2026-11-06 텍스트 점 세 개 대기·동기 요청·경량 모델

파일 없는 텍스트는 단계 표시 없이 점 세 개로 기다리고 `Prefer: respond-sync`인 POST 한 번으로 최종 결과를 받는다. 일반 대화 여부 판단도 같은 모델 호출에 포함한다. 파일·링크 비동기 처리는 유지했다. 공용 OPENAI_MODEL은 `gpt-5.4-mini`로 변경하고 메타정보 조회로 접근 권한을 확인했다. Python 46개·서비스/세션·build 통과, lint 기존 경고 3개. 실제 모델 생성·브라우저 확인은 미수행이다. [상세 기록](구현_기능/홈_응답_구분_및_활동_확인_저장.md)을 따른다.

## 2026-11-06 홈 응답 구분 및 활동 확인 저장

개선계획 1단계를 구현했다. 실제 홈 응답을 일반 대화/분석으로 구분하고 새 활동은 match=new, id=null 제안으로 남긴다. 신규·미확정 제안 카드를 우선 표시하고 사용자 확인 모달에서 새 활동 생성 또는 기존 활동 연결을 확정한다. 분석만으로 기존 활동 메타정보도 수정하지 않는다. 홈 안내 해요체와 짧은 응답 안내를 프롬프트에 추가했다. Python 44개·백엔드 30개·프론트 서비스/세션·build 통과, lint는 기존 경고 3개다. 실제 모델·브라우저 확인은 미수행이다. [기능 기록](구현_기능/홈_응답_구분_및_활동_확인_저장.md) 참고.

## 2026-11-06 전체 삭제 확인 입력 오류 표시

확인 문구가 비어 있거나 틀린 상태에서도 삭제 버튼으로 검증할 수 있도록 수정했다. 잘못된 문구에는 연한 빨간색 테두리와 입력창 하단 오류 안내를 표시하고 초점을 돌려준다. 실제 삭제 API는 정확한 문구에만 호출하며 입력 수정 시 오류를 해제한다.

## 2026-11-06 사용자 설정 전체 데이터 삭제

프로필 톱니바퀴에 설정 모달을 연결했다. `전체 삭제` 확인 입력 후 백엔드가 8개 테이블을 트랜잭션으로 비우고, 성공 시 현재 탭의 채팅 세션을 정리한다. 홈·Journey 분석 중에는 삭제를 거절한다. 메모리 DB 검사 포함 백엔드 29개·빌드 통과, lint는 기존 경고 3개다. 실제 공유 DB 삭제·브라우저 조작 검증은 하지 않았다. [상세 기능](구현_기능/전체_데이터_삭제.md)을 따른다.

## 2026-11-06 서버 시작 시 예시 활동 생성 제거

DB 초기화 뒤 백엔드의 자동 재시작으로 활동 5개가 다시 표시되는 원인을 제거했다. 실행 DB 초기화는 이제 스키마·마이그레이션만 수행하고 예시 활동을 넣지 않는다. 기존 검사 준비 데이터는 메모리·임시 DB 전용 `api-server/test-support/database.js`로 분리했다. 재등장한 미연결 예시 5개를 실제 DB에서 삭제하고 활동·기록 0개를 확인했다. 신규 DB·사용자 활동 보존·전체 활동 삭제 후 재오픈 검사를 추가해 재발 방지를 확인했다.

## 2026-11-06 Journey 분석 분류·아이콘

사용자 요청으로 고정 성장 유형 enum을 제거하고 모델의 `typeOptions(value, label, icon)`와 이벤트 참조로 교체했다. 같은 분류의 이모지를 필터·이벤트 배지에 표시하고 경험 배지에도 `icon`을 분리해 표시한다. 분야 기준은 유지했다. 중복·미등록·미사용 분류와 누락 아이콘을 검증하고 과거 무아이콘 저장 결과의 조회를 보존했다. 프롬프트 버전은 journey-v2다. [Journey API](../journey/성장_분석_API.md) 참고.

## 2026-11-06 Growth Journey 실제 AI·DB 연동

Journey 목 공급자를 실행 코드에서 제거하고 확정 기록 문맥·전용 프롬프트·실제 OpenAI·근거 검증·백엔드 결과 저장/조회·화면 분석/갱신을 연결했다. 원본 스냅샷 비교로 분석 중 변경을 거절하고 수정 후 stale을 표시한다. 홈 기록·Timeline은 변경하지 않는다. 자세한 현재 동작·검증·한도는 [Journey API](../journey/성장_분석_API.md)의 최신 절을 따른다. 실제 모델 통합 검사는 임시 DB로 통과했고 브라우저 전체 조작 검사는 별도다.

## 2026-11-06 홈 AI 목 실행 코드 제거·실제 연동 재검증

홈의 사용하지 않는 목 응답 서비스·파일 분류·진행·상태 예시와 `/example`의 가짜 분석 카드를 제거했다. `/example`은 실제 홈으로 이동한다. 백엔드 목 분석 생성·시간 기반 진행은 실행 코드에서 제거했고 기존 분석 POST·작업 GET은 항상 410으로 FastAPI를 안내한다. 회귀 검사에 필요한 합성 응답은 `api-server/test-support/`, `tests/fixtures/`로 옮겨 실행 앱에서 참조하지 않는다. Swagger 예시는 문서 전용 JSON이다. Growth Journey의 목 응답은 이번 홈 채팅 범위에서 변경하지 않았다.

`check-live-ai.mjs --extended`로 실제 OpenAI 텍스트·단일 파일·다중 파일·공개 링크 분석, 활동 생성/연결, 초안 복원, 저장·중복 방지·분류 수정, 아카이브·원본 다운로드를 통과했다. 임시 DB를 사용했으며 기존 사용자 기록은 변경하지 않았다. 빌드·lint(기존 경고 3개)·채팅 서비스/세션 회귀 검사를 통과했다. 브라우저의 직접 입력·클릭 검증과 PDF/Office/이미지 품질 검사는 별도다.

## 2026-11-06 연결 진단·확정 실패 작업 해제

실제 AI 서버의 HTTPS 진단을 GET `/api/chat/health?checkConnection=true`로 추가했다. 키 없는 도달 검사와 모델 호출을 구분하고 네트워크 권한·TLS·DNS 실패 코드를 제공한다. 프론트는 확정 실패 작업을 대기에서 해제해 다음 입력을 허용하며, 통신 실패·시간 초과는 기존 재조회 상태를 유지한다. 기존 대화·기록을 삭제하거나 자동으로 유료 재호출하지 않는다. 실제 실행 서버의 연결과 저장 없는 합성 모델 호출 HTTP 200 확인, Python 32개·프론트 실패/세션 검사·build 통과, lint 기존 경고 3개. [상세 진단 기록](../../ai-api-server/docs/홈_실제_AI_연동.md) 참고.

## 2026-11-06 홈 실제 OpenAI 분석 전환

텍스트·단일/다중 파일·링크 분석을 프론트→FastAPI→OpenAI gpt-5.6-sol로 전환했다. AI 서버가 DB 문맥과 실제 자료를 분석하고 신규 활동 생성·분석/원본 보관을 처리한다. 기록 확정 저장·수정·아카이브 조회는 기존 백엔드를 사용한다. ai_chat_jobs에 실제 단계·중복 요청·실패를 보관하고 이전 백엔드 분석 접수는 기본 410이다. 프롬프트를 별도 파일로 관리하고 FastAPI OpenAPI를 정적 Swagger에 반영했다.

실제 모델을 사용한 텍스트·파일·다중 파일·공개 링크→저장·조회·다운로드 통합 검사를 임시 DB에서 통과했다. 브라우저 조작·추가 파일 형식 품질·Growth Journey 실제 분석은 후속이다. [최신 구현과 검증 범위](../../ai-api-server/docs/홈_실제_AI_연동.md)를 따른다.

## 2026-11-06 기록·저장 확인 모달 제거

모든 카드의 기록·저장·전체 저장에서 확장 활동 정보 모달을 제거했다. 저장 직전 최신 활동 목록으로 선택한 활동 ID 또는 분석의 기존 활동 ID를 검증하고 기존 저장 서비스를 호출한다. 이름으로 ID를 추측하지 않으며 새 활동 생성·활동 메타정보 수정은 요청하지 않는다. 수정 전용 모달, 원본 파일·분류 연결, 저장 잠금과 실패 재시도·성공 후 표시를 유지했다. 기존 활동이 없거나 삭제됐을 때는 저장을 막고 안내한다. 다중 파일 버튼은 유지하며 새 활동 생성 진입은 후속 작업이다.
