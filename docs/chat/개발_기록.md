# 개발 기록 · 홈 AI 채팅

## 2026-11-04 링크 입력 오류 위치·스타일 조정

잘못된 링크 입력 시 브라우저 기본 검증 팝업 대신 입력창 바로 아래에 오류를 표시한다. 문구는 오른쪽으로 8px 들여쓰고 연한 빨간색(text-red-400), 입력창 오류 테두리는 연한 빨간색(border-red-300)으로 조정했다. 입력을 수정하면 오류를 지우고 기본 테두리로 복귀한다. 기존 HTTP/HTTPS·길이·인증정보 검증과 오류 접근성 연결을 유지했다. build/lint 통과, 실제 브라우저 조작은 미검증이다. [현재 동작](구현_기능/링크_입력_분석.md) 참고.

최종 정리: 2026-11-04

현재 기능·목 응답·실제 API 연결·남은 작업은 [현재 구현 상태](현재_구현_상태.md)를 기준으로 확인한다. 이 문서는 변경 이력만 기록한다.

## 2026-11-04 변화 없음 카드 저장·수정 범위 조정

사용자 요청으로 변화 없음 단일 파일 카드의 아카이브 저장 전 활동 정보 확인 모달을 제거했다. 연결된 기존 활동에 즉시 저장하며, 수정 모달은 활동 선택·자료 유형만 제공한다. 활동 상태·역할·기간·활동 전체 요약과 새 활동 생성은 이 카드의 수정 범위에서 제외했다. 연결할 활동이 없으면 수정 버튼에서 선택하도록 안내한다. 다른 카드의 확인 모달은 유지했다. [현재 동작](구현_기능/변화_없는_파일.md) 참고.

build/lint, `node scripts/check-chat-api.mjs`, `node scripts/check-chat-session.mjs`가 통과했다. API 검사는 임시 메모리 DB를 사용한다. 이번 모달과 바로 저장 버튼의 실제 브라우저 조작은 아직 검증하지 않았다.

## 2026-11-04 홈 최근 목록 DB 연동

최근 활동과 최근 추가된 기록의 목 배열을 GET /api/home/recent로 교체했다. 활동 변경 시각과 최초 자료 저장 시각을 구분하고 각각 최대 3개를 표시한다. 저장·수정 이벤트에서 재조회하고 활동 상세·자료 Drawer에 실제 ID로 연결한다. 활동 이동은 양쪽 활동 시각을 함께 갱신한다. 활동 변경 시각 컬럼은 기존 DB를 보존하고 실제 과거 기록 시각으로 이관한다. [현재 동작과 검증](구현_기능/최근_활동_기록.md) 참고. 이번 홈 변경의 브라우저 확인은 수행하지 않았다.

## 2026-11-04 활동 정보 응답·확인 저장 확장

활동 응답에 기존/신규/미확인 구분·ID와 nullable 유형·상태·역할·기간·활동 요약을 추가했다. 기존 활동 문맥을 공급자 경계에 전달하고 서버·프론트에서 검증한다. 현재 목 분석은 새 값을 추출하지 않고 null로 반환한다. 카드의 저장·수정에 활동 정보 확인 화면을 연결했다. 확인한 새 활동 생성과 기록·이벤트 저장은 원자적으로 처리하고, 기존 정보는 명시적 적용만 허용하며 null은 유지한다. 날짜 컬럼은 기존 DB를 보존해 추가했다. [응답·저장 계약](api/활동_정보_응답_저장.md) 참고.

build/lint, 서버 테스트 10개, 프론트 서비스→Vite→API→임시 DB 검사, 기존 채팅 API·세션 검사를 수행했다. 실제 AI 호출과 브라우저 확인은 완료로 기록하지 않는다.

## 2026-11-04 구현 가이드 통합

사용자 요청으로 기존 가이드 전체를 확인했다. 라우팅·데이터 ID·React 렌더링·접근성·시각 검증 원칙은 [개발 규칙](../개발_규칙.md)에, 미구현 화면의 유효한 원본 대조 메모는 [후속 화면 검토사항](../후속_화면_검토사항.md)에 옮겼다. 초기 홈 이슈 범위·시연 UI 지시·고정 대기 시간·중복 타입/폴더/토큰/서비스 예시는 제거하고 가이드 파일을 삭제했다. 초기 제안을 새 구현 의무나 구현 완료로 기록하지 않았다. 이번에는 문서만 변경했다.

## 2026-11-04 채팅 폴더 분리

채팅 현황·기록·기능·API 문서를 docs/chat으로, 채팅 컴포넌트를 src/components/chat으로 옮겼다. 모달은 chat/modals에 분리했다. Home·미리보기·컴포넌트 import와 문서 상대 링크·코드 경로를 수정했다. 공통 규칙·원본·명세·캡처·Sidebar·서비스·타입·유틸·서버는 기존 위치를 유지했다. 문서 안내는 [채팅 README](README.md)에 정리했다.

build/lint·세션·프론트/API 통합 검사와 서버 테스트 4개가 통과했다. 링크 변환 오류는 복구 후 전체 문서 로컬 링크를 재검사했다. 현재 없는 캡처 폴더는 문서에서 링크 대신 위치 안내로 표시했다. 브라우저 직접 검증과 커밋·푸시는 하지 않았다.

## 2026-11-04 문서·스타일 정리

현재 구현과 다른 미연결·고정 타이머·메모리 전용 설명과 반복된 현황을 기능 문서에서 제거했다. API 문서는 현재 로컬 계약과 예시의 용도를 구분했다. 원본과 앱에서 모두 미사용인 brand-success·brand-warning 테마 색상을 제거했다. 원본 HTML과 사용자 요청으로 변경한 화면 스타일은 유지했다.

build/lint·문서 내부 링크·공백 검사가 통과했다. 정리 전후 생성 CSS는 제거한 두 색상 선언만 다르며, 선언을 복원해 계산한 SHA256이 기존 CSS와 같음을 확인했다. 이번 정리는 서버·동작 코드를 바꾸지 않아 API 검사는 재실행하지 않았다. 브라우저 시각 검증은 수행하지 않았다.

## 2026-11-04 링크 입력·목 분석

원본 스타일의 링크 모달과 POST /api/chat/links를 구현했다. 실제 URL을 보존하고 서버 목 분석·진행, 기록·수정, 작업 복원을 연결했다. 외부 페이지 수집은 하지 않는다. [링크 구현](구현_기능/링크_입력_분석.md) 참고.

## 2026-11-04 대화·진행 복원

sessionStorage에 메시지·시각·대화 ID·첨부 표시·카드 수정값·저장 ID를 보관한다. 접수된 작업 ID를 사용자 메시지와 연결해 새로고침·홈 재진입 시 조회를 재개한다. 완료 결과를 중복 추가하지 않고 실패 시 재확인을 제공한다. 작업 ID를 받기 전 중단은 자동 복원하지 않는다. 서버 DB 저장은 유지한다. [세션 보관](구현_기능/채팅_세션_보관.md) 참고.

## 2026-11-04 진행·저장·수정 연결

파일·링크는 서버 작업을 400ms 간격으로 조회한다. 현재 단계는 서버 시간이 재현하는 목 진행이다. 홈과 /example에서 실제 기록 저장·분류 수정 API를 호출한다. 저장 전 수정은 확정 시 반영하고 저장 후 수정은 PATCH로 처리한다. 원본 파일 연결을 유지하고 변화가 있을 때만 Timeline 이벤트를 생성한다. [진행 API](api/파일_분석_진행.md)·[카드 기록·수정](구현_기능/카드_기록_수정.md) 참고.

## 2026-11-04 개발용 서버와 프론트 연결

api-server에 Node.js 24·Express·Node 내장 SQLite 서버를 추가했다. 원본 파일·입력·목 분석·작업·확정 기록을 보관하고 프론트의 전송·준비 배지를 연결했다. 정식 백엔드 계약과는 별개다. [서버 안내](../../api-server/README.md) 참고.

## 2026-11-03 초기 홈 구현

- 원본 HTML 기준으로 입력·첨부·대기·결과 카드와 사용자 메시지를 구현했다.
- 모든 단일 파일에 공통 카드 구조를 적용하고 홈의 시연 버튼·전용 호출 코드를 제거했다.
- 사용자 요청으로 AI 카드 최대 너비 85%/sm 이상 80%, 사용자 말풍선 80%, 하단 간격 4px를 적용했다.
- 전송/응답 시각과 30초 간격 상대 시간 갱신을 구현했다.
- 변화 없음 전용 카드, 상태 배지, /example 독립 미리보기를 추가했다.
- 분석 데이터와 화면 렌더링을 분리하고 문서·원본·캡처를 docs 아래로 모았다.
- 취소된 말줄임·분류 1개 전용 좌우 마진 등은 다시 적용하지 않는다. 상세 기준은 [개발 규칙](../개발_규칙.md)에 남겼다.

## 검증 기록과 범위

초기 구현에서 lint/build, 목 분기·시각 표시·React 서버 렌더링 등을 확인했다. 이후 서버 작업에서 API·SQLite·파일·진행·저장·수정·세션·링크 검사를 수행했다. 검사 명령과 현재 범위는 [통합 현황](현재_구현_상태.md)의 검증 항목을 참고한다. 실제 브라우저 조작·픽셀 일치·운영 AI 서버 검증은 완료로 기록하지 않는다.
