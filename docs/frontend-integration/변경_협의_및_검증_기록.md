# 변경 협의 및 검증 기록

작성일: 2026-11-09

## 사용자와 확인한 작업 원칙

- 파트별 handoff가 연동 계약의 기준이다.
- Swagger는 해당 계약을 백엔드·AI 담당자가 프론트에서 쉽게 열람하는 수단이다.
- 기존 개발 서버의 openapi.js를 새 Swagger의 입력으로 사용할 필요는 없다. 생성 과정의 서버 소스 의존성을 제거한다.
- 현재 프론트 기능은 완성된 기능 범위로 보존한다. handoff에 맞추기 위한 기능 변경·축소·제거는 적용하지 않는다.
- 먼저 현재 기능과 동작을 문서화하고, 실제 사용 여부를 확인한 불필요 코드만 리팩토링 과정에서 정리한다.
- handoff와 충돌하거나 원격 연동 시 기능 손상이 예상되면 현재 동작·충돌 명세·문제와 영향·기능 보존 방향을 사용자에게 보고한다. 확인 전 해당 기능을 변경·제거하지 않는다.
- 원격 서버 준비 후의 실제 연결 검증은 이번 작업에서 수행하지 않는다.
- 작업 문서는 `docs/frontend-integration/`에 모은다.

이 원칙에 대한 합의는 아래 C-01~03 등 개별 기능 변경에 대한 승인이 아니다.

## 2026-11-09 — 현재 기능 보존 기준 추가

- 사용자는 현재 기능을 완성된 범위로 지정하고, handoff 때문에 동작 중인 기능을 바꾸는 조치를 적용하지 않도록 명시했다.
- 먼저 현재 기능·동작을 문서화하고 handoff와 대조하며, 충돌 또는 기능 손상 가능성이 있으면 사용자에게 사전 보고한다.
- 기준은 README에 추가하고 대조표에도 반영했다. 개별 기능 변경을 승인받은 것은 아니다.

## 2026-11-09 — 실제 브라우저 대조 시도, 도구 연결 단계에서 중단

- 목적: 프론트 기능 및 동작 명세서를 실제 화면과 대조하고 최근 시각의 한국어 표기 재현 여부 확인.
- 사전 확인: 로컬 5173/3001/8000 수신 서버가 없었고, 내장 Browser의 연결 목록은 `[]`였다.
- `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort`는 sandbox spawn EPERM 후 승인 재실행으로 정상 시작했다(Vite 8.3.6, ready). 이는 개발 서버 시작 확인이며 브라우저에서 페이지가 표시됐다는 뜻은 아니다.
- 세션에 노출된 Browser Use의 자동화·읽기 도구로 localhost 접근 가능 여부를 확인하려 했으나, 각각 `Unknown tool(browser_use.automate_browser)`, `Unknown tool(browser_use.read_public_web)`로 플러그인 서버가 호출을 거절했다.
- 페이지 탐색 전에 도구 호출이 실패했으므로 localhost 차단·CORS·브라우저 보안·프론트 결함으로 판정하지 않는다. 설치/도구 목록 노출과 실제 도구 호출 가능 상태는 구분한다.
- 실제 브라우저 탐색·클릭·시각 표시·기능 대조는 수행하지 못했다. 명세 일치 여부와 QA 점수는 판정하지 않는다.
- 개인 DB·실제 AI·저장/삭제는 사용하지 않았으며 프론트 코드는 변경하지 않았다. 이번에 시작한 Vite 프로세스는 중단했다.
- 후속: 호스트에서 실제 호출 가능한 브라우저 연결을 복구한 뒤 로컬 주소 탐색부터 재검증한다. 터널·외부 브라우저 도구 설치·보안 설정 변경으로 우회하지 않았다.

## 2026-11-11 — C-03 작업 조회 경로와 복원 불가 처리

- 사용자는 AI 서버가 ai- 작업 ID만 발급한다는 설명을 확인하고, ai- 없는 작업에 대한 처리도 포함해 진행하도록 요청했다.
- `src/services/chat.ts`의 복원·반복 조회에서 백엔드를 선택하던 분기를 제거하고 AI 조회로 통일했다.
- 복원할 작업에 ai- 접두사가 없으면 서버 요청 전에 복원 불가 안내를 가진 확정 실패를 반환한다. Home의 기존 확정 실패 처리가 pendingJob을 비워 새 전송을 허용하고 채팅 내역은 유지한다.
- 기존 `tests/chat-terminal-error.test.mjs`에 복원 불가 시 요청 차단·확정 실패 판정과 AI 진행→완료 조회 검사를 추가했다.
- 검증은 서비스 검사 3개, `scripts/check-chat-session.mjs`, TypeScript 앱 검사, `git diff --check` 통과. 실제 브라우저 및 원격 서버 연동은 미검증이다.

## 2026-11-11 — handoff 기반 독립 Swagger 구성

- 사용자는 기존에 작성한 handoff를 기준으로 독립 OpenAPI 파일과 생성 경로를 구성하도록 요청했다.
- `openapi/backend.openapi.json`과 `ai.openapi.json`을 OpenAPI 3.1로 작성했다. 공개 백엔드 16개·AI 4개와 서버 전용 6개 작업, 내부 Bearer 인증, 요청·응답·오류·필수·nullable·상태별 응답과 handoff JSON 예시를 담았다.
- Base에는 handoff의 설명용 HTTPS 주소를 사용했다. 실제 날짜·원문 근거·ID 상호 참조·스냅샷·원자성은 명세 설명과 handoff를 함께 따르도록 남겼다. ChatHealth.network는 세부 필드가 정의되지 않아 객체로만 표현하고 그 사유를 설명했다.
- `scripts/build-swagger.mjs`가 두 JSON을 읽도록 바꿔 서버 소스·Zod 스키마·SQLite import 의존성을 해소했다. 기존 UI 선택·정적 파일 경로·Try it out 비활성 설정을 사용한다.
- 명세 검사 3개·예시 30개 제약 대조·npm build·변경 JS lint·git diff 검사 통과. dev·preview에서 문서·명세·자산 제공과 리다이렉트, 생성 JSON의 원본 일치를 확인했다.
- 서버 폴더를 복사하지 않은 임시 디렉터리에 기존 루트 node_modules를 연결해 빌드·문서 생성·명세 검사를 확인했다. 새 설치·원격 통신·실제 브라우저 렌더링·Vercel 배포는 미검증이다.
- 프론트의 기존 서버 의존 통합 검사와 패키지 정리는 후속 범위다.

## 2026-11-11 — 담당자용 Swagger 설명 보완

- 사용자가 백엔드·AI 담당자가 혼동하지 않도록 Swagger 수정을 요청했다.
