# 프론트 API 연동 정비

작성일: 2026-11-09 · 관련 이슈: #17 · 작업 브랜치: `refactor/#17`

## 다음 세션 시작 지점 — 서버 의존성과 계약 차이 검토

최종 기록: 2026-11-11. [프론트 기능 및 동작 명세서](프론트%20기능%20및%20동작%20명세서.md)에 따라 사용자 브라우저에서 주요 화면 동작을 확인했다. 공개 API 20개는 handoff·프론트·개발 서버 코드를 대조했다. **다음에는 발견한 차이의 처리 방향과 분리 서버 의존성을 검토한다.**

### 확인 방식과 브라우저 도구 상태

- 에이전트의 실제 브라우저 검증은 완료되지 않았다. 내장 Browser 연결 목록은 `[]`였고 Browser Use 호출은 플러그인 서버의 `Unknown tool`로 실패했다. 설치·활성화와 실제 호출 성공을 구분한다.
- 이 때문에 사용자가 명세서의 홈 동작부터 에이전트와 함께 직접 확인하기로 했다. 아래 결과는 **사용자의 브라우저 확인 응답**이며 에이전트 자동 검사 결과가 아니다.
- ‘표시돼’라는 응답을 세션 복원·진행 작업 복구·조회 실패 등 모든 분기의 검증으로 확대하지 않는다. 응답을 받은 설명 범위와 실제 세부 확인 수준을 구분한다.
- Node의 최근 시각 테스트 3개 실패는 AM/PM과 오전/오후 표기 차이였다. 사용자는 자신의 브라우저에서 최근 목록의 날짜와 시각이 정상이라고 확인했다.
- 기능 코드는 변경하지 않았다. 도구 연결 문제를 해결하느라 사용자와의 수동 확인을 다시 중단하지 않는다. 도구 복구가 필요하면 별도 작업으로 구분한다.

### 이후 이어갈 순서

서버 작업 실패·재조회는 실패와 복구를 재현할 수 있는 테스트 조건에서 확인한다. 실제 전체 데이터 삭제는 삭제해도 되는 테스트 데이터와 실행 환경을 확인한 뒤 별도로 검증한다. 각 항목은 [명세서](프론트%20기능%20및%20동작%20명세서.md)의 실제 조건을 기준으로 하나씩 설명한다.

저장·삭제·실제 AI 호출이 있는 단계는 실행 전에 영향과 검증 데이터를 확인하고, 개인 데이터 삭제나 유료 호출을 단순 확인 동작에 섞지 않는다. 설명만 한 항목과 실제 사용자 확인 완료를 구분하고, 답변을 받으면 이 진행표와 미확인 항목을 갱신한다.

동작이 설명과 다르거나 handoff와 충돌할 가능성이 발견되면 현재 화면·기대 동작·영향을 기록해 사용자에게 보고한다. 명세가 실제 구현을 잘못 설명한 경우와 기능/계약 충돌을 구분하며 기능을 임의로 변경하지 않는다.

## 목적과 기준

파트별 handoff 명세를 기준으로 프론트의 API 연동 준비 상태를 확인하고, 백엔드·AI 담당자가 그 계약을 프론트의 Swagger에서 열람할 수 있도록 정비한다. 백엔드·AI 개발 서버 없이 프론트 실행·빌드·문서 생성·관련 검사가 가능하도록 의존성을 해소한다.

**handoff가 계약의 기준이다.** 프론트 코드는 계약 적용 상태를 확인하는 대상이고, 기존 개발 서버 코드는 로컬 의존성과 기존 동작을 파악하는 대상이다. 기존 개발 서버 구현이나 `api-server/docs/openapi.js`를 새 명세의 기준으로 삼지 않는다. handoff에 모호하거나 상충하는 내용이 있으면 임의로 확정하지 않는다.

## 현재 기능 보존과 충돌 보고 원칙

아래는 2026-11-09 사용자가 추가로 명시한 기준이며, 기존 계획의 기능 변경 관련 표현보다 우선한다.

- 현재 프론트에 구현되어 동작하는 기능을 완성된 기능 범위로 본다. 이번 작업에서 기능을 추가하거나 기존 기능·화면 동작을 바꾸지 않는다.
- handoff는 연동 계약의 기준이지만, 이를 맞추기 위해 현재 동작하는 기능을 변경·축소·제거하는 조치는 적용하지 않는다. 현재 기능 보존을 우선하고 계약과의 차이는 별도로 기록한다.
- 먼저 [프론트 기능 및 동작 명세서](프론트%20기능%20및%20동작%20명세서.md)에 사용자 입력, API 요청, 응답 처리, 화면 표시, 저장·복원, 취소·오류·중복 방지 흐름을 보존 기준으로 정리한다. 코드에서 확인한 내용과 실제 실행으로 검증한 내용을 구분한다.
- 기능 목록과 handoff를 대조할 때 충돌이 확인되거나 원격 연동 시 기능이 깨질 가능성이 보이면 사용자에게 먼저 보고한다. 보고에는 현재 동작, 충돌하는 명세, 예상 문제와 영향, 현재 기능을 보존할 해결 방향을 포함한다.
- 사용자 확인 전에는 해당 기능을 변경하거나 제거하지 않는다. 대조표에 충돌을 기록하고, 보고 내용과 사용자 확인 결과는 변경 협의 기록에 남긴다. 조사와 충돌과 무관한 작업은 계속할 수 있다.
- 리팩토링은 현재 동작을 보존하는 책임 분리·중복 정리 등을 대상으로 한다. 불필요한 코드·타입·패키지는 화면·서비스·복원·검사 등 실제 참조와 사용 여부를 확인한 뒤 제거한다. handoff에 없다는 이유만으로 불필요하다고 판정하지 않는다.

## 진행 순서와 현재 상태

1. 저장소 상태·지침·기존 검증 이력을 확인한다. 초기 확인 완료.
2. 현재 프론트의 기능과 동작을 문서화해 보존 기준을 확립한다. 코드 기반 명세 작성 및 일부 독립 검사 완료. 사용자 브라우저에서 홈·발자국·자료 Drawer·Project Timeline·Growth Journey·설정의 주요 동작을 대조했다. 에이전트 브라우저·서버 전체 동작 검증은 미완료다.
3. 해당 기능과 공개 API 20개의 handoff·프론트·개발 서버 코드 대조를 완료했다. 차이와 기능 영향은 대조표에 기록했다. 실제 분리 서버 연동은 미검증이다.
4. 개발 서버의 공유 DB·다른 서버 파일 참조와 프론트의 빌드·검사 의존성을 조사한다. 초기 확인만 수행.
5. 현재 기능을 보존할 해결 방향을 정리하고 필요한 사용자 확인을 기록한다. 기능 변경을 전제로 계약에 맞추지 않는다.
6. handoff 기반의 독립 OpenAPI 명세와 Swagger 생성 경로를 구성한다. 충돌은 숨기거나 임의로 확정하지 않는다. 미착수.
7. 현재 기능 보존과 계약 호환을 API 대역 및 서버 폴더 없는 환경으로 검증한다. 미실행.

현재 기능을 보존하는 범위에서 작업하고, 기능에 영향을 줄 가능성이 있는 조치는 건별 보고·사용자 확인 전 적용하지 않는다. 확인 후에도 변경 단위마다 검증 결과를 공유한다. 차이 발견을 수정 승인이나 검증 완료로 기록하지 않는다.

## Swagger 구성 방향

향후 이 폴더의 `openapi/backend.openapi.json`, `openapi/ai.openapi.json`에 handoff 내용을 OpenAPI 형식으로 작성하고, `scripts/build-swagger.mjs`가 이를 읽도록 변경할 예정이다. 현재 이 파일들은 아직 작성하지 않았다.

공개 API와 서버 간 내부 API는 호출 주체·접근 범위를 구분해서 표시한다. 내부 API를 프론트 호출 경로로 연결하거나 내부 토큰을 브라우저에 넣지 않는다. Swagger 제공은 서버 구현 완료나 실제 원격 연결 성공을 뜻하지 않는다.

## 이번 범위와 후속 범위

이번에는 계약 대조, 독립 Swagger, 프론트 설정·의존성 정리, API 대역 기반 로컬 검증을 진행한다. 서버 구현을 대신하거나 실제 AI·개인 DB를 사용한 검증을 전제로 하지 않는다. 서버 폴더는 의존성과 보존 대상을 확인하기 전에 삭제하지 않는다.

실제 원격 주소·CORS·인증·업로드 제한·서버 간 전달·영속 저장의 최종 연결 검증은 각 서버 준비 후 별도 작업이다. 기존 2026-11-06 검사 이력은 참고 근거이며 이번 작업의 재검증 결과가 아니다.
