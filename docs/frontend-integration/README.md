### lint·작은 중복 코드 정리 — 2026-11-11

- useHomeRecent의 요청 컨트롤러·번호를 ref에 보관하고 최신 번호·취소 신호로 성공/실패 응답을 걸러낸다. Effect 해제 때 요청을 취소하고 이벤트 구독을 해제한다.
- Home의 resumeJob을 복원 Effect 앞에 배치하고 중복된 화면 해제 cleanup을 하나로 통합했다. 초기 복원 대기 상태는 기존 state 초기값을 사용하고 수동 재조회 버튼에서 대기·오류 상태를 갱신한다. 전송별 작업 접수 여부는 해당 요청의 상태 객체에서 관리한다. 최신 요청 판별·취소·확정 실패·입력 복원 조건은 유지한다.
- ConnectedChatReplyCard의 분류 수정 인자를 기존 활동 선택 타입으로 좁혀 반복 조건을 제거했다. 저장 시 같은 활동을 some·find로 두 번 찾던 코드는 한 번의 find로 정리했다. 신규 활동 저장·기존 활동 연결·저장 전후 분류 수정의 API 계약은 유지한다.
- tests/home-recent-request.test.mjs에 실제 hook의 Effect 로직을 분리 실행하는 검사 3개를 추가했다. 연속 갱신 시 이전 요청 취소와 늦은 성공/실패 무시, 해제 뒤 응답·이벤트 차단과 setup→cleanup→setup, 오류 후 회복을 확인했다. React 훅·서비스 경계를 대역으로 주입하는 단위 검사이며 실제 React 렌더링·브라우저 StrictMode 검증은 아니다.
- 검증: npm test 42개·세션 복원 통과, npm run build의 Swagger·TypeScript·Vite 통과. lint 오류·경고 모두 0개. 아래 경고 3개와 이전 검사 개수는 당시 이력이다. 실제 브라우저·원격 연동 검증은 원격 서버 준비 후 진행한다.

### 후속 환경설정 정비 — 2026-11-11

- package.json과 lockfile의 engines에 Node 24.x·npm 11.x를 명시했다. .nvmrc에는 검증한 Node 24.14.0, packageManager에는 npm@11.21.1을 기록했다. 패키지 버전과 의존성 목록은 변경하지 않았다.
- .env.example에는 원격 공개 API Base 두 개만 제공한다. 개인 설정은 .env.local로 복사해 작성하며 .env·.env.*는 제외하고 .env.example만 Git에서 공유한다.
- VITE_API_BASE_URL·VITE_AI_API_BASE_URL은 /api를 포함한 원격 Base다. 미설정 시 /api·/ai-api 상대 경로를 유지한다. 빈 설정으로도 프론트 검사·빌드·Swagger 생성이 가능하다.
- 사용자 결정: 앞으로 로컬 백엔드·AI 서버는 사용하지 않는다. 선택형 개발 프록시 변수 두 개와 loadEnv·프록시 생성·AI 경로 변환 코드를 모두 제거했다. 브라우저가 VITE_ 원격 Base로 직접 요청하며 CORS는 각 서버에서 허용해야 한다. Vercel에는 Base를 빌드 환경변수로 지정한다.
- 로컬 프록시 기능 전용 tests/vite-proxy.test.mjs도 제거했다. 프록시를 잠시 제공했던 42개 검사 기록은 이전 이력이며 현재 프론트 검사는 39개와 세션 복원 검사다. 실제 원격 서버는 호출하지 않았다.
- Node·npm 버전 선언·개인 환경파일 제외 규칙·Swagger 경로는 유지한다. 실제 원격 연결·브라우저 검증은 서버 연결 후 진행한다.
- 로컬 프록시 제거 후 재검증: npm test 39개·세션 복원, npm run build의 Swagger·TypeScript·Vite 통과. lint는 오류 없이 기존 경고 3개다.

최종 갱신: 2026-11-11. **사용자가 이전 작업 커밋 완료를 알린 뒤 개발 서버 제거와 미사용 코드 정리를 요청했다. 기준 커밋은 `f54e497`이며 변경 전 작업 트리는 깨끗했다. 개발 서버 두 폴더·로컬 서버 전용 검사·미사용 목데이터·이전 모달과 미사용 분기를 제거했고, 프론트 검사 39개·세션 복원·빌드·Swagger 생성이 통과했다.** 현재 변경의 커밋·푸시는 아직 수행하지 않았다.

### 완료한 테스트 의존성 정리

1. `tests/journey.test.mjs`는 `tests/fixtures/journey.mjs`를 사용하며 유형·분야 필터와 순서·근거·원본 보존 검증을 유지한다.
2. `tests/footprints.test.mjs`는 검색 조건의 query 전송·서버 응답 순서·총계·오류·취소를 검증한다. 미사용 목록 래퍼 제거 후에도 searchFootprintActivities로 빈 목록·손상 응답 검증을 유지한다. 서버 검색 함수 검사는 기준 커밋·외부 백업에 보존한다.
3. `tests/chat-api.test.mjs`, `tests/journey-api.test.mjs`, `tests/footprint-file-timeline.test.mjs`는 서버 앱·DB 없이 프론트 서비스 계약을 검증한다. `tests/support/frontend.mjs`는 실제 프론트 모듈 로딩과 예상 HTTP 요청 검증을 지원한다.
4. 채팅 검사는 analysisId 없는 저장의 사전 차단과 AI 작업 조회·과거 작업 복원 거절을 현재 계약에 맞춰 확인한다. 시간 제한·실패·파일 원본·첨부 이름·링크·저장 요청·갱신 이벤트도 검사한다.
5. `scripts/check-live-ai.mjs`는 실제 모델과 양 서버가 필요한 수동 검사였으며 서버 제거 시 외부에 백업한 뒤 프론트에서 제거했다. npm test에는 포함되지 않는다. 프론트·서버 책임과 과거 검사 목적은 [의존성 점검표](로컬_서버_의존성_점검.md)에 기록했다.
6. 루트 zod의 미사용을 확인해 선언을 제거했고, 서버 폴더와 기존 설치 패키지가 없는 환경에서 새 설치·검사·빌드·문서 생성을 통과했다.

### 제거 전 미사용 목데이터·초기 코드 점검 기록

앱 진입점 `src/main.tsx`의 import 경로와 src·tests·scripts 및 저장소의 이름·경로 참조를 확인했다. 아래 6개 파일은 앱과 프론트 검사·스크립트에서 참조되지 않아 이번에 제거했다. 아래 내용은 제거 판단의 근거이며 이전 소스는 기준 커밋에서 확인한다.

| `src/mocks/Home/recentActivities.ts` | 홈 최근 활동 예시와 이전 RecentActivity 타입 | 미사용, 현재 홈은 useHomeRecent → getHomeRecent로 조회 |

추가 정리 대상도 다음과 같이 처리했다.

- `ActivityReviewModal`의 유일한 호출이 분류 전용임을 확인하고 일반 메타정보 편집·모달 신규 생성 분기와 classificationOnly·saving 옵션을 제거했다. 기존 활동 선택·자료 유형 수정·저장 후 수정·초점 복귀 및 카드의 별도 신규 활동 저장 기능은 유지했다.
- `src/services/footprints.ts`의 `getFootprintActivities()`는 앱에서 미사용이어서 제거하고 해당 검증을 searchFootprintActivities 검사로 전환했다.

- 빈 `src/mocks/journey/` 폴더도 제거했다. Journey 검사 데이터는 tests/fixtures/journey.mjs에서 유지하며 실제 화면은 API에서 받는다.

테스트 fixture, 홈의 초기 인사, FileAnalysisProgress 등 실제 사용 항목은 유지했다. 제거·단순화 후 npm test·npm run build·lint를 실행한 결과는 맨 위에 기록했다.

### 개발 서버 제거와 보존 결과

프론트 설치·검사·빌드·Swagger 생성은 서버 없이 가능함을 검증했고, `api-server/`·`ai-api-server/` 두 폴더와 로컬 서버 전용 검사를 제거했다.

- 서버 소스·검사·보존본은 기준 커밋 f54e497에서 복원할 수 있다. 로컬 DB·WAL·SHM과 AI .env를 포함한 84개 파일은 맨 위 외부 백업 경로에 보존했다. 비밀값·DB·설치 폴더는 Git에 추가하지 않았다.
- 기존 서버를 직접 실행하던 `scripts/check-live-ai.mjs`도 같은 백업에 보관한 뒤 제거했다. 현재 프론트 scripts는 Swagger 생성·프론트 계약·세션 검사만 포함한다.
- handoff 계약·프롬프트 인계 문서·독립 OpenAPI는 유지했다. 과거 문서의 서버 소스 경로는 이전 구현 이력으로 구분하고 실제 원격 연동 검증은 후속 범위로 남겼다.

### 확인 방식과 브라우저 도구 상태

- 에이전트의 실제 브라우저 검증은 완료되지 않았다. 내장 Browser 연결 목록은 `[]`였고 Browser Use 호출은 플러그인 서버의 `Unknown tool`로 실패했다. 설치·활성화와 실제 호출 성공을 구분한다.
- 이 때문에 사용자가 명세서의 홈 동작부터 에이전트와 함께 직접 확인하기로 했다. 아래 결과는 **사용자의 브라우저 확인 응답**이며 에이전트 자동 검사 결과가 아니다.
- ‘표시돼’라는 응답을 세션 복원·진행 작업 복구·조회 실패 등 모든 분기의 검증으로 확대하지 않는다. 응답을 받은 설명 범위와 실제 세부 확인 수준을 구분한다.
- 초기 Node의 최근 시각 테스트 3개 실패는 AM/PM과 오전/오후 표기 차이였다. 사용자는 자신의 브라우저에서 정상 표시를 확인했고, 이번 의존성 조사 환경의 날짜 표시 검사도 통과했다.
- 초기 수동 확인 단계에서는 기능 코드를 변경하지 않았다. 이후 사용자 요청으로 analysisId 필수와 작업 복원 처리를 수정했다. 도구 연결 문제로 확인된 사용자 결과를 다시 미확인으로 되돌리지 않는다.

### 이후 이어갈 순서

프론트 테스트 독립화·새 설치 검증과 개발 서버·미사용 코드 정리를 완료했다. 현재 변경은 커밋·푸시하지 않았다. 재배포는 사용자 담당이다. 저장·복원·실패·재조회 등의 실제 브라우저 검증과 CORS·인증·업로드·저장·삭제의 원격 연동 검증은 다른 백엔드·AI 서버가 원격으로 연결된 뒤 수행한다. 실제 전체 데이터 삭제는 삭제해도 되는 테스트 데이터와 실행 환경을 확인한 뒤 검증한다. 각 항목은 [명세서](프론트%20기능%20및%20동작%20명세서.md)의 실제 조건을 기준으로 확인한다.

저장·삭제·실제 AI 호출이 있는 단계는 실행 전에 영향과 검증 데이터를 확인하고, 개인 데이터 삭제나 유료 호출을 단순 확인 동작에 섞지 않는다. 설명만 한 항목과 실제 사용자 확인 완료를 구분하고, 답변을 받으면 이 진행표와 미확인 항목을 갱신한다.

동작이 설명과 다르거나 handoff와 충돌할 가능성이 발견되면 현재 화면·기대 동작·영향을 기록해 사용자에게 보고한다. 명세가 실제 구현을 잘못 설명한 경우와 기능/계약 충돌을 구분하며 기능을 임의로 변경하지 않는다.

## 목적과 기준

파트별 handoff 명세를 기준으로 프론트의 API 연동 준비 상태를 확인하고, 백엔드·AI 담당자가 그 계약을 프론트의 Swagger에서 열람할 수 있도록 정비한다. 백엔드·AI 개발 서버 없이 프론트 실행·빌드·문서 생성·관련 검사가 가능하도록 의존성을 해소한다.

**handoff가 계약의 기준이다.** 프론트 코드는 계약 적용 상태를 확인하는 대상이고, 기존 개발 서버 코드는 로컬 의존성과 기존 동작을 파악하는 대상이다. 기존 개발 서버 구현이나 `api-server/docs/openapi.js`를 새 명세의 기준으로 삼지 않는다. handoff에 모호하거나 상충하는 내용이 있으면 임의로 확정하지 않는다.

## 현재 기능 보존과 충돌 보고 원칙

아래는 2026-11-09 사용자가 추가로 명시한 기준이며, 기존 계획의 기능 변경 관련 표현보다 우선한다.

- 현재 프론트에 구현되어 동작하는 기능을 완성된 기능 범위로 본다. 이번 작업에서 기능을 추가하거나 기존 기능·화면 동작을 바꾸지 않는다.
- handoff는 연동 계약의 기준이지만, 이를 맞추기 위해 현재 동작하는 기능을 변경·축소·제거하는 조치는 적용하지 않는다. 현재 기능 보존을 우선하고 계약과의 차이는 별도로 기록한다.
- 먼저 [프론트 기능 및 동작 명세서](프론트%20기능%20및%20동작%20명세서.md)에 사용자 입력, API 요청, 응답 처리, 화면 표시, 저장·복원, 취소·오류·중복 방지 흐름을 보존 기준으로 정리한다. 코드에서 확인한 내용과 실제 실행으로 검증한 내용을 구분한다.
- 기능 목록과 handoff를 대조할 때 충돌이 확인되거나 원격 연동 시 기능이 깨질 가능성이 보이면 사용자에게 먼저 보고한다. 보고에는 현재 동작, 충돌하는 명세, 예상 문제와 영향, 현재 기능을 보존할 해결 방향을 포함한다.
- 사용자 확인 전에는 해당 기능을 변경하거나 제거하지 않는다. 대조표에 충돌을 기록하고, 보고 내용과 사용자 확인 결과는 변경 협의 기록에 남긴다. 조사와 충돌과 무관한 작업은 계속할 수 있다.
- 리팩토링은 현재 동작을 보존하는 책임 분리·중복 정리 등을 대상으로 한다. 불필요한 코드·타입·패키지는 화면·서비스·복원·검사 등 실제 참조와 사용 여부를 확인한 뒤 제거한다. handoff에 없다는 이유만으로 불필요하다고 판정하지 않는다.

## Swagger 구성 방향

이 폴더의 [backend.openapi.json](openapi/backend.openapi.json)과 [ai.openapi.json](openapi/ai.openapi.json)에 handoff 계약을 작성했다. `scripts/build-swagger.mjs`가 두 파일을 읽어 정적 Swagger를 생성한다. 서버 소스·DB 모듈을 import하지 않는다. 실제 주소가 정해지기 전에는 handoff의 설명용 HTTPS Base를 표시한다.

각 API의 호출 방향, 담당 파트의 제공 책임, ID 사용 순서와 공개·내부 Base 설명을 표시한다. handoff 원문 21개를 함께 정적 생성하고 Swagger에서 링크로 열 수 있다.

공개 API와 서버 간 내부 API는 호출 주체·접근 범위를 구분해서 표시한다. 내부 API를 프론트 호출 경로로 연결하거나 내부 토큰을 브라우저에 넣지 않는다. Swagger 제공은 서버 구현 완료나 실제 원격 연결 성공을 뜻하지 않는다.

## 이번 범위와 후속 범위

계약 대조·독립 Swagger·프론트 의존성 정리·API 대역 기반 로컬 검증·새 설치 검증을 완료했다. 서버 폴더는 의존성과 보존 대상을 확인하고 외부 백업 후 제거했다. 서버 구현을 대신하거나 실제 AI·개인 DB를 사용한 검증은 수행하지 않았다.

실제 원격 주소·CORS·인증·업로드 제한·서버 간 전달·영속 저장의 최종 연결 검증은 각 서버 준비 후 별도 작업이다. 기존 2026-11-06 검사 이력은 참고 근거이며 이번 작업의 재검증 결과가 아니다.
