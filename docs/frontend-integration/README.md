## 다음 세션 시작 지점 — 미사용 프론트 코드 정리 전

최종 갱신: 2026-11-11. **사용자는 코드 정리 전에 현재 작업을 먼저 푸시하기로 했다. 이번 기록 시점에는 프론트 테스트 독립화·새 설치 검증·미사용 코드 점검까지 완료했으며, 점검한 목데이터·컴포넌트·분기는 아직 삭제하거나 수정하지 않았다.** 커밋·푸시는 사용자가 진행한다.

2026-11-11 후속 작업: Journey fixture를 `tests/fixtures/journey.mjs`로 분리하고 채팅·아카이브·Journey 서비스 검사를 API 대역으로 전환했다. 루트 `npm test`로 검사 39개와 세션 복원 검사가 통과했다. 빌드·Swagger 생성과 lint도 통과했으며 기존 lint 경고 3개는 유지한다. 서버 검색 함수 검사 6개는 `api-server/test/archive-filter.test.js`로 이동해 통과했다. 기존 DB 통합 시나리오는 서버 test-support의 보존본과 기존 서버 검사에서 추적한다. 아래 이전 기록과 이번 실행 결과를 구분한다.

서버 폴더 없는 별도 임시 환경에서 기존 node_modules 재사용 검증에 이어 새 설치 검증도 완료했다. Node v24.14.0·npm 11.21.1에서 `npm ci --no-audit --no-fund`로 50개 패키지를 새로 설치하고 검사 39개·세션 복원·TypeScript·Vite 빌드·Swagger 생성을 통과했다. package.json·lockfile은 변경되지 않았으며 기존 node_modules 연결과 서버 패키지 없이 실행했다.

사용자 결정: `https://1-line-frontend.vercel.app/`의 재배포는 사용자가 직접 진행한다. 에이전트의 배포 작업·Vercel 연결은 진행하지 않는다. 수정한 저장·복원의 브라우저 확인과 실제 백엔드·AI 원격 연동 검증은 다른 파트의 서버가 원격으로 연결된 뒤 진행한다. 현재 범위인 프론트 새 설치·검사·빌드 독립 검증은 완료했다.

이전 인계 기록: 2026-11-11. 공개 API 20개의 코드 대조와 analysisId·작업 복원 처리를 마쳤다. handoff 기반 독립 OpenAPI와 담당자용 Swagger 설명을 구성했다. 당시 다음 작업이던 프론트 테스트의 서버 소스·fixture·DB 의존성 정리는 위 후속 작업에서 완료했다. 재배포는 전체 작업 완료 후 진행한다.

### 완료한 테스트 의존성 정리

1. `tests/journey.test.mjs`는 `tests/fixtures/journey.mjs`를 사용하며 유형·분야 필터와 순서·근거·원본 보존 검증을 유지한다.
2. `tests/footprints.test.mjs`는 검색 조건의 query 전송·서버 응답 순서·총계·오류·취소를 검증한다. 서버 검색 함수 검사는 서버 test로 이동했다.
3. `tests/chat-api.test.mjs`, `tests/journey-api.test.mjs`, `tests/footprint-file-timeline.test.mjs`는 서버 앱·DB 없이 프론트 서비스 계약을 검증한다. `tests/support/frontend.mjs`는 실제 프론트 모듈 로딩과 예상 HTTP 요청 검증을 지원한다.
4. 채팅 검사는 analysisId 없는 저장의 사전 차단과 AI 작업 조회·과거 작업 복원 거절을 현재 계약에 맞춰 확인한다. 시간 제한·실패·파일 원본·첨부 이름·링크·저장 요청·갱신 이벤트도 검사한다.
5. `scripts/check-live-ai.mjs`는 실제 모델과 양 서버가 필요한 수동 통합 검사로 유지하며 npm test에 포함하지 않는다. 프론트·서버 책임은 [의존성 점검표](로컬_서버_의존성_점검.md)에 기록했다.
6. 루트 zod의 미사용을 확인해 선언을 제거했고, 서버 폴더와 기존 설치 패키지가 없는 환경에서 새 설치·검사·빌드·문서 생성을 통과했다.

### 미사용 목데이터·초기 코드 점검 결과 — 정리 미실행

앱 진입점 `src/main.tsx`의 import 경로와 src·tests·scripts 및 저장소의 이름·경로 참조를 확인했다. 아래 6개 파일은 앱과 프론트 검사·스크립트에서 참조되지 않는다. 과거 문서의 설명·링크는 남아 있으므로 삭제 시 함께 갱신해야 한다.

| `src/mocks/Home/recentActivities.ts` | 홈 최근 활동 예시와 이전 RecentActivity 타입 | 미사용, 현재 홈은 useHomeRecent → getHomeRecent로 조회 |

추가 정리 후보는 다음과 같다. 이 목록은 삭제·수정 완료 기록이 아니다.

- `tests/fixtures/chat.ts`의 `mockSingleFileAnalysisMode`, `mockGreetingReply`, `mockFileAnalysisProgress`는 현재 검사·스크립트에서 사용하지 않는다. 나머지 일반·텍스트·파일·변화 없음·다중 파일·링크 응답 fixture는 실제 검사에서 사용하므로 유지한다.
- `ActivityReviewModal`의 유일한 앱 호출은 `ConnectedChatReplyCard`이며 `classificationOnly=true`, `saving=false`다. 활동명·유형·역할·기간·요약 편집 및 모달을 통한 신규 생성 분기는 현재 실행되지 않는다. 정리 시 기존 활동 선택·자료 유형 수정·저장 후 수정·모달 초점 복귀는 보존해야 한다. 카드의 별도 신규 활동 저장 기능도 유지한다.
- `src/services/footprints.ts`의 `getFootprintActivities()`는 현재 앱 호출이 없고 `tests/footprints.test.mjs`에서만 사용한다. 제거 여부를 판단할 때 기존 검증 목적을 searchFootprintActivities 검사로 보존한다.
- ChatReply 타입의 ‘임시 데이터 구조’, ConnectedChatReplyCard의 ‘독립 미리보기’ 등 현재 구성과 맞지 않는 주석과 과거 목데이터 경로 안내는 정리 시 갱신한다. 실제 사용하는 타입·서비스·진행 표시 컴포넌트를 주석만 보고 삭제하지 않는다.
- `src/mocks/journey/`는 빈 폴더다. 현재 Journey 검사 데이터는 tests/fixtures/journey.mjs에 있으며 실제 화면 데이터는 API에서 받는다.

테스트 fixture, 홈의 초기 인사, FileAnalysisProgress 등 실제 사용 항목은 제거 대상이 아니다. 이번 점검에서는 코드를 수정하지 않았으므로 별도의 동작 재검증을 수행하지 않았다. 실제 제거·단순화 후 npm test·npm run build·lint를 실행한다.

### 개발 서버 폴더 제거에 대한 현재 판단

프론트 설치·검사·빌드·Swagger 생성은 `api-server/`·`ai-api-server/` 없이 가능함을 검증했다. 다만 두 폴더 자체는 아직 제거하지 않았다.

- 서버 폴더에는 로컬 data·설치 패키지·AI .env·가상환경이 있고, 이번에 추가한 서버 검사·통합 검사 보존본 중 아직 Git에 기록되지 않은 파일이 있다. 실제 삭제 전 보관 여부를 확인한다. 비밀값·DB·설치 폴더를 프론트 Git에 추가하지 않는다.
- `scripts/check-live-ai.mjs`는 여전히 두 개발 서버를 직접 실행하고 서버 DB 모듈을 가져온다. 서버 폴더 제거와 함께 별도 보관 또는 제거·안내 갱신이 필요한 대상이다.
- 서버 소스·테스트·원본 데이터·환경설정 보존과 미사용 프론트 코드 정리는 별개의 작업이다. 현재 프론트 기능·API 계약은 유지한다.

### 확인 방식과 브라우저 도구 상태

- 에이전트의 실제 브라우저 검증은 완료되지 않았다. 내장 Browser 연결 목록은 `[]`였고 Browser Use 호출은 플러그인 서버의 `Unknown tool`로 실패했다. 설치·활성화와 실제 호출 성공을 구분한다.
- 이 때문에 사용자가 명세서의 홈 동작부터 에이전트와 함께 직접 확인하기로 했다. 아래 결과는 **사용자의 브라우저 확인 응답**이며 에이전트 자동 검사 결과가 아니다.
- ‘표시돼’라는 응답을 세션 복원·진행 작업 복구·조회 실패 등 모든 분기의 검증으로 확대하지 않는다. 응답을 받은 설명 범위와 실제 세부 확인 수준을 구분한다.
- 초기 Node의 최근 시각 테스트 3개 실패는 AM/PM과 오전/오후 표기 차이였다. 사용자는 자신의 브라우저에서 정상 표시를 확인했고, 이번 의존성 조사 환경의 날짜 표시 검사도 통과했다.
- 초기 수동 확인 단계에서는 기능 코드를 변경하지 않았다. 이후 사용자 요청으로 analysisId 필수와 작업 복원 처리를 수정했다. 도구 연결 문제로 확인된 사용자 결과를 다시 미확인으로 되돌리지 않는다.

### 이후 이어갈 순서

프론트 테스트 독립화와 새 설치 검증은 완료했다. 사용자가 현재 작업을 먼저 푸시한 뒤 미사용 코드 정리를 이어간다. 재배포는 사용자 담당이다. 저장·복원·실패·재조회 등의 실제 브라우저 검증과 CORS·인증·업로드·저장·삭제의 원격 연동 검증은 다른 백엔드·AI 서버가 원격으로 연결된 뒤 수행한다. 실제 전체 데이터 삭제는 삭제해도 되는 테스트 데이터와 실행 환경을 확인한 뒤 검증한다. 각 항목은 [명세서](프론트%20기능%20및%20동작%20명세서.md)의 실제 조건을 기준으로 확인한다.

저장·삭제·실제 AI 호출이 있는 단계는 실행 전에 영향과 검증 데이터를 확인하고, 개인 데이터 삭제나 유료 호출을 단순 확인 동작에 섞지 않는다. 설명만 한 항목과 실제 사용자 확인 완료를 구분하고, 답변을 받으면 이 진행표와 미확인 항목을 갱신한다.

동작이 설명과 다르거나 handoff와 충돌할 가능성이 발견되면 현재 화면·기대 동작·영향을 기록해 사용자에게 보고한다. 명세가 실제 구현을 잘못 설명한 경우와 기능/계약 충돌을 구분하며 기능을 임의로 변경하지 않는다.

## 목적과 기준

파트별 handoff 명세를 기준으로 프론트의 API 연동 준비 상태를 확인하고, 백엔드·AI 담당자가 그 계약을 프론트의 Swagger에서 열람할 수 있도록 정비한다. 백엔드·AI 개발 서버 없이 프론트 실행·빌드·문서 생성·관련 검사가 가능하도록 의존성을 해소한다.

**handoff가 계약의 기준이다.** 프론트 코드는 계약 적용 상태를 확인하는 대상이고, 기존 개발 서버 코드는 로컬 의존성과 기존 동작을 파악하는 대상이다. 기존 개발 서버 구현이나 `api-server/docs/openapi.js`를 새 명세의 기준으로 삼지 않는다. handoff에 모호하거나 상충하는 내용이 있으면 임의로 확정하지 않는다.

## 현재 기능 보존과 충돌 보고 원칙

아래는 2026-11-09 사용자가 추가로 명시한 기준이며, 기존 계획의 기능 변경 관련 표현보다 우선한다.

- 현재 프론트에 구현되어 동작하는 기능을 완성된 기능 범위로 본다. 이번 작업에서 기능을 추가하거나 기존 기능·화면 동작을 바꾸지 않는다.
- handoff는 연동 계약의 기준이지만, 이를 맞추기 위해 현재 동작하는 기능을 변경·축소·제거하는 조치는 적용하지 않는다. 현재 기능 보존을 우선하고 계약과의 차이는 별도로 기록한다.
- 먼저 [프론트 기능 및 동작 명세서](프론트%20기능%20및%20동작%20명세서.md)에 사용자 입력, API 요청, 응답 처리, 화면 표시, 저장·복원, 취소·오류·중복 방지 흐름을 보존 기준으로 정리한다. 코드에서 확인한 내용과 실제 실행으로 검증한 내용을 구분한다.
- 기능 목록과 handoff를 대조할 때 충돌이 확인되거나 원격 연동 시 기능이 깨질 가능성이 보이면 사용자에게 먼저 보고한다. 보고에는 현재 동작, 충돌하는 명세, 예상 문제와 영향, 현재 기능을 보존할 해결 방향을 포함한다.
- 사용자 확인 전에는 해당 기능을 변경하거나 제거하지 않는다. 대조표에 충돌을 기록하고, 보고 내용과 사용자 확인 결과는 변경 협의 기록에 남긴다. 조사와 충돌과 무관한 작업은 계속할 수 있다.
- 리팩토링은 현재 동작을 보존하는 책임 분리·중복 정리 등을 대상으로 한다. 불필요한 코드·타입·패키지는 화면·서비스·복원·검사 등 실제 참조와 사용 여부를 확인한 뒤 제거한다. handoff에 없다는 이유만으로 불필요하다고 판정하지 않는다.

## 진행 순서와 현재 상태

1. 저장소 상태·지침·기존 검증 이력을 확인한다. 초기 확인 완료.
2. 현재 프론트의 기능과 동작을 문서화해 보존 기준을 확립한다. 코드 기반 명세 작성 및 일부 독립 검사 완료. 사용자 브라우저에서 홈·발자국·자료 Drawer·Project Timeline·Growth Journey·설정의 주요 동작을 대조했다. 에이전트 브라우저·서버 전체 동작 검증은 미완료다.
3. 해당 기능과 공개 API 20개의 handoff·프론트·개발 서버 코드 대조를 완료했다. 차이와 기능 영향은 대조표에 기록했다. 실제 분리 서버 연동은 미검증이다.
4. 개발 서버의 공유 DB·다른 서버 파일 참조와 프론트의 빌드·검사 의존성을 조사했다. Swagger와 자동 프론트 검사의 서버 소스·fixture·DB 의존성을 해소했다. 초기 Express import 실패 검사는 이전 이력이며 현재 대역 기반 검사는 통과한다.
5. 현재 기능을 보존할 해결 방향을 정리하고 필요한 사용자 확인을 기록한다. 기능 변경을 전제로 계약에 맞추지 않는다.
6. handoff 기반의 독립 OpenAPI 명세와 Swagger 생성 경로를 구성했다. 공개 API 20개와 서버 전용 API 6개를 문서화하고 내부 인증·필수 필드·상태별 응답·JSON 예시를 검사했다.
7. 서버 폴더 없는 임시 작업 디렉터리에서 기존 의존성 재사용 및 npm ci 새 설치를 각각 확인했다. API 대역 기반 검사 39개·세션 복원·빌드·Swagger 생성까지 통과했다.
8. 미사용 초기 프론트 코드와 추가 정리 후보를 점검했다. 사용자 푸시 전 인계 기록을 작성했으며 해당 코드의 삭제·단순화와 서버 폴더 제거는 미실행이다.

현재 기능을 보존하는 범위에서 작업하고, 기능에 영향을 줄 가능성이 있는 조치는 건별 보고·사용자 확인 전 적용하지 않는다. 확인 후에도 변경 단위마다 검증 결과를 공유한다. 차이 발견을 수정 승인이나 검증 완료로 기록하지 않는다.

## Swagger 구성 방향

이 폴더의 [backend.openapi.json](openapi/backend.openapi.json)과 [ai.openapi.json](openapi/ai.openapi.json)에 handoff 계약을 작성했다. `scripts/build-swagger.mjs`가 두 파일을 읽어 정적 Swagger를 생성한다. 서버 소스·DB 모듈을 import하지 않는다. 실제 주소가 정해지기 전에는 handoff의 설명용 HTTPS Base를 표시한다.

각 API의 호출 방향, 담당 파트의 제공 책임, ID 사용 순서와 공개·내부 Base 설명을 표시한다. handoff 원문 21개를 함께 정적 생성하고 Swagger에서 링크로 열 수 있다.

공개 API와 서버 간 내부 API는 호출 주체·접근 범위를 구분해서 표시한다. 내부 API를 프론트 호출 경로로 연결하거나 내부 토큰을 브라우저에 넣지 않는다. Swagger 제공은 서버 구현 완료나 실제 원격 연결 성공을 뜻하지 않는다.

## 이번 범위와 후속 범위

이번에는 계약 대조, 독립 Swagger, 프론트 설정·의존성 정리, API 대역 기반 로컬 검증을 진행한다. 서버 구현을 대신하거나 실제 AI·개인 DB를 사용한 검증을 전제로 하지 않는다. 서버 폴더는 의존성과 보존 대상을 확인하기 전에 삭제하지 않는다.

실제 원격 주소·CORS·인증·업로드 제한·서버 간 전달·영속 저장의 최종 연결 검증은 각 서버 준비 후 별도 작업이다. 기존 2026-11-06 검사 이력은 참고 근거이며 이번 작업의 재검증 결과가 아니다.
