# 로컬 서버 의존성 점검

작성일: 2026-11-09 · 상태: 초기 검색 결과, 전체 조사 전

## 점검 원칙

프론트의 실행·빌드·Swagger·검사 의존성과 개발 서버 내부의 DB·파일 의존성을 구분한다. 독립된 명세 파일을 빌드 시 읽는 것은 허용 가능한 문서 생성 방식이다. 다른 서버의 소스나 저장소를 직접 읽어야 동작하는 구조는 원격 분리 계약과 구분해야 한다.

서버 코드의 로컬 구현을 원격 서버에 그대로 요구하지 않는다. 서버 폴더·DB·업로드·환경설정의 보존 여부는 별도 조사하며 비밀값을 기록하지 않는다. 현재 분리·삭제는 수행하지 않았다.

## 추가 조사

- 백엔드 → AI 요청 본문이 공유 DB 조회를 전제하는 ID 전달인지, handoff의 스냅샷 전달인지 확인.
- 다른 서버 폴더·원본 파일·프롬프트·로컬 경로의 직접 참조를 실제 호출 경로까지 추적.
- sessionStorage의 화면 복원과 서버 영속 데이터·원본 저장을 구분.
- 서버 폴더의 Git 추적 여부와 추적되지 않는 DB·원본·개인 설정의 보존 방안 확인.
- 검사의 임시 DB·포트·파일·모델 호출 부작용 확인 후 실행 대상을 선정.
- 서버 폴더를 삭제하지 않고 독립 환경에서 실행·빌드·Swagger·관련 검사를 검증할 방법 마련.
