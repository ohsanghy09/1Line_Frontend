# 프론트 호환성 점검 결과

## Journey v5 추가 점검 — 2026-11-06

원문 근거 카탈로그 → 모델의 ID 선택 → 정확한 {recordId,quote} 복원 방식으로 보완했다. 모델은 합성 응답을 사용하고 임시 DB에서 검증했다. AI 라우트의 v5 응답을 기존 백엔드 저장 함수에 전달한 뒤 실제 프론트 응답 검증기로 확인했다. v5 저장·stale=false·기존 v4 응답 호환·홈 기록 불변을 확인했다. 공개 API·DB 스키마·프론트는 변경하지 않았다.

AI 서버 전체 자동 검사 65개와 백엔드/프론트 Journey 관련 검사 21개가 통과했다. 근거 ID 없음·활동 불일치·동일 기록만의 전후 비교·문맥/후보 한도 초과를 거절하고, 요약만 있는 기록·원문 공백/유니코드·긴 구간의 인용을 검사했다. 실제 모델 호출·사용자 DB 쓰기·브라우저 UI·새 분리 서버 배포 검증은 수행하지 않았다. 아래 53개 점검은 별도로 수행한 기존 공개 API 호환성 이력이며 v5 내부 모델 검증을 대신하지 않는다.

## 판단

다른 OS·언어·프레임워크라는 이유만으로 현재 프론트와 연동할 수 없는 구조는 아니다. 정의된 공개 HTTP/JSON 계약을 구현하면 현재 프론트가 응답을 읽고 요청할 수 있음을 아래 검사로 확인했다. 다만 실제 백엔드·AI 서버의 데이터 처리와 배포까지 성공했다고 판단한 것은 아니다.

문서만 전달하는 기준으로 계약·프롬프트·논리 데이터·서버 간 전달을 정의했다. 기존 개발 서버와 공유 DB가 없어도 구현하도록 구성했으며 별도 소스 참조는 요구하지 않는다. 인증/사용자 범위·실제 주소는 배포 때 적용할 연결 정보다.

## 수행 방법

1. 정의서의 JSON 예시와 필드 규칙으로 합성 응답을 준비했다. 실제 사용자 데이터·실제 모델 결과를 사용하지 않았다.
2. 현재 프론트의 실제 서비스 함수와 응답 검증을 변경 없이 실행했다. 홈 화면·컴포넌트·백엔드·AI 실행 코드를 수정하지 않았다.
3. 합성 fetch 응답으로 요청·본문·분기·응답 수용 여부를 확인했다.
4. 기존 서버 구현을 사용하지 않는 Python 표준 HTTP 합성 서버로 같은 사례를 다시 실행했다. JSON 오류 상태·multipart 업로드·조회·POST/PATCH/DELETE 전송과 응답 처리를 확인했다.

Python 서버는 기대 응답을 돌려주는 검사 대역이며 활동 저장·모델 분석·분산 잠금의 완성 구현이 아니다. 서로 다른 언어 사이의 실제 HTTP 전송을 검사했지만 같은 개발 PC에서 실행했으며 Linux/macOS 호스트나 브라우저 보안 정책을 검증한 것은 아니다. 검사 실행 코드는 전달물에 포함하지 않는다. 각 파트는 시나리오를 자신의 도구로 구현한다.

## 발견해 보완한 사항

- 일반 활동 정보는 ActivityMetadataValues, 근거 포함 AI 종합은 ActivityMetadataAnalysis로 구분했다.
- Journey 비교/아이콘의 값 없음은 공개 응답에서 생략하며 null을 보내지 않도록 명시했다. 근거 배열도 존재할 때 []/null이면 프론트가 거절함을 명시했다.
- ChatReply.sourceUrl은 없으면 생략하고, stage/files[].previousVersion은 null을 허용하되 키를 포함하도록 명시했다.
- 활동 선택용 nullable 값과 발자국 화면의 표시 문자열·상태 enum을 구분했다.
- 공개 백엔드 JSON 1MiB 제한과 내부 원본 base64 전송의 더 큰 크기 요구를 구분했다.
- 내부 경로를 파트마다 다르게 정하지 않도록 기본 HTTP 경로·Bearer 인증·job 스냅샷 응답·revision 충돌 처리를 문서화했다. 이 내부 규격은 새 구현 대상이며 기존 개발 서버에 적용 완료된 기능은 아니다.

## 아직 확인할 수 없는 부분

- 각 파트가 새로 구현할 서버의 실제 저장·검색·원본 보존·삭제 원자성·잠금·재시작 복구.
- 실제 AI의 파일/링크 해석·활동 매칭·근거 정확성·모델 한도·분석 품질.
- 새 내부 전달 규격의 양 서버 간 실행·게시·버전 충돌·캐시 무효화. 공개 프론트 검사 대역은 이를 대신하지 않는다.
- 실제 HTTPS 주소·CORS preflight·브라우저 인증·쿠키/헤더·배포 플랫폼의 파일/시간 제한.
- 브라우저의 버튼·모달·초점·화면 크기별 전체 시나리오.

따라서 현재 판정은 **공개 프론트 계약 호환 확인**이다. 최종 정상 연동은 실제 서버 두 개를 연결하고 검증 시나리오를 수행한 뒤 확정한다. 문서가 있다는 사실만으로 최종 성공을 보장하지 않는다.
