# 데이터베이스 정의서

기준일: 2026-11-06. [ERD](ERD.md) · [저장·삭제](저장과_삭제_규칙.md)

이 문서는 기존 데이터를 설명하는 논리 모델이다. DB 제품·물리 타입·테이블명·파일 저장 위치는 각 파트가 선택한다. 기존 DB 파일과 마이그레이션 코드는 전달하지 않는다. TEXT/INTEGER/BLOB은 기존 저장 표현으로, 각 DB의 문자열/정수/바이너리 또는 객체 저장소 참조로 대응할 수 있다. 공개 JSON·참조 무결성·유일성과 삭제 결과를 보존한다. 실제 사용자 입력 전 예시 활동을 자동 생성하지 않는다.

## 컬럼 전체 목록

아래 id는 비빈 문자열의 유일한 기본 식별자다. 새 구현에서는 PK·NOT NULL을 명시적으로 보장한다. ‘필수’는 값 필수, ‘허용’은 null 허용이며, 기존 저장 표현과 새 DB의 실제 DDL은 구분한다. 모든 컬럼의 도메인 제약은 API 정의를 함께 따른다.

### activities

| 컬럼 | 타입·NULL·제약 | 용도 |
| --- | --- | --- |
| id | TEXT PK | 활동 ID |
| name | TEXT 필수 UNIQUE | 실제 활동명, 정확한 같은 이름 중복 금지 |
| category | TEXT 허용 | 동적 활동 유형 |
| status | TEXT 허용 | 진행 중/완료/null, 선택 DB 제약 또는 서버에서 검사 |
| role | TEXT 허용 | 사용자 역할 |
| period | TEXT 허용 | 상세 화면용 기간 문자열 |
| summary | TEXT 허용 | 활동 전체 요약 |
| start_date, end_date | 각각 TEXT 허용 | YYYY-MM 또는 YYYY-MM-DD |
| updated_at | TEXT 허용 | 최근 활동 변경 시각 |
| metadata_status | TEXT 허용 | idle/queued/running/ready/failed, 미설정 조회는 idle |
| metadata_fingerprint | TEXT 허용 | 마지막 성공 분석 입력 해시 |
| metadata_error | TEXT 허용 | 사용자용 분석 실패 안내 |
| metadata_model | TEXT 허용 | 마지막 AI 메타정보 모델 |
| metadata_updated_at | TEXT 허용 | 마지막 성공 종합 시각 |

최근 변경 시각은 실제 저장·수정·직접 변경에서 갱신하며 서버 실행 시각을 사용하지 않는다. 새 DB 초기화나 기존 DB 마이그레이션은 각 파트의 배포 절차로 제공한다.

### analyses

| 컬럼 | 타입·NULL·제약 | 용도 |
| --- | --- | --- |
| id | TEXT PK | 분석 초안 ID |
| conversation_id | TEXT 필수 | 대화 묶음, 별도 FK 없음 |
| message | TEXT 필수 | 입력 글 또는 링크. 파일과 보낸 글은 여기에는 남을 수 있음 |
| reply | JSON 대응 값 | 접수/분석 중에는 null 또는 명시적 대기 상태. 완료 상태일 때 ChatReply 또는 activity-update 중간값 필수 |
| created_at | TEXT 필수 | 접수 시각 |

확정 기록과 분리한다. 일반 대화·직접 수정도 analyses에는 남는다. 삭제 후에는 general 안내로 교체해 카드 재저장을 막는다.

### files

| 컬럼 | 타입·NULL·제약 | 용도 |
| --- | --- | --- |
| id | TEXT PK | 원본 파일 ID |
| analysis_id | TEXT 필수 FK analyses.id | 원본이 속한 분석 |
| name, mime_type | 각각 TEXT 필수 | 실제 파일명·업로드 MIME |
| size | INTEGER 필수 | 원본 byte 수. 0보다 크며 업로드 크기 한도 검사 |
| content | 바이너리 또는 저장소 참조 필수 | 실제 원본 bytes를 조회할 수 있어야 함. 공개 API에 저장소 자격정보를 노출하지 않음 |

링크는 files 행을 만들지 않는다. 원본 조회는 분석/파일 관계로 찾는다. 파일별 분석 요약·버전 FK 컬럼은 없다.

### records

| 컬럼 | 타입·NULL·제약 | 용도 |
| --- | --- | --- |
| id | TEXT PK | 확정 기록 ID |
| activity_id | TEXT 필수 FK activities.id | 확정 연결 활동 |
| analysis_id | TEXT 필수 UNIQUE FK analyses.id | 같은 초안 중복 저장 방지. 현재 홈 확정은 초안 참조 필수 |
| message | TEXT 필수 | 독립 텍스트 경험 원문. 파일·링크 신규 확정은 '' |
| reply | JSON 대응 값 필수 | 확정 ChatReply 사본. 초안과 이후 내용이 다를 수 있음 |
| created_at, updated_at | 각각 TEXT 필수 | 최초 저장·마지막 수정 시각 |

### timeline_events

| 컬럼 | 타입·NULL·제약 | 용도 |
| --- | --- | --- |
| id | TEXT PK | 변화 이벤트 ID |
| record_id | TEXT 필수 FK records.id ON DELETE CASCADE | 확정 기록 삭제 시 자동 삭제 |
| change_json | TEXT 필수 | {before,after,category,evidence:[문장 또는 파일명],reason?} |
| is_turning_point | INTEGER 필수 DEFAULT 0 | 신규 이벤트는 0. 조회에서 boolean 변환 |
| created_at | TEXT 필수 | 이벤트 생성 시각 |

### ai_chat_jobs

| 컬럼 | 타입·NULL·제약 | 용도 |
| --- | --- | --- |
| id | TEXT PK | ai-UUID |
| request_key | TEXT 필수 UNIQUE | 요청 중복 방지 키 |
| fingerprint | TEXT 필수 | 메시지·URL·대화·파일명/MIME/bytes 해시 |
| analysis_id | TEXT 필수 UNIQUE FK analyses.id | 작업별 초안 |
| kind | TEXT 필수 | chat/link |
| status | TEXT 필수 | queued/running/completed/failed |
| phase | TEXT 필수 | preparing/analyzing/persisting/completed |
| error | TEXT 허용 | {code,error} JSON |
| input_json | TEXT 필수 | {message,sourceUrl,files:[{id,name}]} JSON |
| created_at, updated_at | 각각 TEXT 필수 | 접수·상태 변경 시각 |

### journey_analyses

| 컬럼 | 타입·NULL·제약 | 용도 |
| --- | --- | --- |
| id | TEXT PK | 저장 분석 ID |
| source_fingerprint | TEXT 필수 | 입력 스냅샷 SHA-256. 삭제 시 deleted:UUID로 강제 무효화 |
| record_count | INTEGER 필수 | 분석 당시 확정 기록 수 |
| result_json | TEXT 필수 | GrowthJourney의 source·summary·badges·options·events |
| model, prompt_version | 각각 TEXT 필수 | 공급자 모델·journey-v5 등 |
| created_at | TEXT 필수 | 저장 시각, 최신 결과 선택 기준 |

## 인덱스·제약과 JSON

필수 유일성: activities.name, records.analysis_id, ai_chat_jobs.request_key/analysis_id. 기본 식별자는 모두 유일하고 값이 있어야 한다. 참조 대상 존재·enum·유효 날짜·JSON 구조는 선택한 DB 제약과 서버 검증으로 보장한다. 검색·정렬·관계 조회용 인덱스는 데이터량과 선택 DB에 맞춰 설계한다. 이전 개발용 시간 기반 analysis_jobs는 공개 기능 재현에 필요 없어 논리 모델에서 제외한다.

reply JSON과 API 구조는 [공통 계약](../common/공통_데이터_계약.md)이 원본 설명이다. 주요 대응은 `records.activity_id → reply.analysis.activity.id`, `files.id/순서 → reply.analysis.files[]`(동일 이름 파일을 구분하고 응답 순서를 일치시킴), `reply.analysis.changes[] → timeline_events.change_json`이다. 모델의 file:id 근거는 카드 변환 시 파일명으로 치환하므로 JSON 근거에 실제 FK는 없다.

`result_json` 안의 evidence.recordId, event.activity.id는 논리 참조다. 독립 FK가 없어 삭제 시 애플리케이션이 모든 성장 결과를 비운다. API의 analysis 메타정보는 DB 컬럼과 현재 fingerprint를 읽어 덧붙이며 result_json에 최신 상태가 고정 저장되는 구조가 아니다.

개인 개발 DB 데이터는 전달하지 않는다. 새 DB는 각 파트가 준비한다. 원본을 별도 저장소에 둘 경우 files.content에 해당하는 실제 bytes 접근과 삭제 일관성을 보장한다.
