## 공통 모델 호출

기존 분석의 참고 설정은 OpenAI 구조화 응답, reasoning.effort=low, max_output_tokens=8192, store=false, 자동 재시도 0회다. 모델·SDK·언어는 선택할 수 있지만 공개 응답과 검증 규칙은 보존한다. 선택한 모델이 같은 옵션을 지원한다고 가정하지 않는다. 홈·활동·Journey·남은 파일 분석은 각각 한 번의 모델 호출이며 텍스트 분류 전용 추가 호출은 없다. 링크 수집은 HTTP 요청이며 모델 호출 수에 포함하지 않는다.

키/모델 미설정·인증·연결·한도·시간 초과·거절·미완료·스키마 오류를 구분한다. 제공자 원문·키·입력을 사용자 오류에 노출하지 않는다. 모델 출력 객체는 정의되지 않은 추가 필드를 거절한다. 이 문서에서 Text는 trim 후 비빈 string 최대 20000자, Identifier는 trim 후 비빈 string 최대 200자를 뜻한다. 특정 언어 클래스나 검증 라이브러리 이름이 아니다.

## 홈 문맥

2026-11-13 Spring 호환 처리: 파일·링크 기록 등 DB의 message가 빈 문자열이면 홈 문맥 records[].message는 JSON null로 보낸다. 원본 파일·요약·DB·채팅 원문을 삭제하는 처리가 아니다. 실제 내용이 있는 message는 공백·줄바꿈을 포함해 유지한다. 활동 종합·Journey의 message 빈 문자열 허용 규칙은 그대로다.

AI는 백엔드의 [서버 간 전달 계약](../../common/handoff/서버간_데이터_전달_계약.md)으로 활동 최대 50개(최근 변경순), 포함 활동의 확정 기록 최대 50개(최초 저장 최신순)를 받는다. 같은 시각에는 안정적인 보조키를 사용한다. 활동은 id,name,category,summary,role,status,startDate,endDate, 기록은 id,activityId,message(null 허용),summary다. JSON 100000자 한도이며 넘으면 조용히 잘라내지 않고 문맥 오류다. selection은 전체/포함 건수와 truncated를 제공한다. 홈은 이 선택 문맥을 사용하며 전 기록을 비교했다고 가정하지 않는다.

최근 완료 chat 작업 6개에서 user/assistant 각각 최대 2000자씩을 recentMessages 최대 12개로 만든다. 저장 기록의 실제 활동 ID, 직접 수정의 updatedActivityId, 기존 활동 제안을 이용해 activeActivityId를 정한다. 직전 new/unresolved가 미확정이면 activeActivityPending=true로 다른 기존 활동에 잘못 수정하는 것을 막는다.

HomeModelInput은 message,sourceUrl,linkContent,context,files:[{id,name}],activeActivityId,activeActivityPending,recentMessages다. 모델에 파일 원본도 별도 입력 part로 전달한다. 사용자 내용 속 지시와 서버의 분석 지시를 구분한다.

### 파일·링크

지원 확장자: `.txt .md .json .csv .tsv .html .xml .py .js .ts .pdf .doc .docx .rtf .odt .ppt .pptx .xls .xlsx .png .jpg .jpeg .webp .gif`.

파일은 10개·각 10MiB·합계 25MiB, 빈 파일 불가다. 텍스트 계열은 UTF-8-sig로 디코딩해 각 100000자까지 input_text로 보낸다. 이미지는 data URL input_image, 기타 문서는 base64 input_file이다. 이 처리가 모든 Office/PDF 레이아웃의 정확한 분석 품질을 검증했다는 뜻은 아니다. 실행 가능한 스크립트 파일도 내용 데이터로 취급한다.

링크는 HTTP(S), 사용자정보 없음, 포트 기본/80/443만 허용한다. 각 대상/리다이렉트 DNS를 5초 내 확인하고 전역 공개 IP만 허용한다. HTTP는 15초 제한, 최대 네 번의 대상 요청, 본문 2MiB 이하·추출 텍스트 1~100000자다. text/html,text/plain,application/xhtml+xml만 지원하며 script/style/noscript는 텍스트에서 제외한다. 로그인·자바스크립트 실행으로만 보이는 본문 수집은 지원하지 않는다. 실제 전환에서는 DNS 검사와 연결 사이 재바인딩 등 네트워크 정책도 운영 경계에서 검토한다.

### 홈 모델 출력과 변환

HomeResponse는 kind(general/analysis/activity-update),content,analysis(HomeAnalysis/null),update(ActivityUpdate/null)다. analysis 종류와 analysis 존재, update 종류와 update 존재가 일치해야 한다. 파일·링크를 general이나 activity-update로 무시하면 502다.

HomeAnalysis는 activity:{match,id,name,confidence,category?},materialType,stage,summary,changes 배열(최대 10),files 배열(각 항목 {id,materialType}, 최대 10)이다. 기존 활동 ID는 실제 문맥에 있어야 하고 이름은 서버 값으로 보정한다. new/unresolved의 ID는 null이어야 한다. 파일 ID는 실제 첨부 각각 정확히 한 번만 포함해야 한다.

변화 근거는 현재 입력·링크 본문·텍스트 파일 본문 또는 연결한 동일 활동의 기록 message/summary의 연속 원문이어야 한다. 첨부는 file:실제ID 인용을 허용하고 카드 변환에서 실제 파일명으로 치환한다. 다른 활동 기록·없는 파일 근거는 거절한다.

모델 출력을 공개 카드로 변환하는 서버 처리는 kind를 다음과 같이 결정한다: 링크→link-analysis, 파일 여러 개→batch-analysis, 단일 파일+변화→file-analysis, 단일 파일+변화 없음→no-change, 파일 없음→text-analysis. groups는 파일 유형별 count, previousVersion은 null, suggestedSaveMode는 changes가 있으면 record-change 아니면 archive다. 신규 활동·미확정 카드 표시가 기본 파일 카드보다 우선할 수 있다.

activity-update는 activityId,activityName,updates:[{field,value}]다. field는 role/status/summary/startDate/endDate이며 1~5개·중복 금지, value=null은 명시적 삭제다. AI는 대상 실재·날짜·상태를 검증하고 백엔드는 완료 작업·첨부 없음·날짜 순서·허용 필드를 다시 검증한다.

## 활동 전체 정보

활동 종합 입력은 activity{id,name,category},previous{summary,status,role,start_date,end_date},records[{id,message,summary,changes,savedAt,updatedAt}],files:[[recordId,fileId,name]],recordCount,sourceFingerprint로 구성된다. 기록 100개·JSON 250000자 초과는 422, 기록 없음도 422다. 원본 bytes는 다시 분석하지 않는다.

ActivityMetadataAnalysis(근거 포함 분석) 출력은 summary Fact 필수, status/role Fact 또는 null, period.start/end DateFact 또는 null이다. 일반 활동 정보 ActivityMetadataValues의 문자열 필드와 혼동하지 않는다. Fact는 value와 evidence 1~10개다. quote는 같은 기록 message/summary에 있어야 하고 날짜는 달력·기존 반대 날짜와 순서를 검증한다. null은 백엔드가 이전 값을 보존한다. fingerprint는 백엔드가 발급한 요청값을 그대로 반환한다. 백엔드는 [저장 규칙](../../backend/handoff/저장과_삭제_규칙.md)에 따라 저장 직전 현재 상태와 대조한다.

## Journey journey-v5

입력 기록은 id,activityId,activityName,message,summary,changes,savedAt,updatedAt,activity{category,role,summary,startDate,endDate},files[{id,name}]다. 미저장 초안·빈 활동·파일 BLOB은 제외한다. 백엔드가 일관된 정렬·직렬화로 스냅샷 fingerprint를 발급해 문맥과 함께 보내며 AI는 이를 재직렬화해 계산하지 않고 그대로 돌려준다. 기록 최대 100개·JSON 250000자이며 초과 시 부분 분석으로 가장하지 않고 422다.

AI 서버는 받은 문맥으로 모델 전용 입력 {records,recordCount,evidenceCatalog}를 만든다. records는 위 필드 중 최상위 message/summary를 제외한 메타정보다. 이 두 본문은 evidenceCatalog의 원문으로 전달해 중복 입력을 피한다. sourceFingerprint는 모델이 생성하지 않으며 서버가 보관해 응답에 그대로 붙인다. 공개 문맥 API와 백엔드→AI 요청은 바꾸지 않는다.

evidenceCatalog 항목은 {id,recordId,source,quote}다. source는 message 또는 summary이며 quote는 해당 필드의 연속 원문이다. 줄바꿈 또는 문장 종결 기호(.!?。！？) 다음 공백으로 나누고 앞뒤 공백만 제거한다. 800자 초과 구간은 400~800자 사이 마지막 일반 공백에서, 없으면 800자에서 나눈다. 내부 공백·문자·유니코드 정규형은 바꾸지 않는다. 같은 기록의 동일 인용문은 첫 후보만 남기되 서로 다른 기록은 같은 문장도 별도로 유지한다. ID는 요청 안에서 evidence-1부터 순서대로 부여하며 다른 요청에서 재사용하거나 영속 저장하지 않는다. 타 언어도 같은 연속 원문·길이·참조 규칙을 지키되 문자 수는 유니코드 코드 포인트 기준이다.

후보 최대 2000개, 실제 모델 입력 JSON도 250000자 이하다. 원래 기록 100개·원문 문맥 250000자 제한도 유지한다. 후보 추가로 한도를 넘으면 모델 호출 전에 422 journey_context_limit, 후보가 없으면 422 journey_evidence_missing이다. 일부 기록을 몰래 제외하거나 문맥 한도를 우회하지 않는다.

모델 출력: summary{title,description,evidence}, typeOptions[{value,label,icon}],axisOptions[{value,label}],badges[{label,icon,evidence}],events[{activityId,type,axis,title,description,comparison:null 또는 {before,after},evidence}]. 모델 전용 evidence는 [{evidenceId}]이며 카탈로그의 실제 id만 선택한다. recordId/quote를 모델 출력 필드로 받지 않는다. 모델은 이벤트/배지 ID·월·전체 선택지를 직접 발급하지 않는다. 유형/분야 최대 8개, 라벨 1~40자, icon 1~16자, 배지 10개·이벤트 20개. 배지 근거 1~5개, 이벤트 1~10개, 요약 1~20개이며 성장 판단 유보 시에도 요약 근거는 필수다.

journey-v5 후처리는 다음 순서다.

0. 모든 evidenceId가 이번 카탈로그에 있는지 검사하고 서버가 {recordId,quote}로 복원한다. 각 근거 배열의 동일 recordId/quote 중복은 제거한다. 알 수 없는 ID를 추측해 다른 후보에 연결하거나 모델을 자동 재호출하지 않는다. 백엔드·프론트·DB에는 evidenceId를 전달하지 않는다.
1. 이벤트에서 실제 사용하는 분류만 남긴다.
2. 라벨을 NFKC·공백 정리·casefold로 비교한다. 정확히 동일한 정규화 라벨의 별칭만 하나로 합치고 이벤트 참조를 치환한다. 의미가 비슷한 서로 다른 라벨을 임의 합치지는 않는다.
3. 동일 value에 다른 라벨, all/전체/전체 분야 같은 예약 값, 미등록·모호한 참조는 거절한다. 유형 icon의 공백도 정리한다.
4. 모든 요약·배지·이벤트의 recordId/quote를 실제 기록 message/summary와 대조한다. 이벤트 활동이 근거 기록 중 하나와 연결돼야 하며 comparison에는 서로 다른 기록 2개 이상이 필요하다.
5. 서버가 전체 선택지, 임시 event-N/badge-N, 실제 활동명, 근거 중 가장 늦은 savedAt의 YYYY-MM을 붙인다. comparison.evidence도 인용에서 만든다.
6. 백엔드가 응답·현재 해시·개수·근거·월·활동을 재검증하고 최종 UUID를 발급해 저장한다. 어떤 검증 실패에도 자동 모델 재호출은 없다.

미등록 근거 ID·복원 후 원문 불일치·활동 불일치·서로 다른 기록이 없는 비교는 502 journey_evidence_invalid다. AI 오류 메시지에는 진단 UUID를 포함하며 서버 로그에 동일 diagnosticId, promptVersion, reason, location만 남긴다. reason은 unknown_evidence_id/record_or_quote_mismatch/activity_mismatch/comparison_needs_distinct_records, location은 summary.evidence[0]/events[0].activityId 등 서버가 만든 경로다. 사용자 원문·모델 응답 전문·기록 ID·키는 로그에 남기지 않는다. 백엔드 공개 오류는 기존 {error} 형식을 유지하며 진단 ID가 있는 메시지를 전달한다. 분류/모델 스키마 등 다른 오류까지 이 코드로 합치지 않는다.

변경 범위는 Journey 내부 모델 계약이다. 공개 SavedJourney 근거는 계속 {recordId,quote}, 기존 저장 결과·DB 스키마·스냅샷 해시·홈·활동 정보 분석은 유지한다. 이전 promptVersion 결과도 조회 가능하다. 근거 존재 검증은 분석 서술의 의미적 타당성을 보장하지 않으므로 프롬프트의 추측 금지 규칙을 함께 지킨다.

## 삭제 후 남은 파일

백엔드는 삭제 대상 기록에서 제외할 파일을 뺀 실제 원본만 AI에 보낸다. 문맥은 현재 활동 id/name/category만이며 records=[]다. 이전 요약·대화·삭제 파일 본문을 넣지 않는다. 고정 지시문은 [프롬프트 정의](프롬프트_정의서.md)에 원문을 남긴다. 한 번의 홈 분석 뒤 changes를 강제로 []로 바꾸고 카드로 변환한다. 기존 활동 연결·activityCreated는 백엔드가 이전 확정값으로 복원한다. 모델이 general로 답하는 등 예상 계약을 위반하면 삭제 성공으로 처리하지 않는다.
