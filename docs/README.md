# 프로젝트 문서

개발 문서와 참고 자료를 `docs/` 아래에 모아 관리한다.

## 작업을 이어갈 때

2026-11-06 추가 결정: 새 활동 여부는 AI 서비스가 판단하며, 새 활동이면 AI 서비스가 DB에 생성하고 기존 활동이면 해당 활동에 연결한다. 프론트의 새 활동 생성 화면은 후속 구현 대상에서 제외한다. 생성/매칭된 활동 ID의 응답 계약과 기록 저장 시점의 연계는 실제 연동 시 확정하며 현재 목 분석에는 자동 생성이 연결되지 않았다.

**다음 작업은 [2026-11-06 인수인계](integration/다음_작업_인수인계.md)부터 읽는다.** 채팅 수정 모달은 기존 활동 선택·자료 유형만으로 통일했고, 기록·저장·전체 저장은 확인 모달 없이 유효한 기존 활동으로 바로 저장하도록 적용했다. 새 활동 생성 흐름은 아직 제공하지 않는다. [현재 동작](chat/구현_기능/카드_기록_수정.md)을 참고한다. 실제 서버·AI 연동과 배포는 미완료이며 인수인계의 역할 분담과 실제 연동 예정 구조는 유지한다.

2026-11-06 최신 결정: 실제 연동은 **홈 분석: 프론트→AI 서비스**, **기록·자료 저장: 프론트→백엔드**, **나의 발자국·Timeline: 백엔드에서 조회**, **Growth Journey: 백엔드·AI 생성/저장 후 프론트가 백엔드에서 조회**로 진행한다. AI 모델·공급자와 상세 계약은 미정이며 현재 호출 코드는 아직 전환하지 않았다. 아래 이전 기록의 호출 주체 미정 안내보다 이 결정과 [API 계약 안내](integration/API_계약/문서_안내.md)를 우선한다.

2026-11-05 최신 작업: **백엔드·AI 연동 준비 문서와 Swagger를 작성하고, Swagger를 프론트 빌드에 포함했다.** 프론트 주소의 `/swagger/`로 직접 접속하며 기존 메뉴에는 링크를 추가하지 않았다. AI 모델·공급자·호출 주체는 미정이며 기존 요청·응답값을 유지한다. 실제 백엔드·AI 연결, 터널 설정, Vercel 배포는 아직 진행하지 않았다.

연동·배포 작업을 이어갈 때는 다음 순서로 읽는다.

1. [연동 작업 계획](integration/작업_계획.md): 진행 내용·완료 범위·다음 단계.
2. [화면별 구현 현황 안내](integration/현재구현_현황_정리/문서_안내.md): 현재 화면·API·목/실제 데이터 구분. 나의 발자국 관련 문서는 하위 폴더에 모았다.
3. [API 계약 안내](integration/API_계약/문서_안내.md): 백엔드·AI 각각의 요청/응답 초안과 미확정 협의사항.
4. [Swagger 사용 안내](integration/API_계약/Swagger_사용안내.md): 정적 생성·실행·Vercel 설정·검증 결과. 소스 확인은 여기서 연결된 생성 스크립트·명세·설정 파일을 따른다.

배포·실제 연동을 진행할 때는 Vercel 배포와 `/swagger/` 직접 접속을 확인하고, 외부에서 접근 가능한 백엔드 주소·환경 변수·CORS를 구성한다. 터널 사용 시 이번 개발 테스트는 접근 제한 없이 진행하기로 했지만 터널 자체는 아직 설정하지 않았다. 문서 작성 완료를 계약 합의나 실제 연동 완료로 기록하지 않는다. 채팅 수정 모달 통일과 기존 활동으로 바로 저장은 적용했으며, 새 활동 생성 진입과 실제 연동은 후속 범위다.

기존 화면 상태(2026-11-04): 나의 발자국은 현재 범위에서 마무리했다. **Growth Journey는 기본 화면·필터·상세와 개발 API GET /api/journey 연결·오류 재시도까지 구현했다.** 응답은 서버 목 분석이며 DB/실제 AI 연결은 후속 단계다. 실제 브라우저 검증은 사용자 확인을 기다린다. Journey 기능을 수정할 때는 [현재 상태](journey/현재_구현_상태.md), [API 계약](journey/성장_분석_API.md)과 [작업 안내](journey/README.md)를 읽는다.

홈 상태는 [홈 채팅 현재 구현 상태](chat/현재_구현_상태.md), 나의 발자국 상태는 [나의 발자국 현재 구현 상태](footprints/현재_구현_상태.md)에 정리했다. 구현 완료·목 데이터·실제 서버 연결·검증 한계를 구분해 읽는다.

채팅 문서는 [docs/chat](chat/README.md)에 모았다. 공통 규칙과 원본 참고 자료는 이 폴더에 유지한다.

나의 발자국은 사용자 화면 확인 후 현재 범위에서 마무리했다. 재개할 때는 [작업 안내](footprints/README.md)의 최신 문서·코드를 확인한다. 홈 최근 목록과 날짜 표시 후속 작업은 [최근 활동·기록](chat/구현_기능/최근_활동_기록.md)에 기록했다.

이후 서버 검색·목록 로딩과 대기 시간 개선까지 진행했다. **나의 발자국과 홈 최근 목록을 이어갈 때는 `docs/footprints/README.md`부터 읽고, 그 안의 현재 상태→검색/로딩→DB→홈 최근 목록→활동 정보 계약 순서를 따른다.** PDF 등 파일 내부 본문 검색은 제외하며 사용자 화면 확인은 후속 변경 전체의 브라우저 검증을 의미하지 않는다.

1. [개발 규칙](개발_규칙.md)에서 작업 방식과 기준을 확인한다.
2. [개발 기록](chat/개발_기록.md)에서 최신 구현 상태와 남은 작업을 확인한다.
3. [기능별 구현 기록](chat/구현_기능/README.md)에서 관련 코드와 동작을 확인한다.
