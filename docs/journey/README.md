# Growth Journey 작업 안내·구현 계획

작성: 2026-11-04. 다음 대화에서 작업을 이어가기 위한 인수인계 문서다. 기본 화면에 이어 성장 유형·분야 필터와 이벤트 상세 펼침까지 구현했다. 브라우저 동작 확인은 사용자 담당이며 아직 완료 보고를 받지 않았다. [현재 구현 상태](현재_구현_상태.md)를 먼저 확인한다. 아래 단계별 계획은 후속 작업의 참고이며 전체 구현 지시가 아니다.

최신 인수인계: 현재 화면 구현과 개발 서버 목 API 연결 범위는 완료했다. 화면 동작 검증은 사용자가 진행한다. 남은 핵심은 실제 백엔드/AI 연동이며, 확정 기록 문맥·최종 성장 분류·분석 결과 저장/갱신·근거 자료 ID 연결을 포함한다. 확인 결과에 따른 수정 외에 화면을 다시 구현하지 않는다.

최신 UI: 모든 카드의 호버 효과와 선 위의 원을 적용했다. 원 채움은 마우스 호버에만 반응하며 클릭/펼침으로 고정되지 않는다. 비교 정보는 사용자 관점 기획 범위 확장·PM 역할 확장 카드에 있다. 사용자 요청으로 요약의 ‘예시 데이터’ 배지는 제거했지만 서버 source는 mock이다. 조회는 진입/재시도에 수행하고 필터는 받아둔 전체 응답에서 처리한다.

성장 분석의 화면용 응답 기준과 다음 구현 순서는 [성장 분석 API](성장_분석_API.md)에 정리했다. GET `/api/journey`와 프론트 HTTP 연결·오류 재시도를 구현했다. 응답은 서버 목 분석이며 DB/실제 AI 분석과 구분한다. 다음 제안 범위는 실제 저장 기록의 분석 문맥 구성이다.

## 최신 사용자 요청과 직전 작업

사용자는 나의 발자국을 현재 범위에서 마무리하고 다음 활동으로 Growth Journey 화면을 구현하기로 했다. 이 문서에 있는 계획 전체를 한 번에 구현하라는 뜻은 아니다. 다음 사용자 요청에 맞춰 한 기능씩 진행하고, 이미 완료한 나의 발자국·홈을 다시 만들지 않는다.

- 나의 발자국 목록·상세·자료 Drawer·Project Timeline은 개발 API와 SQLite의 확정 기록을 조회한다. [완료 범위·검증 한계](../footprints/현재_구현_상태.md) 참고.
- 검색은 한글 조합 중에도 입력 변경마다 즉시 서버에 요청한다. 250ms 대기는 제거했고 이전 요청 취소·최신 결과 반영을 유지한다. 파일 내부 본문 검색은 제외한다.
- 변화 없음 단일 파일 카드는 아카이브 저장 시 기존 활동에 바로 저장하고, 수정 모달은 활동·자료 유형만 변경한다. 활동 전체 메타정보 편집은 제외했다. [현재 카드 흐름](../chat/구현_기능/변화_없는_파일.md) 참고.
- AI 분석은 아직 목 응답이다. 활동명·자료 유형·변화 판단 등을 실제 AI가 추출한 상태로 표현하지 않는다. 실제 AI 연결 시 변화 없음 카드 제목 content에 활동을 알리는 문구를 반환하고 저장 활동 ID와 일치시켜야 한다.
- 마무리 결정과 실제 브라우저의 모든 개별 항목 검증 완료는 구분한다. 기존 사용자 DB를 초기화하거나 예시 기록으로 대체하지 않는다.

## 구현할 화면과 범위

목표는 여러 활동을 통틀어 사용자가 시간에 따라 어떻게 성장했는지 보여주는 화면이다. 한 활동의 변경 이력인 Project Timeline, 활동 관계 그래프인 Growth Map과 구분한다. Growth Map은 이번 계획에 포함하지 않는다.

원본 구성 순서를 따른다.

1. 페이지 제목과 설명.
2. 최근 성장 흐름 AI 분석 요약 배너.
3. 새롭게 쌓인 경험 배지 영역.
4. 성장 유형 버튼과 성장 분야 선택.
5. 날짜·유형·활동명·분야·제목·설명으로 구성된 세로 성장 Timeline.
6. 비교 정보가 있는 이벤트의 Before/After·근거 상세 펼침.

기능명세상 성장 요약·이벤트·활동명·성장 유형·전후 비교·근거가 핵심이다. 배지는 시간 부족 시 생략 가능하고, 유형/분야 필터는 선택 구현, 상세 펼침 조작은 권장이다. 원본 화면 재현을 위한 권장 계획에는 필터와 펼침도 포함하되 최신 사용자 요청 범위를 우선한다.

## 단계별 진행 제안

### 1. 원본 화면과 데이터 계약 구성 — 현재 개발 범위 완료

원본의 Growth Journey 화면을 React로 옮겼고 기존 페이지·공통 레이아웃을 유지했다. 상세 카드는 `src/components/journey/JourneyEventCard.tsx`로 분리했다. 이 단계를 다시 시작하지 않는다.

현재 `src/types/journey.ts`, `src/services/journey.ts`, `api-server/src/mock-journey.js`를 구성했다. 프론트 목 fixture는 제거하고 서버 목 공급자로 이동했다. 정식 AI 공급자 계약은 아니며, 실제 연결 시 서비스에서 변환한다. 화면은 서비스 함수를 통해 타입이 있는 응답을 받고, 요약·배지·성장 판단을 JSX에 고정하지 않는다. 목 응답과 실제 저장 데이터의 경계를 코드와 기능 문서에 명시한다. 기존 사용자 DB에는 화면 확인용 예시를 삽입하지 않는다.

검토할 응답 필드: 전체 성장 요약과 배지, 이벤트의 안정적인 id·시각·활동 ID/이름·성장 유형·분야·제목·설명, 선택적인 Before/After와 근거 자료. 활동 ID나 근거 자료 ID가 없으면 이름만으로 실제 링크를 추측하지 않는다. 날짜는 원본의 월 단위 정밀도를 임의로 일 단위까지 채우지 않는다. 이는 설계 제안이며 정식 서버 계약이 아니다.

### 2. 필터와 이벤트 상세 동작 — 구현 완료·사용자 화면 확인 담당

- 성장 유형과 분야는 AND로 결합하고 다른 조건을 바꿔도 선택을 유지한다.
- 원본 이벤트는 오래된 것부터 시간순으로 표시된다. 별도 요청이 없으면 이 순서를 유지하고, 같은 시각은 안정적으로 정렬한다. 원본 배열을 직접 변경하지 않는다.
- 펼침 상태는 배열 인덱스 대신 이벤트 ID로 관리한다. 비교 정보가 없는 카드에 빈 상세 토글을 만들지 않는다.
- 상세 조작은 키보드로 사용할 수 있는 버튼과 aria-expanded/aria-controls를 사용한다.
- 로딩·오류/재시도·전체 기록 없음·필터 결과 없음을 구분한다.
- 실제 활동 ID가 확인된 경우에만 기존 활동 상세로 연결한다. 근거 자료의 ID까지 확인되면 기존 Drawer 경로를 사용할 수 있다. 원본에 없는 이동 기능은 사용자 요청 없이 자동 확장하지 않는다.

### 3. 실제 DB·AI 연결은 별도 단계

화면과 동작을 확인한 다음, 사용자가 요청하면 Journey 전용 서비스/API 계약을 정하고 연결한다. 현재 DB에서 알 수 있는 값과 AI 판단이 필요한 값을 구분한다. 전체 활동을 가로지르는 분석 대상, 성장 이벤트 판정, 근거 ID, 갱신 시점, 활동 이동/기록 수정 때의 반영 기준을 정해야 한다.

실제 연결은 미저장 초안을 제외한 확정 기록을 기준으로 검토한다. 변화 없음 파일 저장이나 일반 Timeline 이벤트 저장만으로 Journey 이벤트·Turning Point·첫 경험 배지를 자동 생성하지 않는다. 근거가 없는 성장이나 경험 전이를 추측하지 않는다. 실제 AI 연결 전에는 목 분석임을 명시하고, 오류를 성공한 예시 데이터로 대체하지 않는다.

## 검증·완료 기록

구현 후 변경 범위에 맞게 build/lint를 실행한다. 필터 AND·안정 정렬·이벤트 ID별 펼침·빈 결과·오류/취소 등 의미 있는 동작을 검증한다. 브라우저에서는 원본과 같은 조건의 화면, 좁은 화면과 긴 문구, 키보드/초점, 실제 필터·상세 조작을 확인하고 자동 검사와 구분해 기록한다.

서버 연동 단계의 테스트는 임시 DB를 사용한다. 기존 홈 저장·수정·나의 발자국 동작을 바꾸는 경우에만 해당 회귀 검사를 추가한다. 기본 화면 구현 후 검증과 미검증 범위는 [현재 상태](현재_구현_상태.md)에 기록했다.

구현을 시작하면 이 폴더에 현재 동작·관련 코드·목/실제 값·수행한 검증·남은 작업을 기록한다. 채팅 개발 기록에 Journey의 상세 이력을 계속 덧붙이지 않는다. 다음 대화에서는 이 문서를 읽고 최신 사용자 요청과 현재 코드를 확인한 뒤 진행한다.
