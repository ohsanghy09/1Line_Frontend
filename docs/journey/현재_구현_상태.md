# Growth Journey 현재 구현 상태

정리: 2026-11-04. 사용자 요청의 작업 순서 3번(데이터 구조·목 응답·서비스와 기본 화면)까지 구현했다.

## 현재 동작

- 기존 `/journey` 페이지와 공통 Sidebar·MainPage를 유지했다.
- 원본 순서대로 페이지 제목/설명, 최근 성장 흐름 요약, 첫 경험 배지 4개, 필터 외형, 성장 이벤트 5개를 표시한다.
- 이벤트는 날짜·성장 유형·활동명·분야·제목·설명을 표시한다. 월 단위 YYYY-MM을 유지하고 오래된 순으로 정렬한다. 같은 월은 응답 순서를 유지한다.
- 요약·배지·이벤트·필터 선택지는 서비스의 타입이 있는 목 응답에서 읽는다. 컴포넌트에 성장 분석 예시 문구를 직접 고정하지 않았다.
- 실제 사용자 기록이나 AI 분석으로 오해하지 않도록 요약 배너에 ‘예시 데이터’를 표시한다. 원본의 2026.03 1호선톤 예시 날짜는 그대로 보존했으며 실제 DB와 연결하지 않는다.
- 이번 단계의 필터는 기본값 전체/전체 분야로 비활성 표시한다. 카드에는 상세 클릭·키보드 토글·활동/근거 이동을 아직 제공하지 않는다. 다음 구현 단계에서 연결한다.
- 기본 조회 대기·실패·전체 이벤트 없음 처리를 포함한다. 필터 결과 없음·재시도는 후속 범위다.

## 관련 코드와 데이터 경계

| 파일 | 역할 |
| --- | --- |
| [GrowthJourney.tsx](../../src/pages/GrowthJourney.tsx) | 기본 화면·서비스 호출·페이지 이탈 후 응답 무시 |
| [journey.ts 타입](../../src/types/journey.ts) | 요약·배지·성장 유형/분야 선택지·이벤트·선택적 비교 정보 |
| [journey.ts 서비스](../../src/services/journey.ts) | 비동기 조회 경계, 요청 취소 확인, 목 응답 복사·정렬 |
| [목 응답](../../src/mocks/journey/index.ts) | 원본 HTML의 요약·배지·이벤트·분류 선택지 |

실제 API 호출·DB 조회·AI 분석은 없다. activity.id는 null이며 이름으로 실제 활동 ID를 추측하지 않는다. 마지막 이벤트의 Before/After·근거 문자열은 원본 목 응답에 보관하되 아직 화면에서 펼치지 않는다. 근거 파일 ID도 만들지 않는다. 서버·DB·홈·나의 발자국·공통 스타일은 이번 작업에서 변경하지 않았다.

## 검증

- `npm.cmd run build`, `npm.cmd run lint` 통과.
- Node에서 실제 타입 제거 후 서비스·목 응답을 불러와 이벤트 5개/배지 4개·날짜순·고유 이벤트 ID·선택지 참조·응답 수정 시 원본 보존·취소된 신호 거절을 확인했다.
- `git diff --check` 통과.
- 인앱 브라우저 연결이 되지 않아 실제 렌더링·원본 비교·모바일 폭·키보드 동작은 확인하지 못했다. 자동 검사 통과를 브라우저 검증 완료로 기록하지 않는다.

## 다음 작업

1. 사용자 기본 화면 확인 후 성장 유형·분야 AND 필터를 연결한다.
2. 이벤트 ID별 상세 펼침과 Before/After·근거 표시를 구현한다. 정보가 없는 카드에는 빈 상세 조작을 만들지 않는다.
3. 로딩/오류 재시도·필터 빈 결과·반응형·키보드 동작을 확인한다.
4. 실제 DB/AI 연동은 별도 요청 단계에서 응답 계약과 원본/명세의 성장 유형 차이를 정리한 뒤 진행한다.

전체 배경·읽기 순서·계획은 [작업 안내](README.md)를 따른다. 남은 작업은 자동 구현 지시가 아니다.
