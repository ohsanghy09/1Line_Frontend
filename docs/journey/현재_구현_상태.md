# Growth Journey 현재 구현 상태

## 최신 분야 분류 — journey-v3

2026-11-06: 성장 축(분야)도 AI 분석 분류로 전환했다. 고정 enum과 고정 목록을 제거하고, 실제 이벤트에 쓰인 분야 ID·이름을 최대 8개 생성한다. 전체 분야는 서버가 추가하며 중복·예약 값·미등록/미사용 참조를 검증한다. 기존 저장 결과는 조회 호환을 유지한다. [현재 계약](성장_분석_API.md)의 journey-v3 절을 따른다. 실제 모델·브라우저 확인은 대기이며 서버 재시작 후 분석 갱신이 필요하다. 아래 고정 분야 설명은 이전 단계다.

## 최신 동작 — 2026-11-06

현재 실행 방식은 **진입 시 백엔드 GET 자동 조회, 분석/갱신 버튼에서만 실제 모델 호출**이다. 변경 후 방문 시 자동 분석하는 방식은 아직 제안이다. 사용자가 요청한 DB 초기화와 예시 활동 자동 생성 제거 후 8개 테이블 모두 0건을 문서 갱신 시 확인했다. 다음은 실제 입력부터 수동 분석/갱신·분류/아이콘·근거·실패 보존을 브라우저에서 확인하는 단계다.

최근 검사: 예시 활동 분리 후 Python 39개·백엔드 28개·발자국/Journey API 14개와 check-chat-api 통과. journey-v2 실제 모델 통합도 임시 DB에서 통과했다. 아래 최초 연동 시점의 38/27개 검사 수와 구분한다. 이번 문서 정리에서 새 모델 호출·DB 변경·서버 재시작은 하지 않았다.

후속 변경: `journey-v2`부터 고정된 다섯 성장 유형을 제거했다. AI가 실제 이벤트에 맞는 분류명·식별자·이모지를 생성하고 필터와 이벤트 배지에서 같은 분류 아이콘을 표시한다. 경험 배지에도 AI가 생성한 아이콘을 표시한다. 분야 분류는 기존 기준이다. 과거 아이콘 없는 결과는 그대로 조회하며 새로운 생성 결과에는 분류·아이콘 검증을 적용한다. API 계약은 [성장 분석 API](성장_분석_API.md)의 journey-v2 절을 따른다.

- 확정 기록 → FastAPI 실제 OpenAI → 백엔드 검증·DB 저장 → 프론트 조회로 연결했다. 실행 코드에서 목 공급자를 제거했고 예시는 `api-server/test-support/journey-fixture.js`에서 검사에만 사용한다.
- AI 서버 `app/journey.py`는 확정 기록·기록이 있는 활동·관련 파일 ID/이름만 읽는다. 미저장 초안·기록 없는 기본 활동은 제외한다. 문맥은 기록 본문·저장된 분석 요약·변화·활동 메타정보다. 파일 원본 BLOB을 다시 읽거나 분석하지 않는다.
- `app/prompts/journey.md`는 요약·배지·이벤트마다 실제 기록 ID와 연속 원문 인용을 요구한다. Before/After는 서로 다른 기록의 근거가 필요하다. ‘첫 경험’은 기록 범위에 한정한다. 검증은 의미 정확도 전체를 보장하지 않는다.
- `journey_analyses`에 결과 JSON·원본 스냅샷 해시·기록 수·모델·프롬프트 버전·생성 시각을 저장한다. 홈 기록·Timeline은 수정하지 않는다. 같은 저장 결과의 이벤트 ID는 재조회해도 유지한다. 재분석은 새 스냅샷과 새 ID다.
- GET은 최신 결과와 `analysis` 상태를 반환한다. 초기에는 미분석 상태다. 기록 수정/이동/추가로 해시가 다르면 `stale=true`다. 분석 도중 기록 변경 시 409로 새 결과 저장을 막는다.
- ‘성장 분석하기 / 분석 갱신’에서만 모델을 호출한다. 분석 중 중복 클릭을 막고 같은 백엔드 인스턴스의 중복 요청은 409다. 실패 시 기존 결과를 유지한다. 페이지 이탈로 요청을 취소해도 서버 분석은 완료·저장될 수 있으며 재진입은 DB만 조회한다.
- 기존 요약·배지·유형/분야 AND 필터·상세를 유지한다. 비교 없는 이벤트도 인용 근거가 있으면 상세를 열 수 있다. 날짜는 **근거 기록의 저장 월**이다. 실제 활동 발생 시점으로 추측하지 않는다. 분야에 `other`를 추가했다. 분류는 개발 기준이다.
- 한도는 확정 기록 100개·JSON 문맥 250000자다. 초과 시 일부를 몰래 생략하지 않고 422를 반환한다. 분할 분석·분산 작업 잠금·서버 재시작 복구·실제 자료 Drawer 이동은 후속 범위다.

검증: Python 38개·백엔드 27개 통과. 성장 HTTP 검사는 근거 위조·활동/날짜 불일치·분석 도중 수정·중복 실행·실패 시 보존을 확인했다. `node scripts/check-live-ai.mjs --journey`로 실제 모델·임시 DB·프론트 서비스·저장/조회·수정 후 stale을 통과했다. 빌드·lint(기존 경고 3개)·채팅 세션 검사도 통과했다. 브라우저 직접 클릭·반응형·키보드 전체 검증은 미완료다.

아래 목 응답 설명과 2026-11-04 검사 수는 과거 이력이다.

최신 사용자 확인: 화면 동작 검증은 사용자가 맡는다. 현재 화면·개발 API 연결 작업을 기준으로 후속 핵심 작업은 실제 백엔드/AI 연동(확정 기록 문맥, 분석 계약, 결과 저장/갱신, 근거 ID 연결)이다. 화면 검증 담당 지정과 검증 완료 보고는 구분한다.

최신 연결: 프론트 서비스 → Vite `/api` 프록시 → 개발 API GET `/api/journey`로 전환했다. 서버의 원본 예시 응답을 반환하며 source는 mock이다. 프론트와 서버에서 구조·날짜·ID·분류·비교 정보를 검증하고, 연결 실패/응답 오류는 재시도 가능한 오류로 표시한다. 프론트 예시로 대체하지 않는다.

## 현재 동작

- 기존 `/journey` 페이지와 공통 Sidebar·MainPage를 유지했다.
- 원본 순서대로 페이지 제목/설명, 최근 성장 흐름 요약, 첫 경험 배지 4개, 필터, 성장 이벤트 5개를 표시한다.
- 이벤트는 날짜·성장 유형·활동명·분야·제목·설명을 표시한다. 월 단위 YYYY-MM을 유지하고 오래된 순으로 정렬한다. 같은 월은 응답 순서를 유지한다.
- 요약·배지·이벤트·필터 선택지는 서비스의 타입이 있는 목 응답에서 읽는다. 컴포넌트에 성장 분석 예시 문구를 직접 고정하지 않았다.
- 사용자 요청으로 요약 배너의 ‘예시 데이터’ 배지를 제거했다. 응답의 source는 mock이며 실제 AI/DB 분석은 여전히 연결하지 않았다. 원본의 2026.03 1호선톤 예시 날짜도 그대로 보존했다.
- 성장 유형과 분야는 기본값 전체/전체 분야이며 AND로 적용한다. 다른 조건을 바꿔도 선택을 유지한다. 필터는 이벤트 목록에만 적용하고 전체 요약·경험 배지는 유지한다.
- 서버 요청은 페이지 진입·오류 재시도 때 수행한다. 필터 변경·상세 펼침은 받아둔 응답으로 프론트에서 처리하며 서버/AI를 재호출하지 않는다. typeOptions·axisOptions는 서버 선택지이고 이벤트의 type·axis가 필터 분류값이다. 경험 배지(badges)와 구분한다.
- 전체 이벤트 없음과 필터 결과 없음을 구분한다. 기본 조회 대기·실패 및 ‘다시 불러오기’ 재시도를 제공한다.
- Before/After가 모두 있는 이벤트만 카드 전체를 native button으로 제공한다. 클릭 또는 Enter/Space로 상세를 열고 닫으며 aria-expanded·aria-controls·초점 표시를 사용한다. 닫힌 영역은 hidden으로 숨긴다.
- 상세에는 응답의 Before/After와 근거 문자열만 표시한다. 근거가 없으면 만들지 않는다. 상세 정보가 없는 카드에는 토글을 표시하지 않는다.
- 원본처럼 모든 이벤트 카드에 마우스를 올리면 테두리·그림자 효과를 표시한다. 타임라인 선 위에는 흰 바탕·주 색상 테두리의 원을 표시하고 해당 이벤트에 마우스를 올린 동안만 원을 주 색상으로 채운다. 클릭 후 초점이나 펼침 상태로 원 색상을 유지하지 않는다. 선·원은 같은 목록 왼쪽 기준으로 배치하며 상세 펼침 가능 여부와 호버 효과를 구분한다.
- 펼침 상태는 이벤트 ID별 Set으로 관리하므로 여러 카드를 독립적으로 열 수 있고 필터로 숨겼다가 다시 표시해도 유지한다. 현재 예시에서는 ‘사용자 관점 기획 범위 확장’과 ‘PM 역할 수행 및 팀 프로세스 수립’ 카드에 비교 정보가 있다.
- 사용자 요청으로 ‘사용자 관점 기획 범위 확장’의 서버 목 응답에 Before(개발 중심의 기능 기획)·After(사용자 인터뷰를 반영한 기획)·근거(인터뷰 기록, 와이어프레임)를 추가했다. 기존 카드가 응답을 읽어 상세 조작을 제공하며 화면 코드는 변경하지 않았다. 이 내용은 원본에서 추출한 사실이나 실제 AI 결과가 아닌 추가 예시다.

## 검증

- 최신 카드 호버·원 표시 조정, 원의 초점 채움 제거, 예시 데이터 배지 제거 후 각각 build/lint가 통과했다. Journey/API 테스트 12개와 서버 전체 15개는 아래에 기록된 앞선 단계의 결과이며 CSS/배지 변경 뒤 다시 실행한 것으로 간주하지 않는다.

- ‘사용자 관점 기획 범위 확장’ 상세 예시 추가 후 Journey 필터/API/서버 검사 12개가 다시 통과했다. 실제 브라우저에서 두 카드의 클릭·독립 펼침은 아직 확인하지 않았다.

- API 연결 후 build/lint 통과. `node --test tests/journey.test.mjs tests/journey-api.test.mjs api-server/test/journey.test.js` 12개(상위 통합 검사 포함) 통과: 실제 프론트 서비스→Vite→API, 빈 응답, source=mock, 정렬/원본 보존, 잘못된 응답 거절, 서버/연결 오류, 재호출 회복, 취소 확인. 테스트는 메모리 DB를 사용한다.
- 개발 서버 `npm.cmd test` 전체 15개 통과: 기존 활동 저장·아카이브·검색·홈·진행·링크 회귀 포함. 이 중 Journey 서버 검사 3개는 위 12개와 중복된다.
- 이번 연결의 재시도 버튼 클릭·페이지 이탈·렌더링은 실제 브라우저 검증 결과가 아니다.

- `npm.cmd run build`, `npm.cmd run lint` 통과.
- Node에서 실제 타입 제거 후 서비스·목 응답을 불러와 이벤트 5개/배지 4개·날짜순·고유 이벤트 ID·선택지 참조·응답 수정 시 원본 보존·취소된 신호 거절을 확인했다.
- `git diff --check` 통과.

- 인앱 브라우저 검색 결과 연결 가능한 브라우저가 없어 실제 렌더링·원본 비교·모바일 폭·키보드 동작은 확인하지 못했다. 자동 검사 통과를 브라우저 검증 완료로 기록하지 않는다.

사용자 확인 예시:

1. 전체에서는 5개, 능력 확장에서는 2개가 표시되는지 확인한다.
2. 능력 확장+AI·기술은 결과 없음, 성과 향상+AI·기술은 1개인지 확인한다.
3. 성장 축을 전체 분야로 되돌려도 선택한 유형이 유지되는지 확인한다.
4. 전체/전체 분야에서 PM 카드 클릭과 Enter/Space로 상세를 열고 닫는다. Before는 기획 담당, After는 PM + 기획, 근거는 회의록·역할분담표다.
5. PM 상세를 연 뒤 다른 필터로 숨겼다가 돌아오면 펼침 상태가 유지되는지 확인한다. 비교 정보가 없는 카드는 클릭 조작이 없어야 한다.
6. 모바일에서 줄바꿈·가로 넘침과 키보드 초점 표시를 확인한다.
