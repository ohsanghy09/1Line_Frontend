# Growth Journey 현재 구현 상태

정리: 2026-11-04. 기본 화면에 이어 사용자 요청의 성장 유형·분야 필터와 이벤트 상세 펼침까지 구현했다. 실제 브라우저 조작 확인은 사용자 담당이며 완료 보고는 아직 없다.

최신 연결: 프론트 서비스 → Vite `/api` 프록시 → 개발 API GET `/api/journey`로 전환했다. 서버의 원본 예시 응답을 반환하며 source는 mock이다. 프론트와 서버에서 구조·날짜·ID·분류·비교 정보를 검증하고, 연결 실패/응답 오류는 재시도 가능한 오류로 표시한다. 프론트 예시로 대체하지 않는다.

## 현재 동작

- 기존 `/journey` 페이지와 공통 Sidebar·MainPage를 유지했다.
- 원본 순서대로 페이지 제목/설명, 최근 성장 흐름 요약, 첫 경험 배지 4개, 필터, 성장 이벤트 5개를 표시한다.
- 이벤트는 날짜·성장 유형·활동명·분야·제목·설명을 표시한다. 월 단위 YYYY-MM을 유지하고 오래된 순으로 정렬한다. 같은 월은 응답 순서를 유지한다.
- 요약·배지·이벤트·필터 선택지는 서비스의 타입이 있는 목 응답에서 읽는다. 컴포넌트에 성장 분석 예시 문구를 직접 고정하지 않았다.
- 사용자 요청으로 요약 배너의 ‘예시 데이터’ 배지를 제거했다. 응답의 source는 mock이며 실제 AI/DB 분석은 여전히 연결하지 않았다. 원본의 2026.03 1호선톤 예시 날짜도 그대로 보존했다.
- 성장 유형과 분야는 기본값 전체/전체 분야이며 AND로 적용한다. 다른 조건을 바꿔도 선택을 유지한다. 필터는 이벤트 목록에만 적용하고 전체 요약·경험 배지는 유지한다.
- 전체 이벤트 없음과 필터 결과 없음을 구분한다. 기본 조회 대기·실패 및 ‘다시 불러오기’ 재시도를 제공한다.
- Before/After가 모두 있는 이벤트만 카드 전체를 native button으로 제공한다. 클릭 또는 Enter/Space로 상세를 열고 닫으며 aria-expanded·aria-controls·초점 표시를 사용한다. 닫힌 영역은 hidden으로 숨긴다.
- 상세에는 응답의 Before/After와 근거 문자열만 표시한다. 근거가 없으면 만들지 않는다. 상세 정보가 없는 카드에는 토글을 표시하지 않는다.
- 원본처럼 모든 이벤트 카드에 마우스를 올리면 테두리·그림자 효과를 표시한다. 타임라인 선 위에는 흰 바탕·주 색상 테두리의 원을 표시하고 해당 이벤트에 마우스를 올린 동안만 원을 주 색상으로 채운다. 클릭 후 초점이나 펼침 상태로 원 색상을 유지하지 않는다. 선·원은 같은 목록 왼쪽 기준으로 배치하며 상세 펼침 가능 여부와 호버 효과를 구분한다.
- 펼침 상태는 이벤트 ID별 Set으로 관리하므로 여러 카드를 독립적으로 열 수 있고 필터로 숨겼다가 다시 표시해도 유지한다. 현재 예시에서는 ‘사용자 관점 기획 범위 확장’과 ‘PM 역할 수행 및 팀 프로세스 수립’ 카드에 비교 정보가 있다.
- 사용자 요청으로 ‘사용자 관점 기획 범위 확장’의 서버 목 응답에 Before(개발 중심의 기능 기획)·After(사용자 인터뷰를 반영한 기획)·근거(인터뷰 기록, 와이어프레임)를 추가했다. 기존 카드가 응답을 읽어 상세 조작을 제공하며 화면 코드는 변경하지 않았다. 이 내용은 원본에서 추출한 사실이나 실제 AI 결과가 아닌 추가 예시다.

## 검증

- ‘사용자 관점 기획 범위 확장’ 상세 예시 추가 후 Journey 필터/API/서버 검사 12개가 다시 통과했다. 실제 브라우저에서 두 카드의 클릭·독립 펼침은 아직 확인하지 않았다.

- API 연결 후 build/lint 통과. `node --test tests/journey.test.mjs tests/journey-api.test.mjs api-server/test/journey.test.js` 12개(상위 통합 검사 포함) 통과: 실제 프론트 서비스→Vite→API, 빈 응답, source=mock, 정렬/원본 보존, 잘못된 응답 거절, 서버/연결 오류, 재호출 회복, 취소 확인. 테스트는 메모리 DB를 사용한다.
- 개발 서버 `npm.cmd test` 전체 15개 통과: 기존 활동 저장·아카이브·검색·홈·진행·링크 회귀 포함. 이 중 Journey 서버 검사 3개는 위 12개와 중복된다.
- 이번 연결의 재시도 버튼 클릭·페이지 이탈·렌더링은 실제 브라우저 검증 결과가 아니다.

- `npm.cmd run build`, `npm.cmd run lint` 통과.
- Node에서 실제 타입 제거 후 서비스·목 응답을 불러와 이벤트 5개/배지 4개·날짜순·고유 이벤트 ID·선택지 참조·응답 수정 시 원본 보존·취소된 신호 거절을 확인했다.
- `git diff --check` 통과.
- 필터·상세 후속 변경 뒤 build/lint와 `node --test tests/journey.test.mjs` 3개 통과. 필터 AND·빈 결과·필터 해제·시간순/ID/비교 근거·원본 보존을 자동 검사했다. 상세 버튼의 실제 클릭·키보드 조작을 테스트한 결과는 아니다.
- 인앱 브라우저 검색 결과 연결 가능한 브라우저가 없어 실제 렌더링·원본 비교·모바일 폭·키보드 동작은 확인하지 못했다. 자동 검사 통과를 브라우저 검증 완료로 기록하지 않는다.

사용자 확인 예시:

1. 전체에서는 5개, 능력 확장에서는 2개가 표시되는지 확인한다.
2. 능력 확장+AI·기술은 결과 없음, 성과 향상+AI·기술은 1개인지 확인한다.
3. 성장 축을 전체 분야로 되돌려도 선택한 유형이 유지되는지 확인한다.
4. 전체/전체 분야에서 PM 카드 클릭과 Enter/Space로 상세를 열고 닫는다. Before는 기획 담당, After는 PM + 기획, 근거는 회의록·역할분담표다.
5. PM 상세를 연 뒤 다른 필터로 숨겼다가 돌아오면 펼침 상태가 유지되는지 확인한다. 비교 정보가 없는 카드는 클릭 조작이 없어야 한다.
6. 모바일에서 줄바꿈·가로 넘침과 키보드 초점 표시를 확인한다.
