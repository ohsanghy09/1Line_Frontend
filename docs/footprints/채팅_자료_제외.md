# 입력 채팅을 보관 자료에서 제외

최신 정리: 2026-11-06.

## 파일·링크에 함께 입력한 채팅 저장 제외 (2026-11-06)

- 파일 원본 또는 sourceUrl이 있는 자료를 확정할 때 `records.message`를 빈 문자열로 저장한다. 여러 첨부 파일에도 동일하게 적용한다.
- 자료 API의 `content` 필드와 상세 화면의 ‘입력한 내용’을 제거했다. 자료 검색에서도 함께 입력한 채팅 원문을 제외한다.
- 기존 자료의 입력문은 DB에서 삭제하지 않지만 자료 상세·검색에는 노출하지 않는다. 파일 원본·링크·AI 요약은 유지한다.
- 별도 대화/분석 이력인 `analyses.message` 등은 유지한다. 업로드 시 입력문은 AI 분석 문맥으로 계속 사용할 수 있다. 자료가 없는 독립 텍스트 경험 기록도 보존한다.
- 백엔드 40개(Swagger 제외), 프론트 자료·검색 13개, TypeScript/Vite 빌드 통과. lint는 기존 경고 3개다. 실제 사용자 DB 수정과 Swagger 갱신은 하지 않았다.
- 반영하려면 백엔드를 재시작하고 화면을 새로고침한다.

## 원인 확인

사용자 요청으로 실제 공유 DB를 읽기 전용 확인했다. 기존 활동 전체 요약 작성 요청이 `text-analysis`와 자료 유형 `참고 자료`로 분류되어 확정 records에 저장되어 있었다. 일반 대화/활동 수정 타입이 records에 들어간 사례는 없었다. 이전 아카이브는 첨부가 없으면 record.message로 가상 자료를 만들어 폴더와 최근 추가 목록에 표시했으므로 저장된 채팅이 참고 자료처럼 보였다.

## 변경 동작

- 보관 자료 폴더·자료 수·최근 추가 자료는 실제 files 원본 행이 있는 첨부 또는 명시적으로 저장한 sourceUrl 링크만 사용한다.
- 입력한 글로 `record:기록ID` 텍스트 자료를 만들지 않는다. 원본 없이 모델 응답에 파일 이름만 있어도 첨부 자료로 간주하지 않는다.
- 이미 저장된 채팅도 조회 규칙으로 제외한다. 이전 텍스트 자료 상세 URL은 더 이상 보관 자료로 조회되지 않는다. 실제 파일·링크는 유지한다.
- 사용자 데이터 행은 삭제하지 않는다. 확정된 텍스트 경험 기록은 검색·활동 정보/성장 분석의 근거로 보존한다. 이번 변경은 모든 텍스트 경험 기록을 삭제하거나 분석에서 일괄 제외하는 작업이 아니다.
- 자료 수와 확정 기록 수를 구분하도록 `recordsCount`를 반환한다. 텍스트 경험 기록만 있어 자료가 0개인 활동도 활동 정보 분석 상태·재시도를 표시할 수 있다.
- 기존 활동 전체 요약 작성·갱신 요청은 새 경험 기록이 아니라 summary 수정 또는 일반 안내로 처리하도록 홈 프롬프트를 보완했다. 일반 질문·작업 지시 자체를 참고 자료로 분류하지 않도록 명시했다.

원본 채팅 본문이나 AI 요약을 DB에서 다시 쓰거나 기존 행을 재분류하지 않았다. 따라서 과거의 잘못 분류된 원문/요약은 기존 확정 기록으로는 남는다. 참고 자료 목록에서 제외하는 것과 기존 데이터 삭제·정정은 구분한다.

## 코드와 검증

- `api-server/src/archive.js`: 텍스트·원본 없는 가상 파일 제외, recordsCount 추가. 홈 최근 목록도 같은 아카이브를 사용하므로 함께 제외된다.
- `api-server/src/archive-search.js`: 확정 텍스트 검색을 폴더 자료와 분리해 보존.
- `src/types/footprints.ts`, `src/services/footprints.ts`, `src/pages/ActivityArchive.tsx`: 기록 수 계약·자료 없는 활동 분석 상태.
- `ai-api-server/app/prompts/home.md`: 요약 작성 요청과 실제 경험 입력 구분.

검사 결과:

- 백엔드 39개 통과(Swagger 전용 검사 제외). 텍스트 경험 저장 후 자료 0개/기록 1개, 최근 자료 제외, 가상 파일명 제외, 실제 첨부/링크 보존과 검색 회귀를 확인했다.
- TypeScript/Vite 직접 빌드 통과. lint 기존 경고 3개. Swagger 갱신은 하지 않았다.
- 실제 DB 읽기 전용 조회에서 텍스트 기록 1건, 그 기록의 보관 자료 항목 0건·최근 자료 항목 0건, 실제 자료 총 3건을 확인했다. 사용자 DB 행 삭제는 하지 않았다.
- 프론트 서비스 회귀 검사 결과는 개발 기록을 따른다. 실제 모델의 새 분류 응답·브라우저 직접 확인은 미수행이다.
