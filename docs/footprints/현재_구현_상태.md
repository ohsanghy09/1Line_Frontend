그 후 추가 요청으로 홈 최근 목록 연동·반응형 카드·날짜 표시, 서버 검색과 PDF 내부 본문 제외, 목록 로딩/재시도와 검색 외 250ms 대기 제거를 구현했다. 이 문서는 해당 후속 작업까지 포함한다. 기본 화면의 이전 확인과 후속 UI 검증 범위는 구분한다. 다음 작업의 읽기 순서는 [작업 안내](README.md)에 정리했다.

## 현재 연결 범위

목록·활동 상세·자료 Drawer·Project Timeline은 `src/services/footprints.ts` → Vite `/api` 프록시 → 개발용 REST API → SQLite의 확정 기록을 조회한다. 서버 오류를 원본 예시 활동/자료로 대체하지 않는다. 기존 홈 저장·수정 API를 유지하며, 저장 후 화면에 진입하거나 다시 방문하면 최신 데이터를 조회한다. 이미 열린 화면의 실시간 구독·다른 탭 자동 갱신은 구현하지 않았다.

실제 값은 입력 텍스트·URL·원본 파일명·파일 ID·기록 ID·저장/수정 시각·자료 수다. 저장된 분류·요약·변화는 현재 서버 목 분석 결과일 수 있다. 실제 AI 호출·문서 본문 추출·Growth Journey 분석을 연결한 것은 아니다.

후속 확장: [활동 정보 응답·확인 저장](../chat/api/활동_정보_응답_저장.md)을 연결했다. AI 후보와 확인한 활동 메타정보를 구분하고, 카드의 확인 화면에서 새 활동 생성 또는 기존 정보의 명시적인 적용을 선택한다. 목 분석은 새 메타정보를 추출하지 않고 null로 반환한다. 저장 후 나의 발자국에는 확인된 값이 표시된다.

홈 연동 후속: [최근 활동·최근 추가된 기록](../chat/구현_기능/최근_활동_기록.md)도 같은 DB·자료 ID를 사용한다. 최근 활동은 변경 시각순, 최근 추가된 기록은 최초 저장순으로 각각 최대 3개이며 저장·수정 성공 시 재조회한다. 홈 두 목록의 날짜는 프론트에서 현재 날짜와 비교해 오늘은 오전/오후 시각, 어제는 ‘어제’+시각, 이전은 연월일로 표시한다. 30초마다 현재 시각을 갱신하며 DB·API 원본 시각과 나의 발자국 날짜 표시는 그대로다.

## 활동 목록

- `/archive`에서 DB 활동을 조회한다. 초기 서버 활동은 5개이며 원본 예시 6개와 다르다. 사이드바 활동 수도 서버 활동 수로 표시한다.
- 활동명·유형·상태·역할·기간·활동 요약·자료 수·최근 업데이트를 표시한다. 기존 DB에 없는 유형은 ‘미분류’, 상태·역할·기간은 ‘미설정’, 요약은 ‘활동 전체 요약이 아직 없습니다.’로 안내한다. 기록 하나의 요약을 활동 전체 AI 요약으로 사용하지 않는다.
- 자료 수는 확정한 파일 자료 수 + 파일 없는 텍스트/링크 기록 수다. 다중 파일 기록은 실제 파일 수만큼 센다. 분석만 하고 저장하지 않은 초안은 포함하지 않는다.
- 최근 업데이트는 활동의 변경 시각과 소속 기록의 최신 수정 시각 중 최신 값이다. 기록 이동 시 출발 활동에도 변경 시각을 남긴다. 알려진 시각이 없으면 ‘기록 없음’이다. 홈 최근 활동도 같은 집계를 사용한다. 날짜는 서비스에서 한국어 표시로 변환하며 고정 상대 시각 목 문구를 사용하지 않는다.
- 검색은 API에 연결했다. 활동명·활동 전체 요약·확정 자료 이름·입력 글/URL·저장된 기록 요약을 검색해 해당 활동 카드를 반환한다. PDF 등 파일 원본 BLOB이나 내부 본문은 읽거나 검색하지 않는다. [검색 API](검색_API.md) 참고.
- 검색은 NFC·대소문자·공백을 정규화한다. 검색·유형·상태는 AND이며 다른 조건을 바꿔도 선택을 유지한다.
- 검색어·유형·상태·정렬을 서버에 전달한다. 응답은 items와 조건 적용 전 전체 활동 수 total이다. 화면에서 재필터링하지 않으며 한글 조합 중에도 입력이 바뀔 때마다 즉시 요청한다. 최초 진입·필터·정렬·재시도도 즉시 요청하며 이전 요청을 취소한다.
- 유형 선택은 원본의 전체·해커톤·수업(전공수업)·프로젝트·공모전이다. 미분류 활동도 전체에서 조회된다. 상태 필터는 전체·진행 중·완료이며 미설정은 전체에서만 조회된다.
- 최근 업데이트·자료 많은 순·오래된 순을 지원한다. 오래된 순도 업데이트 시각 기준이다. 동률은 응답 순서를 유지하며 원본 배열은 변경하지 않는다. 알려진 변경 시각이 없는 활동은 최근순에서 뒤로 보낸다.
- 카드 Link로 `/archive/:activityId`에 진입한다. 로딩·실패·빈 목록·조건 결과 없음을 구분한다. 목록 복귀 시 필터는 기본값으로 초기화된다.
- 최초 로딩은 큰 회전 아이콘·안내 카드(최소 높이 280px), 재조회는 기존 목록을 옅게 유지하고 상단 회전 아이콘·안내를 표시한다. 실제 요청 중 이전 목록의 키보드/마우스 이동을 막고 실패 시 재시도를 제공한다. role=status·aria-busy·모션 감소 설정을 반영했다. 로컬 시각 측정과 구현 범위는 [검색 API의 로딩 설명](검색_API.md)에 기록했으며 이번 로딩 UI의 실제 브라우저 검증은 아직 하지 않았다.

## 활동 상세와 폴더

- 활동 ID로 기본 정보·AI 활동 요약·분류별 자료 폴더를 조회한다. 상단 목록 복귀와 ‘변화 과정 보기’ 링크를 제공한다.
- 현재 DB에는 폴더 엔터티가 없으므로 저장된 자료 유형으로 묶는다. 폴더 개수는 실제 자료 수이며, 원본 예시의 기획/디자인 폴더나 고정 자료 수를 섞지 않는다.
- 폴더는 처음 모두 펼치며 ID별로 독립적으로 접고 펼친다. 자료 행에는 이름·유형·실제 입력/업로드 시각을 표시한다.
- 실제 업로드 파일은 DB 파일 ID를 쓴다. 원본 없는 독립 카드의 자료는 기록 ID+인덱스로 구분하며 원본 파일이 있는 것으로 간주하지 않는다. 파일 없는 텍스트/링크는 기록 ID로 자료를 구성한다.
- 활동 ID 변경 시 조회·폴더 상태를 초기화하며 이전 응답 반영을 차단한다. 없는 활동·빈 폴더·폴더 없음·요청 실패를 구분한다.

## 자료 상세 Drawer

- 자료 버튼 또는 `/archive/:activityId?file=:fileId`에서 연다. 파일 조회 API는 요청 활동의 확정 기록 안에서만 자료를 찾는다. 다른 활동으로 이동된 자료의 예전 주소는 404다.
- 선택 자료의 유형·시각·저장된 AI 기록 요약·실제 입력 내용을 표시한다. 현재 요약은 기록 단위이며 다중 파일도 공유할 수 있어 ‘AI 기록 요약’으로 안내한다. 파일 본문을 추출한 것처럼 표시하지 않는다.
- 자료가 근거로 연결된 이벤트만 표시한다. 주요 변화는 Before/After를 표시하되 DB의 Turning Point 플래그가 false이면 전환점으로 표시하지 않는다. 변화 없는 자료는 비교 카드를 생성하지 않는다.
- 현재 서버 계약의 근거는 이름 문자열이다. 같은 기록 안에서 유일한 파일명 또는 명확한 텍스트/링크 근거만 ID로 연결한다. 중복 파일명·해결할 수 없는 근거는 Timeline에서 문자열로 남기고 임의 자료로 연결하지 않는다.
- DB에는 확정된 ID 기반 버전 관계가 없으므로 버전 이력은 빈 배열이다. 파일명이나 previousVersion 문구로 추측해 버전을 연결하지 않는다.
- 모바일 전체 폭, sm 이상 440px 우측 패널과 0.25초 등장 모션을 사용한다. reduced-motion에서는 모션을 없앤다.
- native dialog로 배경 비활성화·초점 제한을 적용한다. 최초 초점은 X 버튼이며 X·Escape·배경 클릭으로 닫고 기존 버튼이 있으면 초점을 복귀한다. 배경 스크롤 차단과 패널 내부 스크롤을 분리한다.
- Timeline 링크는 같은 활동으로 이동하며 관련 이벤트가 있으면 해당 해시 위치로 스크롤하고 초점을 옮긴다. 다운로드·미리보기는 아직 UI에 연결하지 않았다.

## Project Timeline

- `/archive/:activityId/timeline`에서 DB 이벤트를 날짜순으로 조회한다. 주요 변화 수는 이벤트 수, Turning Point 수는 DB 플래그가 true인 수다. 현재 저장 API는 목 분석만으로 Turning Point를 확정하지 않으므로 기본 0개다.
- 일반 변화에도 저장된 Before/After를 표시한다. 전환점은 별도로 강조하고 Reason을 표시한다. 같은 시각은 DB 삽입 순서를 유지한다.
- Evidence에서 같은 활동 자료의 Drawer로 돌아간다. ID 연결이 불가능한 근거는 문자열로 표시한다. 활동 상세 복귀·관련 자료 보기·없는 활동·빈 Timeline·오류를 처리한다.
- 기록의 활동을 바꾸면 자료와 이벤트 모두 새 활동에서 조회된다. changes를 빈 배열로 수정하면 이벤트가 제거된다. 변화 없는 자료 저장은 이벤트를 만들지 않는다.

# 활동 유형 분석·동적 필터 — 2026-11-06

- 홈 실제 AI 분석의 `activity.category`로 활동 유형을 생성한다. 해커톤/수업/프로젝트/공모전으로 제한하지 않는다. 자료 유형과 별개이며 근거 부족 시 null이다.
- 신규 활동 생성 시 유형을 저장한다. 기존 활동은 유형이 없을 때만 채우고 기존 유형은 보존한다. 과거 활동을 일괄 재분석하지 않는다.
- 활동 검색 API의 `categories`는 검색·상태·유형 조건 적용 전 전체 활동에서 중복 제거한 유형명이다. 미분류 활동은 ‘미분류’, 빈 DB는 빈 배열이다.
- 나의 발자국은 고정 유형 버튼 대신 이 목록을 표시하고 ‘전체’만 화면에서 추가한다. 검색 결과가 없어도 유형 목록을 유지한다. 조회에서 AI 호출은 없다.
- 빌드·백엔드 검사 28개·Python 검사 39개 통과 후 기존 분류 보존·잘못된 유형 검사를 추가했다. 실제 유료 모델·브라우저 검증은 미수행이다.
