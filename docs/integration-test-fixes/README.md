# 통합 테스트 후속 프론트·백엔드 작업 계획

작성일: 2026-11-14  
근거: 2026-11-13 「Growth AI 통합 테스트 결과 보고서」 및 후속 작업 협의  
담당: 프론트·백엔드 담당자 / 공동 이슈의 AI 구현은 AI 담당자

## 목적과 범위

통합 테스트에서 확인된 사용자 안내·전송 처리·삭제 후 데이터 손실·파일 중복 문제를 개선한다. 이 문서는 **프론트 8개, 백엔드 단독 4개, 공동 이슈의 백엔드 구현 2개로 구성된 총 14개 작업**의 진행 상태와 완료 기준을 관리한다. 작업 단위로 묶은 개수이며 보고서의 이슈 건수와 일대일 대응하지 않는다.

2026-11-14 프론트 FE-01~08의 코드 수정과 로컬 자동 검증을 완료했다. 아래 프론트 체크는 이 범위의 완료를 뜻한다. 실제 브라우저·운영 AI/백엔드 연결·배포 검증은 별도로 남아 있다. 백엔드 단독·공동 구현은 미착수이며, 과거 구현 기록이나 Swagger 제거 검증을 이번 수정의 완료 근거로 사용하지 않는다.

- AI 단독 분석 품질 개선은 AI 담당자가 별도로 관리한다.
- 공동 API의 상세 제안·역할 분담은 [백엔드·AI 공동 작업 제안서](통합테스트_공동작업_책임범위.md)를 기준으로 검토한다. 제안은 아직 양쪽 합의·구현·배포 완료를 뜻하지 않는다.
- Swagger 화면 제거는 별도로 완료한 작업이다. OpenAPI 원본·계약 검사는 유지하며, 재배포 후 운영 경로의 404 확인은 별도다.

## 3. 공동 이슈의 백엔드 구현 — 2개

### CO-01 / F19 — 부분 삭제 후 타임라인 소실

우선순위: 최우선. 현재 계약이 changes=[]를 강제하고 백엔드도 비어 있지 않은 변화를 거절하므로 계약과 양쪽 구현을 함께 수정한다.

- [ ] AI 담당자와 계약 버전·변화별 근거 응답·원문 검증 방식을 합의한다.
- [ ] 삭제 대상을 제외한 남은 원본을 전달한다.
- [ ] 기존 changes=[] 강제 검증을 새 스키마·파일 ID·인용 검증으로 교체한다.
- [ ] 변화별 근거 연결을 저장하고 자료 링크에 반영한다.
- [ ] 스냅샷 충돌을 검사하고 파일 삭제·기록 교체·타임라인 갱신·Journey 무효화를 원자적으로 반영한다.
- [ ] 실패·응답 오류·계약 미지원·동시 변경 시 삭제 전 데이터를 보존한다.
- [ ] A·B·C에서 A만 삭제했을 때 남은 근거의 변화는 반영되고 삭제된 근거는 제거되는지 공동 검증한다.

AI 담당: 남은 원본 분석, 변화별 전후 근거 반환, 정상 빈 결과와 분석 실패 구분. 기존 이벤트 개수를 맞추기 위해 변화를 만들지 않는다.

### CO-02 / F11 — 동일 파일 중복 판별

우선순위: 보통. 보고서상 원인은 추정이므로 실제 업로드·문맥 조회 경로를 확인한 뒤 구현한다.

- [ ] 비교 범위·조회 API·응답 필드·저장 정책을 AI 담당자와 합의한다.
- [ ] 실제 원본 바이트 기준 SHA-256 관리와 내부 중복 조회 API를 구현한다.
- [ ] 작업 게시·재조회·공개 reply에 중복 결과를 전달할 스키마를 반영한다.
- [ ] 확정 활동과 원본으로 저장 직전 재검사하고 동시 저장·재전송을 처리한다.
- [ ] 중복 거절 응답과 프론트 안내·저장 차단·신규 자료 재전송 흐름을 연결한다.
- [ ] 동일 이름/다른 내용, 다른 이름/동일 내용, 혼합 업로드, 활동 변경, 조회 실패, 동시 저장을 공동 검증한다.

AI 담당: 원본 해시 계산, 내부 조회, 신규·중복 파일 구분, 중복 파일 자체를 새 변화로 생성하지 않는 처리와 결과 게시.

현재 제안 정책은 같은 활동의 중복 저장 차단·다른 활동의 파일 재사용 허용·중복/신규 혼합 요청 전체 저장 거절이다. 합의 전 확정 정책으로 취급하지 않는다. 이에 따른 프론트 추가 구현은 CO-02에 포함하며 프론트 8개에 중복 집계하지 않는다.

## 4. 권장 진행 순서

1. 공동 제안서를 AI 담당자에게 전달하고 API·정책·지원 버전을 합의한다.
2. 협의와 병행하여 독립적인 FE-01~04를 진행한다.
3. 데이터 손실에 영향을 주는 BE-01·CO-01을 우선 구현하고 함께 회귀 검증한다.
4. BE-02 파일 정리, FE-05~08, BE-03~04를 진행한다.
5. CO-02와 관련 프론트를 합의한 계약에 맞게 구현한다.
6. 실제 서버 연결·배포 버전을 확인하고 공동 검증 후 완료 처리한다.

공동 계약이 필요한 부분을 추정 구현한 뒤 상대 서버가 이미 지원한다고 가정하지 않는다. 프론트에서 AI·백엔드의 데이터 손실을 숨기거나 없는 결과를 생성하지 않는다.

- CO-02의 중복 조회 API·저장 차단 UI는 아직 구현하지 않았다.

## 6. 별도 보완 및 후속 협의

- 테스트 자료: 10MiB 성공 경계 샘플 교체, 03번 자료의 빈 DB 선행 실행 안내. 기본 14개 외 보완 작업이다.
- Journey 결과 수준: 성장 확인·가능성·판단 보류를 표현할 필드를 AI·백엔드와 합의한 후 프론트에 표시한다. 요약 문장으로 추측하지 않는다.
- 손상 PDF 오류 분류 등 AI 단독 수정이 필요한 사항은 AI 담당자에게 전달한다.
- F3 활동 정보 추출 누락은 AI 담당 범위이며 BE-01과 같은 저장·삭제 흐름에서 함께 재검증한다.
